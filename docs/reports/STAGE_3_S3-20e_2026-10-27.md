# S3-20e — bounded RIP-relative MOV memory sites

**Date:** 2026-10-27. **Status:** implementation complete locally; independent review pending. Physical Mac mini validation is deferred to the final S3-21 gate after local Stage 3 work.

## Scope

The V2 production compiler admits only qword `48 8B/89 /r` with ModRM `mod=00,r/m=101`, RAX..RBX data register, signed disp32, exactly seven instruction bytes, and no extra prefixes or trailing bytes. `long_decode::decode` remains the sole decoder. The immutable site binds the seven source bytes to the decoded `MemoryOperand` and decoder-derived `next_rip`. Runtime requires `state.rip == site.guest_rip` and calls `MemoryOperand::access_address_48(state, site.next_rip)`; no emitter or host-side target calculation was added.

Load and store retain their existing V2 ABI and commit ordering. Store still requires the private synchronous ordinary-RAM unsafe capability; code/executable aliases remain prohibited. This slice does not add general IR, PC maps, caching, rebasing, or other RIP-relative forms.

## Local evidence

- `od-jit` compiler coverage exercises load and store for all four data registers and displacements `i32::MIN, -8, -7, -1, 0, 1, 8, i32::MAX`. The instruction is placed after two bytes in its `CodeView`; tests verify exact source identity, seven-byte length, `AddressBase::NextRip`, displacement, and `next_rip`.
- Negative profile cases reject truncated displacement, trailing bytes, other ModRM modes, unsupported registers, prefixes, and other existing out-of-profile forms.
- Native ARM64 differential cases exercise both operations, all four data registers, and all eight displacements at two distinct guest RIPs (128 cases); this boundary matrix covers fault behavior where targets leave fixture RAM. A focused success test separately uses identical seven-byte instructions at RIPs `0x100` and `0x180`, both inside GuestMemory, with disp32 `+0x20`; it verifies distinct effective targets (`RIP + 7 + 0x20`), distinct load values, and one store changing only its computed target. Its immutable source snapshot is held outside the independent mutable data-RAM backing. Full CPU state and RAM are compared against `od_isa::execute::step` on independent copies, including RIP, retirement, GPRs, and RFLAGS.
- Additional native checks verify stale entry RIP rejection before memory access, a noncanonical NextRip+disp32 address rejected before GuestMemory access, and a RIP-relative store that raises STOP only after one successful write and architectural retirement.
- The targeted `cargo test -p od-jit --offline memory_load_v2` passed 8 tests. The targeted host differential test passed after adding this slice.
- Final local suites passed: `cargo test -p od-jit --offline` (110 tests), `cargo test -p od-host --offline` (41 tests), `cargo check --workspace --all-targets --offline`, `cargo fmt --all -- --check`, and `git diff --check`. The targeted S3-20e host tests were rerun after adding the in-RAM success cases.
- `graphify update .` completed. The changed-file list contains only `crates/od-host/src/lib.rs`, `crates/od-jit/src/memory_load_v2.rs`, `crates/od-jit/src/runtime.rs`, and S3-20e docs; no Stage 2 paths were edited. Local host: macOS 26.7.1, arm64.

## Checks and limits

No physical Mac mini test was run. The local ARM64 macOS results are not physical x86 evidence and do not close S3-21.

Unsupported: other prefixes/overrides, tail bytes, non-`mod=00,r/m=101` RIP forms, other data registers, and any claim of generic RIP-relative lowering. Independent reviewer status: pending.
