# S4-16d: tracked code-walk writes invalidate aliased code

**Status:** accepted after independent code and documentation review. Parent
S4-16 and Stage 4 remain open.

## Scope

One vCPU, fixed Long64 paging snapshot, one captured physical RAM code page,
two aliases, and inactive native blocks. The slice forwards actual committed
page-walker A/D writes from the existing tracked snapshot and alias-patch APIs
into the host session's physical-code-page reconciliation. It does not add TLB
semantics, page-table remapping policy, cross-page code, additional writers,
MMIO/DMA, SMP, or active native-block retirement.

## Implementation

- Added callback-bearing `MachineBus::tracked_code_snapshot_with_callback` and
  `patch_tracked_code_byte_with_callback`. Existing methods preserve their
  interface and delegate with a no-op callback.
- Snapshot callbacks report physical page-walker writes in order, even if a
  later walk or physical backing check fails. Patch callbacks report committed
  writes from the read preflight, write walk, and operand byte in their actual
  order. An error can retain earlier A/D writes but never reports an uncommitted
  patch byte.
- `PagedCodeSession::execute_alias` and `patch_alias_byte` reconcile all
  callback ranges before propagating snapshot, identity/admission, or patch
  results. An overlap with the captured code page advances the view to its
  current generation and invalidates both idle alias entries before any later
  lookup/publication.

## Evidence

- Successful alias patch callback order: four read-preflight Accessed writes at
  `0x1000`, `0x2000`, `0x3000`, and `0x4020`; write-walk Dirty update at
  `0x4020`; committed patch byte at `0x7002`.
- Snapshot fault at linear `0x4000_0000_0000`: exact committed callbacks at
  `0x7400` and `0x2000`, followed by a non-present mapping page fault with CR2
  equal to the requested address and PFEC `0x14`.
- CPL3 patch write-protection fault at linear `0x0040_1202`: exact callbacks at
  `0x7000`, `0x2000`, `0x3010`, and `0x4008`; #PF CR2 is `0x0040_1202`, PFEC is
  `0x7`, and no operand callback is reported.
- Expected-frame mismatch after the read preflight: the same four Accessed
  callbacks are preserved; expected page is `0x8000`, actual physical operand
  address is `0x7202`, and no write walk or patch-byte notification occurs.
- Host integration warms both aliases. In the patch-error case, changing the
  PDPT on physical page `0x2000` leaves code generation unchanged; the read
  preflight commits the alternate PDE Accessed update at `0x7010`, then the
  write walk faults. The code immediate remains unchanged and both cache
  entries are cleared before returning the error. In the snapshot-error case,
  the unused PML4 entry at `0x7400` has A=0
  before the call; the fetch sets it, then faults at a missing PDE. Both cache
  entries are cleared and caller CPU state is unchanged.

## Limitations

This closes committed A/D notification for the current tracked snapshot and
one-byte alias-patch paths. It does not generalize notifications to every
physical or device writer and does not add TLB/remap invalidation, cross-page
code, MMIO/DMA, SMP, or active-block retirement. No performance measurements or
speed claim are made.
