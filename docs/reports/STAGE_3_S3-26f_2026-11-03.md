## Scope

The only newly admitted pair is the exact six-byte source
`48 89 03 48 89 02` (`MOV [RBX],RAX; MOV [RDX],RAX`). It uses the existing
uncached typed-IR two-site V2 entry. Site 0 binds `[RBX]` at `A`; site 1 binds
`[RDX]` at `A+3`; each writes the eight-byte RAX value through its own checked
helper. The shared IR contains two ordered stores and separate instruction
commits. The generated entry's second checked-store helper resolves to
operation index 4 in `[Begin, Store, Commit, Begin, Store, Commit, Exit]`.

Each individual write requires private synchronous ordinary RAM and an
all-or-nothing eight-byte callback. The two writes are ordered but the pair is
not transactional: a second-site guest fault leaves the first write committed
and returns at `A+3` with one instruction retired. Equal effective addresses
still cause two callbacks. Owner/MMU integration, MMIO, concurrent vCPUs,
executable backing and production memory ownership remain outside scope.
`CachedPublishedMemoryPairBackend` explicitly rejects `StoreThenStore`.

## Added evidence

- JIT fixture asserts the exact source bytes, sequence kind, both site indices,
  operation kinds, source GPR, base registers, RIPs and next RIPs, and the
  two-site PC-map contract. It rejects altered payload/base encodings and a
  neighboring displacement form.
- Lowering fixture asserts two separate checked stores and commits in guest
  order, with RAX payload, RBX/RDX address bases, and terminal RIP `A+6`.
- PC-map table includes the new sequence and checks both helper sites, commit
  phases, `A+3`/`A+6` retired boundaries, and absence of replayable post-helper
  ranges.
- Host fixture compares full CPU state and RAM against two interpreter steps,
  records write addresses and payloads, and keeps two callbacks when addresses
  are equal. It covers first-write fault with no architectural or RAM commit;
  second-write fault with the first write preserved, full GPR/flags unchanged,
  RIP `A+3`, retired count 1, remaining budget 1, and the second fault payload;
  a repeated second-site fault, same-artifact continuation and singleton retry
  without replaying site 0; backend errors as host errors; budgets 0/1/2;
  entry STOP, stop-RIP `A+3`, STOP raised by the first write, and a failed
  callback that raises STOP where the guest fault wins. It also asserts cached
  publication rejection.
- Uncached dispatch fixture records that the initial entry is compiled as a
  pair and that continuation at `A+3` compiles only the second singleton.
- Local Stage 3 harness identities pin both JIT cases and the host lifecycle
  case. A harness self-check validates uniqueness, source coverage and exact
  gate registration.
