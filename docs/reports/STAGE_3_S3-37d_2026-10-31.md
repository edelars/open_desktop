# Stage 3 S3-37d: first complete FIFO16 lifecycle stress run

## Result

The first completed v4 scored process ran the recommended 29,682,315 epochs
and exited successfully after 439.481992708 seconds (7 minutes 19.482
seconds). It completed below the profile's 660-second minimum by
220.518007292 seconds. This is a completed lifecycle and counter result, but
it does not meet the planned sustained-duration acceptance. No second scored
process was started.

Earlier attempts that overlapped Stage 2 are inconclusive and are excluded
from this report. Run1 started after a fresh two-snapshot quiet window. No
Stage 2 process was observed during the completed run or in the completion
inventory.

## Lifecycle and counter evidence

All 29,682,315 epochs completed on the existing FIFO16 path. The report has
128 bounded checkpoints, a 16-entry high-water, and a full 16-entry cache at
the final post-refill snapshot. Final current resident code is 22,572 bytes
and current logical metadata is 52,236 bytes; their high-water values are
23,744 bytes and 54,160 bytes. The final arena snapshot has 16 total slots and
zero free slots because the cache was refilled after the last clear.

For `E = 29,682,315`, `C = floor(E/128) = 231,893`, and
`R = floor(E/512) = 57,973`, the cumulative totals reconcile exactly:

| Counter | Reported | Expected |
| --- | ---: | ---: |
| Hits | 59,364,630 | `2E` |
| Misses, compiles, publications | 63,074,934 each | `16 + 2E + 16C` |
| Evictions, invalidations, invalidated entries | 29,682,315 each | `E` |
| Dispatches and blocks executed | 122,439,564 each | `16 + 4E + 16C` |
| Periodic clears | 231,893 | `C` |
| Runtime reopens | 57,973 | `R` |
| Checkpoints | 128 | 128 |

The runner's parity contract checked full GPR state, RIP, masked flags, exit,
budget, and retired-instruction count for each dispatch against the
interpreter oracle. It also checked distinct interpreter results for the two
code versions and invalidated the old backing before dispatching the new
version. Periodic clear assertions required zero current resident entries,
code, and metadata and all 16 arena slots before refilling. These checks are
internal assertions whose aggregate counters are serialized in the scored
report.

## Timing evidence and calibration mismatch

The v4 calibration observed 11,313,582 ns of epoch-body time across only 512
epochs (22,096 ns per epoch). Its 128 report/RSS checkpoints therefore occurred
every four epochs. It measured 1.981 seconds of checkpoint time and 2.159
seconds of fixed process cost, then projected 660.000014 seconds for the
recommended count.

The scored process reports 432.315102379 seconds of epoch-body time, or
14,564.737 ns per epoch, plus 2.210876324 seconds of checkpoint time. The
remaining reported process time is 4.956014005 seconds. Recomputing each
checkpoint interval from differences in cumulative epoch-body time gives a
minimum 14,162.379 ns, median 14,541.535 ns, maximum 15,300.932 ns, and first
interval 14,235.005 ns per epoch. The sample rates are consistent across the
run. These measurements establish a mismatch between the v4 calibration sample
and this scored run; they do not identify its cause.

Process RSS was 6,062,080 bytes before runtime creation, 8,945,664 bytes after
stress and before runtime drop, and 8,896,512 bytes after drop. RSS is
process-wide auxiliary evidence; it does not establish cache attribution or
prove leak-free behavior.

## Scope and next step

This run exercises supported cache APIs with one runtime and one arena at a
time. It does not test production owner notification, guest-write SMC,
active-code modification, guest faults, simultaneous arenas, SMP, or
leak-free behavior. The duration miss prompted the v5 calibration methodology
slice; its source review and recalibration are pending. This v4 run remains
useful for the completed sequence, parity, exact counter totals, occupancy,
and auxiliary resource snapshots, but it is not a passing sustained-duration
result and must not be combined with future v5 runs.
