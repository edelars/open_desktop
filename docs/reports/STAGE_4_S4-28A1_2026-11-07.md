# S4-28a1 — one-shot Local APIC timer device

## Result

Added an opt-in one-shot Local APIC timer profile to the existing `LocalApic`
MMIO device. The profile supports LVT Timer, Initial Count, read-only Current
Count and Divide Configuration registers. It uses an explicit nonzero timer
frequency, separate from TSC frequency, and a caller-driven `VirtualClock` with
a private capacity-one deadline queue.

Writing zero to Initial Count cancels the timer. A nonzero write atomically
arms or replaces its deadline. The current count is derived from elapsed
virtual time. At most one due event is dispatched per call: an unmasked expiry
requests its fixed-edge vector in IRR; masked expiry consumes the deadline
without requesting an interrupt. Queue generations make extracted events stale
after rearm, cancellation and reset. APIC reset, global disable and software
disable preserve the timer invariants. Software disable with a queued deadline
is rejected; disabling an idle APIC masks the timer LVT, and unmasking while
disabled is rejected. Divider writes are admitted only while no deadline is
active. A timer vector may share the IOAPIC level vector only while the timer
LVT is masked.

The implementation follows the one-shot, divider, count, vector and software
disable register profile described in Intel SDM Volume 3A §§11.4.7.2, 12.5.2
and 12.5.4 ([release 089](https://cdrdv2-public.intel.com/868137/325462-sdm-vol-1-2abcd-3abcd-4.pdf)).

## Boundaries

The timer owns a separate caller-driven clock; it is not connected to a vCPU
session or production scheduler. Time advancement and due dispatch are explicit
host operations. There is no CPU interrupt entry, HLT wakeup, periodic or
TSC-deadline mode, general event pump, or Linux timer-profile evidence. Parent
S4-28, S4-27 and Stage 4 remain open. No new confirmed issue was found for
`KNOWN_ISSUES.md`.
