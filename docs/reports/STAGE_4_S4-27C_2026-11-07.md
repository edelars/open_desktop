# S4-27c — caller-driven STI-profile APIC quantum

## Result

Added `DiagnosticVcpuSession::run_sti_apic_quantum` as an opt-in caller-driven
one-instruction-budget operation. Each invocation checks one APIC-eligible
vector at the supplied boundary. When IF and STI-shadow state permit delivery,
the method performs interrupt entry, acknowledges the exact vector, then
attempts one handler instruction through the same existing STI profile. With
no eligible vector it attempts one ordinary instruction through that profile.
The old S4-27a `DiagnosticInterruptResult` remains unchanged; the new method
has its own result type.

The operation preserves STI inhibition across calls. The current exact
`NonPviLong64V1` profile admits CLI/STI with IF clear and shadow clear, STI with
IF set and shadow clear, and NOP/STI/CLI with IF set and a blocking shadow.
Consequently, a held APIC request remains pending through `CLI; STI; NOP` and
can be delivered at the following caller boundary. The profile is intentionally
not a general-purpose instruction runner. A handler instruction outside that
profile becomes terminal after successful entry; the committed entry and APIC
acknowledgement are not undone.

Admission checks happen before APIC selection or guest-memory access. The
session must be Runnable, Long64/CPL0, explicitly Running, carry an explicit
STI-shadow state and `rflags_defined = INTEGER_FLAGS`, have no configured
TSC/RDTSC or CR0/CR3/CR4, and track a completed instruction boundary. Invalid
Blocking+IF=0 is rejected without mutation. A partial REP iteration-budget
exit invalidates the boundary and blocks this quantum, S4-27a delivery and
IRETQ until a normal `run()` retires the instruction.

## Boundaries

This remains a caller-driven flat identity diagnostic profile. It does not
support arbitrary guest instructions, MOV SS/NMI scheduling, HLT wakeup,
TSC/RDTSC, REP continuation within the STI quantum, JIT exits, automatic EOI
or IRET, board registration or Linux acceptance. Parent S4-27 and Stage 4
remain open.
