# S3-40ae Unit-variant predicates in interpreter RUN on M1 Pro

The stock and candidate builds use the same `5275d67` sources and the
S3-40z public RUN driver. The candidate replaces six equality predicates
with `matches!` for the unit variants `Fxam`, `Fsqrt`, `Fprem`,
`Fprem1`, `Fucomp` and `FldM64FpRax`. The conditions and their order
stay equivalent. The measured input sequences contain only MOV
instructions and reach these checks during execution.
[Previous public RUN measurements](STAGE_3_S3-40z_2026-11-19.md)

Separate four-second profiles on the M1 Pro used `/usr/bin/sample`
with a 1 ms interval. In ordinary RUN, `Operation::eq` was at the top
of 285 samples in the current image and 202 in the historical image.
In the predecoded S3-40ac runs the counts were 445 and 292. For the
current predecoded image, disassembly confirmed direct call sites for
149 equality samples. The six sampled unit predicates guided the patch.
The profiles supply call-site evidence. The paired series below
supplies elapsed times.

For the signed M1 Pro binaries, disassembly followed the benchmark's
public RUN call to the timed `FixtureMemory` STEP specialization.
It confirmed 99 static `Operation::eq` calls in stock and 93 in the
candidate. All six selected calls disappeared. Both untimed M1 checks
covered 2,400 frozen MOV inputs at budgets 0, 1 and 2 and the separate
zero-budget unmapped-code case. They verified CPU state, defined flags,
RAM, ordered callbacks, retirement and budget exit. In the separate
local workspace both builds passed all 2,609 `od-isa` tests, including
20 focused x87 cases.

## Results

The six paired rounds alternated build order and sequence order.
Each process used all six permutations of budgets 0, 1 and 2.
The fixed S3-40z counts were 4,374,000 calls per interval for store
then load and 4,339,200 for load then store. The series retained
432 intervals and 1,882,051,200 RUN calls. The shortest interval
was 103.477 ms, above the 45 ms floor.

The candidate reduced time by 5.62% and 6.74% at budget 1 and by
6.33% and 6.25% at budget 2, using the paired medians. Both sequences
improved in every paired round at both nonzero budgets. The zero-budget
ranges included 1.0. The measured patch is used in the interpreter.
The timings cover the full linked RUN path on this M1 Pro. The residual
historical performance gap remains open in ISSUE-521.
[Interpreter performance issue](../KNOWN_ISSUES.md#issue-521)

## Environment and reproduction

MacBookPro18,3, Apple M1 Pro, eight logical CPUs, macOS 14.6.1
(23G93), Xcode 15.4 (15F31d), Rust and Cargo 1.99.0, and Python 3.12.5.
The signed ARM64 release builds used minimum macOS 14.0 and SDK 14.5.
Both passed strict signature verification with Hardened Runtime and
`allow-jit`.

The machine was on AC power. All twelve scored processes recorded
UID 501, nice −5 and QoS `0x21`. The 24 preflight probes ranged
from 82.5% to 84.6% idle CPU, with a median of 83.85%. The 41 probes
in the run monitor ranged from 69.9% to 98.1%, with a median of 76.6%.

checkout with `5275d67` and the S3-40m, S3-40w and S3-40z archives.

untimed checks and host monitoring. `python3 offline_audit.py
