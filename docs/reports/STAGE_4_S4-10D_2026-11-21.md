# S4-10d: матрица прав, XD и reserved bits 2 MiB leaf, 2026-11-21

Статус: тесты реализованы и проходят локально; ревью не проводилось, в плане не отмечено.
Родители S4-10 и S4-10b-полный остаются открытыми. Код walker не менялся: матрица подтвердила
текущее поведение `access_long64_2m_ram` и родственных точек входа.

## Что сделано

Новый тестовый модуль `crates/od-machine/src/page_walk_2m_matrix_tests.rs` (подключён в `lib.rs`
под `#[cfg(test)]`) закрывает оговорку S4-10b «не покрыта полная матрица U/S, R/W, WP, NX/NXE по
уровням» для 2 MiB leaf (PDE PS=1) в IA-32e, предпосылку S7-32 (S8-01).

- Независимая reference-модель по Intel SDM vol. 3A, таблица 4-18 и разделы про права доступа и
  PFEC: user-отказ, write-отказ (Ring3 или WP=1), fetch-отказ только при NXE=1, XD при NXE=0 —
  reserved bit на первом уровне, где он стоит; I/D в PFEC только при NXE=1.
- Полная матрица 2 (2 MiB / 4 KiB leaf) x 5 вариантов предков (разрешающие, PML4 R/W=0, PDPTE U/S=0,
  XD на PML4E, XD на PDPTE) x 8 комбинаций R/W, U/S, XD листа x Ring0/Ring3 x Read/Write/Fetch x WP
  x NXE = 1920 случаев: класс исхода, точный PFEC, CR2, причина (`ReservedBits` с уровнем и битом 63
  либо `Protection`), A на всех пройденных entry, D только на листе при успешной записи, D не
  ставится при любой ошибке, операнд не записывается при отказе.
- Паритет: 2 MiB leaf и 4 KiB leaf с теми же правами дают одинаковые PFEC, CR2 и класс исхода.
- Единый walker: `translate_long64_2m_ram_read_only` (без коммита, та же ошибка) и
  `translate_long64_2m_ram_write_check` (A без D, операнд не записан, та же ошибка) совпадают с
  tracked-доступом на всей матрице 2 MiB.
- Reserved bits PDE: каждый из бит 20:13 и 51:36 даёт #PF P|RSVD (+W/U/I по доступу) на уровне Pd с
  offending_bits = этот бит, A только на предках; бит 12 (PAT), 8 (G), 11:9, 58:52, 62:59, PWT/PCD
  трансляцию не меняют; PS=1 без P — not-present на PD.
- XD в листе: блокирует только fetch (PFEC 0x11), чтения и записи проходят; при NXE=0 бит 63 —
  reserved для любого доступа, I/D=0.
- Геометрия: страницы 2 MiB с базой 0 и 0x200000, смещения от 0 до 0x1fffff; лист за границей RAM —
  `OperandPhysical`, не гостевой fault.

## Не входит и открыто

Невыполненная часть родителя S4-10 не изменилась: 1 GiB leaves (не объявляются, S4-10c даёт
#PF RSVD для PDPTE.PS), иные paging modes, TLB, SMEP/SMAP/PKU (CR4 их не допускает), MMIO-операнд
на уровне CPU-шага `step_paged_mov_2m_ram`, fetch RIP внутри 2 MiB в отдельном CPU-тесте, Linux boot
prerequisites и системная приёмка. CPUID-биты не объявляются (S2-57).
