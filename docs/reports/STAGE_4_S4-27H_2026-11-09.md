# Stage 4 S4-27h — paged IRQ entry и IRETQ (разовый handler)

Статус: срез реализован; независимое ревью (Opus, high) ещё не проведено. Срез не
закрывает S4-27, S4-33 и Stage 4. В плане `[x]` не ставился. Оговорка «только плоская
identity» в S4-27 снята для одного профиля (формулировка ниже); статус S4-27 в плане не
менялся. Решения консультации Opus (S4-27h, 2026-11-09) применены; отступления перечислены.

## Что найдено до реализации

- **Внешний вектор на paged-кадре не принимался.** `od_isa::deliver_maskable_interrupt`
  отвергал любой CPU-state с `cr0`/`cr3`/`cr4` (`OutsideProfile(UnsupportedCr0State |
  UnsupportedCr3State)`), единственные потребители (`DiagnosticVcpuSession::
  deliver_interrupt_and_step`, `run_apic_quantum`, `deliver_pending_irq`) работают через
  `IdentityMemoryAdapter`. Paged delivery (`deliver_paged_page_fault`, S4-19b) жёстко
  завязан на вектор 14/8, шесть qword кадра и `PageFaultRecord`. Это было сообщено
  координатору до реализации; решения по трём вопросам получены (Q1 доставка, Q2 EOI,
  Q3 отказ).
- **IRETQ paged есть** (`step_paged_iretq`, S4-19e1): пятиqwordный кадр, CR0/CR4 = BASE,
  EFER = `0xD00`. Подходит без изменений.
- **EOI-store на paged коде не было:** paged MOV-профили — qword и база RBX
  (`48 89 0b`), запись только в RAM (`PagedExceptionMemory`). Dword-запись в MMIO
  Local APIC требует нового точного профиля. MMIO-диспатч есть в `MachineBus::
  access_tracked` и `PagedMovMemoryAdapter`.
- **Local APIC по умолчанию не готов принимать:** `SVR = 0xFF` (бит 8 software enable = 0),
  `eligible()` пуст. Загрузчик профиля включает APIC записью `0x1FF` в SVR.

## Что сделано

- **`od-isa`** (`crates/od-isa/src/interrupt.rs`): `deliver_paged_maskable_interrupt` —
  второй фронт общего приватного тела `deliver_interrupt`; предусловия CR0/CR4 = BASE,
  `cr3 < 2^36`, EFER = `0xD00`; запись кадра как `AccessOrigin::ImplicitStack`
  (flat-фронт пишет `Explicit` — расхождение записано в контракте). Flat-поведение не
  менялось (все прежние тесты зелёные), добавлено 2 теста paged-фронта.
- **`od-isa`** (`crates/od-isa/src/execute.rs`): `step_paged_mov_dword_store`
  (`PagedMovDwordStoreLong64V1`) — точный `89 03` (`MOV [RBX],EAX`): fetch (оба байта в
  одной странице), затем запись одного dword (не пересекает 4 KiB; не-канонический RBX —
  #GP(0)). Отступление от решения консультации: автономный шаг по образцу
  `step_paged_lidt`, а не запись в таблицы `Cr0Profile`/`Cr4Profile` интерпретатора как
  `PagedMovCrossPageDwordReadLong64V1` (исполнитель не расширялся; семантика и память с MMIO
  те же).
- **`od-machine`:** `deliver_paged_external_interrupt` (`paged_exception_delivery.rs`,
  `PagedExceptionMemory`, `descriptor_accessed_target: None`, без #DF);
  `step_paged_mov_dword_store` и `PagedDwordStoreStepReport` (`paged_memory_adapter.rs`,
  флаг `dword_write_profile` у `PagedMovMemoryAdapter` с MMIO-диспатчем);
  `stage4_paged_irq_probe.rs` — профиль `Stage4PagedIrqProbeV1`, последовательность шагов,
  инъекции, строгий загрузчик образа.
- **Fixture** `tests/fixtures/guest/stage4/paged_irq/` (`entry.S`, `layout.ld`): таблицы
  (пять страниц), main (`INVLPG [RBX]` дважды), handler (`89 03`, `48 CF`), IDT (вектор `0x41`),
  GDT, страница стека; страница Local APIC отображена на `0x602000`.
- **Builder** `tools/build/build_stage4_paged_irq_probe.py` + `test_build_stage4_paged_irq_probe.py`:
  manifest с mappings, IDT-входом, ожидаемыми PTE (initial, final, A/D) и кадром.
- **Runner** `--stage4-paged-irq-probe IMAGE [--budget N] [--inject-idt-gate-not-present |
  --inject-stack-readonly | --inject-handler-without-eoi]`
  (`tools/runner/src/stage4_paged_irq_probe.rs`, `main.rs`) +
  `tools/runner/tests/stage4_paged_irq_build_cli.rs`.
- **Документы:** `docs/specs/MACHINE_CONTRACT.md` (раздел S4-27h), `docs/testing/MACHINE.md`
  (пункт 64), этот отчёт, данные
  [`s4-27h-paged-irq.json`](data/stage4/s4-27h-paged-irq.json). В плане (S4-27h) заменено
  «host error» на «архитектурная причина» по решению консультации.
- **Выбор main:** два `INVLPG [RBX]` — уже принятый точный paged-шаг без обращения к данным.
  MOV-профили (`48 89 0b`, `48 8b 03`) используют RBX, а он нужен handler'у как адрес EOI;
  `INVLPG` не расходует RBX и ничего не пишет.

## Границы и модельные расхождения

- Отказы доставки терминальны; аппаратный исход — последовательный #PF (стек) или #NP
  (gate P=0); вложенная доставка, #DF и shutdown — S4-33. Слово «host error» не
  используется: причина — архитектурная.
- Подтверждение IRR -> ISR «после входа» расходится с INTA на железе (вектор выбирает APIC
  до записи кадра); решить в S4-33.
- Для S4-34 (KVM) инъекция read-only стека на железе даст shutdown/reset: результат
  model-only, не сравним.
- Тип памяти страницы APIC (PCD/PWT/PAT) не моделируется; A-бит дескриптора CS не пишется
  (должен быть выставлен); один вектор; IST = 0; CPL0.
- Включение APIC (SVR) выполняет загрузчик профиля, а не гость.
- Не входит: вложенные #PF/#NP/#DF, CPL3 (TSS RSP0), paged STI и HLT, `run_apic_quantum`
  на paged, event pump (S4-27i), JIT, 2 MiB, TLB, SMAP/SMEP, x2APIC, MOV SS, NMI,
  подключение к плате.
- Риск: Linux гасит EOI через `movl` с disp32 при CR0 `0x80050033`, шире BASE; exact-профили
  не масштабируются, нужен S4-27i.

## Снятие оговорки в S4-27

«Оговорка "только плоская identity" снята для одного профиля: одиночный внешний APIC-вектор,
Long64/CPL0, 4 KiB (S4-32), CR0/CR4=BASE, EFER=0xD00, gate `0xE` с IST=0 без смены CPL,
handler `89 03` + `48 CF` (S4-27h). STI/HLT/`run_apic_quantum`/JIT остаются flat-only до
S4-27i; вложенные события при доставке — S4-33.»
