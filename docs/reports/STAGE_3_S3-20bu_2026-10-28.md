# Stage 3 S3-20bu: address32 indexed SIB with RSP base and RSI/RDI index

## Implemented profile

Added the exact qword singleton forms `67 48 8B/89 /r sib`, with ModRM `mod=00/01/10,r/m=100`, SIB base RSP, index RSI or RDI, scale 1/2/4/8, data RAX..RBP, and lengths 5/6/9. Effective-address calculation remains solely decoder-owned `MemoryOperand::access_address_48`: `(low32(old RSP)+low32(old index)*scale+signed displacement) mod 2^32`, then zero-extended for the qword transfer. A data=RSP load uses the old RSP for its address and commits the new RSP only after a successful read; a data=RSP store uses the old RSP payload. RSI/RDI are address-only indices and remain preserved.

Exact admission is wired through the checked block builder, shared IR validator, direct V2 metadata/source validator, runtime site validator, and bounded dispatcher. The profile does not widen the generic register whitelist, add other base/index forms, or change pair/V3 handling. This remains borrowed fixture evidence; production owner/MMU integration is open.

## Evidence

- JIT descriptor and host matrices cover load/store, data RAX..RBP, both index registers, all four scales, and no-displacement/disp8/disp32 forms with signed boundary values. Direct V2, shared IR, and interpreter executions are compared using independent state and RAM snapshots, including complete CPU/RAM state, decoded EA, callback address/width/count, and retirement.
- Host cases verify upper-half truncation, modulo-32 product/add wrap, and one contiguous qword callback across the 4 GiB boundary. Two immutable nine-byte sources differing only in the final displacement byte produce expected targets `0x30` and `0x0100_0030`.
- Architectural and backend load/store failures preserve state and RAM; the data=RSP store+STOP case uses the pre-state RSP as its address and payload, commits the qword once, and returns at the exact next RIP. Entry STOP, stop-RIP, and zero budget produce no callbacks. Partial windows 1..8 and unsupported neighbors produce no memory effects.
- Dispatcher continuation covers the 5-, 6-, and 9-byte forms from actual RIP with budget splitting and no replay; the subsequent NOP fallback and existing native pair retain their retirement accounting.
- Older negative fixtures that used forms now admitted by this profile were changed to genuinely unsupported data/base shapes. Existing S3-20 profiles remain covered.
