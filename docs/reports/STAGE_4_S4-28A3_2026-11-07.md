# S4-28a3 — shared one-shot APIC timer wakes HLT wait

## Result

`DiagnosticHaltWait` now retains the session's unique `VirtualClockAdvancer`.
The caller may advance virtual time only while the wait is `Waiting`, explicitly
dispatch a due Local APIC one-shot event, then poll the existing APIC wake path.
After the handler and same-CPL IRETQ, the resumed RDTSC observes the time that
advanced during HLT.

## State and atomicity

The lifecycle is caller-driven: `Runnable → Waiting → Entered → Runnable`.
While Waiting, the timer dispatch gate is open and `DiagnosticHaltWait` owns
the only advancement capability. Before `poll_apic` inspects IF/vector or
performs guest memory callbacks, it closes the dispatch gate and releases the
clock lock. No eligible vector or `OutsideProfile` returns to Waiting and
reopens dispatch. Successful entry, STOP, terminal failure and advancer drop
leave the gate closed; `into_running` reopens it after committed entry.

Timer expiry dispatch locks APIC pair state first, then the shared clock. It
checks the gate and deadline, removes the queue event and publishes IRR while
both locks are held. This makes STOP/wake gate closure linearizable against
IRR publication. Neither lock is held over guest execution or bus callbacks.
APIC reset invalidates its timer deadline but preserves the session clock.
Overflow leaves clock and TSC unchanged.

The integration case verifies an overflowing wait advance is atomic, a 3 ns
one-shot expiration dispatches vector `0x40` into IRR, and APIC entry wakes the
HLT wait. It arms a second vector `0x41` while still Waiting, advances to that
deadline, confirms dispatch returns `Busy` while state is Entered without
losing the event, then returns to Runnable and dispatches it. After executing
the handler and IRETQ, guest RDTSC returns 5 at the advanced virtual time.

## Boundaries

Expiry, dispatch and wake are explicit caller operations; there is no automatic
poll loop, host monotonic-time source, periodic/TSC-deadline mode, NMI/debug
wake, production scheduler, or Linux timer acceptance. Full S4-22, S4-27,
S4-28 and Stage 4 remain open.
