## CPU → RAM path

The integration test executes `od_isa::execute::run` through
`IdentityMemoryAdapter → MachineBus → PhysicalMemory`. Its profile is
**diagnostic flat identity** (`linear == physical`), not the selected Ubuntu
Linux machine manifest.

The program contains three instructions:

1. `MOV RAX,[RBX]` loads the original qword from RAM.
2. `MOV [RBX],RCX` stores the replacement qword; the run retires two
   instructions and advances RIP to `0x1006`.
3. `MOV RCX,[RDX]` targets the unmapped hole at `0x3000` on the next run.

The first two instructions succeed. The first load puts the original qword in
RAX, and the store writes the replacement qword to RAM. The committed-write
callback reports exactly one range: the eight-byte write at the data address.
The third instruction returns `MemoryError::Backend` with zero instructions
retired. CPU state (including RIP at `0x1006`), RAM and the committed-write
callback history remain unchanged by that failed instruction.

## Separate page-walk snapshot control

The control test constructs immutable diagnostic snapshots from CPU state.
Changing the source state does not mutate the earlier snapshot. Explicit CR3
roots `0x1000` and `0x5000` select distinct literal translations (`0x5abc`
and `0x9abc`, respectively) for the same linear address. This verifies the
page-walk snapshot/probe boundary separately; it does not connect paging to the
CPU execution memory path.

## Non-claims

This baseline does not establish production CPU-integrated paging, `#PF`
delivery or retry, JIT memory behavior, privileged hardware behavior, or Linux
boot. The flat identity execution test and the separate page-walk snapshot
control do not combine into a Linux machine manifest.
