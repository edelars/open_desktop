# S3-36a — bounded resident warm benchmark

**Status:** three local release process runs completed for the bounded
resident register-only slice. The warm FIFO dispatcher remained slower than
the interpreter on this workload. This is partial S3-36 evidence; it does not
complete the branch/helper/memory workload matrix or Stage 3 performance gate.

## Scope and method

The opt-in command `od-bench warm-first-run` accepts only the frozen S3-17
case-list and trace hashes, admits the full 1,010-case input set, then selects
a deterministic prefix of complete cases whose summed per-case
`unique_entries` fit the FIFO(16) capacity. This sum is a conservative entry
budget, not a count of globally distinct keys; shared keys may make the actual
resident set smaller. The report retains the full case-list/trace provenance
and lists the selected case IDs and budget. All three runs selected 14 cases
with budget 16.

The full corpus cannot be treated as a resident warm workload with FIFO16. A
previous cold-run report recorded 1,320 misses/compiles and 2 hits for one
1,322-visit corpus sweep, showing that the corpus working set churns this
cache. The warm runner therefore measures an explicit resident subset rather
than mislabeling full-corpus churn as warm execution.

One FIFO runtime/cache/arena is initialized and warmed before calibration. The
same runtime remains alive through all calibration and measured samples.
Warmup dispatch time records only accumulated dispatch-call intervals,
excluding initialization, state cloning, and validation. Warmup reported 16
successful misses, compiles, and publications with zero eviction. Every
measured FIFO sample reported hits and zero miss/compile/publication/eviction
deltas. Interpreter and FIFO samples use the same selected cases, common
sweep count, reset state, budgets, and retirement checks; their order
alternates. State cloning/reset and result validation are outside timed calls.

## Results

The time values below use each report's integer-nanosecond
`median_ns_per_sweep`, converted to microseconds for one 14-case sweep. Each
paired ratio is the median of that report's
`paired_interpreter_over_fifo_ratios` array; both variants used equal sweeps
within each pair.

| Variant | Run 1 (µs/sweep) | Run 2 | Run 3 | Median across runs | Range across runs |
|---|---:|---:|---:|---:|---:|
| FIFO(16) warm block dispatcher | 12.129 | 12.343 | 12.218 | 12.218 | 12.129–12.343 |
| Interpreter | 2.019 | 2.045 | 2.053 | 2.045 | 2.019–2.053 |
| Paired interpreter/FIFO elapsed ratio | 0.166408 | 0.165960 | 0.168366 | 0.166408 | 0.165960–0.168366 |

The interpreter was about 6.0× faster for this selected hot register-only
slice. This describes only this workload and timer boundary; it does not
predict other inputs or guest programs. No general performance claim is
supported.

## Verification and limits

`cargo fmt -p od-bench -- --check` and `cargo check -p od-bench --all-targets
--offline` passed for the implementation. Three release benchmark runs were
collected as listed above. Mini/physical x86 and Stage 2 checks were not run.
Host power, thermal, and background-load telemetry was not recorded.

This path covers register-only cases, not branch-heavy/helper-heavy/memory
workloads, fallback frequency, or resource churn. S3-36 remains partial;
broader Stage 3 acceptance remains separate.
