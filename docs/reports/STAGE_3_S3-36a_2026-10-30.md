# S3-36a — bounded resident warm benchmark path

**Status:** the opt-in benchmark path is implemented and compiles. No warm
benchmark has been run. This is partial S3-36 tooling evidence only; it does
not establish a performance result or complete the Stage 3 warm-workload gate.

## Scope

The command `od-bench warm-first-run` accepts only the frozen S3-17 case-list
and trace hashes, admits the full 1,010-case input set, then selects a
deterministic prefix of complete cases whose summed per-case `unique_entries`
fit the FIFO(16) capacity. This sum is a conservative entry budget, not a
claim about globally distinct cache keys; shared keys may make the actual
resident set smaller. The report retains the full case-list/trace provenance
and lists the selected case IDs and entry budget. Only the selected
register-only slice is timed.

The full corpus cannot be treated as a resident warm workload with FIFO16. A
previous cold-run report recorded 1,320 misses/compiles and 2 hits for one
1,322-visit corpus sweep, which shows that the corpus working set churns this
cache. The warm runner therefore measures an explicit resident subset rather
than mislabeling full-corpus churn as warm execution.

## Measurement method

- One FIFO runtime/cache/arena is initialized and warmed before calibration.
  The same runtime remains alive through all calibration and measured samples.
  `warmup_dispatch_elapsed_ns` records only the accumulated dispatch-call
  intervals, excluding initialization, state cloning, and validation.
- Warmup must report successful misses, compiles, and publications with no
  eviction. Every later FIFO sample must report at least one hit and zero
  misses, compiles, publications, and evictions; otherwise the command fails.
- Interpreter and FIFO samples use the same selected cases, common sweep
  count, state reset, budgets, and retirement checks. Sample order alternates.
- State cloning/reset and outcome validation happen outside timed call
  intervals. The dispatcher timing includes lookup, dispatch, and native block
  execution; interpreter timing includes interpreter execution.
- Per-run output contains raw elapsed/work counts, normalized median/range/IQR,
  paired interpreter/FIFO ratios, cache counters, host metadata, and the frozen
  input fingerprints. Calibration and any measured-series restart are recorded.

Reproduction command after review:

```sh
cargo run --release -p od-bench --offline -- warm-first-run \
  --case-list work/tmp/stage3/s3-17/cases.txt \
  --trace work/tmp/stage3/s3-17/dispatch-trace.json \
  --process-run 1 \
  --output work/tmp/stage3/s3-36/warm-first-run-1.json
```

## Verification and limits

`cargo fmt -p od-bench -- --check` and `cargo check -p od-bench --all-targets
--offline` passed for this implementation. No benchmark, performance test,
Mini/physical x86 check, or Stage 2 check was run.

No timing output exists yet. The path covers register-only cases, not
branch-heavy/helper-heavy/memory workloads, fallback frequency, or resource
churn. The exact selected prefix and counter evidence depend on the frozen
fixture files available at measurement time. S3-36 remains open until reviewed
release runs are collected, and broader Stage 3 acceptance remains separate.
