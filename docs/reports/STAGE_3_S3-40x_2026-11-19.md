# S3-40x. Статически пустые профили для обычного STEP

Обычный STEP через `step_tracked_with_stop` использует специализацию
с `ExecutionProfiles::EMPTY`, уже применённую в обычном RUN. Общий
исполнитель получает контекст, маску определённых флагов и callback
STOP из вызывающего кода. Через тот же путь проходят обычные
инструкции в двух циклах продолжения REP.

## Методика

Базовая и экспериментальная сборки взяты из `d9ecaa2`. В кандидате
применено только изменение обычного STEP. Обе ARM64 Release-сборки
подписаны с Hardened Runtime и `allow-jit`. Измерялось на Apple M3 Max
(Mac15,11), macOS 26.7.1 (25G241), rustc 1.99.0. Все 14 измеряющих
процессов подтвердили обычный UID, `nice -5` и QoS `USER_INTERACTIVE`
до запуска таймеров.

Драйвер S3-40w повторяет 2 400 входов, по 1 200 на порядок операций.
Для проверки исполнения он сверяет состояния CPU и RAM, обращения и
завершение на заданном бюджете. Эталон STEP формируется через RUN той
же сборки. Отдельно измеряются полный RUN, два публичных STEP и два
декодирования. Общие числа проходов 2 210 и 2 146 дали по 2 652 000
и 2 575 200 пар на интервал. Шесть раундов чередуют порядок сборок,
а внутри каждого процесса проверяются все шесть порядков трёх
контролей. Аудит подтвердил 432 интервала и 1 129 075 200 измеренных
пар. Кратчайший интервал составил 79,807 мс при пороге 45 мс.

Первый запуск остановлен на пятом раунде после двух проб с
простоем ниже 15%. Его интервалы исключены. Непосредственно перед
зачётным запуском 12 проб дали 52,0–82,1% простоя CPU. Во время
второго запуска 30 проб дали 48,3–85,4%, медиана 73,85%.

## Результат

В таблице приведены медианы отношений candidate/baseline по шести
парным раундам. В скобках указаны минимум и максимум.

| Поток | Два STEP | RUN | Два decode |
| --- | ---: | ---: | ---: |
| Store → load | 0.747 [0.714, 0.786] | 1.009 [0.924, 1.061] | 1.004 [0.934, 1.009] |
| Load → store | 0.743 [0.723, 0.762] | 1.008 [0.981, 1.033] | 1.001 [0.973, 1.013] |

Время двух STEP снизилось во всех шести раундах для обоих потоков.
Медианы всех интервалов в нс/пару составили 351,5 → 257,4 и
346,8 → 259,3. Диапазоны RUN и decode пересекают единицу.
Устойчивой разницы времени контролей по этим замерам не установлено.
В подписанном измерительном Mach-O размер файла изменился с
1 262 320 до 1 061 424 байтов, секция `__TEXT,__text` с 815 292 до
631 100 байтов. Изменение принято по результатам STEP.

Обе изолированные Release-сборки прошли 22 теста bare RUN/STEP и
шесть точечных проверок. Они включают REP, undefined AF,
настроенный XORPD и fixed-seed корпус памяти. Для компиляции тестов
в изолированные исходники добавлены статические данные тестового
набора из того же пина. Архив сохраняет привязку этих данных и
хеши подписанных бинарников до и после тестов.

Дифференциальный тест
`execute::tests::bare_tracked_step_matches_configured_empty_profile`
сравнивает специализированный и прежний исполнитель с пустыми
профилями. Он прошёл в изолированном дереве на записи MOV, чтении
с `#PF` и остановке REP MOVSB после одной итерации. Проверяются
состояние CPU, RAM, порядок и контекст обращений, STOP и маска флагов.
В рабочем дереве полный набор `od-isa --lib` прошёл 2 609 тестов без
ошибок и пропусков. Форматирование и проверка всех целей workspace
в offline-режиме также прошли.
Результат замера относится к двум профилям S3-34a на локальном ARM64.
Оставшийся исторический разрыв полного RUN и ISSUE-521 открыты.

## Воспроизведение

[Архив с измерениями и исходниками](data/stage3/s3-40x-20261119/bare-step-controls.json.gz)
имеет SHA-256 `16ce134c1919d7480049671528a165a86d7f63e954087e35adfa2a9235e30219`.
В нём 73 файла, включая исходный патч, точные команды, CSV и stderr
измерений, нагрузку, проверки и метаданные сборок.
Для аудита извлеките `offline_audit.py` и `audit.py` из поля
`files`, сверьте их по `file_sha256` и запустите
`python3 offline_audit.py bare-step-controls.json.gz`.
Результат побайтово совпал с `run/audit.json`. Команды нового
прогона приведены в сохранённом `README.md`.
