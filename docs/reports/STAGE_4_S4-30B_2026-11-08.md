# Stage 4 S4-30b — legacy conf1 0xCF8/0xCFC поверх общей таблицы функций

Статус: ограниченный срез реализован и проверен локально; ревью (Opus, high) ещё не проведено. Родительский S4-30 остаётся открытым.

## Что сделано

`crates/od-machine/src/pci_ecam.rs`: `PciEcam` теперь обслуживает два пространства одним объектом. `IoSpace::Mmio` — окно ECAM (как в S4-30a), `IoSpace::Pio` — legacy conf1 в `0xCF8..=0xCFF`. Новые публичные константы `PCI_CONF1_BASE_PORT = 0xCF8`, `PCI_CONF1_PORT_BYTES = 8` (экспорт в `lib.rs`). Единственное новое состояние — 32-битный address latch.

## Выбранная архитектура и почему

Один объект `PciEcam`, один `device_index`, две привязки (`MmioBinding` и `PortRegionBinding`). `MachineBus` это допускает (проверено по `bus.rs`: привязки ссылаются на индекс устройства, уникальность требуется только для адресов; тот же приём уже применён в тесте шины). Чтение/запись функции идут через общие `config_read`/`config_write`, поэтому состояние ECAM и conf1 общее без `Rc<RefCell<…>>` и без нового слоя `PciConfigSpace`. Альтернатива (общее ядро + два адаптера) потребовала бы второго `BusDevice` с общим владением таблицей, то есть `Rc<RefCell<…>>`; она отвергнута как избыточная.

## Поведение

- 0xCF8: dword — латч. Хранятся биты 31, 23:16, 15:11, 10:8, 7:2 (маска `0x80FF_FFFC`); биты 30:24 и 1:0 отбрасываются при записи и читаются как 0. Байтовая/словная запись игнорируется, байтовое/словное чтение даёт все единицы (байты латча узким доступом не раскрываются).
- 0xCFC..=0xCFF: ширины 1/2/4; регистр = `(latch & 0xFC) + n`. bit31=0, bus≠0 или отсутствующая функция → чтение все единицы, запись игнорируется.
- 0xCFB, 0xCFA: байтовая/словная запись игнорируется, чтение все единицы.
- 0xCF9: reset control не реализован → `DeviceError::UnknownOffset` на байтовое чтение и запись; слово → `Misaligned`. Тихий игнор скрыл бы неработающий reset (ядро первым делает `inb(0xCF9)` и затем в любом случае переходит к `BOOT_TRIPLE`).
- Qword → `UnsupportedWidth` (шина отвергает раньше устройства; устройство тоже), невыровненный в блоке → `Misaligned`, выходящий за 0xCFF → `CrossesRegion` (шина). Ошибки — до изменения состояния.
- bus>0: conf1 даёт absent (все единицы); ECAM даёт `UnknownOffset` (зафиксировано тестом).

## Linux-пробы

Тексты сверены по `linux-source-7.0.0`, `arch/x86/pci/direct.c`: `pci_check_type1` строки 223–241, `pci_check_type2` строки 243–261 (совпадают с описанием ниже); `pci_sanity_check` — строки 204–216.

- `pci_check_type1`: `outb 0x01→0xCFB`; `tmp=inl 0xCF8`; `outl 0x80000000→0xCF8`; `inl 0xCF8 == 0x80000000`; `pci_sanity_check`; `outl tmp→0xCF8`. Тест воспроизводит последовательность через `MachineBus::read_port`/`write_port`. `pci_sanity_check` (`direct.c:204–216`) без host bridge и без DMI-года BIOS ≥ 2001 отвергает conf1; после этого Linux пробует conf2, и он тоже не проходит — ожидаемо, не дефект. На bus 0 нет ни одной функции с классом 0x0600/0x0300 или vendor Intel/Compaq (тестовый endpoint 00:03.0 не подходит), `pci=nochecks` не используется. Задача для S4-31/S4-38: DMI/SMBIOS с годом ≥ 2001 или функция класса host bridge/VGA на bus 0.
- `pci_check_type2`: `outb 0→0xCFB, 0xCF8, 0xCFA`; условие `inb(0xCF8)==0 && inb(0xCFA)==0`. Проба различает состояния: если бы байтовое чтение 0xCF8 раскрывало байт латча, то и при свежем латче (0), и после `0x80000000` (младший байт 0) условие прошло бы ложно, и Linux начал бы читать порты 0xC000–0xCFFF (`UnmappedPort`). Поэтому байтовые чтения 0xCF8/0xCFA возвращают 0xFF; тест `conf2_probe_is_rejected_for_any_latch_state` проверяет три состояния латча, что байтовые записи пробы латч не портят и что 0xC000 остаётся unmapped.

## Отклонение от формулировки задачи

Для 0xCFA запрос требовал явной ошибки, как для 0xCF9, и одновременно «записи байтовой/словной ширины в 0xCF8–0xCFB игнорируются» для conf2-пробы. Они несовместимы: проба делает `outb(0, 0xCFA)`, и ошибка устройства оборвала бы её до проверки `inb`. Выбрано: 0xCFA игнорирует запись и читается как все единицы, явная ошибка — только у 0xCF9. Если нужна ошибка и на 0xCFA, conf2-проба станет ошибкой шины, а не отказом.

## Ревью

- Первое независимое ревью (Claude Opus, high, read-only): блокеров нет. Вердикты по спорным пунктам: `0xCFA` — запись игнорируется, чтение `0xFF` (явная ошибка сломала бы conf2-пробу `outb(0, 0xCFA)`); `0xCF9` — `UnknownOffset` приемлем, отдельный вариант `DeviceError` не нужен. Замечания по документам и тестам (ссылки на `direct.c`, порядок `outb 0xCFB` → `inl 0xCF8`, обоснование 0xCF9, противоречие в S4-30a, комментарии тестов, дубль ветки `read_conf1`) исправлены.
- Повторное ревью затронутой части (тот же ревьюер): все пункты закрыты, кроме одной фактической неточности в условии `pci_sanity_check` (проверяются все функции bus 0, не только `00:00.0`; не упомянут `pci=nochecks`). Формулировка исправлена в контракте и в этом отчёте; комментарий теста уточнён до «every rejected access on the bus».
- Срез соответствует контракту по заключению ревьюера.
