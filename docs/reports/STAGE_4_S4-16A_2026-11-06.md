# S4-16a: loader patch через два alias неактивной code page

**Статус:** срез принят после финального независимого ревью без замечаний.
Родительский S4-16 остаётся открытым.

## Граница

Один vCPU, фиксированный Long64 paging snapshot, одна физическая RAM page
размером 4 KiB, два linear aliases и exact register-only `NativeRegisterV1`
code range, целиком помещённый в эту страницу; range может начинаться с
ненулевого page offset. Alias должны отображать один и тот же physical byte
range. Patch — один byte внутри точного диапазона через tracked writable guest
alias между завершёнными dispatch-вызовами. Cross-page code,
guest-generated stores, другие writers, remap/TLB, MMIO/DMA, SMP и active-code
mutation сюда не входят.

## Реализация

- `PhysicalMemory` держит version каждой пересекаемой RAM guest page,
  первоначально `1`. После полной проверки access и до committed-write callback
  версия каждой затронутой страницы повышается без wrap. Не-RAM и invalid access
  отклоняются до изменения generation и RAM. Версии страницы не меняются при
  записи в другие страницы.
- `MachineBus::tracked_code_snapshot` требует ненулевой range внутри одной
  guest page, делает tracked `Fetch` первой byte с `AccessOrigin::Explicit`,
  проверяет executable mapping на фактическом CPL, наличие полной физической
  RAM page и копирует owned bytes. Descriptor-table origin отклоняется, чтобы
  не применять supervisor permissions к CPL3. Snapshot содержит физическую
  page identity, точный диапазон и только её version.
- `PagedCodeSession` держит `MachineBus` заимствованным на срок сессии и имеет
  две отдельные capacity-one cache entries и две published arena slots. Перед
  каждым lookup свежая версия связывается с backing identity; backing, длина и
  alias фиксируются только после успешного NativeRegisterV1 admission.
  Committed patch через alias A повышает page version и синхронно удаляет
  записи обоих aliases.
- Loader patch выполняет tracked read preflight и затем одну tracked byte write
  по guest virtual address и разрешён только внутри точного captured range.
  Отказ не коммитит сам patch byte. Оба walk могут закоммитить Accessed effects;
  только write walk может закоммитить Dirty effects до более позднего отказа.
  В тестовом fixture таблицы страниц не перекрывают code backing, поэтому
  read-only отказ сохраняет его bytes/generation и cache entries. Если таблицы
  физически перекрывают backing, эффекты могут менять code bytes и generation
  даже при отказе. Такой overlap исключён из гарантии неизменности code backing. Каждый новый
  lookup получает свежую generation и инвалидирует выбранный alias cache до
  dispatch; устаревший блок не исполняется. Idle cache другого alias удаляется
  при следующем lookup этого alias.
- Dispatch работает с локальной копией CPU state с CR3 снятым только на время
  вызова fixture-profiled register-only executor. Caller state обновляется из
  этой копии после штатного возврата; при unwind caller state сохраняется.
  Published allocation и PC map принадлежат выбранной cache entry до завершения
  native вызова и result decode.

## Проверки

- `cargo test -p od-host --lib --offline s4_16a_loader_patch_through_one_alias_invalidates_the_other_alias` — **1 passed** на macOS ARM64. Регрессия использует 10-byte code range с offset `0x100`, проверяет rejection другого alias offset и patch вне диапазона, а также что отказ admission не резервирует сессию.
- Machine test расширен проверкой CPL3 supervisor-only fault для fetch/write и отклонением `DescriptorTable` context.
- `cargo test -p od-machine --lib --offline` — **105 passed**. Включает полный alias snapshot, сохранение tracked fetch A effects, изменение только затронутой page version, cross-page write generation и прежнюю ошибку `ReadOnlyRegion` для ROM/Reserved.
- `cargo check -p od-host --all-targets --offline` — прошёл, только существующие warnings в `od-jit` и `od-host`.
- `cargo fmt --all -- --check`, JSON parse, local Markdown links в четырёх изменённых документах и `git diff --check` — прошли.
- Graphify обновлён; точные итоговые счётчики записаны в manifest. Финальное независимое повторное ревью завершилось без замечаний. Срез зафиксирован отдельным commit.

## Ограничения и измерения

Per-page generation добавляет 8 байт metadata на каждую RAM guest page и
проверяет/обновляет версии затронутых страниц на успешной записи. Это изменение
потенциально горячего write path; целевых замеров нет, поэтому решение
provisional и speed claim отсутствует. Backing/mapping IDs в host entry
привязаны к lifetime одной bus-bound session. Этот срез не доказывает общую
инвалидацию всех возможных code writers и не закрывает S4-16.
