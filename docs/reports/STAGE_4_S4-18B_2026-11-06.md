# S4-18b: bounded paged LGDT and guest-loaded GDT delivery

**Date:** 2026-11-06  
**Status:** implementation, independent review, and focused verification complete; S4-18b is accepted. Stage 4/S4-18 remain open.

## Scope and behavior

Added the exact `PagedLgdtLong64V1` / `step_paged_lgdt` CPU entry and the
`od-machine` tracked RAM adapter. It admits bare `0F 01 55 ib` in a fixed
Long64/CPL0 profile, reads one canonical ten-byte pseudo-descriptor wholly
contained in one 4 KiB guest page, and commits only GDTR and RIP after the
complete read and base check. The existing decoder and `load_gdtr` semantics
are reused. The adapter reports actual fetch/operand Accessed-bit updates in
order, does not set Dirty, and distinguishes architectural page faults from
physical RAM errors. It does not route the operand through MMIO/PIO. Decode
fetch stops at the current guest page: the exact four-byte form at offset
`0xffc` is admitted, while unsupported forms needing a fifth byte stop without
fetching from the next page.

The end-to-end case executes guest LIDT, guest LGDT, a protected-page store,
page-fault delivery through those guest-loaded tables, and the first handler
load on one CPU state. It checks the saved fault RIP, CR2, all six exception
frame values, the exact ordered page-table/stack write notifications, and the
handler sentinel. Host code does not patch IDTR/GDTR between the guest
instructions and delivery.

## Coverage and limits

CPU tests cover exact opcode admission, signed displacement, fetch and operand
fault ordering, CPL and LOCK priority, canonical loaded-base validation,
cross-page refusal, atomic GDTR/RIP commit, and unchanged unrelated state. The
integration case establishes guest-loaded GDT delivery through handler entry.
The bounded slice does not implement TSS/IST, segment-cache loading, descriptor
Accessed writes, `#DF`, shutdown, PTE repair, `IRETQ`, or retry/recovery. It
makes no performance claim and does not close S4-18 or S4-19.
