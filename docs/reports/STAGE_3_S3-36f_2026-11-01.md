# S3-36f: cached NativeRegisterV1 recurrence-loop comparison

## Scope and method

This is a synthetic recurrence microbenchmark for the committed profile at
`a5b368eab1d1cdfa3e47a28d0d7c1263b12978c7`. It compares the full cached
NativeRegisterV1 dispatcher invocation, including validation, capacity-one
cache lookup and published native execution, with the interpreter's full run
call. Profile setup, state reset, fixed native warmup, calibration, result and
counter validation, and serialization are outside the scored intervals. The
first full dispatch is measured separately as `cold_first_dispatch_ns`.

The input set contains two fixed synthetic recurrence kernels (`a` and `b`),
each run for 1, 64 and 4,096 loop iterations: six strata total. Each stratum
has 20 alternating cached/interpreter pairs in each of three release-process
runs, giving 60 pairs per stratum and 360 pairs overall. Calls per side are
calibrated to a common count within each run and stratum. Each measured side
must exceed 200 ms.

## Correctness, floors and cache activity

Release preflight passed for all six strata before timing began. It checked
recurrence completion, the exact instruction boundary, mid-loop STOP and
budget exits, and zero-work behavior. Cached and interpreter results matched
full CPU state, exit boundary, retirement and remaining budget; their named
budget exits are `BudgetExhausted` and `InstructionBudgetExhausted`, respectively.
Each stratum retained one entry after one initial miss, compile and
publication. Preflight resident sizes were 1,408 emitted code bytes / 7,193
logical bytes for kernel `a`, and 2,188 emitted code bytes / 10,552 logical
bytes for kernel `b`; these values were the same across each kernel's three
iteration-count strata.

Across the 360 scored pairs, all 720 measured sides passed the 200 ms floor;
the shortest side was 207,669,506 ns. Each cached timed sample recorded exactly
`calls × iterations` hits, with zero misses, compiles, publications or
evictions. Interpreter samples recorded zero cache activity. Native and
interpreter retirement counters each equalled calls multiplied by the frozen
guest work per call (three instructions per iteration for kernel `a`, five for
kernel `b`). There were 20 raw ratio samples per process and stratum, with no
trimming.

## Results

The ratio is cached native elapsed time divided by interpreter elapsed time.
The summary reports the median and full range of the 60 stored paired ratios
across three processes. Values above 1 mean the cached native path took longer
on this synthetic profile.

| Stratum | Iterations | Native/interpreter ratio, median [range] | Cold first dispatch, median [range] |
|---|---:|---:|---:|
| `a_1` | 1 | 4.7661 [4.4800, 5.1930] | 18.958 µs [17.625, 27.208] |
| `a_64` | 64 | 4.8890 [4.4135, 5.1931] | 72.042 µs [64.375, 80.292] |
| `a_4096` | 4,096 | 4.8938 [4.6885, 5.2546] | 3.004 ms [2.960, 3.019] |
| `b_1` | 1 | 3.7205 [3.5583, 3.9703] | 24.625 µs [21.584, 31.917] |
| `b_64` | 64 | 3.8092 [3.2670, 4.0133] | 86.209 µs [82.041, 87.125] |
| `b_4096` | 4,096 | 3.7805 [3.4622, 4.0340] | 4.086 ms [4.037, 4.495] |

For every stratum, the cached native dispatcher was slower than the interpreter
in all measured pairs. The cold values are first-dispatch durations, not a
paired cold interpreter comparison. These observations apply only to the two
small generated recurrence kernels and their frozen compiler/profile path.
They do not establish a general JIT speedup, a whole-workload result, or a
Stage 3 performance/default-policy decision.
