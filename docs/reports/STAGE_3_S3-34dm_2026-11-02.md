# S3-34dm — fixed-seed differential corpus for S3-20eg

## Scope

This slice adds one deterministic differential host test for the existing
exact S3-20eg singleton `67 89 04 24` (`MOV [ESP],EAX`). It does not change
runtime semantics or expand the accepted instruction set.

Use three fixed seeds (`0x2034_d001`, `0x2034_d002`, `0x2034_d003`) with a
local SplitMix64 stream to produce 400 unique initial CPU/RAM inputs per seed,
1,200 total; assert uniqueness within and across seeds. For each input, run
the interpreter twice and JIT twice, resetting CPU and RAM to the identical
pre-state before every execution. Require deterministic equality between the
two runs of each backend and interpreter/JIT parity for complete CPU state
and complete fixture RAM state. Also require `RIP == A+4`, one retired
instruction, one contiguous four-byte store callback at `u64(RSP as u32)`,
and unchanged canaries immediately outside the target. The callback stores
low32 RAX exactly once. Cover zero, unaligned, ordinary, and
`0xffff_fffd..=0xffff_ffff` start addresses. A store crossing 4 GiB continues
contiguously above the boundary; upper RSP bits, payloads, and remaining
defined initial CPU state vary while every generated input remains unique.

This is successful-path coverage only. Existing focused S3-20eg tests retain
fault/retry and callback STOP coverage. The S3-34dm slice did not introduce a
persistent corpus or replay envelope/reducer API; subsequent S3-34dn/do added
that bounded implementation, while broader S3-34.2 execution acceptance
remains pending.

interpreter. It is bounded local macOS/aarch64 acceptance.
