# Stage 4 S4-29d — гостевая калибровка PIT и порт-тик порта 0x61

Статус: срез реализован; независимое ревью (Opus, high) ещё не проведено. Срез не
закрывает S4-29, ISSUE-067 и Stage 4. В плане `[x]` не ставился. ISSUE-067 не закрывалась
(см. ниже, что именно сделано для неё).

## Что найдено до реализации

- **RDTSC.** В модели RDTSC даёт virtual time: `DiagnosticVcpuSession::new_with_clock_handle`
  claim-ит единственного продвигающего часы и отдаёт `clock.snapshot().tsc()` в Long64
  `RDTSC` (S4-22a/S4-28a2). Новой семантики не добавлялось.
- **PIO-путь.** `step_pio_u8` (`EC`/`EE`) исполняет `IN AL,DX` / `OUT DX,AL` через шину;
  часы он не двигает. В `LoadedFirmwareBoard::run_boot` и `PagedVcpuSession` время идёт
  только между квантами, внутри цикла опроса `0x61` и `PM_TMR` стоит (ISSUE-067).
- **Gate2 в коде S4-29c не отвергал ничего** (хранился), хотя решение консультации п. 6
  требует отказов. Отказы реализованы в этом срезе (устройство PIT), существующие тесты
  S4-29c адаптированы (`setup()` поднимает gate 2; загрузка канала 2 при gate 2 = 0 теперь
  отвергается, и запись `0x61` с gate 2 = 0 при загруженном канале тоже).
- **HLT.** `DiagnosticVcpuSession::run` HLT вне halt wait не исполняет (`Unsupported`, опкод
  `0xf4`); владелец профиля сам воспринимает HLT как завершение (`halted`).
- **UART.** Polling TX отказывает в записи THR без настройки 8N1/divisor
  (`UnsupportedConfiguration`); гость настраивает COM1 первым.

## Что сделано

- **Устройство PIT (`crates/od-machine/src/pit_8254.rs`).**
  - Порт-тик: каждое успешное чтение порта B считается и ставит в очередь
    `PIT_PORT_B_READ_TICK_NS = 1000` нс (`Pit8254Handle::port_b_reads`, `take_port_tick_ns`);
    значение снято до тика. Устройство часы не двигает: единственный продвигающий — сессия
    (решение п. 5: «владелец clock — сессия»). Владелец профиля применяет очередь после
    каждой PIO-инструкции.
  - Gate 2 (п. 6): отказ `UnsupportedConfiguration` без изменения состояния — загрузка
    канала 2 при gate 2 = 0; чтение счётчика, латч и чтение порта B при загруженном
    канале 2 и gate 2 = 0; запись в порт B, опускающая gate 2 при загруженном канале 2.
    Чтение порта B при незагруженном канале допустимо. Gate счёт не останавливает.
- **Fixture** `tests/fixtures/guest/stage4/pit_calibrate/` (`entry.S`, `layout.ld`):
  `pit_calibrate_tsc` (gate high, `0xb0`, счёт 11931, RDTSC, цикл по `0x61` до бита 5,
  `pitcnt >= 1000`, `tscmax <= 10 * tscmin`, `delta / 10`) и MSB-форма
  `quick_pit_calibrate` (счёт `0xffff`, латч `0x80`, чтение MSB порта `0x42`, пороги `> 5`
  проходов, `delta * 1193182 / 256000`). Вывод в COM1 через `OUT DX,AL`, затем HLT.
  Вариант `PROBE_OMIT_GATE=1` (инъекция: без gate high).
- **Builder** `tools/build/build_stage4_pit_calibrate_probe.py` + тест: независимая
  байтовая кодировка кода (сверяется с результатом clang/lld; при сборке она нашла мою
  опечатку в константе 1193182), manifest с ожидаемыми значениями из эталонной модели
  (формула PIT + порт-тик), `--omit-gate`.
- **Machine** `crates/od-machine/src/stage4_pit_calibrate_probe.rs`
  (`Stage4PitCalibrateProbeV1`, владелец часов, инъекции `NoPortTick` и
  `CoarsePortTick`, строгий декодер записи) + `crates/od-machine/tests/stage4_pit_calibrate_probe.rs`.
- **Runner** `--stage4-pit-calibrate-probe IMAGE [--budget N] [--inject-no-port-tick]`
  (`tools/runner/src/stage4_pit_calibrate_probe.rs`, подключён в `main.rs`) +
  `tools/runner/tests/stage4_pit_calibrate_build_cli.rs`.
- **Документы:** `docs/specs/MACHINE_CONTRACT.md` (раздел S4-29d; три фразы S4-29c про
  gate уточнены), `docs/testing/MACHINE.md` (пункт 63), этот отчёт, данные
  [`s4-29d-pit-calibrate.json`](data/stage4/s4-29d-pit-calibrate.json).

## Ожидаемые значения и источники

Все выведены из формулы PIT `T(t) = floor(t_ns * 1193182 / 1e9)`, режима 0 (OUT2 высокий
при `e = T(now) - T0 >= N`, счётчик `(N - e) mod 65536`) и порта-тика (чтение `0x61`:
значение снято на `t`, затем `t += 1000` нс); TSC = нс (1 ГГц); инструкции и записи
времени не занимают. Вычисления: эталонная модель в builder (`reference_model`) и закрытые
формулы в тестах (Rust и Python), не вывод гостевого кода.

| Значение | Ожидание | Вывод |
| --- | --- | --- |
| Загрузка счёта A | `t_load = 1000` нс, `T0 = 1` | первое чтение `0x61` (rmw gate) на `t = 0` стоит 1 мкс; `floor(1000 * 1193182 / 1e9) = 1` |
| Первое чтение, видящее OUT2 | `j = 10001` (`t = 10 001 000` нс) | наименьшее `j`: `floor(1000 j * 1193182 / 1e9) - 1 >= 11931` |
| `pitcnt` | 10000 | `j - 1` (чтения, видевшие OUT2 низким) |
| `tscmin = tscmax` | 1000 | между двумя RDTSC ровно одно чтение `0x61` |
| `delta_tsc` A / частота A | 10 000 000 / 1 000 000 кГц | `t2 - t1 = 1000 * pitcnt`; `delta / ms`, `ms = 10` |
| Чтений `0x61` в фазе A | 10002 | rmw + 10001 чтение цикла |
| Проходы MSB стадия 1 / 2 | 214 / 213 | MSB = `0xff` пока `e <= 255`, `0xfe` пока `256 <= e <= 511`; `e = T(t) - T0`, `t` кратно 1 мкс |
| `delta_tsc` B / частота B | 214 000 / 997 425 кГц | `tsc` последнего прохода стадии 2 минус стадии 1; `delta * 1193182 / 256000` (0,26 % от 1 ГГц: квантование 1 мкс) |
| Чтений `0x61` всего / конец часов | 10432 / 10 432 000 нс | сумма фаз (10002 + 430); часы двигаются только портом-тиком |

| Негатив 100 мкс на чтение | A: `pitcnt = 100 < 1000`, статус 1; B: проходы 2 и 1, статус 3 (побеждает стадия 2); 108 чтений, 10 800 000 нс | модель с `port_tick_ns = 100000`: `T0 = 119`; первое OUT2 на `j = 101` |

## ISSUE-067

Не закрыта (запись в `docs/KNOWN_ISSUES.md` не менялась). Реализован порт-тик для чтений
`0x61` в PIT-устройстве и в владельце профиля `Stage4PitCalibrateProbeV1`; его проверяют
`calibration_completes_and_matches_the_formula_derived_values` и
`injected_regression_without_port_tick_spins_until_the_budget_runs_out` (machine),
`built_kernel_calibrates_the_tsc_and_matches_the_manifest_expectation` и
`injected_regression_without_port_tick_exhausts_the_budget_and_fails` (runner CLI). Для
закрытия остаётся: `PM_TMR` (S7-14a) и чтение `0x42` как временные порты; применение
очереди в `LoadedFirmwareBoard::run_boot` и `PagedVcpuSession`; решение о синхронизации
часов по числу выполненных инструкций (п. 5).

## Не проверено, отклонения и открытое

- **Расхождение с буквой решения п. 5:** чтение `0x42` и `PM_TMR` не тикают (поручение
  среза — порт `0x61`). Поэтому MSB-форма `quick_pit_calibrate` в fixture адаптирована:
  драйвер времени — `0x61` на каждом проходе, MSB читается через latch (`0x80`) и два
  чтения `0x42`; в Linux `pit_verify_msb` читает `0x42` дважды без латча. Пороги и этапы
  сохранены, но это не побайтовая копия `pit_verify_msb`.
- Тик применяет владелец профиля (сессия), не «квант» общей платы; синхронизация часов по
  числу выполненных инструкций в профиле не моделируется (инструкция = 0 нс), что в
  решении п. 5 названо отдельным компонентом.
- `Stage4PitCalibrateProbeV1` — диагностический профиль со своим owner-циклом; к плате,
  `LoadedFirmwareBoard` и PIT IRQ (S4-29f) не подключён, cmdline (S4-29g) не затронут.
- Гость не пробует `pit_calibrate_tsc` на режиме 2 и не повторяет error-extrapolation
  `quick_pit_calibrate` (ppm-проверки); TSC-частота 1 ГГц и 0 нс на инструкцию — модель,
  не реальная машина. Реальное железо не проверялось.
- Правило «чтение при загруженном канале и gate 2 = 0» достижимо только принудительным
  состоянием (unit-тест); состояние недостижимо через порты.
- `CoarsePortTick` — дополнительная инъекция сверх поручения (контроль порогов гостя); в
  runner не выведена (флаги по поручению: `--budget`, `--inject-no-port-tick`).
- JIT: кейс `not_supported` (диагностическая сессия, интерпретатор).
- Ревью Opus (high) перед коммитом: не проведено, назначается координатором.
