# Stage 3 S3-20bm: address32 indexed SIB with RSI/RDI base

## Scope

This slice admits only singleton `67 48 8B/89 /r sib [disp8|disp32]` instructions: ModRM `mod=00/01/10,r/m=100`, SIB base RSI or RDI, index RAX..RBX, scale 1/2/4/8, data RAX..RBP, exact lengths 5/6/9. The effective address remains the decoder's `MemoryOperand::access_address_48` result: `(low32(old base) + low32(old index) * scale + signed displacement) mod 2^32`, zero-extended to u64. Data transfer remains qword, and the full RSI/RDI base value is preserved.

No other address-size SIB base/index, prefix, pair, V3, production owner/MMU integration, Stage 2/ISA, Mini, or performance work is included.

## Evidence

- JIT descriptor tests cover loads and stores for both bases, all six data registers, all four admitted indices and scales, mod00 no-displacement and signed disp8/disp32 boundaries. They also reject no-index, RSP/RBP/RSI/RDI index, and prefix-neighbor forms.
- Host tests compare direct V2 and shared IR native execution against the interpreter for full CPU/RAM state, callback address/count, and retirement. They run a mod00 no-displacement case for every load/store × base × index × scale × data combination. Their independent target oracle truncates both base and index to 32 bits, applies scale and signed displacement with modulo-2^32 wrapping, then zero-extends. `data=index` cases use the pre-instruction index value.
- A qword load at `0xffff_fffc` is one contiguous eight-byte callback across 4 GiB. Two immutable disp32 artifacts differing only in the ninth source byte target `0x1000` and `0x0100_1000`.
- Dispatcher tests resume from the actual next RIP across the new five-, six- and nine-byte forms, then run interpreter NOP fallback and the existing pair without replaying prior reads. They also cover store+STOP commit, entry STOP/stop-RIP/zero budget, partial byte windows 1..8, unsupported neighbor, architectural and backend load/store faults with CPU/RAM snapshots and exact callback counts.

## Validation

Validation passed:

```sh
cargo test -p od-jit --offline
cargo test -p od-host --offline
cargo fmt --all -- --check
cargo check --workspace --all-targets --offline
cargo check -p od-host --all-targets --target x86_64-unknown-linux-gnu --offline
python3 tools/check_layout.py
git diff --check
graphify update .
```

Results: `od-jit` 183 passed; `od-host` 78 unit tests and 12 integration tests passed, with 2 ignored. Formatting, workspace check, Linux `x86_64-unknown-linux-gnu` host check, diff check and Graphify update passed. The Linux host check emitted existing dead-code warnings.

`python3 tools/check_layout.py` was run. It reports the existing unmapped root `.git` and two broken links from the Stage 2 report to unavailable Stage 1/2 manifests under `work/`; it found no new layout issue. No Stage 2 files or manifests were changed.
