# Этап 4 — S4-20d: paged CPL3 store/load after IRETQ

**Дата:** 2026-11-06
**Объём:** ограниченный CPL3 user-store path; родительский S4-20 и Stage 4
остаются открытыми.

## Реализация

Добавлен отдельный opt-in `step_paged_cpl3_mov` для точных форм
`48 89 0B` (`MOV [RBX],RCX`) и `48 8B 03` (`MOV RAX,[RBX]`). Он повторно
использует существующую MOV execution path, но не расширяет прежний
load-only entry. Machine выводит CPL из committed CS selector/cache и CR3 из
CPU state; syscall MSR state и caller-provided privilege override не нужны.

Положительная последовательность выполняет paged IRETQ CPL0→CPL3,
существующий S4-20b user load, затем CPL3 store и reload. Проверяется
изменённый nonce в RAM и RAX, отдельные retirement, последовательный RIP и
неизменность CPL3 CS/SS, RSP и CR3.

Bounded профиль фиксирует Long64, canonical48, physical36, четырёхуровневые
4 KiB tables, `CR0=0x80010033`, `CR4=0x20`, `EFER=0xd00`. Live TF, RF и AC
должны быть очищены до fetch. Каждая инструкция и qword operand помещаются в
одну guest page. Load и store одинаково проверяют пересечение operand с
границей страницы до canonicality; совмещённый crossing/noncanonical адрес
возвращает `Rejected(CrossPageOperand)` без доступа к операнду. Fetch уже
состоялся и мог обновить A bits. Прежний load-only entry сохраняет своё
поведение.

Системные проверки покрывают user RO и supervisor-only store `#PF` PFEC
`0x07`, supervisor-only read `0x05`, supervisor-only fetch на каждом уровне и
NX fetch `0x15`, non-present instruction fetch `0x14` и non-present
read/store `0x04`/`0x06`. Сверяются точные CR2 и saved RIP. Для первого
пользовательского fetch-fault, non-present data и store-fault cases сверяются
A/D PTE readbacks и callback order; supervisor-only read и late non-present
fetch проверяются по fault record и сохранению прежних effects. Faults не retirement-ят
инструкцию, не записывают operand и не выставляют D. Отдельный первый CPL3
fetch-fault path проверяет точные PTE A bits и callbacks при исходно чистых
A bits. Отказ физической записи остаётся `OperandPhysical` на GPA `0x30000`.
Уже завершённые IRETQ, user load и store сохраняются при последующих ошибках.
