# S3-23d — shared interpreter/JIT/control fixture write transaction

**Date:** 2026-10-27. **Status:** implemented locally; independent review clean.
This bounded one-vCPU fixture slice does not complete S3-23.

## Scope and implementation

`TrackedCodeFixture` now routes three write origins through one checked
transaction:

- the existing interpreter `GuestMemory::write` reached through
  `od_isa::execute::step`;
- the compiler-issued V2 `MOV [base],reg` store helper;
- the between-call control write adapter.

The common preflight resolves the full guest address range to a backing span,
checks write permission, the requested executable permission, backing-version
overflow, and active-source overlap by backing offset (so aliases are covered).
The common all-or-nothing writer commits bytes once and stages the next backing
version. Interpreter/JIT adapters apply the notification after the current
execution call returns and before the next snapshot or cache lookup. Control
writes apply it synchronously before returning. The existing decoded
interpreter semantics are reused; no Stage 2 code was changed.

## Local evidence

- Independent interpreter and JIT owners execute `48 89 18` with equivalent
  source state and destination. Full CPU state, backing bytes and version match;
  both invalidate cached B, retain unrelated C, then recompile and execute B
  with the newly stored qword.
- Interpreter store into its active source alias is rejected before mutation.
- Injected interpreter backend failure leaves CPU state, RAM, backing version,
  and cache entries unchanged.
- Control write through an alias invalidates B only; the next B dispatch sees
  changed bytes. Injected control backend failure leaves RAM/version/cache
  unchanged. Successful control write count is exactly one.
- No retry is performed by these adapters after a committed write.

Targeted tests:

- `interpreter_and_v2_store_share_tracked_write_commit_and_cache_invalidation`
- `tracked_control_write_uses_shared_preflight_commit_and_alias_notification`

## Boundaries

This remains a test fixture with fixed ordinary RAM, explicit backing IDs and
aliases, and synchronous single-vCPU calls. It is not a production MMU or
control-plane integration. Shared/asynchronous RAM, MMIO, DMA, SMP, REP/RMW,
compile/publication races, and active-code retirement are not covered. The
fixture's `GuestMemory::write` integration is bounded to existing interpreter
semantics; Stage 2 implementation files are untouched. Physical Mac Mini
checks and long benchmarks remain deferred to the final Stage 3 gate.
