# Stage 3 S3-33j: exact native LEA RAX,[RBX+disp8]

Date: 2026-10-30  
Status: implementation, independent review, focused checks, and full local
harness pass.

## Scope

This slice adds an opt-in uncached profile for only the bare four-byte encoding
`48 8D 43 db`, covering every raw displacement byte. Admission requires the
decoder to report W64 RAX, address64, RBX base, no index, scale one, and the
same `i64::from(db as i8)` displacement. Existing bare `48 8D 03` admission is
unchanged and remains a separate profile.

Lowering reads RBX, creates a W64 sign-extended displacement constant, adds it
with `FlagEffect::Preserve`, writes RAX, and commits once. The emitter's direct
preserving integer path now accepts only W64 Add/Subtract with a result;
Compare, no-result, W32, and unsupported flag shapes remain rejected. LEA has
no memory operation, data access, canonicality/fault check, helper, or flags
update. Eager and demand-flags candidate APIs are separate. Native arithmetic
wraps modulo 2^64, and pending flag state is retained.

## Focused evidence

- Admission test covers all 256 displacement bytes and rejects other
  destinations/bases, SIB, disp32, RIP-relative, no-displacement, width/address
  changes, prefixes, truncation, and branch targets inside the instruction.
- Preserving-emitter test accepts W64 Add/Subtract with a result and checks
  Compare, missing result, and W32 rejection. The renamed NOT-specific test
  remains in the harness to preserve its previous no-helper regression.
- Compiler test covers pending register ADD → disp8 LEA → JNZ through eager and
  demand-candidate paths and verifies instruction count, code end, provenance,
  and PC-map coverage.
- Host test compares complete state and retirement with the interpreter for
  displacement bytes `00`, `01`, `7f`, `80`, `ff` and RBX values including zero,
  one, signed extrema, `u64::MAX`, and noncanonical values. Its rejecting
  interpreter data-memory probe sees zero callbacks. Pending ADD/CMP → LEA →
  JZ/JNZ cases cover taken and fallthrough outcomes in eager and candidate
  dispatch. The following NOP is an interpreter fallback on fallthrough, so
  the test checks native and interpreter retirement separately and their sum.
  It also checks consecutive LEAs, LEA followed by a flags-writing ADD, and
  STOP/budget immediately before and after LEA, with full state/RIP and
  retirement accounting. Candidate and eager modes both exercise ADD-pending
  boundaries immediately before LEA and immediately after its commit; stop
  cases compare the complete state against the corresponding interpreter
  boundary.

  focused admission/emitter/compiler tests, the focused od-host test, and
  `PYTHONPATH=tests/cpu python3 -m unittest test_stage3_harness` (28 tests).
