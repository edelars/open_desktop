# S4-36: минимальный initramfs с настоящим /init

**Дата:** 2026-11-09
**Статус:** `passed` для статической сборки и проверок структуры. При исходной приёмке
S4-36 Linux не загружался. Последующая диагностическая серия S5-07 запустила обновлённый
`/init` в госте и подтвердила отдельные строки маркеров в двух прогонах; строгий comparator
серии остался `matches=false`, поэтому это не приёмка S5-07.

## Что собрано

- `tests/fixtures/guest/stage4/initramfs/init.S` и `layout.ld`: статический freestanding ELF64
  x86-64 (ET_EXEC, адрес 0x400000, без libc, без INTERP/DYNAMIC, без debug и символов), 4448 байт.
- `tools/build/build_stage4_initramfs.py`: собирает `/init` (`clang --target=x86_64-unknown-none-elf`,
  `ld.lld` из Rust sysroot, как в S4-34a), пакует cpio newc (070701) детерминированно (mtime 0,
  uid/gid 0, ino 1, порядок фиксирован, `/init` 0100755, trailer `TRAILER!!!`, без сжатия),
  пишет `work/stage4/initramfs/initramfs.cpio` (ignored; рядом `init.elf`) и evidence
  [s4-36-initramfs.json](data/stage4/s4-36-initramfs.json) (около 7,7 КБ, без временных меток; `--evidence` принимает только путь внутри
  `docs/reports/data/stage4/`; при `--init-binary` поле `repeatable_build.runs` равно 1).
- `tools/build/test_build_stage4_initramfs.py`: 23 теста (без ядра, во временных каталогах). Линкер вызывается без `-z noexecstack`: `layout.ld` задаёт
  явные PHDRS без PT_GNU_STACK, и флаг ничего не добавлял (SHA-256 `init.elf` без флага не изменился);
  PT_GNU_STACK в `/init` нет, и сборка его не добавляет.

Поведение `/init`: `mkdir /proc`, `mount proc /proc`, чтение `/proc/cmdline`, поиск токена
`od.nonce=<значение>` (в начале строки или после пробела; значение до пробела/перевода строки,
до 128 символов), `nanosleep` 1 мс, вывод `OD_NONCE=<значение>\n` в fd 1, `getpid`, `exit(0)`.
Без токена: `OD_NONCE=MISSING\n` и `exit(1)`. Коды: 3 write, 4 getpid, 5 nanosleep.
Nonce в архив не запекается: его передаёт cmdline (хост-раннер S4-37/S4-38).

Syscalls (номера сверены с `arch/x86/entry/syscalls/syscall_64.tbl` из linux-source-7.0.0
7.0.0-38.38): read 0, write 1, close 3, nanosleep 35, getpid 39, exit 60, mkdir 83, mount 165,
openat 257.

## Что подтверждено

- Follow-up S5-07 от 2026-11-16: после переноса существующего `nanosleep` перед выводом
  nonce два уникальных прогона выдали `Run /init as init process` и точный
  `OD_NONCE=<nonce>` отдельными строками именно в таком порядке. Строгий comparator
  остался `matches=false` из-за различий machine observations и UART, включая 34/33
  доставленных `#PF`; это подтверждает только гипотезу порядка маркера. Подробности:
  [отчёт S5-07](STAGE_5_REPORT.md#s5-07-temporary-pre-marker-delay-diagnostic-2026-11-16) и
  [evidence](data/stage5/s5-07-marker-delay-before-nonce-n2-20261116.log).
- Точный diff fixture: блок проверки `nanosleep(&{0 s, 1000000 ns}, NULL)` перенесён из
  участка после `getpid` перед построением nonce output buffer; проверка положительного
  `getpid`, `fail_sleep` (код 5), `fail_getpid` (код 4), проверки записи и используемые
  syscalls сохранены. Проверка builder и evidence обновили SHA-256 initramfs на
  `65acac38cd4c791154f33179fe2c9f2103dd7fdec51aacfd969ab4d9eb0aedb7`; SHA-256 `/init`:
  `fad513259cd88ba9d50c51aeccd1a8d50a1d09ab8a98f80cec9d11b36c00daff`.

- Структура архива: один regular file `/init` (mode 0100755, uid/gid/mtime 0, nlink 1) и trailer;
  разбор собственным парсером и распаковка системным `/usr/bin/cpio -id` (файл побайтно равен
  `init.elf`, executable).
- ELF/ABI: ELF64 LE, ET_EXEC, EM_X86_64, нет PT_INTERP/PT_DYNAMIC, нет W+X сегментов, entry
  в исполняемом PT_LOAD; каждая инструкция `syscall` предварена `mov $imm32,%eax` с номером из
  разрешённого набора; нет `int 0x80`/`sysenter`. Нет host paths (`/Users`, `/home`, `/private`,
  `/opt`, `/var/folders`, `/Volumes`, `/nix`) и secret-маркеров.
- Nonce не запечён: ни значение пробы, ни шаблон `od.nonce=`/`OD_NONCE=` + 16 и более
  алфанумерических символов в архиве не встречаются.
- Воспроизводимость: две независимые компиляции дают побайтно одинаковый `/init`, cpio
  и SHA-256; evidence побайтно совпадает при повторном запуске.
- Совместимость с config (`work/vms/s2-00-ubuntu-26.04.1/source/extracted/config`, sha256
  совпадает с записью S4-35): `CONFIG_BLK_DEV_INITRD=y`, `CONFIG_X86_64=y`, `CONFIG_BINFMT_ELF=y`,
  `CONFIG_PROC_FS=y`, `CONFIG_TMPFS=y`, `CONFIG_INITRAMFS_FORCE` не задан (иначе внешний initrd
  игнорировался бы); справочно `CONFIG_RD_GZIP=y` (нужен только для сжатого архива, наш не сжат),
  `CONFIG_DEVTMPFS=y`, `CONFIG_INITRAMFS_SOURCE=""`.
- Негативы (builder выполняет их сам, 12 из 12 отклонены; каждый засчитывается только если сообщение
  `BuildError` содержит ожидаемый фрагмент, иначе builder падает; фрагмент записан в evidence как
  `expected_fragment`, поле `exit_code` убрано, так как внутренние негативы CLI не запускают):
  отсутствующий `/init`; `/init` без бита x; лишняя запись; nonce пустой, короче 16, с пробелом,
  не `[A-Za-z0-9]`; nonce запечён в архив; `od.nonce=<значение>` в бинарнике; `/Users/...`
  в бинарнике; не-ELF; неверный `e_machine`. Только в тестах (с проверкой фрагмента причины)
  дополнительно: nonce длиннее 128, ET_DYN, PT_INTERP, W+X сегмент, `int 0x80`, номер syscall вне
  набора, uid/gid/nlink/mtime не 0 в cpio, дубликат записи, mode 0100777, обрезанный/испорченный cpio,
  мусор после trailer, `--evidence` вне `docs/reports/data/stage4/`. Код выхода CLI 1 проверяют
  только тесты, которые запускают CLI: missing_init, non_executable, неверный nonce, host path,
  не-ELF через `--init-binary`, evidence вне каталога.

## Что НЕ подтверждено

- Строго воспроизводимая серия S5-07 ещё не получена: отдельные маркеры подтверждены только
  в двух диагностических прогонах, а межпрогонные различия machine observations и UART не
  объяснены. Этот follow-up не снимает блокировку S5-07.
- Вывод в `/dev/console`: узел создаёт встроенный default cpio ядра
  (`usr/default_cpio_list`: `/dev/console` c 5 1; `CONFIG_INITRAMFS_SOURCE=""`), он
  распаковывается раньше внешнего initrd (`do_populate_rootfs`). Это чтение исходников, не
  запуск; сам архив `/dev` не содержит.
- Номера syscalls сверены с таблицей исходников, а не с исполнением в ядре.
- Подлинность ядра/config не подтверждена (ограничения S4-35). Поле `vmlinuz_sha256` в evidence
  скопировано из манифеста S4-35 и в S4-36 не сверялось с файлом (ядро здесь не используется);
  рядом стоит `vmlinuz_sha256_source`.
- Альтернативные и негативные случаи логики разбора nonce в `/init` тестами репозитория не
  покрыты. Наблюдение вне репозитория, не доказательство среза: копия `/init` с путём
  `/cmdline.txt` вместо `/proc/cmdline` (то есть изменённый, не собранный артефакт) запускалась
  как PID 1 в Docker (`linux/amd64`, эмуляция на arm64). Результаты: `od.nonce=AbCd1234EfGh5678`
  среди других аргументов даёт `OD_NONCE=AbCd1234EfGh5678`, rc 0; `xod.nonce=...`, пустой
  `od.nonce=`, пустой файл дают `OD_NONCE=MISSING`, rc 1; при двух токенах берётся первый; сам
  собранный `/init` с хостовым `/proc/cmdline` даёт `OD_NONCE=MISSING`, rc 1. Скрипта и evidence
  этого прогона в репозитории нет, воспроизвести его по репозиторию нельзя. Это эмуляция
  user-mode/контейнера, а не загрузка ядра.

## Ограничения и отклонения

- Помимо перечисленных в задаче syscalls добавлены `mkdir` (83) и `mount` (165): ядро не
  монтирует `/proc` в initramfs, без этого `/proc/cmdline` недоступен. Каталог `/proc` создаёт
  сам `/init`, поэтому архив остаётся «только `/init` и trailer».
- Значение nonce длиннее 128 символов `/init` молча обрезает до 128 и выводит с rc 0; хост сравнивает
  значение целиком, а `validate_nonce` длиннее 128 не пропускает, так что штатно ситуация не возникает.
- Разделитель токенов cmdline в `/init` только пробел (0x20); таб и кавычки не учитываются.
  Для cmdline, который формирует хост, допустимо.
- Ошибки `openat`/`read`/`mkdir`/`mount` сводятся к `OD_NONCE=MISSING` и rc 1 без отдельного кода;
  различение причин отложено до S4-38 и зафиксировано как ограничение.
- `exit(0)` у PID 1 приводит к панике ядра (`Attempted to kill init`): маркер выведен до выхода,
  панику S4-37/S4-38 следует считать штатным концом прогона либо заменить ожидание.
- Cpio без дополнения нулями до 512 байт: Linux `unpack_to_rootfs` принимает архив и с нулевым
  хвостом, и без него.
- Строка ELF-проверок использует эвристику «`mov $imm32,%eax` непосредственно перед `syscall`»;
  она соответствует этому исходнику, но не является общим дизассемблером.
- Не покрыто тестами: entry вне исполняемого PT_LOAD; secret-маркеры; бинарь без `syscall`;
  `syscall` без предшествующего `mov $imm32,%eax`; PT_DYNAMIC отдельно от PT_INTERP; ошибки
  разбора ELF-заголовков (phnum/phentsize); сопоставление ошибок CLI для `--verify-archive` с
  `--nonce`; логика `/init`.
- В `docs/plans/STAGE_4.md` пункт S4-36 отмечен `[x]` как принятый с ограничениями (по ревью
  Claude Opus, по образцу S4-35).
