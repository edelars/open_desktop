# S3-40d: cached composed NativeRegisterV1 flags comparison

## Result

Three scored release-process runs completed on an Apple M3 Max (macOS 26.7.1,
ARM64) from source revision `588c21f2e1b6642dd98e2d9c5703ba7481256546`.
They compare the eager flags reference with the opt-in demand-flags candidate
on the frozen 1,200-input S3-34p composed corpus. The preflight checked all
1,200 stored interpreter observations, 2,400 interpreter/cached-strategy
parity results, and exact per-input cache baselines. The frozen corpus SHA-256
is `3fddc5c753f3d2884850468480ec68d13a6069d1aed16e8973e1acef56ffac1f` and
the ordered input digest is `fnv1a64:172fb17b01c502df`.

All three scored reports passed independent counter, parity, pairing, and
binding review. Wall-clock report durations were 172.090 s, 177.762 s, and
149.288 s. Run 2 is accepted as a noisy bounded run after its initial attempt
showed material Stage 2 load: host 1-minute load reached 8.46 and a Stage 2
fixture test was observed at 223.5% CPU while the benchmark snapshot fell to
66.3%. That attempt is diagnostic-only; all excluded attempts remain
preserved. The accepted run 2 retry had early Stage 2 compiler overlap at
sampled load 3.16, while run 3 also had low-load Stage 2 activity. These are
disclosed bounded measurements, not three quiet runs. Snapshots are
point-in-time and samples do not carry per-pair wall-clock timestamps. Numeric
executor exit status was not captured for accepted runs 2 and 3. The raw host
metadata reports `working_tree_dirty: null`, so dirty-state status is unknown.

Across runs, the median of the three per-run paired-ratio medians is 1.02787
cold and 1.02297 for repeat dispatch. Per-run timing spread crosses parity,
and the 2–3% central differences are smaller than observed variation. The
measurements do not select a faster strategy or justify changing the eager
default.

The candidate published 14.27% more code bytes than eager in cold mode and
13.07% more in repeat mode across the reviewed suite. These cumulative
published-byte totals count every successful publication; resident high-water
code and logical metadata are reported separately. They are not memory-use or
RSS measurements. Publication-byte instrumentation is enabled for both
strategies and its isolated latency cost was not measured.

## Scope and limits

Cold mode creates an empty capacity-one cache for each input and times its
first complete dispatch. Repeat mode performs one untimed dispatch to prepare
the same per-input cache, then times a second complete dispatch; it is not a
hit-only measurement. A composed dispatch can compile multiple blocks, hit a
block again, or replace the one cache entry during redispatch. All timed
samples use the same inputs, work counts, interpreter retirement split, and
cached-strategy parity checks. The sample count is 20 paired measurements per
mode; sweeps were calibrated to at least 200 ms of dispatcher time per side.

This result applies only to this frozen composed register corpus and current
Apple Silicon host. It does not measure memory/fallback warm workloads, a full
guest workload, physical x86, Mac mini, or full Stage 3 performance. Eager
remains the default; there is no winner inference. Mac mini checks stay deferred
until the end of Stage 3, and S3-40/S3-41 remain open.
