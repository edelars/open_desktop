# S4-14c: mutable diagnostic translation session

## Scope and implementation

Adds a feature-gated `MutableTranslationProbeSession` in `od-machine`. The
session exclusively borrows one `&mut PhysicalMemory`, fixes the S4-14b
Long64/canonical48/physical36/four-level/4 KiB control profile and one CR3,
and shares the immutable cache's private capacity-one values-only state. It
returns diagnostic translation values, never memory references or reusable
access handles.

`write_pte` accepts 8-byte-aligned guest physical addresses only when the full
`[address, address + 8)` range fits physical36, then uses the existing checked
`PhysicalMemory::write_u64`. A successful write commits once and invokes its
callback once; it leaves the cache entry intact. Failed alignment, physical
width or memory-region validation leaves RAM unchanged and does not invoke the
callback. A 37-bit map fixture proves that a writable RAM range at `1 << 36`
is rejected by the session. No automatic write-triggered invalidation is
added.

The session executes the standalone exact INVLPG profile using a pure fetch
adapter over the current `PhysicalMemory`; this bypasses the resident entry and
does not commit tracked A/D updates. A CR3 mismatch is rejected before fetch.
Only a retired CPL0 canonical invalidation effect is synchronously consumed,
clearing the whole entry before returning. Faults, fetch failures and the
retired noncanonical no-op preserve the entry.

Acceptance tests prove same-session remap and `Walk → Hit → PTE write → Hit →
INVLPG → Walk → Hit`. The INVLPG instruction page starts with a cached stale
Fetch/Ring0 translation; only the replacement physical page contains the
instruction, demonstrating that fetch bypasses the resident cache. The absent
PTE case checks #PF vector 14, error code `0x10`, saved RIP and no retirement.
R/W and U/S permission tighten/relax and NX fetch refresh use literal fault
codes. Failed unaligned and out-of-range writes are checked after the mutable
borrow ends and before any restoration, including a 37-bit physical-map case.
Cache preservation is checked on noncanonical NOP, CPL fault, LOCK fault and
instruction-fetch fault. Prior immutable-cache, INVLPG and tracked-walker
regressions remain included in the crate suite.

## Independent reviewer findings addressed

1. `write_pte` now checks the full 8-byte range against the exclusive
   physical36 limit; a 37-bit `PhysicalMemory` fixture verifies rejection at
   `1 << 36` with unchanged RAM and zero callbacks.
2. Unaligned and unmapped write assertions now run after the mutable borrow
   ends and compare the original PTE bytes before any restoration.
3. The remap case warms a stale Fetch/Ring0 entry, places INVLPG only on the
   replacement physical page, then proves the instruction succeeds through
   fetch bypass. The absent-PTE path asserts #PF(14), PFEC `0x10`, unchanged
   RIP and zero retirement.
4. The resolved ISSUE-053 link was removed from this report. The main checkout's
   `smoke/` layout failure is tracked independently in ISSUE-056.

## Limits and status

This is a diagnostic prototype, not a production TLB or tracked memory path. It
does not cache A/D effects, integrate guest stores, handle CR3/reset transitions
or generations, model huge pages/PCID/global behavior, or integrate DMA, SMP,
JIT and active-code invalidation. INVLPG clears the entire capacity-one entry
conservatively. Full S4-14 and Stage 4 remain open. No commit was created; the
worktree is `feat/s4-14c-session` based on `c5b35b9`.
