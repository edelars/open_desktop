## Fail-closed harness changes

Each Rust gate runs through a separate Cargo command pinned to its crate,
identity and `--exact` filter. The input manifest records each step/package/
identity and hashes the harness/test sources. Each summary row records exact
argv, crate, identity, return code, output tail and the digest of its per-step
log under the same run directory. Final validation requires a generated-format
single-component run ID and rejects run-directory aliases, logs-directory
symlinks and per-step log symlinks. Every step log must use the exact lexical
`work/stage3-harness/<run-id>/logs/<step>.log` path and resolve to that file. It
checks the log digest and tail, then requires exactly one matching non-ignored
`test <identity> ... ok` row. Missing steps, wrong identities/crates, zero or
duplicate matches, ignored tests, nonzero/timeout results and forged `passed`
summaries fail validation. Self-tests cover missing manifest and summary gates,
wrong command/output, zero/duplicate matches, ignored and failed runs, invalid
run IDs, sibling run aliases and run/log/step-log symlink escapes.

The local harness remains ARM64-only. Its `local_acceptance` summary is separate
from `local_lifecycle`, Stage 1 and the memory corpus. Mini, physical x86,
performance, Stage 2 and owner-backed suites remain `not_run`; process VMHost
tests also remain separate from this unit-level harness.
