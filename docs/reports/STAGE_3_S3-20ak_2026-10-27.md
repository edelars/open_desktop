# S3-20ak — RIP-relative qword MOV with RSP/RBP data

## Scope and implementation

Added only the exact singleton instructions `48 8B 25 disp32`, `48 89 25 disp32`,
`48 8B 2D disp32`, and `48 89 2D disp32`. They encode ModRM `mod=00,r/m=101`
with data register RSP or RBP and have length seven. Shared IR, direct V2,
runtime source validation and the bounded fixture dispatcher use the existing
decoded `MemoryOperand::NextRip` path. Generic register admission, pair/V3
profiles, frame layout and RuntimeContext/C ABI are unchanged. No owner/MMU
integration, Stage 2, `od-isa`, Mini, physical x86, or performance work was
included.

## Evidence

- JIT descriptor coverage checks both directions and data registers, signed
disp32 edge values, exact seven-byte source identity and decoded `NextRip`
metadata at an instruction entry inside CodeView. Partial 1..6 byte windows,
address override, SIB and malformed/trailing shapes reject.
- Host tests compare direct V2 and shared IR with interpreter for loads and
stores, RSP and RBP data, negative/zero/positive displacements, and interior
CodeView entry. They compare full CPU state and data RAM, callback counts and
retirement; target selection is independently calculated from `entry RIP + 7 +
disp32`. Stores transmit the full 64-bit source value, and loads commit only
the destination register after success. Exact-profile successful IR stores
with a write callback that raises STOP retain all eight payload bytes, retire
once and return at the actual next RIP.
- Noncanonical NextRip targets produce exact #GP (13, error 0, no linear
address) for both directions and both data registers before any RAM callback,
with unchanged CPU, RAM and budget/retirement. Existing backend error behavior
remains a host error in the generic RIP-relative tests.
- Bounded dispatch composes NOP → RSP/RBP RIP-relative singleton → two
following singleton memory operations (store stack register to `[RBX]`, then
load `[RBX]` to RCX). Budgets
0..4 compare complete state and RAM with interpreter; a split after NOP and
the singleton resumes at the actual RIP without repeating the first memory
access. STOP-RIP at the post-singleton boundary also pauses before the two
following singleton operations, then resumes without repeating the load.
Partial dispatcher windows 1..6
return the explicit fixture boundary with no retirement or data callback. A
loaded noncanonical RSP or RBP is committed as data; the following
`[RSP]` or `[RBP+0]` instruction raises #SS while preserving the first
retirement and making no second data callback.
- No code changed the host frame or callee-save handling; the existing ARM64
canary/frame regressions remain in the suite.
