# S3-20dw — address-size-32 RBP-base dword checked store with disp8

**Status:** bounded implementation slice; S3-20 and Stage 3 remain open.

Runtime commit `c67cb92` adds only the exact four-byte singleton
`67 89 45 ib` (`MOV [EBP+disp8],EAX`) to the shared typed-IR Dword-store
path. The decoder-owned operand uses low32 EBP plus sign-extended disp8,
wraps the sum modulo 2^32, then zero-extends the starting effective address.
A successful checked operation transfers four contiguous bytes from low32
EAX and advances to `A+4`. Address-size wrapping applies to the starting
address: a write beginning at `0xffffffff` proceeds contiguously beyond the
4-GiB boundary instead of wrapping each byte to zero.

The JIT descriptor test binds all 256 encoded displacement bytes to distinct
source/site identities and checks the `A+4` guest boundary. The host fixture
does not execute all 256 values: it checks six encoded displacement/base pairs,
each with low and high full-width RBP values. Native execution is compared
with the interpreter for CPU state and RAM, including successful writes at
the 4-GiB boundary. Budget and STOP guards prevent a write; callback STOP
follows the committed write. For each injected architectural or unmapped
write error, the guest-memory callback records exactly one write attempt and
returns an error; CPU state and RAM bytes remain uncommitted.

This is address-size-32 EBP addressing, not address-size-64 RBP addressing;
it makes no address-size-64 `#SS` claim. Other bases/forms, prefixes, SIB, and
displacement widths remain closed. This fixture does not establish MMIO, SMC,
owner/MMU integration, or hardware behavior.
