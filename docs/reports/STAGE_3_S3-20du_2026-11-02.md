# S3-20du — exact RBP-base dword checked-memory store with disp32

**Status:** bounded implementation slice; S3-20 and Stage 3 remain open.

Runtime commit `d22dd82` adds only the six-byte singleton `89 85 id`
(`MOV [RBP+disp32],EAX`) to the shared typed-IR Dword-store path. The decoded
memory operand supplies full-width RBP plus signed disp32 with wrapping. The
JIT source/site test covers twelve representative disp32 values, and then
mutates each of the four displacement bytes to check that its site identity
changes. The host parity fixture's successful-value loop covers ten values.
These checks bind the tested displacement bytes; neither is an exhaustive
sweep of all 2^32 possible disp32 values. A successful write transfers exactly
four bytes from low32 RAX and advances the guest boundary to `A+6`.

The bounded host fixture compares published execution with the interpreter.
RBP noncanonical-start and range-end faults report `#SS`. The RBX `#GP`
control inside this fixture is the disp8 encoding `89 43 01`; the separate
S3-20cu tests cover RBX disp32. Effective-address addition wraps
`u64::MAX+1` to zero. A width-four range overflow returns before the write
callback or architectural commit. Architectural/backend faults leave writes
and state uncommitted. Budget and entry STOP perform no write; a successful
callback STOP preserves its committed write and state, and resuming at the
committed RIP does not replay it. This is bounded fixture evidence and makes
no separate PC-map claim. No other base, address form, prefix, SIB, or
displacement width is admitted, and no MMIO, SMC, owner/MMU, or hardware
integration is established.
