# S3-31l Warm and first-dispatch comparison against the pre-memo dispatcher

Both arms use `a4dbc7d`. The original arm restores exactly
`run_cached_store_controlled` from `ac3395da`, yielding the same
`dispatch.rs` bytes as the original arm of S3-31i. The current arm
uses the memo and the explicit hit arguments adopted in S3-31k.
All remaining source files, dependencies, toolchain inputs and
per-mode drivers are shared. Both warm builds passed 11 focused
emitter, cache and STOP tests on M1 Pro. The cold executables link
the same respective release libraries as the warm executables.
[Previous warm hit experiment](STAGE_3_S3-31k_2026-11-19.md)

## Warm JIT

Six rounds used each ordering of original, current and a repeated
launch of the same signed current file. Each process collected eight
alternating JIT/interpreter pairs for each S3-31i profile. Raw JIT
ratios compare process medians within each round. The normalized
column first computes each process median of the eight pairwise
JIT/interpreter ratios, then compares those medians within each round.
The table reports median [min, max] across six rounds.

| Profile | Current/original JIT | Current repeat/current JIT | Current/original normalized |
| --- | ---: | ---: | ---: |
| `same_1` | 1.0005 [0.9936, 1.0032] | 1.0020 [0.9933, 1.0067] | 0.9806 [0.9731, 1.0039] |
| `same_3` | 1.0007 [0.9955, 1.0096] | 1.0020 [0.9878, 1.0067] | 0.9843 [0.9726, 0.9962] |
| `same_64` | 0.9997 [0.9977, 1.0025] | 0.9996 [0.9975, 1.0027] | 0.9830 [0.9814, 0.9870] |
| `same_4096` | 1.0033 [1.0020, 1.0077] | 0.9999 [0.9916, 1.0005] | 0.9886 [0.9843, 0.9895] |
| `two_64` | 0.0814 [0.0808, 0.0817] | 1.0002 [0.9953, 1.0049] | 0.0799 [0.0793, 0.0802] |
| `two_4096` | 0.0659 [0.0655, 0.0667] | 1.0003 [0.9994, 1.0010] | 0.0648 [0.0645, 0.0654] |

The `same_64` raw range overlaps the same-file control. `same_4096`
took 0.33% more time by paired median, with all six ratios above
the control range. The current dispatcher took 8.14% and 6.59% of
original time on the two alternating-RIP profiles.

## First dispatch

The dedicated S3-31h driver starts before `Session::new` and stops
after the first `Session::run`. It includes two empty-cache
observations and excludes teardown. Both pilots use the same
seed counts and choose shared call counts from the faster sides at
a 32 ms target. Four rounds alternate original and current. The
table reports median [min, max] of the raw and normalized ratios.

| Profile | Current/original first dispatch | Current/original normalized |
| --- | ---: | ---: |
| `same_1` | 0.9880 [0.9729, 1.0033] | 0.9919 [0.9626, 1.0186] |
| `same_3` | 0.9909 [0.9785, 0.9999] | 0.9895 [0.9821, 1.0033] |
| `same_64` | 0.9920 [0.9725, 1.0572] | 0.9941 [0.9773, 1.0529] |
| `same_4096` | 1.0036 [1.0028, 1.0058] | 1.0015 [0.9968, 1.0074] |
| `two_64` | 0.2097 [0.1938, 0.2171] | 0.2099 [0.1940, 0.2171] |
| `two_4096` | 0.0683 [0.0675, 0.0693] | 0.0684 [0.0679, 0.0692] |
| `three_64` | 1.0004 [0.9707, 1.0495] | 1.0006 [0.9742, 1.0617] |

The raw `same_64` range includes unity. `same_4096` took 0.36% more
time by raw paired median. All four raw ratios are above one and
the normalized range includes one. At two alternating RIPs the
current dispatcher took 20.97% and 6.83% of the original time.

ISSUE-520 stays open for the remaining raw time difference on
`same_4096` in warm execution and first dispatch. Both alternating-RIP
profiles remain faster in both measured modes.

## Environment and reproduction

Apple M1 Pro, eight logical CPUs, macOS 14.6.1 (23G93), Xcode 15.4,
and Rust and Cargo 1.99.0. The native ARM64 executables target
macOS 14.0 and passed strict signature checks with Hardened Runtime
and `allow-jit`. The warm, pilot and cold timing processes verified
the ordinary UID 501, nice −5 and QoS `0x21`.
The warm run retained 2,016 intervals with a minimum of 57.022 ms.
The cold run retained 896 scored intervals with a minimum of 30.153 ms.
Median preflight idle CPU was 98.8% and
98.8% respectively. The recorded measurement
windows had median idle CPU of 86.35% and
86.70%, respectively.

The warm archive’s harness replays from raw intervals using
`offline_audit.py`. The cold harness uses `evidence.py replay` and
the archived S3-31h numerical auditor. Each README includes the
exact source, toolchain, benchmark commands and prerequisites.
