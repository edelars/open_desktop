# S3-40n. Decoder controls for the checked-memory MOV pairs

The experiment uses the 2,400 frozen S3-34a inputs and the same
production entry boundaries as [S3-40m](STAGE_3_S3-40m_2026-11-19.md).
The two six-byte streams are `48 89 03 48 8B 0B` and
`48 8B 03 48 89 02`. The input corpus varies state and RAM. The
decoder coverage is limited to those byte streams and their two
instruction boundaries.

The signed build is based on `7e31f99` with generated diagnostic
functions in an isolated source tree. The decoder comparisons use
the ordinary decoder and two guarded clones:

- `mov_arm` preserves the prefix parser, the general checks before
  the operation match, the original MOV arm, and the original
  instruction assembly. The operation match in the clone accepts
  the MOV arm alone.
- `mov_prefix` uses the same prefix parser, MOV arm, operand
  decoder and instruction assembly. It omits the intervening
  general checks before the operation match. Both clones enforce
  one `48` prefix and primary opcode `89` or `8B`.

All three decode sides time two calls and verify full decoded
`Instruction` equality, zero data callbacks and unchanged RAM.
The execution sides time ordinary `run`, the empty-profile
probe from S3-40m, and a combined probe that calls `mov_prefix`
from the same empty-profile step. They verify full state, RAM,
ordered callbacks, exit, retirement and defined flags. Fixture
reset and result checks sit outside the timed intervals.

## Results

Each of three processes uses six timing-side rotations per sequence.
Each side appears once in each position. Process two reverses the
sequence order and rotation direction. Pilot timing set shared sweep
counts of 1,883 and 1,881 per sequence with an 80 ms target.
All 216 scored intervals met the 45 ms floor. The shortest
lasted 77.558 ms.

Absolute cells show the median and full range of 18 samples
in nanoseconds per two-instruction input. Absolute latency varies
by process. The per-process medians for the ordinary store-first
run span 502–927 ns. The paired ratios below compare sides in
the same rotation.

The decoder medians fall from 185–276 ns to 95–136 ns when the
operation match retains the MOV arm. The second clone falls to
36–47 ns. The combined execution probe takes 212–316 ns and
reduces the paired median by about 58–59% relative to ordinary
run. The speed difference appears while using the same prefix
parser and MOV operand logic for these inputs.

The clones change the optimizer's view of the entire control flow.
The measured differences give the effect of those interventions.
Exact costs of the individual checks and of the remaining
interpreter work are open. Production work requires a path that
preserves the decoder's general admission, fetch-fault priority
and profile behaviour. [ISSUE-521](../KNOWN_ISSUES.md#issue-521)

## Reproduction

The archive includes the signed native executable identity,
toolchain, exact source bindings, raw timings, and scripts to
regenerate both decoder clones and both execution probes.
The current fixed-seed memory corpus regression passed 1/1.

Extract the archive's `files` into a fresh directory and run
`audit.py` there to verify the saved rows. For new measurements,
copy the scripts and Rust sources to an empty scratch directory.
From the repository root run its `build.sh` under `zsh` with
`7e31f99 current`, then run the scratch directory's `run.py`
and `audit.py`.

Physical x86 and Mac mini checks remain deferred. The archive
SHA-256 is `44a0796caa08568c2726e073ff61bb8382798047aae55c86ec8adace4dd8c984`.
