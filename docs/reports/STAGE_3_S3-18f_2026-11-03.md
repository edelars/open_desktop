# Stage 3 S3-18f: opt-in retained Load→Load profile

Status: partial; exact retained admission and local regression coverage are
implemented, but Rust execution remains blocked by ISSUE-030.

## Scope

The capacity-one retained memory cache and `od-host` retained publisher now
admit only the existing exact S3-26e Load→Load sequence
`48 8B 03 48 8B 0B`. The typed profile is included in the full cache key and
maps to the existing `LoadThenLoad` sequence. Capacity, the 512 KiB bound,
key validation, replacement/drop behavior, and the one-shot executor contract
are unchanged. `StoreThenStore` and all other unlisted forms remain rejected.

The host regression covers distinct same-address reads with changing returned
values; a same-key hit with fresh CPU, RAM, access context, STOP, event, budget,
and stop-RIP inputs; exactly one miss/compile/publication followed by resident
hits; second-read fault state and remaining budget; continuation at `A+3`
without replay; and retained entry rejection at internal RIP `A+3`. An event
raised during the pair does not interrupt either read, and the exact result is
the existing code-end `BoundaryReached` at `A+6`. A separate fresh pre-entry
event returns `EventPending` with zero reads and zero retirement.

ADR-0004 now records the exact added profile and preserves its revisit rule for
future profiles. `JIT_CONTRACT.md`, `ARCHITECTURE.md`, the Stage 3 plan, and
JIT test instructions describe the bounded support and its limits.
