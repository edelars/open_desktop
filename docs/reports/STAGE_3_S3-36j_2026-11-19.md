# S3-36j. One NativeRegisterV1 cache lookup on a hit

The cached NativeRegisterV1 dispatcher already records a hit and updates
the cache policy before borrowing a published block. It now uses the
post-policy index returned by `record_hit`. It previously searched for
the same key again to locate the entry after a possible LRU move. This
applies to both freshly built and prepared keys. Each published entry
still passes dependency and code-view validation before execution.

## Paired release measurements

Both builds start from `d99ce3b` and use the same driver for the four
[S3-55 mixed profiles](STAGE_3_S3-35g_S3-36i_2026-11-19.md). The timed
route uses eager flags and FIFO16. Warm starts with all entries resident.
Cold includes mixed admission, new cache and arena, and first dispatch.
Each call verifies the full CPU state against the interpreter, exit,
retirement, remaining budget, helper counts, cache activity, code size
and logical metadata size. State reset, validation and teardown are
outside timing. Both alternatives publish the same code and account for
the same resident metadata.

Each timing mode uses four sequential rounds with baseline-first order
in rounds one and three and candidate-first order in rounds two and four.
Each process has eight JIT/interpreter pairs per profile, alternating call
order. Pilots set common counts for both variants within each mode, with
a 60 ms target and a 30 ms floor. The 512 warm and 512 cold timed sides
all met the floor. The shortest warm and cold intervals were 58.518 ms
and 59.601 ms.

For each round, the raw ratio divides the candidate's median JIT time
per call by the baseline's median. The normalized ratio divides the
candidate's median paired JIT/interpreter ratio by the baseline's median
paired ratio. Both columns show the median and range over four rounds.
The last column summarizes the candidate's 32 JIT/interpreter pairs.

Both straight-line warm profiles improved in every round before and
after normalization. Their normalized medians were 1.86% and 2.58%
lower. Warm loop medians were 2.42% and 2.09% lower after normalization,
with one round above parity in each loop. The cold straight-line ranges
crossed parity. In the cold loops, the 64-iteration raw range and the
512-iteration normalized range stayed below parity. The interpreter
remained faster in every pair.

The change removes a cache search and retains the simpler hit path.
Performance claims apply to the four bounded mixed FIFO eager workloads.
Other NativeRegisterV1 strategy and policy combinations have correctness
checks. Physical x86 and Mac mini checks are deferred.

## Correctness and reproduction

Both signed builds passed all four mixed profiles with FIFO and LRU in
cold and warm smoke calls. The LRU runs verified the same work and cache
footprint as FIFO. The measured candidate source also passed 105 JIT
dispatcher unit tests with one ignored and the exact
`tests::s3_54_native_multi_cache_reuses_published_handle` host gate.
The host test checks eager and demand flags, FIFO and LRU, full guest
state and publication identity.

The tests and measurements ran on Apple M3 Max with macOS 26.7.1
(25G241) and rustc 1.99.0. Ad-hoc signatures enable the Hardened Runtime
and the JIT entitlement. The archive contains the exact runtime patch,
driver and scripts, signed binary and library hashes, work counts,
schedule, raw timings and offline audit.

Extract the archive's `files` to a scratch directory and run `audit.py`
with Python to reproduce the ratios. To measure again, copy the
drivers and scripts to a fresh scratch directory. From the repository
root run the scratch `build.sh` using `zsh`, revision `d99ce3b`, and
`baseline` or `candidate`. Build both variants, then run `run.py` and
`audit.py`. For the LRU smoke, use `link_lru.py` with each built side and
its target directory. Invoke each resulting binary in both modes with
`1 0 2 2 2 2` after the mode name.
