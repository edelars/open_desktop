# S3-36g. Warm same-RIP dispatch in the retained Session

The cached S0-09 dispatcher now remembers the most recent resident entry
within one invocation. When control returns directly to the same RIP, it
records a hit at that index and uses the index returned by FIFO or LRU hit
handling. A different RIP takes the existing build and full-key lookup path.
The dispatcher validates the cached code and dependency snapshot and checks
control before each host entry. The retained Session used by VMHost calls
this dispatcher. The test for A, A, B, B checks that FIFO and LRU execute the
right published handles across same-RIP reuse and RIP changes.

## Release comparison

The benchmark times the full Rust `Session::run` call and the synchronous
Rust interpreter on the same bytes, state, budgets and guest work. Each JIT
measurement uses a resident session. State reset, correctness checks, session
creation and teardown are outside the timer. Each execution checks full CPU
state, exit, retirement and remaining work. Timed JIT samples also verify
hit-only cache activity and the executed block count.

The one-RIP loop uses `48 2B C1 75 FB` from the S0-09 subtract-and-branch
fixture. The comparison varies the initial counter over 1, 3, 64 and 4096
iterations. The two-RIP control uses `48 2B C1 74 02 75 F9` at 64 and 4096
iterations. The first conditional branch exits when the counter reaches zero.
Otherwise the next block jumps back to RIP 0. The second profile exercises
normal lookup on every transition.

Both signed drivers link the `od-host` release library built with the same
Cargo command and toolchain. The only runtime source difference is the
dispatcher patch. The comparison uses three sequential process rounds and
runs the candidate executable first in the middle round. For each profile
both builds and both engines use the same call count in all eight samples
per round. The driver alternates JIT-first and interpreter-first order.
Each timed side must reach 100 ms. A first attempt aborted on a 98.296 ms
candidate side.
The restart used larger matched counts for `same_3`, `same_64`, and
`same_4096` based on calibration with the signed candidate.

## Results and decision

The audit verified 576 timed sides, with a minimum of 139.682 ms. The raw
column divides median candidate JIT time by median baseline JIT time within
each round. The normalized column first divides each JIT sample by its paired
interpreter sample, then compares the median ratios in that round. Both
columns show the median and full range across the three rounds. The last
column pools 24 paired ratios from the candidate build.

| Profile | Candidate / baseline raw | Candidate / baseline normalized | Candidate / interpreter |
| --- | ---: | ---: | ---: |
| `same_1` | 1.0375 [1.0339, 1.0504] | 1.0425 [1.0247, 1.0440] | 1.4897 [1.4398, 1.5199] |
| `same_3` | 0.4234 [0.4191, 0.4310] | 0.4209 [0.4209, 0.4376] | 0.6444 [0.6304, 0.6687] |
| `same_64` | 0.0761 [0.0757, 0.0769] | 0.0760 [0.0749, 0.0770] | 0.1147 [0.1134, 0.1211] |
| `same_4096` | 0.0564 [0.0561, 0.0688] | 0.0577 [0.0573, 0.0577] | 0.0870 [0.0805, 0.1004] |
| `two_64` | 1.0448 [1.0005, 1.2219] | 1.0222 [1.0217, 1.0357] | 1.8097 [1.1610, 1.9480] |
| `two_4096` | 1.0373 [0.9988, 2.4132] | 1.0347 [1.0197, 1.0588] | 1.8131 [1.5263, 2.7200] |

Use same-RIP reuse in the retained S0-09 path. The one-RIP loop beat the
interpreter in every paired sample at 3, 64, and 4096 iterations. A single
pass cost 3.75% more by the median raw comparison. The alternating controls
had 2.22% and 3.47% median normalized overhead. In the final `two_4096`
round, interpreter time increased alongside the large raw JIT ratio.
Resident code and logical metadata were identical across the builds for each
case. Whole-process memory, the cold matrix and broader S3-36 acceptance
remain open. The first dispatch on an empty cache is recorded as a diagnostic
sample. Physical x86 and Mac mini checks are deferred.
