# S3-40m. Interpreter controls for ISSUE-521

This comparison uses the same 2,400 frozen S3-34a inputs as
[S3-35h and S3-36k](STAGE_3_S3-35h_S3-36k_2026-11-19.md). It
runs on historical revision `d24865d` and current revision
`8243cfd` with one release driver and shared per-sequence call
counts. Each input has two three-byte MOV instructions, with
the store and load orders measured separately.

The ordinary side times the complete interpreter `run` helper
used by the earlier benchmark. The step side times two public
`step` calls. Those calls start with fresh defined flags and
leave the same state on the measured MOV pairs. They have their
own control boundary. The decode side times two calls to the
public long-mode decoder and checks the returned instructions
and the absence of data callbacks.

The isolated current build adds a fourth side. It uses copies
of the existing configured run loop and step bodies, with the
138 profile configuration fields bound to the compile-time empty
configuration of ordinary `run`. It uses the same budget and
initial defined flags. Its separate wrapper and generated code
layout are part of the probe. All execution sides compare full
state, RAM and ordered memory events with the ordinary interpreter.
Run and probe also check the budget exit, exact retirement and
defined flags. State and fixture reset and result checks happen
outside the timed intervals.

## Results

Four rounds alternate which revision runs first. Even rounds reverse
the sequence order and the direction of timing-side rotation. Each
sequence and side has four samples
per process. Pilot measurements set shared sweep counts of
1,611 and 1,644 for an 80 ms target. All 224
scored intervals met the 45 ms floor. The shortest side was
77.932 ms. Each time below is the median
and full range of 16 samples, in nanoseconds per two instructions.

| Sequence | Build | Run | Two steps | Two decodes | Empty-profile probe |
| --- | --- | ---: | ---: | ---: | ---: |
| `store_then_load` | `d24865d` | 115.8 [111.3, 120.0] | 111.2 [108.3, 117.0] | 41.7 [40.3, 44.6] | — |
| `store_then_load` | `8243cfd` | 483.1 [470.4, 506.5] | 484.0 [476.8, 505.7] | 179.8 [176.1, 187.6] | 353.8 [347.1, 377.6] |
| `load_then_store` | `d24865d` | 114.7 [110.9, 120.5] | 111.7 [108.2, 113.6] | 41.5 [40.5, 43.2] | — |
| `load_then_store` | `8243cfd` | 483.1 [472.4, 503.6] | 486.0 [475.9, 505.6] | 178.9 [177.1, 185.6] | 355.4 [346.9, 375.0] |

The first three ratios compare the current and historical medians
within each matched process round. The last ratio compares the
probe with ordinary `run` within the current binary and uses all
16 paired samples per sequence. Cells show the median and full range.

| `store_then_load` | 4.213 [4.101, 4.238] | 4.381 [4.239, 4.422] | 4.308 [4.175, 4.387] | 0.739 [0.721, 0.751] |
| `load_then_store` | 4.238 [4.118, 4.426] | 4.376 [4.310, 4.528] | 4.304 [4.262, 4.409] | 0.737 [0.717, 0.758] |

Two separate steps retain the gap seen with the complete run loop.
Two decodes alone show a 4.30–4.31× median ratio. Binding the empty
profiles in the isolated build brings the current full call from
about 483 ns to 354–355 ns. Its paired median falls by about 26%.
These controls identify increased decode cost and a partial recovery
from specializing the empty-profile execution path. The timings
cover separate calls and code layouts. Attribution within the
decoder and the remaining execution cost is open.
[ISSUE-521](../KNOWN_ISSUES.md#issue-521)

This is diagnostic evidence for the two frozen Stage 3 sequences.
The profile probe runs in the isolated benchmark build. The
production path requires its own correctness and performance
verification before adopting a specialization. Physical x86 and
Mac mini checks are deferred.

## Reproduction

Both builds use ad-hoc Hardened Runtime signatures and the local
JIT entitlement. The archive records host and toolchain, signed
binary identities, build inputs, source bindings and all raw rows.
The existing fixed-seed memory corpus regression passed 1/1 on the
current worktree.

Extract the archive's `files` to a fresh scratch directory and run
`audit.py` there to verify saved data. For fresh measurements, copy
the Rust sources and scripts into an empty directory. From the
repository root invoke its `build.sh` under `zsh` with
`d24865d historical` and `8243cfd current` respectively, then
run `run.py` and `audit.py` from the scratch directory.
