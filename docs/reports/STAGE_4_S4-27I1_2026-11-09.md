## Что сделано

- **`InterruptPump`** (`crates/od-machine/src/interrupt_pump.rs`): владеет
  `Cpu { Running(DiagnosticVcpuSession) | Waiting(DiagnosticHaltWait) }` и `LocalApicHandle`.
  `run(budget, stop) -> PumpResult { exit, quanta, retired }`: STOP -> бюджет -> проверка APIC
  (IF=1, shadow Clear, завершённая граница, `eligible()`) -> доставка через
  `run_apic_quantum` или одна инструкция (HLT -> `into_halt_wait`; STI и CLI ->
  `run_sti_apic_quantum`; IRETQ -> `run_same_cpl0_iretq`; остальное -> `run_apic_quantum`);
  Waiting -> `poll_apic`. Выходы: `IdleHalt`, `Budget`, `Stopped`, `Terminal`, `Rejected`.
  Трасса событий (`Irr`, `Entry{Boundary|HaltWake}`, `Eoi`, `Sti`, `Cli`, `Hlt`, `Iretq`),
  инъекции `SkipShadowCheck` и `HltAsOrdinary`. Без clock, таймера, очереди, paged, JIT.
- **Загрузчик профиля** `Stage4InterruptPumpProbeV1`
  (`crates/od-machine/src/stage4_interrupt_pump_probe.rs`): строгая проверка образа

- **Builder** `tools/build/build_stage4_interrupt_pump_probe.py` (+ тест, 7 тестов):
  ожидания (кадр, RFLAGS, трасса, финальное состояние, IRR/ISR) выведены из Intel SDM и

- **Тесты** `crates/od-machine/tests/interrupt_pump_flat.rs` (12 тестов).
- **Runner** `--stage4-interrupt-pump-probe IMAGE [--budget N] [--request VECTOR@AFTER_QUANTA]...
  [--inject-skip-shadow-check | --inject-hlt-as-ordinary]`

## Что найдено при реализации

- **Профиль STI (S4-27c) узкий:** в shadow допускаются только NOP, STI, CLI (иначе
  `Unsupported`); CLI обычный интерпретатор не исполняет — его нужно вести через
  `run_sti_apic_quantum` (как STI). Pump так и делает; fixture использует `STI; NOP`.
- **HLT в `run(1)`:** обычный интерпретатор не имеет HLT, результат — terminal
  `Unsupported`, а не `Halted` (как предполагал план); `Halted` возвращается только при
  запуске уже остановленного CPU, что через API pump недостижимо. Инъекция
  `HltAsOrdinary` фиксирует terminal `Unsupported`.
- **Инъекция «пропуск shadow»:** принятый `run_apic_quantum` сам отказывает в shadow
  (`ProfileRejected`), поэтому обход проверки pump даёт `Rejected(ApicQuantumProfile)`, а не
  неверный кадр. Принять вектор в shadow без изменения принятых API нельзя.
- **Локальный APIC:** по умолчанию `SVR = 0xFF`, `eligible()` пуст; гость включает APIC
  записью `0x1FF` (пролог из трёх инструкций), запросы caller подаются после пролога.
- **Приоритеты:** для случая «self-IPI B во время A» выбраны `A = 0x51` (класс 5), `B = 0x41`
  (класс 4): B не eligible, пока A в обслуживании, и без EOI не принимается никогда. Сам по
  себе IF=0 внутри handler A не пускает B; порядок, показанный трассой с EOI, сам по себе
  приоритет не доказывает; приоритет на уровне pump доказывает вариант без EOI (после IRETQ
  IF=1, а B всё равно не принят), на уровне APIC — `eligible() == None`.

## Ожидания и источники (не вывод кода)

- Кадр внешнего прерывания (SDM Vol. 3A 6.14.2–6.14.3): пять qword SS, RSP, RFLAGS, CS, RIP,
  выравнивание RSP по 16 (`0x6FF0` уже выровнен) -> новый RSP `0x6FC8`; RFLAGS в кадре
  `0x202`, в handler `0x002` (IF сброшен шлюзом прерывания); CS `0x08`, SS `0x10`.
- STI/HLT (SDM Vol. 2): после STI граница перед HLT приёма не допускает; прерывание,
  разбудившее HLT, кладёт RIP после HLT (`0x4012` при HLT на `0x4011`); при IF=1 без shadow
  приём на границе перед HLT кладёт RIP самого HLT (`0x4012`); при IF=0 маскируемый вектор
  HLT не будит (`IdleHalt`, вектор в IRR).
- Приоритет и EOI (SDM Vol. 3A 10.8.3.1): класс вектора должен быть выше обслуживаемого;
  EOI снимает ISR.

## Отклонения от плана и ограничения

- **Частичный REP (по плану записать как отклонение).** После `WorkLimit(RepIterationBudget)`
  (1024 итерации) граница не завершена: `run_apic_quantum` отказывает в незавершённой
  границе, поэтому pump довершает инструкцию без проверки APIC. Прерывание принимается после
  REP, тогда как железо может принять его между итерациями (RIP на REP, частичный RCX).
  Проверено тестом `partial_rep_delays_the_interrupt_until_the_instruction_completes`.
- **CLI через `run_sti_apic_quantum`** (план называет только STI); иначе CLI не исполняется.
- **Доставка через `run_apic_quantum` исполняет первую инструкцию handler** в том же кванте:
  она не может быть STI/CLI/HLT/IRETQ; при wake из HLT инструкция handler не исполняется.
  Evidence кадра читается из RAM, а не из состояния сразу после входа.
- **CLI при IF=1 вне STI-shadow не поддержан.** Принятый путь (`StartIfSet` в
  `od-isa/execute.rs`) допускает только `sti`; CLI при IF=1 и shadow Clear даёт terminal
  `Unsupported`, pump на обычном `cli` с включёнными прерываниями завершается `Terminal`.
  Сценарий `CLI; HLT` идёт при исходном IF=0 и этот случай не покрывает.
- **`Entry.rip` в трассе различается по источнику:** у `Entry{Boundary}` — адрес handler плюс
  длина его первой инструкции; у `Entry{HaltWake}` — адрес handler (инструкция handler при wake
  не исполняется).
- **«HLT в `run(1)` даёт terminal `Halted`»** в плане — на деле `Unsupported` (см. выше).
- Добавлены два crate-private метода `peek_ram_qword` (чтение RAM без побочных эффектов)
  для evidence кадра; поведение принятых API не менялось.
