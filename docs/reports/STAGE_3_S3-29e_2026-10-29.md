# S3-29e / S3-15p: bounded arithmetic/checked-load coordinator

**Status:** bounded runtime API implemented and independently reviewed.
Eager remains the default and demand-flags remains opt-in and uncached. This
does not close S3-15 or S3-29.

## Scope and contract

`od_jit::memory_dispatch::run_bounded_arithmetic_load` composes the existing
register compiler, checked-load V2 compiler/dispatcher, and controlled
executor interfaces for one/two exact `48 03 C3`, `48 2B C3`, or `48 3B C3`
writers; the exact `48 8B 03` qword load; JZ/JNZ to the global code end; and
the existing `48 03 C3` fallthrough suffix. A full decode of the immutable
`CodeView` validates the complete plan before execution. The same full view is
used in every phase, so RIPs retain the original guest addresses and the prefix
end is only an internal handoff.

The API accepts restart at every decoded arithmetic boundary, the load RIP,
the Jcc/fallthrough boundary, or code end. It carries one remaining budget
and STOP/stop-RIP/event through native and memory phases and validates report
counts and phase RIPs, including terminal exits. It returns typed
plan, entry, compile, executor, accounting, progress, memory-dispatch, and
phase errors. The host `ControlledBlockExecutor` hook can sample cooperative
control after publication and before native entry. The real host adapters
release the native mapping before the memory step and release the memory
mapping before suffix compilation.

## Evidence

- The native differential host test now calls the coordinator for eager and
  demand-flags candidate runs and compares complete CPU state, RAM and
  separate retirement counts with the interpreter for ADD/SUB/CMP, JZ/JNZ,
  both branch paths, and one/two arithmetic writers.
- Guest #PF and noncanonical #GP preserve the committed arithmetic prefix and
  load RIP, retire no load, leave RAX/suffix untouched, and resume at the
  returned load RIP without replaying the prefix for both strategies. The #PF state at handoff
  matches a complete interpreter prefix snapshot.
- Callback event yields after a committed load and before suffix execution;
  resuming at suffix RIP does not repeat the memory operation.
- Invalid branch plan and malformed native and memory report mocks are
  rejected with typed errors before further callbacks. Existing companion
  checks additionally exercise backend errors and repair/retry for both
  strategies; errors remain host errors rather than guest faults.
- Test coverage includes STOP-RIP, STOP, zero budget, and event priority at
  entry/load/suffix boundaries, exact code-end completion/stop-RIP priority,
  and zero-retirement STOP after publication. Budget stops within the
  two-writer prefix and at Jcc fallthrough resume at the returned RIP with
  their native/memory counters intact and no replay. Physical mapping release
  is exercised by the existing `PublishedBlockExecutor` and
  `PublishedMemoryBlockExecutor` adapters.

## Limitations

The supported byte profile is deliberately exact and uncached. This API still
borrows caller-supplied `CodeView` and `GuestMemory`; it does not provide
owner-backed code fetch, permission/revocation guarantees, production RAM/MMU
integration, alias invalidation, general multi-block dispatch, or a complete
interpreter fallback. S3-15 owner/corpus acceptance, physical x86, Stage 2,
Mini and performance remain outside this slice. The final Stage 3 performance
and Mini checks remain deferred until the end of the stage.
