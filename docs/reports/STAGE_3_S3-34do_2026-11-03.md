# S3-34do — bounded value-only reducer for one S3-34dn artifact

## Scope and status

This bounded implementation reduces one validated S3-34dn artifact for
`67 89 04 24`. Runtime commits `5ae5e47`/`0e64b07` and harness commit
`2c24eec` are integrated and passed independent static Sol/high review. The
reducer self-check and pinned harness self-test have now passed, but this is
synthetic self-check evidence only; no real artifact was reduced. Stage 3
remains partial.

The original artifact must first reproduce twice from its saved CPU/RAM state
with deterministic observations and the exact recorded mismatch signature.
If original replay returns `not_reproduced`, stop and produce no reduced
artifact. Candidate mutation may change only non-address GPR values and bytes
already present in the mapped fixture RAM. Preserve source/profile, RIP,
effective address, RSP, flags, seed/index provenance, and RAM address
map/layout. Preserve the callback protocol: exactly one contiguous width-four
write at the fixed address, with callback bytes matching candidate write data
and resulting RAM.

Candidates are generated deterministically in a fixed order with at most 256
candidate attempts per artifact. Each starts from the current best input and
runs interpreter and JIT twice from reset state. Accept only if observations
match across each backend's repeats, the comparator mismatch string equals the
original artifact's `mismatch` field, the structured mismatch signature
exactly matches the original, and mutable-value popcount is lower than the
current best. The first passing candidate in order becomes the new best, then
the search regenerates candidates and repeats until no candidate passes or the
attempt cap is reached. This deterministic greedy search does not claim global
minimality. If the original reports `not_reproduced`, or no candidate passes,
no reduced artifact is written.

## Validation boundary

The existing `classify_replay` validates only the original artifact: it
compares complete observations against those recorded there, so modified
candidates cannot pass against the original observations. Candidate
acceptance instead uses `candidate_passes_ordinary_replay` with candidate-
specific recorded observations. It requires repeat determinism, the exact
recorded mismatch string, the structured stable mismatch signature, and the
profile/callback constraints. Do not use `classify_replay` for candidate
acceptance and do not generalize this into a replay/reducer framework.

Write a reduced artifact with create-only semantics only after a candidate
passes every condition and has a strictly lower mutable-value popcount. Never
replace the original or an existing reduced artifact. The reducer self-check
is a fail-closed acceptance gate using labeled synthetic data. It verifies
bounded deterministic candidate generation, preserved profile/value classes,
popcount reduction, stable structured signature retention, and rejection when
a mismatch class is lost or observations are unstable. It does not run the
reducer on a real S3-34dn artifact; synthetic evidence cannot establish
runtime mismatch behavior.

## Controlled runtime capture, replay and reduction

On local macOS ARM64, the exact Rust case
`s3_34do_captured_runtime_mismatch_replays_and_reduces` passed. It executes
the interpreter and the published native store. After checking the native
result against the expected observation, it flips one bit in the recorded
R9. The differential comparator captures the discrepancy and the artifact
writer saves the observed results and original input.

The saved original reproduces when replay applies the same injection to both
native repetitions. The ordinary replay reports `not_reproduced`, and the
ordinary reducer performs four observations and tries zero candidates. With
injection enabled, the reducer saves a separate artifact with fewer set bits
in the mutable input values. Its profile, seed, case index and mismatch class
are preserved, its saved observations replay, and the original file retains
its exact bytes.

The complete `stage3_dword_store_corpus` Rust target passed 6/6. Under
default parallel execution, the initial test exposed `MappingAlreadyLive`
when the corpus and replay published at the same time. Both publication
paths now serialize the lifetime of the executable mapping with one
test-local lock. The focused Python harness self-test passed and checks
exact selection and evidence for the new mandatory local gate
`s3_34do_captured_runtime_mismatch`. These
results cover the exact store profile and a controlled discrepancy. General
S3-34 acceptance remains open. Physical x86 and Mac mini checks are deferred.
