# Stage 4 S4-33a — guest RAM alias store→load

Статус: bounded case принят после независимого `gpt-6.1-sol/high` review.
Этот ограниченный case не закрывает parent S4-33 или Stage 4.

## Контракт

`Stage4AliasProbeV1` — отдельный строгий raw-image profile. Page tables
отображают data GVA `0x800000` и stack GVA `0xa00000` на одну RAM-страницу GPA
`0x9000..0xa000`, которая находится внутри raw image. В образе лежат разные
initial и store qwords. Guest выполняет `MOV [RBX],RCX; POP RAX; OUT DX,AL; HLT`:
первая операция изменяет физическую страницу, `POP` читает новое значение
через второе GVA. Runner считает сценарий успешным только если HLT дополнен
совпадением ожидаемого qword в RAM, RAX и UART.

## Проверки и границы

Machine tests проверяют guest-visible RAM transition, alias load, leaf A/D
effects, единственную operand write и полный порядок committed callbacks;
разорванная alias mapping отвергается строгим loader. Runner/builder tests
проверяют несколько initial/store значений, raw reproducibility, manifest
GVA→GPA и stack layout, budgets и injected broken alias, который достигает
HLT, но должен провалить acceptance oracle. Старые S4-32 loader profiles
сохраняют прежний non-alias layout.

Это uncached interpreter evidence. TLB-on/JIT invalidation, cross-page access,
guest `#PF` repair/retry, Linux, IRQ/APIC и physical hardware не подтверждены.
S4-13/14/16 и S4-18/19 остаются отдельными criteria.

Reviewer отметил необязательное P3: runner regression проверяет operand entry
в JSON callback trace, но не сравнивает весь trace; точный callback order
проверяется machine-level test.

Число тестов, точные команды и review result записаны в
[`s4-33a-ram-alias.json`](data/stage4/s4-33a-ram-alias.json).
