# S3-23c — tracked V2 executable-code store fixture partial

**Date:** 2026-10-27. **Status:** implemented locally; independent review clean.
This is a bounded one-vCPU fixture slice and does not complete S3-23.

## Scope and path

The host arena now accepts a typed V2 store artifact in a dedicated slot that
shares its single executable mapping with cached V1 runtime blocks. The V2
store handle and metadata remain distinct from the V1 cached-block executor.
The arena reports cache capacity after subtracting reserved V2 store slots.

A fixture-only unsafe owner contract wraps the existing compiler-issued V2
store entry. Before generated entry, the owner computes the destination with
the decoded MemoryOperand address semantics and preflights the full qword range,
mapping write/execute permission, next nonwrapping backing version, and
backing-relative overlap with the owner-held active source span, including
aliases. It also verifies the artifact RIP and immutable source bytes match
that active-source lease. Preflight decisions are staged and only surfaced if
the generated helper reaches the write, preserving stop-RIP → STOP → budget
priority. The owner stores guest executable bytes in fixed ordinary host RAM, never in the
MAP_JIT arena. The existing unsafe private-data V2 store API and its
non-executable backing precondition remain unchanged.

Generated code performs one checked write. The host decodes the result while
the typed store handle and arena borrow are live. Only after that return does
the owner commit its backing version and emit CodeInvalidation; the caller
applies it before another cache lookup. Notification draining also occurs when
result decoding returns an error, preserving any write already committed by
the backend. There is no retry or fallback.

## Behavioral evidence

- Warmed target B and unrelated C as cached native V1 blocks in the same arena.
- Published a compiler-issued 48 89 /r V2 store in a separate typed arena slot.
- Stored a qword through an alias mapping to B's backing. Exactly one
  little-endian write occurred; backing version advanced once after result
  decoding; B was invalidated and C remained cached.
- Requested STOP from the successful write helper. The store's RIP and
  retirement commit remained visible, the notification was consumed, and the
  next B dispatch compiled and executed the updated bytes/value.
- Confirmed cache capacity excludes the reserved V2 slot and releasing the
  store handle restores that capacity.
- Verified stop-RIP, STOP, and zero-budget exits leave the owner untouched even
  with an invalid active-source destination.
- Rejected an artifact whose RIP/source bytes do not match the owner-held active
  source lease, plus active-source alias overlap, out-of-range access, missing
  write/execute permission, and exhausted backing version before mutation.
- Injected backend write failure and verified CPU state, bytes, version, and
  cache entries remained unchanged.

Targeted tests:

- tracked_v2_store_invalidates_alias_after_return_and_preserves_late_stop_commit
- tracked_v2_store_preflight_overlap_and_backend_failure_are_atomic

## Boundaries

The fixture models fixed RAM, explicit executable backing IDs and aliases, and
one synchronous vCPU. It does not integrate a production MMU, interpreter or
other writer paths, MMIO, DMA, concurrent writers, SMP, active-code invalidation,
or general self-modifying-code retirement. It does not relax or call the
private-data unsafe store API. Physical Mini checks and long benchmarks were
not run; Mini remains the final Stage 3 gate.
