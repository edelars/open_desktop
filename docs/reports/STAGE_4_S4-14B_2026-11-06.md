# S4-14b: standalone INVLPG effect and experimental cache consumer

## Scope

Adds the feature-independent `InvlpgLong64V1` CPU entry for exact bare
`0F 01 3B` (`INVLPG [RBX]`) and exact LOCK encoding `F0 0F 01 3B` for its #UD
behavior. The profile fixes Long64, canonical48/physical36 four-level paging,
one vCPU, CR0=`0x80010033`, CR4=`0x20`, EFER=`0xd00`, valid CPU-owned CR3,
Running state and clear interrupt shadow. It rejects instruction starts at
`0xff2–0xfff` before fetch. Other forms remain Unsupported.

Bare INVLPG at CPL1–3 raises #GP(0) after full fetch; exact LOCK raises #UD
after full fetch. CPL0 with canonical RBX retires once and emits
`TranslationInvalidation::Invlpg { linear_address }`, preserving the original
address value. CPL0 with noncanonical RBX retires as a no-op without an effect.
Privilege is checked before canonicality. The CPU preserves GPRs, CRs, concrete
RFLAGS and definedness; RBX is never dereferenced, so the target creates no
translation, data access, page fault or A/D update.

Under `experimental-translation-probe-cache`, `od-machine` consumes a typed
invalidation by clearing the entire one-entry experimental cache before the
next lookup. Consumption reports success even for an empty cache and does not
walk or modify RAM/A/D. The composition uses a fetch-only pure-translation
adapter over the same immutable memory snapshot, bypasses the resident cache
for instruction fetch, and proves `Walk → Hit → INVLPG → consume → Walk → Hit`.

## Review and checks

- Architecture: `gpt-6-astra/high` approved the bounded profile, exception
  ordering, typed effect, full-clear policy and acceptance boundary.
- Independent implementation review: `gpt-6.1-sol/high` clean; no P0–P3
  findings remain after fixing early-mismatch fetch and strengthening the
  post-consumption Walk/Hit assertions.
- Focused ISA INVLPG tests: 3 passed.
- Focused feature-gated cache tests: 13 passed, including preserved warm-cache
  hits for noncanonical NOP, privilege fault, LOCK fault and fetch failure.
- Full `od-machine` tests without the cache feature: 82 unit and 98 integration
  tests passed. With the feature: 94 unit and 98 integration tests passed.
- `cargo check -p od-isa -p od-machine --all-targets --locked --offline` passed
  with the feature enabled and disabled; formatting and diff checks passed.
- Graphify was updated after code integration; final graph counts are recorded
  in the manifest: 26,542 nodes, 66,136 edges and 970 communities.
- The final `tools/check_layout.py` run reports `Unmapped root directory: smoke`.
  `smoke/` was empty and left untouched; this slice adds no root directory.

The slice does not integrate the cache with mutable tracked memory. S4-14a's
drop–mutate–recreate boundary remains required for page-table writes. Remap and
permission refresh, tracked A/D caching, huge pages, global/PCID, CR3-triggered
invalidation, JIT invalidation and production TLB correctness remain open.
Full S4-14 and Stage 4 remain open.

Normative semantics: Intel SDM Revision 093, Vol. 2A, Chapter 3,
`INVLPG—Invalidate TLB Entries`, and Vol. 3A §5.10.4.1, “Operations that
Invalidate TLBs and Paging-Structure Caches.” See the
[official Intel Vol. 2A](https://cdrdv2-public.intel.com/812383/253666-sdm-vol-2a.pdf)
and [official Intel Vol. 3A](https://cdrdv2-public.intel.com/835781/325462-sdm-vol-1-2abcd-3abcd-4.pdf).
