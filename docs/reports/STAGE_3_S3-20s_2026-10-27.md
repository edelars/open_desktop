# S3-20s — Address32 signed disp8 SIB through shared IR and bounded dispatch

## Scope

The checked singleton admits exactly `67 48 8B/89 /r sib disp8`, ModRM
`mod=01,r/m=100`, RAX..RBX data/base/index encodings, SIB scale 1/2/4/8,
qword data, dword address size and exact length six. The fixed source field is
eight bytes, so address32 SIB disp32 (nine bytes) is rejected. No other
prefixes, SIB specials, pair sequences, decoder changes, owner integration,
Stage2 changes, Mini work or benchmarks are included. The decoder's
`MemoryOperand` and `access_address_48` remain the only source of signed
displacement and address/range semantics.

## Evidence

- The `od-jit` descriptor test covers both operations, every supported
  data/base/index/scale combination and disp8 `-128/-1/0/127`; it checks exact
  next RIP and decoder metadata and rejects malformed/truncated, extended,
  prefixed, trailing and disp32 forms.
- Native direct V2, shared IR and interpreter parity checks both operations,
  register aliases, ignored high register halves, signed modulo-2^32
  base/index/displacement arithmetic, and one contiguous qword callback
  crossing 4 GiB. Architectural fault payloads preserve state, RAM, budget and
  retirement; backend errors stay host errors; successful store+STOP retains
  its commit.
- Bounded dispatch composes the six-byte singleton → bare NOP fallback →
  existing pair across budgets 0..4. An execution boundary exactly after the
  singleton proves the form is not selected as a pair by length. Partial
  windows and unsupported SIB forms stop without publication or data access;
  continuation from actual RIP does not repeat the singleton's effects.
