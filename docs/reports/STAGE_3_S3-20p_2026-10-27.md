# S3-20p — address32 signed-displacement qword MOV in shared IR and dispatch

## Scope

Extended the borrowed, uncached checked-memory singleton profile to exact
`67 48 8B/89 /r disp8|disp32` forms: ModRM `mod=01/10`, base and data/source
RAX..RBX, qword data, dword effective address, and exactly five/eight source
bytes. Shared descriptors retain the decoder-provided signed displacement.
Raw-byte checks only bind prefix/opcode/mode/register/length to decoded
metadata; `MemoryOperand::access_address_48` remains the sole address and
access-range implementation. No emitter, decoder, pair profile, Stage2, or
production owner changes were made.

## Evidence

- `od-jit` shared descriptor cases compare direct V2 and IR for load/store,
  all base/data register combinations, and disp8 -128/-1/0/1/127 plus disp32
  MIN/MIN+1/-1/0/1/MAX-1/MAX. They reject malformed prefixes, SIB, unsupported
  registers, truncation, and trailing bytes.
- Native direct V2, shared IR, and interpreter results are compared for both
  operations across those displacement boundaries. The destination/source
  aliases RAX base, whose high bits are noncanonical; effective addresses
  exercise modulo-2^32 signed addition. Callback logs verify one contiguous
  qword operation at the expected address, including the qword starting at
  `0xffff_fffc` and ending at `0x1_0000_0003`.
- Shared IR architectural faults preserve the exact payload, full CPU and RAM
  snapshots, budget, and retirement. Backend failures remain host errors.
  Successful store+STOP returns at the next RIP with the written qword intact.
- Bounded dispatch composes disp8 singleton → bare NOP interpreter fallback →
  existing pair over budgets 0..4, and resumes from actual RIP after STOP
  without repeating the first access. Partial disp8 and disp32 fixture windows
  stop before publication or data access.
