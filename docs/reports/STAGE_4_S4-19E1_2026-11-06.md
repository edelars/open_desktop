# Этап 4 — S4-19e1: guest error-code discard and paged IRETQ

## Результат

После S4-19d guest handler продолжает настоящий fault-delivery путь. Точная
`LEA RSP,[RSP+8]` удаляет восьмибайтовый #PF error-code slot; затем отдельный
paged IRETQ profile читает пять qword frame и CS/SS descriptors через tracked
memory. Гостевой возврат восстанавливает исходный faulting RIP, исходный
невыравненный RSP и RF=1. Сценарий останавливается до повторного MOV, поэтому
faulting data остаётся прежним.

В fixture добавлен реальный заранее accessed writable CPL0 SS descriptor.
Paged IRETQ требует Long64 CPL0 и фиксированный CR0/CR3/CR4/EFER профиль,
допускает только exact `48 CF`, и отвергает live RF=1 до чтения. CS читается и
проверяется до проверки SS selector/bounds. Сохранённый RF из frame восстанавливается
только после успешного чтения frame и обоих descriptors. CPU return state не
частично коммитится; уже совершённые tracked A/D updates сохраняются. Tracked
#PF и backend errors остаются отдельными результатами, а #PF обновляет CR2.

RF и удаление error code зафиксированы по Intel SDM: Vol. 3A §6.14 и Vol. 3B
§20.3.1.1 (revision 090US). Профиль не покрывает privilege transitions,
TSS/IST, FRED, CET/shadow stack, VMX, SMM или другие формы IRETQ. Путь tracked
execution не имеет TLB, поэтому INVLPG necessity/stale-TLB eviction не
утверждаются. Повтор исходного MOV и commit данных остаются S4-19e2.
