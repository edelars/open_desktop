# S3-20ag — RBP data with the exact RSP-base SIB

## Scope and implementation

Admitted only exact four-byte singleton `48 8B/89 2C 24`: ModRM
`mod=00/reg=5/rm=4`, SIB `0x24` (RSP base, no index, scale 1, no
displacement), qword data and 64-bit EA. Decoded `MemoryOperand` and
`access_address_48` remain the address authority. Admission is an exact
exception; generic register predicates, other profiles, pairs, V3, frame
layout and ABI are unchanged.

## Evidence

- Direct V2/shared IR descriptors agree on operation, source bytes, RSP base,
  RBP data, no index, unit scale, zero displacement and `next_rip=entry+4`.
  Both opcodes compile; truncated SIB, changed index/scale, other unsupported
  data register, displacement and prefix variants reject. Existing RSP-data
  `24 24` remains supported.
- Host parity compares complete CPU/RAM state, callbacks and retirement for
  direct V2, shared IR and interpreter. RSP=16 and RBP=`0x1122334455667788`
  distinguish address from value. Load reads at old RSP and changes only RBP
  after success; store writes the full old RBP at old RSP.
- Noncanonical RSP for this exact source returns #SS before helper callbacks
  and preserves state/accounting. Noncanonical RBP is allowed as store data;
  callback STOP returns at the next RIP after committing all eight bytes.
- Dispatcher STOP after `MOV RBP,[RSP]` commits the new RBP. Resume at
  `ENTRY+4` uses that new RBP for the following RBP-relative read; the first
  read is not repeated. The fixture retains the earlier RSP/RBP profile and
  canary lifecycle coverage.
