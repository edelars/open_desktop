# Stage 3 S3-34p — cached NativeRegisterV1 corpus and replay

## Scope

This bounded S3-34 slice extends the existing deterministic S3-34n corpus to
the cached eager and demand-flags-candidate NativeRegisterV1 entrypoints. It
reuses the same 1,200 generated inputs, saved interpreter observations, and
uncached eager/candidate observations. The S3-34n `SavedCase` v1 format and
value reducer remain unchanged. No production API, ISA, ABI, cache policy,
default profile, Stage 2 source, owner/MMU, or `od-machine` behavior is changed.

## Artifacts and replay contract

The generated corpus gate now preserves all 1,200 source inputs and both
uncached repeats for interpreter, eager and demand-candidate in the separate
`native-register-v1-observations.json` artifact. It keeps the existing v1 saved
sample and reducer inputs intact.

The cache trace uses its own version-1 envelope. Each step binds the complete
input and digest, expected interpreter and matching uncached observations,
cached observation, strategy, NativeRegisterV1 execution-context identity,
complete dependency span/version identifiers, code digest, ordered sequence
number, and full cumulative single-entry cache counters. Two generated-corpus
segments contain all 1,200 cases each, one for eager and one for
demand-flags-candidate. Two additional retained-hit segments total run the
same one-instruction ADD artifact, one segment per strategy, with different
incoming RAX/RFLAGS. Each retained segment proves one miss/compile/publication
followed by one hit with no new compile/publication. No hit-only property is
inferred for the generated multi-block inputs.

Replay validates the source input order against the deterministic generator,
all input/trace digests, cache bindings, full state and exit parity, retirement
split, remaining budget and counter sequence. Every strategy segment starts
with a newly empty cache and its handle is released at segment end. Tampered
inputs, counter sequences, missing steps, unknown fields and altered digests
are rejected. The Python harness binds the trace path, SHA-256 and internal
digest to the corpus and replay gates. Producer and final validation also bind
the source-observation path and SHA-256, and recompute its envelope digest.

If a generated-corpus or retained-hit execution fails, the producer writes a
separate versioned failure envelope with the complete successful prefix, failing input,
observations, before/after counters, and a digest. A bounded reader verifies the
source corpus identity, replays each prefix step and the failing input on a
fresh cache, and checks the failure signature and exact observations/counters.
Its reproduction command addresses that reader and the saved failure file
directly. A third exact gate exercises the save/read/replay path with an
explicit local observation injection for both segment kinds, then verifies
rejection of a tampered digest and a failure that does not recur. The injected
observations are labeled as self-check data, not JIT defects.
