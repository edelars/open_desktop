# Stage 3 S3-20bg: address32 indexed no-base SIB with RBP index

## Scope

Added only singleton `67 48 8B/89 /r sib disp32`: ModRM `mod=00/rm=100`, SIB base `101` (none), index RBP, scale 1/2/4/8, data RAX..RBP, Dword EA/Qword transfer, exact length nine. This is separate from the address64 S3-20bf profile. Effective address remains decoder-owned through `MemoryOperand::access_address_48`: `(low32(RBP)*scale + signed disp32) mod 2^32`, then zero-extended. No base or RIP contribution is present. Generic index admission, other SIB profiles, pairs and V3 were not broadened.

## Evidence

- JIT descriptor checks load/store × six data registers × four scales × signed disp32 MIN/-1/0/1/MAX; they check decoded base/index/scale/address/data widths, source identity and next RIP. The previous `RBP-index` negative now uses unsupported RSI-index SIB (`0x35`); non-exact no-index remains rejected.
- Host checks compare direct V2/shared IR/interpreter CPU state, RAM, callback address/count and retirement for both operations, six data registers, four scales and the signed displacement set. Targets are independently computed from low32(RBP), scale and displacement. `data=RBP` uses pre-state, stores retain all 64 payload bits, and high RBP bits do not affect Dword EA.
- A qword at `0xffff_ffff` is one contiguous 8-byte callback. Immutable artifacts differing only in displacement byte nine reach independently asserted targets 0 and `0x0100_0000`.
- Architectural load/store faults preserve state and store bytes; backend failures remain host errors with exact callback. Store+STOP commits once. The bounded dispatcher resumes at the actual next RIP after a budget split, then handles NOP and the existing pair without repeating the first read. Partial instruction windows 1..8 and unsupported RSI-index neighbors have no memory effects.
- Existing 20bf address64 no-base/RBP-index tests remain separate; Dword-only admission is length 9 with address-size Dword. The prior forged Dword len8 verifier regression remains in place.
