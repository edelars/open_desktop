# S3-32a — exact aliased W64 ADD candidate

**Date:** 2026-11-01
**Status:** bounded correctness candidate and diagnostic A/B profile completed and reviewed; no speedup/default conclusion. S3-32 and Stage 3 remain open.

## Scope and boundaries

Commit `30febb1` adds an opt-in uncached candidate for only the exact bare
`48 03 C0` encoding (`ADD RAX,RAX`, W64). A separate
[`S3_32aAddRaxRaxAdmission`](../../crates/od-jit/src/block.rs) admits the exact
form and validates its code boundaries. The candidate compile path uses the
normal verified block pipeline via
[`compile_block_for_s3_32a_add_rax_rax_candidate`](../../crates/od-jit/src/block_compile.rs)
and candidate-specific lowering in
[`lowering.rs`](../../crates/od-jit/src/lowering.rs); the ordinary `lower`
path and baseline compiler remain unchanged.

The baseline arithmetic arm emits a read for each decoded operand. In the
candidate-only arm, the exact alias reads RAX once and reuses that temporary as
both inputs to `Integer`. Integer execution and arithmetic flag materialization,
result generation, `WriteGpr`, guest commit, guards and retirement remain in
place. Both comparison sides use `register_homes=4`. The candidate is not
inserted into a cache; default compiler, eager-flags behavior, cache
admission/key, allocator defaults and production policy are unchanged. This is
not cross-instruction read reuse or general common-subexpression elimination.

## Bounded diagnostic A/B result

The release build used source revision
`958be7edf97dd0e421454630285dc4d6e711b2a7`, source SHA-256
`97d0130cb448f4834840fcbbeadb449067c6b05a0d664c4d99d03e7f1a4898c3`, and a
clean build source tree. The binary SHA-256 is
`98e7fafa0a548e4eb56d77639949527be0b6c8b0b2fb076feb8e96d7b6165a65`. Runs were
on Apple M3 Max, macOS 26.7.1, aarch64, rustc 1.99.0. Runtime
`working_tree_dirty` is `null`: Git status timed out after two seconds, so the
runtime tree is not asserted clean.

Three sequential process runs each completed preflight and shared calibration
bounds. Every fixture preflight matched; each run retained 20 compile pairs
and 20 native pairs for each branch stratum. Across runs, each of the three
sets has 60 pairs. Each side used 32,768 compile calls or 8,388,608 native
calls as applicable, with 64 warmups per publication. All 360 timed sides
passed the 200 ms floor; the minimum side was 283,092,167 ns. Sol's independent
raw audit passed 3,074 assertions.

Candidate/baseline ratios are calculated from raw paired totals and pooled
across 60 pairs per set; these are not ratios of run medians:

## Limits and decision

These results are a bounded diagnostic A/B on one frozen S3-30b-derived
fixture. They do not establish broad workload performance, an allocator
winner, or a speedup that warrants default enablement. S3-32 and Stage 3 remain
open; Mini checks remain deferred until the end of Stage 3. The Stage 2 suite
was not invoked by this slice; parallel Stage 2 activity is not a blocker. The S3-30b
diagnostic budget0 is not the candidate; both measured variants use budget4.
The [S3-32a plan](../plans/STAGE_3.md) retains the scope and remaining gates.

## First native return on M1 Pro, 2026-11-19

The follow-up compared the same exact `ADD RAX,RAX` candidate and frozen
fixture with eager flags, four register homes and a six-instruction budget.
Both sides ran in the same signed release binary from base `963a0f6` on
an Apple M1 Pro with macOS 14.6.1 (23G93) and Rust 1.99.0. The binary
targeted macOS 14.0 with the `allow-jit` entitlement. Every timed child
recorded UID 501, effective nice −5 and QoS `0x21`.

The cold timer starts with a fresh uncompiled block and ends at its first
native return. It includes candidate-only admission, compilation and a fresh
executable publication. State reset, architectural validation and teardown
occur outside the timer. The harness checks both branch outcomes against the
interpreter. Process startup and dispatcher cache operations are outside the
measured boundary. Compile and warm controls come from the same binary.

Three cold and three control child processes contributed 60 paired samples
per row. Each side used 32,768 compile or cold calls, or 8,388,608 warm calls.
The 600 scored intervals all cleared the 200 ms floor. The smallest was
336.1 ms. Preflight recorded 24 samples at 95.9–99.3% CPU idle with a
98.8% median. During measurement, 61 samples recorded 82.0–87.7% idle
with an 86.4% median.
