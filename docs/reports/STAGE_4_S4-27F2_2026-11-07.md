# S4-27f2 — JIT event, APIC entry and resume

## Result

Added an ARM64 host integration case to the existing serialized diagnostic JIT
test binary. It uses the real `PublishedBlockExecutor` and existing public
machine APIs. The native prefix retires two instructions and the dispatcher
returns `EventPending` before NOP, with RIP at the completed boundary and the
remaining budget preserved. The caller posts one fixed APIC edge, confirms the
vector is eligible, then calls `run_apic_quantum`.

Interrupt entry saves the JIT boundary in the frame and moves the selected
vector from IRR to ISR. The guest handler reads the saved RIP and ISR bit,
writes Dword zero to LAPIC EOI over `MachineBus`, reads the cleared ISR bit, and
executes same-CPL IRETQ. The caller explicitly clears its event notification
after handling, then resumes `run_jit_nop` with the original full code range
and remaining budget. Assertions prove that the native prefix is not repeated,
NOP retires once in the interpreter, and the native suffix runs separately.
The test checks JIT counters independently from interpreter handler retirement.
Pause/resume before APIC entry preserves the CPU boundary and event flag.

## Boundaries

This verifies one synchronous caller-driven vector at a completed boundary.
The event flag is a notification separate from APIC acknowledgement, which
occurs only after eligibility and successful entry. It does not asynchronously
interrupt a running native block or add a general scheduler, event queue,
automatic polling, NMI/MOV-SS handling, paged delivery, recovery after guest
EOI or Linux acceptance. Parent S4-27 and Stage 4 remain open.
