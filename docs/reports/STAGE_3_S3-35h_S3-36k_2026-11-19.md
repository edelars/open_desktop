# S3-35h / S3-36k. Matched cold and warm checked-memory cache calls

The same release driver measures the current Stage 3 revision
`cabf88c` and replays the comparison on `d24865d`, the build revision
from the final historical S3-36e round. Each build uses the frozen
S3-34a corpus with 1,200 `StoreThenLoad` and 1,200 `LoadThenStore`
inputs. The three seeds are `0x5343344100000001` through
`0x5343344100000003`, with 400 cases per seed and sequence. The
input digest is `b09478b556aa91234d8c453f20e70f637222c5de2d7369d305ffe7c78caae540`.

The native timer covers one complete `MemoryPairCache::run` in
both modes. Each cold call starts with an empty capacity-one cache
and publishes one block. Its cache and handle are dropped after
the timer. Each warm side publishes once before timing and then
records a hit for every scored call. State, RAM, callback resets,
code-view and dependency setup, result checks and teardown are
outside the timer. The interpreter timer covers the corresponding
two-instruction run. Both modes check full guest state, RAM, the
two ordered callbacks, retirement, budget and the exact guest
exit boundary. Each native side reports a one-entry logical
footprint of 4,782 bytes.

## Matched times

Each revision has three signed release processes. Each process
uses all six side orders for both sequences, with six matched
triples per sequence. The sequence order reverses in process two.
A pilot sets common fixed sweep counts within each revision and
sequence using a 60 ms target. All 108 scored sides per revision
passed the 35 ms floor. The shortest sides were
55.901 ms on the current build and
58.292 ms on the replay.
The builds scored 21,448,800 and
52,941,600 calls across all sides respectively.

Times are microseconds per complete timed call. Columns show the
median and full range over 18 samples or paired ratios for each
sequence and revision.

On the current build the interpreter won every cold comparison,
and the resident cache won every warm comparison. On the historical
replay the interpreter won every warm comparison, as it did in the
saved S3-36e results. Median interpreter calls were 3.93× and 3.78× as
long on the current build. The resident native times are much closer
between the two builds. These are separately calibrated runs using
the same driver and corpus. The source of the interpreter cost
increase remains open. [ISSUE-521](../KNOWN_ISSUES.md#issue-521)

## Reuse estimate

For each matched triple, estimate the first whole number of calls
for which one cold call followed by warm hits costs less than the
same number of interpreter calls. The model compares
`cold + (calls - 1) × warm` with `calls × interpreter`.
This uses the per-call times of the scored sides under unchanged
cache residency. It estimates a crossover from side totals.
End-to-end burst costs, teardown and re-publication after invalidation
require separate measurements.

| Current sequence | Median first cheaper call count | Range |
| --- | ---: | ---: |
| `store_then_load` | 38 | 35–42 |
| `load_then_store` | 38.5 | 34–44 |

For these inputs, the current interpreter has the lower first-call
cost and the resident cache has the lower steady-state cost.
The historical replay has no modeled crossover since warming the
cache still leaves it slower than the interpreter in every triple.
Physical x86 and Mac mini checks remain deferred.

## Reproduction

Both builds ran locally on Apple Silicon with the archived
toolchain, ad-hoc Hardened Runtime signature and JIT entitlement.
The current native lifecycle regression
`capacity_one_memory_cache_republishes_after_fault_and_backend_error`
passed 1/1. The measurements and replay use the existing benchmark
fixtures and parity checks.

Extract each archive's `files` into its own scratch directory.
Run its `audit.py` in place to check the saved rows. To reproduce
the measurements, copy the scripts and Rust sources to an empty
scratch directory, run the extracted `build.sh` from the repository
root under `zsh` with the archive's revision and run `run.py` followed
by `audit.py`. The build script adds two lines of Rust plumbing
with their conditional-compilation attributes and the experiment
driver in its isolated source tree. The archives bind the injected
sources, runtime sources, binary, logical work, order and timings.
