# S3-20ac — RSP as qword MOV data and exact SIB base

## Scope and implementation

Admitted only exact singleton `48 8B/89 24 24`: ModRM `mod=00/rm=100`,
reg/data RSP, SIB exactly `0x24`, RSP base, no index, scale 1, no displacement,
qword data, 64-bit effective address and exact four-byte length. The decoded
`MemoryOperand` and `access_address_48` remain the only address authority.
Generic GPR validation, six-GPR frame, RuntimeContext/C ABI, pair/V3, Stage2,
and prior RSP/RBP profiles remain unchanged.

## Evidence

- Descriptor/direct V2/shared IR accept both opcodes for the exact form and
  reject partial SIB, no-base, changed scale/index, displacement, and prefix
  variants. The adjacent RSP-base-only SIB profile remains covered separately.
- Direct V2/shared IR/interpreter compare complete CPU/RAM state,
  callback address/count, and retirement. The tested target equals the entry
  RSP. Load commits a different value only after success; store callback and
  payload both use old RSP and all eight payload bytes are checked.
- Current noncanonical `[RSP]` load/store returns #SS before backend access
  and leaves RSP/RAM/RIP/budget/retirement unchanged. The ARM64/macOS x19
  canary exercises repeated native success, budget guard and fault exits for
  this exact profile.
- Dispatcher budget split and callback STOP both commit `MOV RSP,[RSP]`,
  resume at its actual next RIP, then fault on the following `[RSP]` access
  while preserving the first commit and not repeating its read. Malformed
  and partial dispatcher inputs produce BoundaryReached/Unsupported with no
  publication progress or data callback.
