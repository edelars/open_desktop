# S3-35e. First run of an empty-cache S0-09 Session

This comparison uses the six countdown profiles from S3-36g. The one-RIP
loop `48 2B C1 75 FB` runs for 1, 3, 64 and 4096 iterations. The two-RIP
control `48 2B C1 74 02 75 F9` runs for 64 and 4096 iterations. Each case
starts at RIP 0 with the counter in RAX, RCX set to 1, RFLAGS set to 2 and
the instruction budget set to expected retirement plus one. Both engines
reach the end of the same code and return the same full CPU state.
[Warm comparison](STAGE_3_S3-36g_2026-11-19.md)

Each JIT call creates a fresh `Session` inside the timed interval. Session
initialization copies and admits the code and acquires the executable-memory
lease. An intermediate timestamp separates initialization from the interval
covering two empty-cache probes and the first `Session::run`. Total elapsed
time spans that whole interval continuously. State reset, result validation
and session teardown are outside the timer. The interpreter timer covers
the fetch adapter and synchronous interpreter call. Cold here refers to
the Session and its code cache in an existing process after preflight.
Fresh process launch has its own S3-35d measurement.

Preflight checks all six profiles in each executable. Every sampled call
checks the full state, exit and retired work. Each initial JIT cache has
zero resident entries and zero counters. The first visit to each entry
records a compile and publication, one for the one-RIP loop and two for
the two-RIP control. Repeat visits are hits and there are zero evictions. The
driver validates the remaining guest budget and the executed block count.

The current executable uses `4e03bc5`. The baseline reverses only its S0-09
runtime patch. Both link release `od-host` artifacts and use the same
hardened-runtime smoke entitlements. The calibration uses four unscored
pairs per build. Fixed counts target 24 ms on the fastest observed side.
The scored run uses eight pairs per case per process, alternating JIT-first
and interpreter-first, with a 12 ms minimum per timed side. Three process
rounds run the two executables sequentially, with current first in the
middle round. Both builds and both engines use identical calls per case.

At 64 and 4096 iterations the current one-RIP JIT beat the interpreter in
every pair, including initialization and publication. At 3 iterations it
improved against the baseline JIT and remained slower than the interpreter.
The one-iteration build comparison spans parity. Both two-RIP controls
remained slower than the interpreter and showed 2.16–3.17% median overhead
against the baseline after normalizing by the interpreter. Published code
and logical metadata sizes matched between builds for each profile.

This supplies a cold-cache counterpart to S3-36g for the same S0-09
workloads. Fine-grained compiler phases and the broader S3-35 workload
matrix remain open. Physical x86 and Mac mini checks are deferred.

build 25G241 and rustc 1.99.0. The archive contains the drivers, the exact
runtime patch, selected Cargo artifact identities, build-log and executable
hashes, the fixed counts, the calibration, all scored rows and the audit.
