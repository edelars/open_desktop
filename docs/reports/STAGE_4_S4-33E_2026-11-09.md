# Stage 4 S4-33e — huge pages на собственном ядре (2 MiB позитив, 1 GiB негатив)

Статус: ограниченный системный кейс реализован; независимое ревью (Opus, high)
ещё не проведено. Кейс не закрывает родителя S4-33, S4-10 и Stage 4. В плане
`[x]` не ставился.

## Принятые примитивы

Использованы без изменений и без расширения allowlist:

- `step_paged_mov_2m_ram` (S4-10b) — позитив: `48 8B 03` и `48 89 0B` через
  `access_long64_2m_ram`; PDE PS=1 — 2 MiB leaf, A/D ставятся на PDE.
- `step_paged_mov` (4 KiB-walker, S4-10c) — негатив: PDPTE.PS=1 -> гостевой #PF
  P|RSVD; PDE PS=1 в этом API остаётся `UnsupportedPageSize`.
- `step_paged_pio_u8` (`EE`) и квант `PagedCpl0ProbeV1` (`F4`, budget 1) — хвост.
- Образец смешанной карты S4-12f (`stage4_cr3_mixed_probe`) — только как образец
  фикстуры 2 MiB PDE; его квант не использован (в нём нет store и смены RBX).

Нужный примитив был; останавливаться не пришлось. Расхождений плана с кодом и с SDM
не найдено. Единственная особенность: в разрешённых allowlist нет инструкции,
меняющей RBX, а все формы читают `[RBX]`. Три смещения выбирает sequencer (ставит RBX
перед шагом), гостевая инструкция на всех шагах чтения одна (`48 8B 03`). То же
сделано для шага негатива и инъекций. Это зафиксировано как ограничение.

## Что сделано

`Stage4HugePagesProbeV1` — строгий raw-image профиль (GPA `0x1000`, размер
`0x400000`, RAM 6 MiB, polling UART `0x3f8`), слой за слоем как S4-33d.

- Страницы: код — одна 4 KiB-страница (GVA `0x400000` -> кадр `0x7000`, PTE `0x7001`).
  Данные — один 2 MiB leaf: PD[4] (GPA `0x3020`) = `0x8000000000200083` (P, R/W,
  PS=1, NX, A/D сброшены), GVA `0x800000`, кадр `0x200000`. PD[5] (GVA `0xa00000`) =
  `0x8000000000400083` — следующий 2 MiB-кадр `0x400000` с sentinel. Негатив — отдельный
  PML4E[1] (`0x5003`) -> PDPT 1 (GPA `0x5000`), PDPTE[0] = `0x40000083` (P, R/W, PS=1),
  GVA `0x8000000000`. Отдельный PML4E нужен, чтобы A на PML4E негатива не приходил от
  fetch (код идёт через PML4E[0]).
- Данные: три разных qword на смещениях 0 (GPA `0x200000`), `0x100000`
  (GPA `0x300000`), `0x1ffff8` (последний qword, GPA `0x3ffff8`); store-цель на
  `0x1fff00` (GPA `0x3fff00`), предзаполнена `0x5a`x8; sentinel `0xfeedface0badf00d`
  в начале кадра `0x400000`; decoy `0xa5`x8 в 4 KiB-кадре `0x8000` (для инъекции).
- Код: `48 8B 03` x3 (RIP `0x400000/3/6`), `48 89 0B` (`0x400009`), `48 8B 03`
  (`0x40000c`), `EE` (`0x40000f`), `F4` (`0x400010`).
- Handoff (loader): CPL0, RFLAGS `2` (AC=0), CR0 `0x80010033`, CR3 `0x1000`
  явно, CR4 `0x20`, EFER `0xd00` (NXE=1), RIP `0x400000`, RAX `0xdeadbeefcafebabe`,
  RCX `0xc0dec0de123456ab` (значение store), RDX `0x3f8`.
- Sequencer `TwoMiB` из 7 шагов и `GibNegative` из одного шага; бюджет в шагах
  (runner: по умолчанию 16, максимум 1024).
- Файлы: fixture `tests/fixtures/guest/stage4/huge_pages/`, builder
  `tools/build/build_stage4_huge_pages_probe.py`, модуль
  `crates/od-machine/src/stage4_huge_pages_probe.rs`, runner
  `--stage4-huge-pages-probe`.

Loader и builder отвергают значения, при которых инъекции или шаги становятся
невидимыми: совпадение трёх значений между собой, с decoy, sentinel, prefill, RAX0,
значением store, и совпадение младшего байта end-значения с младшим байтом store
(UART-байт). (В S4-33d это осталось открытым.)

## Ожидаемые значения и источники

Значения выведены из Intel SDM Vol. 3A (гл. 4), код проверялся против них. Тесты
собирают образ и ожидания независимо от модуля.

| Значение | Ожидание | Источник |
| --- | --- | --- |
| PDE 2 MiB leaf | `0x8000000000200083`: P=bit 0, R/W=bit 1, PS=bit 7=1, адрес бит 51:21 (`0x200000`), бит 20:13 и PAT (bit 12) = 0, XD=bit 63 | SDM Vol. 3A §4.5 (формат PDE, отображающей 2-MByte страницу; номера таблиц зависят от издания SDM) |
| Физический адрес | база кадра `0x200000` + биты 20:0 линейного адреса: `0x200000`, `0x300000`, `0x3ffff8`, `0x3fff00` | SDM Vol. 3A §4.5 (биты 20:0 — смещение в 2 MiB странице) |
| Значения RAX | little-endian qword из RAM: start, middle, end; store RAX не меняет; read-back `0xc0dec0de123456ab` | SDM Vol. 1 §1.3.1 (порядок байт); `MOV r64,m64` / `MOV m64,r64`, Vol. 2 |
| A после шага 1 | PML4E `0x2023`, PDPTE `0x3023`, PD[2] `0x4023`, code PTE `0x7021`, PDE `0x80000000002000a3` | SDM Vol. 3A §4.8 (A ставится на каждой записи, использованной при трансляции) |
| D | нет до store; после store (шаг 4) PDE `0x80000000002000e3`; остальные записи без D | SDM Vol. 3A §4.8 (D только в записи, которая отображает страницу — для 2 MiB это PDE; запись ставит D, чтение нет) |
| Committed writes | шаг 1: `0x1000, 0x2000, 0x3010, 0x4000, 0x3020`; шаг 4: `0x3020` (D) и `0x3fff00` (8 байт); остальные пусты | SDM §4.8 (общие верхние уровни один раз); порядок — контракт S4-10b/S4-11b |
| UART-байт | `0xab` (AL после read-back) | `OUT DX,AL`, SDM Vol. 2 |
| Итоговый RIP | `0x400011`, CPU halted | размеры инструкций 3+3+3+3+3+1+1 |
| Негатив: PFEC | `0x09` = P (bit 0, запись present) + RSVD (bit 3); W/R=0 (чтение), U/S=0 (CPL0), I/D=0 | SDM Vol. 3A §4.7 (формат PFEC, рис. 4-12); PS=1 в PDPTE зарезервирован при Page1GB=0 — Vol. 3A §4.5 (формат PDPTE, отображающей 1-GByte страницу), контракт S4-10c |
| Негатив: CR2 | `0x8000000000` (адрес доступа) | SDM Vol. 3A §4.7 (CR2 = линейный адрес) |
| Негатив: saved RIP, retirement | `0x400000`, retired 0, RIP/RAX неизменны | SDM Vol. 3A §6.15 (#PF — fault: RIP на сбойную инструкцию) |
| Негатив: A | PML4E[1] `0x5023`; PDPTE[0] `0x40000083` без A и D; PDE данных не тронут | SDM Vol. 3A §4.8; контракт S4-10c (A на успешно пройденном предке) |
| Негатив: committed writes | fetch-путь `0x1000, 0x2000, 0x3010, 0x4000`, затем маршрут данных только `0x1008` | как выше |
| Инъекция PDE.PS -> 4 KiB | первая запись PT -> decoy `0xa5a5a5a5a5a5a5a5`; смещение `0x100000` = PT-индекс `0x100`, не present -> #PF PFEC `0x00`, CR2 `0x900000` | SDM Vol. 3A §4.5 (PDE PS=0 -> PT), §4.7 |
| Инъекция offset за 2 MiB | RBX `0xa00000` -> PD[5] -> кадр `0x400000` -> sentinel | SDM Vol. 3A §4.5 |

## Инъекции (все по одному, `values_a`)

| Инъекция | Результат |
| --- | --- |
| `--inject-pde-4k-table` | `page_fault` на шаге 2, PFEC `0x00`, CR2 `0x900000`, steps 2, retired 1, RAX `0xa5a5a5a5a5a5a5a5` (decoy), PDE `0x6023|NX` (PS нет); код 5 |
| `--negative-1gib --inject-pdpte-host-error` | `backend_rejected`, `UnsupportedPageSize` (PDE `0x3020`), без #PF, steps 1, retired 0, RAX/RIP не меняются; провалены 7 из 11 проверок негатива (`page_fault_stop`, `vector_14_pfec_p_rsvd_read_cpl0`, `cr2_is_the_access_address`, `saved_rip_is_the_faulting_instruction`, `a_on_pml4e_only_ps_entry_untouched`, `data_walk_commits_only_pml4e_a`, `no_backend_error`); код 5 |
| `--inject-offset-past-page` | `case_complete`, steps 7, retired 7, RAX шага 3 = sentinel `0xfeedface0badf00d`; провалены `per_step_rip_rax_rbx_and_entries`, `rax_follows_architecture_per_step`, `unused_entries_untouched` (A на PD[5]); код 7 |

Различимы по (stop, steps, retired, PFEC, RAX по шагам): none/успех, PDE.PS ->
4 KiB, offset, негатив, host-ошибка — пять попарно разных ключей (тест
`injections_are_pairwise_distinguishable_by_stop_steps_retired_pfec_and_rax`).
Итоговый RAX у успеха и у `offset_past_page` совпадает (read-back), различие — в RAX
шага 3, поэтому ключ — трасса RAX, а не только финальный RAX.

Важно про инъекцию `pdpte_ps_host_error`: код walker не откатывался (принятая логика
S4-10c нетронута), поэтому инъекция воспроизводит тот же класс исхода, что давал
PDPTE.PS до S4-10c, — host-ошибка `UnsupportedPageSize` вместо гостевого #PF, — путём
маршрута к PDE с PS=1 через 4 KiB-walker. Она проверяет, что oracle отличает host-ошибку
от #PF, а не что откат walker будет пойман: откат ловят unit-тесты `s4_10c_*`.

Мутационная проверка (machine-тесты): инъекция `pde_ps_cleared` сделана no-op —
падают 2 из 10; неверный RBX шага `ReadEnd` — падают 3 из 10.

## Не проверено и открыто

- Только uncached tracked walker: TLB-on не проверяется (S4-14 не принят). JIT: кейс
  `not_supported` в матрице.
- 1 GiB позитивный путь не входит (Page1GB=0, не объявлен). Из PFEC литералов S4-10c
  кейс исполняет только CPL0 read `0x09`; write `0x0b`, fetch NXE=1 `0x19` и CPL3
  (`0x0d/0x0f/0x1d`) покрыты тестами S4-10c, не этим кейсом.
- MMIO, CPL3, доставка #PF и коммит CR2 (CR2 в состоянии CPU остаётся `None`,
  #PF-запись хранит значение, которое получил бы CR2), cross-page, PAT не входят.
- Смещения выбирает sequencer (RBX ставит loader/sequencer перед шагом), не сам гость:
  в разрешённых allowlist нет инструкции, меняющей RBX. Поле `cpl`, `nxe()`, `efer()`
  — константы модели, как в S4-33d.
- Инъекция `pdpte_ps_host_error` — подстановка класса исхода, не откат walker (см.
  выше).
- A на PML4E негатива отделён от fetch за счёт отдельного PML4E[1]; для маршрута
  через общий PML4E[0] это различие невозможно.
- Образ 4 MiB (разреженный; нужны 2 MiB-выровненные кадры `0x200000`, `0x400000`).
- Приоритет reserved-бита PDPTE.PS относительно других reserved-битов не заявляется
  (оговорка S4-10c). Эффект A-бита на PML4E при reserved-fault ниже по иерархии
  следует принятому S4-10c; SDM допускает, но не определяет однозначно — помнить для
  S4-34.
- Ревью Opus (high) перед коммитом: не проведено, назначается координатором.
- Родители S4-33 и S4-10 открыты.
