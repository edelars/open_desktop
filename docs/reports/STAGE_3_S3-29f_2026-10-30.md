# S3-29f — single-block eager/demand-flags measurement path

**Status:** the opt-in `od-bench flags-compare` path completed three local
release measurements for a fixed S0-09 profile. Across these seven single-block
cases the demand-flags candidate showed no measured speed advantage and
emitted larger code. Eager remains the reference/default; this narrow result
does not close S3-29.

## Fixed workload

The command accepts no caller-selected guest program. Its seven cases use
exact accepted W64 register-only forms (`48 03 C0`, `48 03 C3`, `48 3B C3`,
and short JZ/JNZ) and bind program bytes, initial state,
budget, expected native exit and branch outcome into one profile SHA-256:

| Case | Program shape | Purpose |
|---|---|---|
| `overwritten-add-cmp-live-jnz` | `ADD RAX,RBX; CMP RAX,RBX; JNZ back to entry` | ADD's flags are overwritten; JNZ observes CMP's flags. |
| `budget-exit-between-add-and-cmp` | Same full block, budget 1 | Materialize ADD flags at a budget exit before CMP executes. |
| `alias-add-live-jz` | `ADD RAX,RAX; JZ back to entry` | Exercise aliased arithmetic inputs and JZ flag consumption. |
| `cmp-live-jz-taken` / `cmp-live-jz-not-taken` | `CMP RAX,RBX; JZ back to entry` | Exercise both JZ outcomes. |
| `cmp-live-jnz-taken` / `cmp-live-jnz-not-taken` | `CMP RAX,RBX; JNZ back to entry` | Exercise both JNZ outcomes. |

Every code view must compile to one complete block: compiled guest code end and
PC-map instruction count must match the fixed program. `NoNativePrefix`, a
partial block, a wrong code end, or code larger than 4 KiB aborts the run.
Compilation output is built once for eager and once for the uncached candidate;
neither is inserted into the shared cache.

## Correctness preflight and timing

Before collecting samples, the harness compiles and interpreter-checks all
seven cases, then runs both native variants for all seven cases. No case is
timed until this global preflight passes. It compares full `LongModeState`, native
exit/branch continuation, retired instructions and remaining budget. A taken
back-edge returns from the emitted block with RIP at its target; the
interpreter reaches the same state/accounting at its budget boundary. Not-taken
branches fall through to the fixed code-end stop address. The expected native
exit is `BlockComplete` for these direct single-block branches; the dispatch
candidate exit tag belongs to a separate dispatch-compilation path.

The benchmark publishes one variant, executes that same artifact repeatedly,
then drops its mapping before publishing the paired variant. This preserves the
single-live-MAP_JIT mapping constraint. Initial state cloning and reset,
publication, compile, validation, and mapping drop stay outside the summed
`execute_block` call intervals. Each of 20 pairs uses the same execution count,
alternates eager-first/candidate-first order, and requires at least 200 ms per
variant. Calibration elapsed times are explicitly bound to their 10,000-call
calibration count; the report separately records the initial estimated and
final common measured execution counts. If either side is short, the partial
series is discarded and restarted at a larger common count. The raw report
records elapsed times, executions, per-sample publication duration, compile
duration, emitted code sizes, expected state/accounting and paired
candidate/eager ratios. The timed call includes the `PublishedCode` safe
wrapper, runtime state materialization/snapshot and arithmetic-flags helper
work; checked-memory and interpreter-fallback helpers are outside this profile.

Each successful report embeds SHA-256 fingerprints for the benchmark, JIT compiler,
published host execution, interpreter source files, profile input bytes, and
emitted native code. An earlier attempt was rejected during preflight because
its ADD/SUB bytes were outside the admitted subset; it produced no timing or
output artifact and is recorded here only as a rejected preflight attempt.
The failed invocation's exact command, source revision, and profile hash were
not preserved, so this historical note is not embedded into subsequent run
JSON and cannot be replayed as a result.

Example command:

```sh
cargo run --release -p od-bench --offline -- flags-compare \
  --process-run 1 \
  --output work/tmp/stage3/s3-29f/flags-compare-1.json
```

## Measurements

Three sequential release processes ran on Apple M3 Max, macOS 26.7.1,
`aarch64-apple-darwin`, Rust/Cargo 1.99.0. All used source revision
`53e7fe56eb25fb2f2df4e8871329cffe1e9a613d`, clean working tree, source SHA-256
`120caec5ff89596385fc7bfab6c470c50cbfd2aab5c27ce171d59b2fea9bf110`, and
profile SHA-256
`4ddb4ceb1292723c6cdb73fcbcb449cf5b5fb80743409965f6030712784ae897`. All
seven cases passed the full preflight in each process. Every case had 20
paired samples with equal work per variant and at least 200 ms per accepted
sample. Final measured work ranged from 7.33M to 9.55M executions per variant
per sample; calibration restarts ranged from 0 to 7. Whole-run durations were
195.458 s, 169.645 s, and 210.933 s.

The table reports the median of each process's 20 paired candidate/eager
elapsed ratios, then the median and range of those three process-level
medians. A ratio above 1 means candidate elapsed time was higher. Code sizes
are bytes in the emitted guest block for each compiler.

| Case | Run 1 ratio | Run 2 | Run 3 | Cross-run median (range) | Eager/candidate code bytes |
|---|---:|---:|---:|---:|---:|
| Replaced ADD→CMP flags, taken JNZ | 1.102109 | 1.085941 | 1.071580 | 1.085941 (1.071580–1.102109) | 1,596 / 2,352 |
| Budget exit after ADD | 1.008989 | 1.004361 | 1.014914 | 1.008989 (1.004361–1.014914) | 1,596 / 2,352 |

| CMP, taken JNZ | 1.009492 | 1.004619 | 1.004210 | 1.004619 (1.004210–1.009492) | 1,112 / 1,568 |

All seven cross-run median paired ratios were above 1; the aliased ADD case
was near parity at 1.003352. The overwritten-writer chain
had the largest observed difference: candidate was about 8.6% slower by its
cross-run median paired ratio. Candidate code size was 40–47% larger across
these cases. Per-pair ranges and cross-process variation remain relevant; this
small single-block profile does not establish a general demand-flags slowdown,
speedup, break-even point, or production policy. Compile and publication costs
are separately recorded in raw data but not folded into these execution
ratios.

The first invocation before the code correction was rejected during the first
case's preflight because its ADD/SUB encodings were outside the admitted
subset. It produced no timing or output artifact. Its exact command, revision,
and profile hash were not preserved; see the historical note in the method
above. It is not included in the three measurements.

## Verification and limits

This is a single-block comparison only. It excludes dispatcher lookup,
shared-cache admission, interpreter fallback, checked-memory helpers,
guest-memory operations, persistent cache behavior, physical x86 and Mini. The
arithmetic-flags helper and safe-wrapper/snapshot work are included in timed
calls. It does not select the production default or
close the full S3-29 correctness/performance requirement. Mini and physical-x86
checks remain deferred until the end of Stage 3.

Host power, thermal and background-load telemetry was not recorded; the small
differences near parity may reflect measurement variation. This three-process
single-block profile cannot establish a stable general slowdown.
`cargo fmt -p od-bench -- --check` and
`cargo check -p od-bench --all-targets --offline` passed for the implementation.
Three local release measurements were performed as described above. No test
suite, Stage 2, physical-x86 or Mini run was performed for this subtask.
