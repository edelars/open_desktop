# Stage 4 S4-27i2 — owner-driven таймер в pump: dispatch и idle advance

Статус: срез реализован; ревью Opus проведено: срез принимается; правки ревью учтены. Срез не закрывает S4-27i, S4-27 и
Stage 4. В плане `[x]` не ставился. Принятые S4-27a–h, S4-27i1 и S4-28 не менялись, кроме
явно записанного ослабления gate S4-27c по clock (см. ниже).

## Что сделано

- **`LocalApicHandle::next_timer_deadline() -> Option<u64>`** (`crates/od-machine/src/local_apic.rs`):
  read-only срок ближайшего срабатывания, способного поднять прерывание; `None` — нет таймера,
  не взведён, отменён, one-shot уже сработал или LVT Timer замаскирован. Добавлен
  `LocalApicHandle::has_timer()` (read-only), чтобы pump без таймера не получал
  `UnsupportedConfiguration` от `dispatch_timer`. Существующие методы не менялись.
- **`InterruptPump`** (`crates/od-machine/src/interrupt_pump.rs`): если у APIC есть таймер, на
  каждой границе (Running и Waiting) вызывается `dispatch_timer`; в Waiting без eligible-вектора
  часы сессии продвигаются до `next_timer_deadline()`, затем dispatch и wake на следующем шаге;
  нет срока — `IdleHalt` без продвижения времени. Время на инструкцию 0 нс. Инъекция
  `PumpInjection::NoTimerDispatch` (ни dispatch, ни idle advance). Новые отказы
  `TimerDispatch`, `TimerAdvance`, `TimerNoProgress`; `InterruptPump::virtual_time_ns()`.
  Добавлен `DiagnosticHaltWait::virtual_clock()` (read-only snapshot).
- **Gate `run_sti_apic_quantum`** (`crates/od-machine/src/diagnostic_vcpu.rs`): clock разрешён;
  RDTSC на RIP (`0F 31`, опционально REX) на сессии с clock отвергается `ProfileRejected`.
- **Загрузчик** `Stage4InterruptTimerProbeV1` (`crates/od-machine/src/stage4_interrupt_timer_probe.rs`):
  строгая проверка образа (GDT, ровно один gate `0x61`, нет посторонних ненулевых байтов),

## Ожидания и источники (не вывод кода)

- **Формула таймера (Intel SDM Vol. 3A 10.5.4):** счёт идёт на частоте входа, делённой на
  делитель (биты 3, 1, 0 Divide Configuration: `0x3` -> 16); периодический режим перезагружает
  Initial Count при каждом срабатывании. P = Initial Count × делитель / частота =
  625 × 16 / 100 МГц = 100 мкс = **100000 нс**. Тот же вид правила (`count × делитель × 1e9 / hz`
  с округлением вверх) принят в S4-28a4/S4-28b (тесты `periodic_timer_tests`).
- Гость взводит таймер при времени 0 (инструкции 0 нс); k-е срабатывание в k × P; после N = 5
  пробуждений время **500000 нс**, счётчик 5.
- Кадр внешнего прерывания (SDM Vol. 3A 6.14.2–6.14.3): RSP `0x6FC8`, RIP после HLT, RFLAGS
  `0x202`, CS `0x8`, SS `0x10`; RFLAGS в handler `0x2`; EOI снимает ISR (10.8.3.1).

## Изменение принятого контракта S4-27c

Gate `run_sti_apic_quantum` прежде отвергал сессию с clock или RDTSC. Теперь clock разрешён,
RDTSC (`0F 31` с опциональным REX) в STI-кванте по-прежнему отвергается (`ProfileRejected`).
Отказ выражен проверкой байтов по RIP, а не полем `rdtsc_controls`: `new_with_clock_handle`
всегда задаёт и clock, и `RdtscControls`, поэтому «ослабить только clock, оставить RDTSC» через поля
невозможно. Тест принятого S4-27c, проверявший отказ по clock
(`sti_apic_rejects_invalid_admission_without_mutation`, случай 2), не удалён: он переписан на
отказ RDTSC на сессии с clock (комментарий «S4-27i2: ослаблен clock gate»), с теми же
проверками «состояние и устройства не изменены». Принятие clock доказывают
`sti_quantum_accepts_a_session_clock` и успешный периодический сценарий.

## Отклонения от плана и ограничения

- **Gate S4-27c** ослаблен по clock; запрет RDTSC — проверка байтов (см. выше).
- **IF=0 в Waiting:** время не продвигается, результат `IdleHalt` (в плане этого нет): при
  IF=0 маскируемый вектор HLT не будит, иначе периодический таймер сжигал бы бюджет. Если
  решение не подходит, альтернатива — продвигать время до исчерпания бюджета.
- Добавлены read-only `LocalApicHandle::has_timer()` и `DiagnosticHaltWait::virtual_clock()`
  (в задании назван только `next_timer_deadline`).
- Время по инструкциям 0 нс: TSC и Current Count не меняются при исполнении кода (синхронизация
  по инструкциям — S4-37a).
- Первая инструкция handler исполняется внутри `run_apic_quantum`; handler состоит из
  инструкций обычного интерпретатора (ограничение S4-27i1 сохранено).
- Не проверено: очередь событий (i3), paged-таймер (i4), поведение при вложенном приоритете
  (вектор в ISR) с периодическим таймером — бюджет сгорает на idle advance до EOI.

## Мелочи ревью

- **RDTSC и gate.** Запрет RDTSC в STI-кванте задаёт сам профиль (`run_with_sti_profile` передаёт
  `None` вместо RDTSC controls и source; язык профиля — CLI/STI/NOP/HLT, ISSUE-069). Байтовая
  проверка (`next_is_rdtsc`) переводит в `ProfileRejected` только форму `0F 31` с опциональным
  REX. Остальные формы (префиксы 66/F2/F3/2E, два REX подряд, RDTSCP `0F 01 F9`, RDPMC
  `0F 33`, первая инструкция handler после доставки) дают terminal `Unsupported`, TSC не
  читается. Отказ избыточен: при IF=1, shadow Clear, eligible-векторе и RDTSC на RIP квант
  отвергается, хотя мог бы исполнить инструкцию handler (случай 2 теста
  `sti_apic_rejects_invalid_admission_without_mutation`, RIP `0x4100`). Вариант через
  `Option<RdtscControls>` отложен (ISSUE-069, S4-37a).
- **Dispatch на границе в Running не наблюдаем.** В i2 инструкции идут 0 нс, внешнего advance у
  pump нет, все срабатывания приходят через idle advance. Инъекция выключает оба механизма
  сразу. Это структурная часть; наблюдаемой станет в S4-37a.
- **Открыто: отказы `TimerDispatch`, `TimerAdvance`, `TimerNoProgress` тестами не покрыты.**
- **Открыто: нет lib-теста на `Delivered` из `run_sti_apic_quantum` у сессии с clock**; pump этим
  путём не ходит.
- **DRY-долг:** загрузчик `stage4_interrupt_timer_probe.rs` примерно наполовину повторяет
  `stage4_interrupt_pump_probe.rs`. Владелец — S4-27i5 или отдельный подсрез.
- **Открыто: ISSUE-070** — idle advance сжигает бюджет, когда вектор таймера заблокирован
  (см. «Отклонения»).
