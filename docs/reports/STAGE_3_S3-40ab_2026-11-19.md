# S3-40ab RUN loop and two tracked STEP calls on M1 Pro

The benchmark compared `d24865d` and `5275d67` on the same 2,400
S3-34a inputs at budget 2. The first arm retains the S3-40aa predecoded
RUN. The second arm uses that RUN logic with its tracked STEP calls
routed to an explicit out-of-line function. The third arm calls the same
function twice through the same predecoded callback, with a shared mask
of defined flags. Both STEP calls must return `Advanced`. The driver
constructs the pair's synthetic budget result after timing.
[Earlier fetch/decode boundary measurements](STAGE_3_S3-40aa_2026-11-19.md)

The exact S3-40aa generated source is the prefix of the new scratch
source in both revisions. Disassembly of each signed binary verified
one shared tracked STEP destination per memory type for the routed RUN
and direct pair, for both timed fixture memory and untimed fetch recording.
The untimed checks verified two retirements, the exact CPU state and RAM,
ordered data accesses including access context, and the defined flags on
every input and all three arms. All arms recorded zero FETCH callbacks.
The timed arms use the original fixture memory without fetch recording.

Six paired rounds alternated build and sequence order. Each process
covered all six variant permutations for each sequence. Pilots set
877,200 and 870,000 calls per interval. The retained series contains
432 intervals and 377,395,200 calls. The shortest interval was 80.017 ms,
above the 45 ms floor.

The pooled current-minus-historical gaps were 178.4 and 178.0 ns for
predecoded RUN, approximately 176.7 ns for both routed RUN sequences,
and 170.5 and 170.3 ns for the direct pair. The gap survives when the
measured call omits RUN's loop and entry logic. The shared-function
boundary changes generated code, and the pair includes its own call
and sequence logic. The results compare full paths. They leave attribution
between STEP's entry checks and postdecode execution open.

## Environment and reproduction

MacBookPro18,3, Apple M1 Pro, eight logical CPUs, macOS 14.6.1 (23G93),
Xcode 15.4 (15F31d), Rust and Cargo 1.99.0. Both release binaries used
the standard Rust `aarch64-apple-darwin` CPU settings, minimum macOS 14.0
and SDK 14.5. The ARM64 binaries passed strict Hardened Runtime signature
verification with `allow-jit`. The host was on AC power. All 14 pilots
and scored processes recorded UID 501, nice −5 and QoS `0x21`. The 24
preflight probes ranged from 97.7% to 99.5% idle CPU. The nine scoring
probes ranged from 74.4% to 86.9%, with a median of 86.7%.

Extract the archived `files` and place the harness scripts in
`work/tmp/s3-40-run-loop-boundary/` in a repository with the two pinned
Git revisions and the S3-40m and S3-40w input archives. Use an isolated
Cargo home with the lockfile dependencies. Build from the harness
directory with the following settings.

```sh
export MACOSX_DEPLOYMENT_TARGET=14.0
unset RUSTFLAGS CARGO_ENCODED_RUSTFLAGS CARGO_BUILD_RUSTFLAGS
unset CARGO_TARGET_AARCH64_APPLE_DARWIN_RUSTFLAGS
zsh build.sh historical
zsh build.sh current
zsh check.sh
```

The archived `README.md` gives the monitored `python3 run.py run-NAME`
and packaging commands. `python3 offline_audit.py /path/to/evidence.json.gz`
reproduced the saved audit on the M1 Pro and after transfer. The archive
has 83 files including raw timings, exact source and executable bindings,
untimed receipts, shared STEP call checks and host load logs.
