# S3-20am — address32 qword MOV with RSP/RBP data

## Scope

This slice adds only exact direct-base singleton forms `67 48 8B/89 /r` with
ModRM `mod=00/01/10`, RSP or RBP in the data field, and RAX..RBX as the base.
Address size is Dword, data size is Qword, and accepted lengths are 4/5/8 for
no displacement, signed disp8 and signed disp32. No SIB, RIP-relative,
additional prefix, pair, V3 or owner/MMU integration was added.

The existing decoder `MemoryOperand` remains the source of effective-address
semantics. The host/compiler source checks bind the bytes to the decoded direct
base profile and keep the architectural 64-bit data width explicit.

## Evidence

- Descriptor tests cover both MOV directions, both stack data registers, all
  four low bases, all exact lengths, and signed displacement boundaries.
- Direct V2, shared IR and interpreter are compared for complete state and RAM,
  retirement and exact helper callback address/count. Each case uses high bits
  in the base register and independently targets low address `0xffff_fffc`;
  the eight-byte access crosses 4 GiB contiguously through `0x1_0000_0003`.
- The data payload remains full 64-bit. Missing backing bytes return the
  existing host memory error without CPU/RAM commit or retirement. Store
  callback STOP preserves the write and reports the next RIP.
- Bounded dispatch checks the address32 load of a noncanonical RSP value,
  budget split and actual-RIP continuation, then #SS on subsequent 64-bit
  `[RSP]` use without repeating the first access. Entry STOP/budget-zero,
  partial windows and invalid prefix/register/SIB shapes have no memory effect.
