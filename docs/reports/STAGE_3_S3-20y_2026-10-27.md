# S3-20y — RBP-base signed disp32 qword MOV

## Scope

This bounded singleton adds only `48 8B/89 /r disp32`, ModRM
`mod=10,r/m=101`, RBP base and data register RAX..RBX. Operand data is qword,
address size is 64-bit and instruction length is exactly seven bytes. Decoder
`MemoryOperand` and `access_address_48` remain authoritative for displacement
and effective-address semantics. The existing `mod=00,r/m=101` profile remains
RIP-relative and uses the instruction's `next_rip`. No SIB, `67`, other
prefix/base, pair/V3 or emitter changes are included.

## Evidence

- Descriptor compilation checks both load and store at disp32 MIN/-129/-1/0/
  127/128/MAX, exact source bytes, decoded RBP/no-index/scale/displacement and
  next RIP. The same displacement with RIP-relative `mod=00,r/m=101` is kept
  distinct.
- Direct V2, shared IR and interpreter agree for both operations across those
  displacements, including complete CPU/RAM state, one callback at the expected
  address, callback count and retirement. The RBP and RIP-relative target
  expressions are explicitly checked against base and `next_rip`, respectively.
- Noncanonical RBP access start and qword end preserve #SS payload; equivalent
  RBX cases preserve #GP. These faults make no memory callback and do not
  commit CPU/RIP/RAM/budget/retirement state. AddressOverflow remains a host
  diagnostic and ordinary backend failures remain host errors. Entry STOP and
  zero budget suppress callbacks; successful store+STOP keeps the write.
- Bounded dispatch composes the seven-byte RBP singleton → bare NOP
  interpreter bridge → existing pair. Budgets 0..4 match interpreter state
  and RAM; STOP-RIP after the singleton and actual-RIP continuation avoid
  repeating effects. Partial windows 1..6 and invalid address/prefix/SIB/data
  shapes have no memory effects.
