# S3-31f. Prepared-key ownership on one-pass dispatch

The opt-in prepared-key dispatcher now moves the newly built `TranslationKey`
into its per-invocation memo and stores the computed minimum key size in
place of cloning the decoded `BasicBlock`. The memo uses the same size on a
reuse hit and still calls the cache size check. Cold replacement, RIP changes,
fallback, snapshot validation and exit handling preserve their existing
behavior.

## Local release comparison

Two builds used revision `88655e9c7e7327d28880cef9a38d1411effce87e` and the
same temporary benchmark patch. The patch restricted timing to `a_1` and
`b_1` and changed the scored profile label. Both binaries performed untimed
correctness preflights for all six original S3-31c profiles, with matching
state, exits, retirement, cache counts and partial controls. The only
source difference between the builds was the memo ownership change.

Three release process rounds alternated build order as baseline–candidate,
candidate–baseline and baseline–candidate. Within each build, every timed
triple used the same fixed guest work and call count for the ordinary cached
JIT, prepared-key JIT and interpreter. The existing timer covered full
dispatch and rotated all six engine orders. The audit checked 720 retained
sample sides, each above 200 ms, with a minimum of 292.340 ms. It also
checked retirement, hit-only cache behavior and build fingerprints. The
library suites passed 500 `od-jit` tests and 486 `od-host` tests, with two
and one ignored respectively.

two one-iteration profiles. Longer workloads passed correctness preflight,
and their timing under this change remains open. General S3-31, S3-36 and
Stage 3 acceptance remain open. Physical x86 and Mac mini checks are deferred.

## Reproduction and evidence

The host was Apple M3 Max with 14 CPU cores and 36 GB RAM running macOS
26.7.1 ARM64. Both binaries used rustc 1.99.0 and the release profile.
Build source SHA-256 was
`9f1c585ed229c625441ae100047b73ab2d69b9c84a4d6531eb0b23b2f92ab3b6`
for baseline and
`a73c376282849904e41cb3b8511d38489181f0a297b1349a71725bdf6dbc7259`
for candidate. The temporary driver patch accounts for the dirty build
state of both binaries. It was removed after they were copied for timing.

The archive contains both patches, both preflights, six raw process reports,
the audit, timing order, original hashes and the local driver scripts.
To reproduce, build `cargo build --release --offline -p od-bench --bin od-bench`
from the stated revision with the common `short-benchmark.patch` in both
builds and `production.patch` in the candidate build. Copy the executables
as `baseline-od-bench` and `candidate-od-bench` beside the archived `run.py`
and `audit.py`. From the workspace run `python3 run.py` using the extracted
script path, then run `audit.py` with `PYTHONPATH=tools/bench`. The archive
records the working directory as `.` and retains the SHA-256 values of the
