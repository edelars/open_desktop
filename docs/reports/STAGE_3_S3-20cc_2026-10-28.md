# Stage 3 S3-20cc: address64 RBP-base SIB with displacement and no index

## Scope and implementation

Added only singleton `48 8B/89 /r sib disp8|disp32`: ModRM `mod=01/10,r/m=100`, SIB exactly `0x25` (scale one, index absent, RBP base), data RAX..RBP, qword transfer, and exact lengths 5/8. `mod=00` with the same SIB byte remains the distinct absolute/no-base S3-20au profile. No address-size override, other SIB shapes, data registers, pair/V3 forms, owner/MMU integration, Stage 2 or ISA changes were added.

Effective address remains decoder-owned through `MemoryOperand::access_address_48`: old RBP plus signed displacement with the existing wrapping u64 semantics. RSP is not an index. The exact shape is enforced consistently by checked block admission, shared IR and direct V2 descriptors, immutable runtime source matching, and bounded dispatcher compilation.

## Evidence

The JIT profile test covers load/store, data RAX..RBP, disp8 and disp32 boundary values, decoded operands and next RIP, the direct ModRM RBP-base semantic reference, the separate mod00 absolute SIB form, partial windows and rejected neighboring encodings. It also explicitly rejects the same `0x25` SIB under addr32 `67` with mod01/mod10, for both operations using supported RAX data.

The host test compares direct V2 and shared IR native execution with the interpreter, checking full CPU/RAM state, independent RBP-plus-displacement target, callback address/width/count and retirement. It covers data=RBP pre-state semantics, a pair of immutable disp32 artifacts that differ only in the final encoded byte and produce distinct target callbacks, noncanonical start/end #SS before any callback, separate AddressOverflow, architectural and backend no-commit, committed store+STOP, entry STOP/zero-budget guards, and actual-RIP dispatcher continuation across 5/8-byte instructions without repeating the first read. Partial fixture windows return `BoundaryReached` before publication or memory access.

Existing negatives that used mod01/mod10 SIB `0x25` as unsupported were updated because that exact addr64 shape is now admitted. Their replacements use an out-of-profile data register or a genuinely unsupported SIB neighbor; exact mod00 absolute/no-base tests remain separate. The addr32 `67` mod01/mod10 sibling remains unsupported and is covered independently.
