# S3-34n: reproducible NativeRegisterV1 generated corpus

## Scope

This slice adds deterministic generated-input coverage and saved-input replay
for the committed `NativeRegisterV1` profile. It does not change the profile,
ISA, interpreter, JIT runtime, or admission contract. The corpus is bounded to
1,200 unique inputs (three fixed seeds, 400 inputs each), and each input runs
twice from a fresh state through the interpreter, eager `NativeRegisterV1`, and
the demand-candidate backend. The test guest memory rejects reads, writes, and
atomic callbacks.

Uniqueness is checked from canonical bytes for the actual input: code, guest
base RIP, all initial GPRs, RIP, RFLAGS, explicitly defaulted auxiliary state,
STOP controls, and budget. Seed, index, profile, and digest metadata do not
make otherwise identical inputs unique. The reported digest is
`fnv1a64:172fb17b01c502df`.

All 13 committed extra forms were observed. Per-form occurrence counts in
profile order (S3-33a through S3-33m) were `228, 151, 144, 131, 136, 124,
134, 131, 149, 129, 129, 129, 1197`. Counts can overlap because one input
may contain multiple forms. Every repeated backend result compares complete
modeled CPU state, exit/RIP, retirement split, and remaining budget.

The versioned saved-case envelope contains the exact source bytes, guest base,
initial state, controls, profile/version, seed/index, canonical digest, both
repeat observations for all backends, and a reproduction command. The replay
gate reads this envelope and reruns the saved case. Mismatch artifacts retain
the original input and available observations under the ignored run directory.
Malformed envelopes, bad digests, unsupported forms, missing results, backend
errors/timeouts, and corrupted CPU/exit/retirement comparisons fail closed.
