# S3-13 report: one-block fixture CLI

Date: 2026-10-26

## Implemented slice

- Added the opt-in fixture-v1 engine `--engine jit-block` and the distinct
  serialized backend tag `jit_ir_block`. Legacy `jit`, direct `--hex`, the C
  fragment ABI and fixture-v2 JIT denial remain separate.
- Added `od_jit::block_compile::compile_block`, which connects the bounded
  builder, decoder-derived lowering, allocation and runtime block emitter.
  It preserves `NoNativePrefix` and deferred decode-boundary metadata and
  rejects emitted output above 4096 bytes before publication.
- On macOS/aarch64, the runner performs existing whole-fixture v1 decoder
  compatibility admission and checks that the initial RIP is a decoded
  instruction boundary, then compiles from that RIP, publishes and executes
  exactly one block with `stop_rip = code_end`. It does not dispatch or fall
  back to the interpreter. On other hosts this backend reports unsupported.
- `BlockComplete` maps to code end first, then exhausted budget; another
  internal RIP is unsupported because it needs a later dispatcher. Invalid
  input exits 3, unsupported exits 4, and compile/publication/runtime contract
  failures exit 5.

## Evidence

On the current macOS/aarch64 host, CLI child tests exercised native published
code for a MOV-to-code-end case, instruction-budget completion, taken and
not-taken terminal branches, a branch before an unreachable valid instruction,
and legacy `jit` compatibility. The branch case retires one instruction and
lands at code end; there is no subsequent block dispatch. Child tests also
cover unsupported decoded forms, an initial RIP inside another instruction, an
internal branch requiring another block, fixture-v2 denial, invalid input,
direct `--hex` rejection for `jit-block`, result-tag round-trip and
emitted-code-cap failure.

## Limits and follow-up

The compatibility layer's static fixture-v1 decoder still scans the complete
fixture before the bounded compiler is entered. The bounded builder itself
continues to stop at the first branch and does not decode unreachable tail
bytes. An unresolved branch target remains unsupported in this one-block CLI;
no target-based dispatch or interpreter fallback is attempted. Independent
review is clean after adding the fixture-v1 initial-RIP boundary check. The
primary-checkout layout check passed.
