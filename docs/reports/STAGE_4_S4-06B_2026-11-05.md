# Stage 4 S4-06b: CPU-connected paged MOV

## Результат

Принят ограниченный CPU-to-paged-RAM срез на baseline `b2a093c`. Добавлены
`step_paged_mov` и внутренний `PagedMovMemoryAdapter` для двух exact Long64 encodings:
`48 8B 03` (`MOV RAX,[RBX]`) и `48 89 0B` (`MOV [RBX],RCX`). Каждый вызов
исполняет максимум одну инструкцию через существующий decoder/interpreter.

CPU entry валидирует CR0/CR4 до fetch, использует `AccessOrigin::Explicit` и
сохраняет входные mode, privilege, CPL и `rflags_defined`. Architectural
fault, backend error и unsupported instruction остаются разными исходами.
Faulting MOV не retire-ится и не меняет destination или RIP.

Machine adapter строит `Long64ProbeConfig::from_cpu_state` с профилем
canonical48, physical36, four-level, 4 KiB и RAM-only. Integration cases задают
literal non-identity translations для кода и данных. Adapter использует
существующий tracked walker, `MachineBus` и единственный `PhysicalMemory`
owner. Проверены page-fault record/PFEC/original RIP, A/D effects, callbacks и
их порядок, NX, разные CR3, holes, unsupported huge/cross-page accesses и
отказ MMIO без side effects.

## `GuestMemory` guarantees

Для этих двух MOV форм контракт ограничен следующим:

- Ошибочный read не меняет caller result buffer.
- Ошибочная operand write не выполняет частичный commit самого operand.
- Уже совершённые A/D metadata writes и их callbacks сохраняются при
  последующем page fault или ошибке operand access; полного RAM rollback нет.
- Page-table bytes могут физически alias-ить operand. Поэтому A/D effects могут
  изменить эти байты даже при отказавшей инструкции. Каждый фактически
  committed write получает callback в порядке выполнения; повторяющиеся
  диапазоны не объединяются.

Это разрешает конфликт между tracked walk и прежней формулировкой
`GuestMemory` только для bounded S4-06b. Другие rollback consumers требуют
отдельной проверки. [ISSUE-054](../KNOWN_ISSUES.md#issue-054-s4-11-cross-page-cpu-integration)
остаётся открытой для cross-page/partial progress, REP/RMW и broader rollback
assumptions.

## Проверки и review

Package-level commands, запущенные независимым reviewer:

```text
cargo test -p od-isa --locked --offline
cargo test -p od-machine --locked --offline
```

`od-isa`: **2,014 unit tests passed**. `od-machine`: **85 tests passed**
(69 unit, 7 API, 1 event-queue и 8 integration). В реализации также отдельно
зафиксированы 8 `PagedMov` CPU tests, 3 legacy CR0 tests, 2 legacy CR4 tests и
8 тестов `paged_mov_step`.

Следующие проверки завершились успешно:

```text
cargo check --workspace --all-targets --locked --offline
cargo fmt --all -- --check
python3 tools/check_layout.py
git diff --check
```

Независимый `gpt-6.1-sol/high` review одобрил полный code diff; P0—P3 findings
не осталось. Reviewer подтвердил совпадение Graphify AST hashes с исходниками
в manifest. В реализации Graphify query выполнялся до изучения исходников;
`graphify update .` при machine integration не получил подтверждённого
завершения из-за ожидания graph rebuild lock. При этой документационной
интеграции `graphify update .` также не завершился после 35 секунд и был
прерван во время detect/re-extract. Запрос Graphify по S4-06b и контрактам
выполнен до чтения документов; code AST hashes сверены reviewer с manifest.

## Границы

Этот срез не подтверждает полную paging matrix, TLB/invalidation, CR2 commit,
exception delivery/retry, cross-page operands, REP/stack/atomic semantics,
JIT, IRQ/devices, SMP или Linux boot. Родительский S4-06 и этап 4 остаются
открытыми.
