# S3-28b: Cooperative events in bounded checked-memory dispatch

**Status:** Implementation, local verification and independent review complete. This report covers only the bounded checked-memory fixture dispatcher.

## Contract implemented

`run_controlled` and `run_with_nop_fallback_controlled` accept an optional invocation-local `AtomicBool`; the existing entrypoints remain event-disabled wrappers. The host-only `BoundedMemoryExit::EventPending` does not change V2/V3 ABI tags, generated code, or helper semantics. The dispatcher samples events after stop-RIP, STOP, fixture-boundary and budget guards, before compiling the next artifact or stepping a bare NOP. The published host executor checks after publication and before native entry, and drops the mapping on a pre-entry exit.

An event raised by a memory callback is observed only after the artifact returns. Absent a higher-priority terminal exit, both helper sites of a pair therefore finish before event sampling. STOP/fault/backend exits keep their established helper-boundary behavior and are not masked by the event. The host fixture raises STOP and event from the first read callback, verifies one committed retirement at `A+3` with read-only callback prefix, then clears both and resumes without replay; the resumed CPU/RAM/callback sequence matches the interpreter. Valid accounting and actual RIP are committed first; guest faults and code invalidation retain their result. Malformed `EventPending` accounting is rejected. The event remains set and the caller resumes from actual RIP after clearing it.
