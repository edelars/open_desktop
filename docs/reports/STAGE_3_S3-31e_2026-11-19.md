# S3-31e. Prepared-key reuse after exact snapshot validation

The S3-31c comparison was repeated after S3-31d on clean revision
`b142e96303e9d9257d0d6c95a364824ff5502f48`. One release executable ran the
ordinary cached NativeRegisterV1 dispatcher, the opt-in prepared-key
dispatcher, and the interpreter. The six workloads are the fixed LEA/XCHG
recurrences with 1, 64 and 4,096 iterations per invocation.

The timer covered the complete dispatcher or interpreter call, including
prepared-key setup, reuse and drop. State reset and CodeView/control setup
stayed outside the timer. Each timed triple performed the same guest work
and call count on all three sides. The benchmark rotated through all six
execution orders and checked state, retirement and cache deltas. Preflight
also checked STOP, events, budget boundaries, dependency replacement and the
six partial/control cases. It recorded one prepared key and `iterations - 1`
reuses per invocation.

## Results

The repository verifier accepted the preflight and all three sequential
processes. Each profile retained 60 triples, with 1,080 timed sides in total.
The minimum elapsed time was 201.103 ms against a 200 ms floor. The first
process discarded one `b_64` attempt and retained its recalibrated samples.
Process elapsed times were 1,022.639 s, 772.737 s and 720.958 s.

Values are pooled medians and full retained ranges. Ratios below one favor
the prepared-key variant.

| Profile | Prepared / ordinary cached JIT | Prepared / interpreter |
| --- | ---: | ---: |
| `a_1` | 1.1275 [0.9805, 1.2950] | 1.4018 [1.2668, 1.4759] |
| `a_64` | 0.0926 [0.0869, 0.1824] | 0.1217 [0.0772, 0.1462] |
| `a_4096` | 0.0744 [0.0577, 0.1174] | 0.0975 [0.0854, 0.1412] |
| `b_1` | 1.0816 [0.8888, 1.6405] | 1.3290 [1.2283, 1.8164] |
| `b_64` | 0.0692 [0.0489, 0.1162] | 0.0878 [0.0625, 0.1547] |
| `b_4096` | 0.0522 [0.0349, 0.0765] | 0.0664 [0.0383, 0.0931] |

All retained samples for the four longer profiles favor prepared-key reuse
against both comparators. At one iteration its median is 8.2–12.8% higher
than ordinary JIT, with both ranges crossing one. Keep prepared-key reuse
opt-in. The measured benefit applies to resident same-RIP recurrences on the
fixed register-only workloads. The crossover between 1 and 64 iterations,
alternating-RIP workloads and cold costs remain open. S3-31, S3-36 and full
Stage 3 acceptance remain open. Physical x86 and Mac mini checks are deferred.

## Reproduction and evidence

The host was Apple M3 Max with 14 CPU cores and 36 GB RAM running macOS
26.7.1 ARM64. The executable used rustc 1.99.0 and the release profile.
The build recorded source SHA-256
`0b77ecc7ca5323b80b20c2b432c58144799f415debfe3a45f28f2d2478accbd1`
and binary SHA-256
`df33f8307c6ad6aa0a5a9f06860b9f1c66684ed87300f185fe548aafa5cf1fb2`.
Runtime Git status probes timed out, and the build reported a clean source
tree. The hardware model and memory were read with `system_profiler`.

```sh
mkdir -p work/tmp/stage3/s3-31e-replay
cargo build --release --offline -p od-bench --bin od-bench
target/release/od-bench cached-native-loop-reuse --preflight-only \
  --output work/tmp/stage3/s3-31e-replay/preflight.json
for run in 1 2 3; do
  target/release/od-bench cached-native-loop-reuse --process-run "$run" \
    --output "work/tmp/stage3/s3-31e-replay/process-$run.json"
done
python3 tools/bench/validate_s3_31c.py work/tmp/stage3/s3-31e-replay/process-{1,2,3}.json \
  --preflight work/tmp/stage3/s3-31e-replay/preflight.json
```
