# S3-20ga: Address32 RCX-base Dword store signed disp32 `67 89 81 id`

## Planned scope and contract

Runtime implementation is integrated in commit `b7b361b`. Independent Sol/high
static review passed. No behavior checks are claimed; execution remains
deferred.

Admit exactly seven bytes `[67,89,81,id0,id1,id2,id3]`:
`MOV [ECX+signext(disp32)],EAX`. `67` is the only prefix; data/address sizes
are Dword; RCX provides the addr32 alias base; there is no index, scale is 1,
and the displacement is signed little-endian i32. Starting EA is computed
from pre-state as
`zero_extend((low32(RCX) + signed_i32_disp32) mod 2^32)`. Perform exactly one
contiguous checked four-byte write of low32 pre-state RAX. Preserve every GPR,
including full RAX and RCX, and RFLAGS; successful next RIP is `A+7`. Only the
starting EA wraps at 32 bits. Bytes after `0xffffffff` transfer contiguously
above 4 GiB without byte-wise wrap.

Explicit fences: no matching load `67 8B 81 id`, no addr32 RCX singleton or
disp8 store (`67 89 01`, `67 89 41 ib`), no other base, SIB/index, additional
prefix or REX, or other encoding. Supported neighbors retain distinct
source/site bindings. Reject truncated and trailing-byte sources.

Preserve checked memory/backend fault behavior: a failed write does not commit
CPU state or RIP. Entry STOP/stop-RIP/budget guards do not perform the store;
guard/fault retry uses the original state and EA. A callback STOP after a
successful write preserves the committed store and does not replay it.
Published IR uses immutable compiler-issued source bytes and does not fetch
guest instruction bytes during runtime execution. Instruction-fetch errors
are checked through the demand interpreter path and propagate directly.

## Planned identities and acceptance

The integrated Rust test identities and harness gates are:

- JIT: `memory_load_v2::tests::ir_dword_addr32_rcx_disp32_store_binds_exact_source_and_site`
- Host: `tests::s3_20ga_addr32_rcx_disp32_dword_store_uses_wrapped_ecx_and_low_eax_payload`
- Harness JIT: `s3_34dl_ir_addr32_rcx_disp32_dword_store_source_binding`
- Harness host: `s3_34dl_host_addr32_rcx_disp32_dword_store_wrapped_ecx_and_low_eax_payload`
- Fail-closed self-test: `test_s3_34dl_addr32_rcx_disp32_dword_store_gates_are_pinned_and_fail_closed`

Acceptance should bind all seven source bytes, signed displacement metadata,
and the exact site through compiler, decoded, IR, runtime, and host publisher
admission. Check distinct source/site identities against `67 89 01`,
`67 89 41 ib`, `67 8B 81 id`, and unsupported neighbors; forged metadata;
truncated/trailing forms; and the PC-map boundary `A+7`. Host parity should
cover signed displacement edges, modulo-32 wrap in both directions,
full-RCX/low32 decoys, unaligned/zero/boundary starts, contiguous writes across
4 GiB, low32 payload independence, full CPU/RAM state, fault/retry, each entry
guard, and committed callback STOP without replay.
