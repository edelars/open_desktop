## Implemented slice

`od-jit::block_emitter::emit_runtime_block` emits a runtime entry for the
currently supported W64 register-only IR profile. It verifies Program and
Allocation ownership, stages the guest GPRs/flags/RIP in an aligned frame, and
commits canonical guest state plus retirement/budget only after successful
effects. Every included instruction boundary samples stop RIP, cooperative
STOP, then budget. Jcc target selection occurs within the same commit as RIP
publication. Unsupported/NeedInterpreter exits retain the committed prefix and
return at the current guest RIP. Helper failure uses an instruction-specific
stub and returns a host-only sentinel before current-instruction commit.

`PcMap` validates complete contiguous half-open host byte coverage, alignment,
range bounds (including rejection of reversed ranges) and separate guest
commit-boundary points. Ranges state either a fixed guest RIP or that RIP must
be read from canonical state for shared control-flow/epilogue paths. It records
service, instruction, helper, commit and exit phases with snapshot
admissibility.
`PublishedCode::publish_block` retains the map beside the mapping; safe
`execute_block` requires matching entry RIP and production-helper provenance.

## Evidence and limits

On the current macOS ARM64 host, `cargo test -p od-host --offline` ran 22/22
tests, including generated native entry/commit, internal stop/budget ordering,
JZ/JNZ taken and not-taken, committed-prefix helper failures, helper-set STOP,
and Unsupported/NeedInterpreter exits. `cargo test -p od-jit --offline` passed
54/54 tests. `cargo check --workspace --all-targets --offline` passed.

`cargo test -p od-isa --offline` ran 711 tests; 706 passed and the same five
pre-existing x87/decoder expectation failures tracked by
[ISSUE-023](../KNOWN_ISSUES.md#issue-023--stage-1-test-expectations-reject-currently-accepted-x87-forms)
remain. They concern FABS/FCHS/FSTP acceptance and FCMOVNB/FNINIT decode
expectations, outside this implementation.

This map attributes emitted code ranges and planned helper failures. It does
not recover arbitrary host crashes, SIGSEGV/#PF, panic/unwind, ABI violations,
memory faults or asynchronous/concurrent snapshots. The slice has no memory
operations or fault replay. Native ARM64 execution is not the physical-x86
comparison required by S3-14, and no performance claim is made.
