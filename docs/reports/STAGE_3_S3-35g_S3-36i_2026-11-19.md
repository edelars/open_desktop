# S3-35g / S3-36i. Cold and warm mixed register dispatch

This measures the actual S3-55 mixed route using `MixedRegisterV1Admission`,
the FIFO multi-entry cache and `PublishedArenaBackend`. Four input
profiles exercise the exact CLD/STD interpreter steps alongside published
native instructions. Both straight-line inputs match the S3-55 host
fixture. The two countdown inputs execute CLD, SUB RAX,RCX, STD and JNZ
for 64 and 512 iterations. RAX starts at the iteration count and RCX is 1.
JNZ returns to CLD until RAX is zero. The instruction budget is the
expected total retirement plus one.

| Profile | Guest instructions | Native retired | Interpreter steps | Resident blocks |
| --- | ---: | ---: | ---: | ---: |
| ADD → NOP → CLD → STD → ADD | 5 | 2 | 3 | 2 |
| ADD → CLD → ADD → STD → ADD | 5 | 3 | 2 | 3 |
| CLD/SUB/STD/JNZ ×64 | 256 | 128 | 128 | 2 |
| CLD/SUB/STD/JNZ ×512 | 2,048 | 1,024 | 1,024 | 2 |

The driver verifies strict native admission rejects each input before
measuring. Every call compares full CPU state, exit and retirement with
the same interpreter reference. The JIT also verifies remaining budget,
native block executions, helper calls, successful interpreter steps and
cache counters. Each compiled block contains one native instruction in
these profiles. Cold publication counts match the distinct native
blocks. Warm calls hit all native entries with zero compile, publication
or eviction. Published bytes and logical metadata match across modes.

The cold interval includes mixed admission, cache and arena construction,
and the first dispatcher call. Warm times the dispatcher with a resident
cache. Each interpreter call executes the whole input under the same
instruction budget. State reset, verification, the warmup call, teardown
and process launch occur outside timing.

Four calibration pairs per mode set fixed counts for both modes. Counts
targeted 40 ms on the fastest pilot side. In each of four rounds the
signed executable ran cold and warm as separate, sequential processes.
The order reversed in rounds two and four. Each process retained eight
alternating JIT/interpreter pairs per profile. All 512 timed sides met
the 20 ms floor. The shortest took 32.578 ms.

## Results

Absolute times are medians in microseconds per complete call. The ratio
columns contain the median and full range of 32 paired ratios per mode
and profile.

| Profile | Cold JIT (µs) | Cold interpreter (µs) | Cold JIT / interpreter | Warm JIT (µs) | Warm interpreter (µs) | Warm JIT / interpreter |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| ADD → NOP → CLD → STD → ADD | 15.677 | 1.177 | 13.306 [10.905, 14.632] | 2.483 | 1.159 | 2.130 [2.069, 2.170] |
| ADD → CLD → ADD → STD → ADD | 19.649 | 1.145 | 17.113 [15.053, 18.912] | 2.676 | 1.139 | 2.351 [2.277, 2.578] |
| CLD/SUB/STD/JNZ ×64 | 133.102 | 56.712 | 2.353 [2.302, 2.470] | 119.254 | 56.900 | 2.102 [1.878, 2.148] |
| CLD/SUB/STD/JNZ ×512 | 971.057 | 452.558 | 2.149 [2.096, 2.238] | 949.300 | 451.307 | 2.101 [2.016, 2.160] |

The interpreter was faster in every pair. Across four rounds the
median warm/cold ratios of JIT medians were 0.159 and 0.138 for the
two straight-line profiles, and 0.895 and 0.976 for the 64- and
512-iteration loops. Both loop lengths repeatedly invoke the helpers.
These ratios reflect the combined cost of setup, first compilation and
publication versus resident execution. Phase costs would require
separate timing inside the dispatcher.

The result covers the bounded register-only mixed path with eager flags.
General memory fallback, production owner/MMU and the broader workload
matrix remain open. Physical x86 and Mac mini checks remain deferred.
[Mixed-path contract and tests](../testing/JIT.md#s3-55-mixed-register-and-interpreter-handoff)

## Reproduction and evidence

The host used Apple M3 Max with 14 cores, 36 GB RAM, macOS 26.7.1
(25G241) and rustc 1.99.0. The release build comes from the isolated
source snapshot of `5d0ae60`. The archive includes the build and link
scripts, source and signed executable hashes, the Rust driver, pilot
samples, fixed schedule, all scored samples and audit. The driver was
signed with ad-hoc Hardened Runtime and the smoke JIT entitlement.

Extract the archive's `files` into a scratch directory and run
`audit.py` to reproduce the table. For fresh measurements, copy the
scripts and `measure.rs` into a separate empty scratch directory,
invoke its `build.sh 5d0ae60` from the Git repository root, then run
`run.py` followed by `audit.py` with Python. The archive SHA-256 is
`bbbfed2a4082933fbedc219cc516fe21f7bcafb34bb016b09acccb16929b4cbc`.
