## Implemented boundary

`Uart16550PollingTx` is attached to COM1 `0x3F8–0x3FF` through the existing
`MachineBus` PIO binding. It accepts byte accesses only. Public
`Uart16550Handle` and device clones share the same `Arc<Mutex<UartState>>`, so
the caller can advance the state owned by the bus without creating a second
transmitter.

The model supports THR, DLL/DLM through DLAB, LCR, LSR and SCR. It accepts 8N1
with a nonzero divisor, requires IER=0, keeps FIFO disabled and reports no
interrupt through IIR. One holding byte and one shift byte form the bounded TX
path. THRE is `0x20` when holding is empty; TEMT is `0x40` when both stages are
empty. Transfer to the shift stage, completion (which returns the raw byte) and
reset happen only through explicit handle calls. No host output is generated.

This register subset follows TI's [PC16550D datasheet, SNLS378C](https://media.digikey.com/pdf/Data%20Sheets/Texas%20Instruments%20PDFs/PC16550D.pdf)
for register selection and THRE/TEMT definitions. The implementation does not
claim full 16550A compatibility.

diff with no P0–P3 findings. The code review and the test/check results above
are recorded from the implementation/review runs; this documentation-only
integration did not rerun those Rust checks.

## Limits

This slice does not establish baud-accurate timing, RX or FIFO behavior, IRQ4,
guest CPU `IN/OUT`, Linux serial-driver compatibility, guest boot, or scheduler
behavior. It does not connect a host serial sink. The target virtual-board
profile and the full UART task remain open until guest I/O and interrupt paths
are implemented and verified.
