# Stage 4 S4-32a: reproducible freestanding flat probe

## Result

Accepted bounded slice S4-32a connects a project-owned freestanding x86-64
fixture to the existing `od-machine` paged interpreter quantum and the
headless runner. The guest artifact is a real assembly/linker product, not a
runner-generated instruction sequence. Its fixed raw image is loaded verbatim
at GPA `0x1000`; the loader validates the complete page-table layout, code,
data and stack mappings before installing the direct Long64/CPL0 handoff.

The fixture executes exactly `MOV RAX,[RBX]`, `OUT DX,AL`, `HLT`. The runner
accepts only the image path and an instruction budget, invokes the existing
bounded paged quantum, completes the bounded polling-UART transmission and
reports the byte actually produced by the guest. It does not inject an
expected output or dispatch guest opcodes itself.

## Artifact and handoff contract

- Raw image: exactly `0x9000` bytes, placed at GPA `0x1000`.
- Page tables: six fixed pages covering GPA `0x1000..0x6fff`; code is GVA
  `0x400000` → GPA `0x7000`, payload is GVA `0x800000` → GPA `0x9000`, and
  the NX stack is GVA `0xa00000` → GPA `0xa000`.
- Entry: `CR0=0x80010033`, `CR4=0x20`, `CR3=0x1000`, `EFER=0xd00`,
  `RIP=0x400000`, `RBX=0x800000`, `RSP=0xa01000`, `DX=0x3f8`, Long64/CPL0.
- Build inputs: `entry.S` and `layout.ld` under
  `tests/fixtures/guest/stage4/flat_probe/`.
- Build tools: Apple Clang `21.0.0`, Rust-toolchain LLD `23.1.1`, and
  `rust-objcopy` `LLVM 23.1.1-rust-1.99.0-stable`; the macOS build supplies
  the active Rust sysroot's `libLLVM.dylib` through `DYLD_LIBRARY_PATH`.

Two clean builds with payload `0x1122334455667788` produced identical
artifacts:

- ELF SHA-256: `4484a6a9246ac64b4b888e24879d94757b150142b16e2131b2c1ef2a6573ce65`
- Raw SHA-256: `e78a7af7306e31fa316f1d64332ea4bd64abf0e854883106b1933f68bef97204`

A different payload `0x8877665544332211` changed the raw hash to
`e9254476ccd24bf4c741309365bd3825e11fd48c848c636cb07b146e608a6c34` while
preserving the fixed layout and instruction bytes.

## Boundaries

S4-32 and Stage 4 remain open. This slice does not claim a general kernel
loader, Linux boot protocol, exception delivery/CR2, IOPL/TSS, IRQ/APIC,
scheduler, physical hardware execution, JIT integration or full guest OS
compatibility. S4-34 hardware evidence, S4-35 Linux provenance and the
remaining S4-32 acceptance work are still required.
