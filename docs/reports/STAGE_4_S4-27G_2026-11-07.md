# S4-27g — queued IRQ and JIT/interpreter parity

## Result

Added `queued_irq_jit_and_interpreter_have_same_observable_order` to the
serialized ARM64 host integration target. It schedules a due IRQ and a future
event in `EventQueue` before execution. On the JIT path, after the real
`PublishedBlockExecutor` returns from the native prefix, a synchronous test
caller removes the due event, requests one fixed APIC vector and raises the
caller-owned event notification. The JIT dispatcher returns `EventPending`
before the NOP fallback with exact RIP, remaining budget and counters.

The interpreter path executes the same prefix and consumes the same scheduled
event at the corresponding completed boundary. Both paths then confirm APIC
eligibility, enter the same handler, read saved RIP and ISR state, write guest
EOI through LAPIC MMIO, verify ISR clearing, execute same-CPL IRETQ and resume.
The test compares the complete final `LongModeState` and the observed ordering
of queue extraction, APIC request, notification, entry, EOI, return and resume.
Pause/resume before entry preserves the notification and future queue event.

This is an explicit test-caller bridge. No production event pump or scheduler
was added.

## Boundaries

The queue-to-APIC route is driven by the test caller at a synchronous completed
boundary. It does not implement production queue routing, queue-driven HLT
wakeup, concurrent event producers, automatic scheduling, MOV-SS/NMI handling
or asynchronous interruption inside native execution. Parent S4-27 and Stage 4
remain open. No new confirmed issue was found for `KNOWN_ISSUES.md`.
