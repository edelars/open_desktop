# S4-19c: secondary #PF, #DF delivery, and shutdown

**Status:** bounded implementation accepted after independent review and
corrections. Parent S4-19 and Stage 4 remain open.

## Scope

The existing paged Long64/CPL0/same-CPL/IST=0 path now distinguishes the initial
vector-14 attempt from one optional vector-8 attempt. A real page fault during
the first delivery constructs a `DoubleFaultRecord` with both fault records and
tries #DF once. The #DF frame uses error code zero, preserves CR2, and does not
force RF into saved RFLAGS. Its saved RIP is retained for diagnostics only;
execution is not resumed from it. Already committed frame and paging effects
remain visible in order.

A real page fault during #DF delivery sets `CpuActivity::Shutdown`, records the
latest CR2 and the second attempt's partial effects, and prevents another
delivery. The paged CPU execution entry returns `PagedProbeExit::Shutdown`
before instruction fetch or memory effects. Backend and profile failures do
not synthesize a page fault or shutdown. The V2 testkit snapshot converter
rejects Shutdown because its existing activity wire schema has no matching
variant.

System coverage includes a read-only GDT with an unaccessed target descriptor:
the Accessed-bit write raises nested #PF, #DF is delivered through vector 8,
and the first handler MOV executes. A separate missing-stack-page case raises
#PF while writing the #DF frame, enters shutdown, retains the completed frame
prefix, and proves a later paged step performs no fetch or memory access.

The emulator behavior is limited to the stated #PF → #DF path and a page fault
during #DF delivery. It does not claim general exception-pair precedence,
TSS/IST, privilege transitions, guest PTE repair, INVLPG, IRETQ, fault retry,
or a complete vCPU lifecycle. The #DF error code and shutdown rule follow the
[Intel SDM, volume 3](https://cdrdv2-public.intel.com/868137/325462-089-sdm-vol-1-2abcd-3abcd-4.pdf);
the saved RIP choice and partial-effect sequence are explicit bounded emulator
contract decisions, not claims about universal hardware fault ordering.
