# S6-42: межпроцессорная инвалидация и безопасное освобождение блоков

Дата: 2026-11-18. Состояние: реализовано частично, ожидает gate-ревью (чекбокс плана не отмечен). Профиль приёмки — «одна инструкция на блок» (формы `PagedFetchedLoadSession`, решение 2026-11-18). Нормативный текст — [JIT_CONTRACT.md, S6-42](../specs/JIT_CONTRACT.md#s6-42-межпроцессорная-инвалидация-и-безопасное-освобождение-блоков) и [S6-40](../specs/JIT_CONTRACT.md#s6-40-кэш-кода-при-нескольких-vcpu-контракт); решение о владении region — [ADR-0010](../decisions/ADR-0010-process-map-jit-region-partitioned-between-vcpu-threads.md) (предложение, файл написан исполнителем S6-42: координатор до начала кода его не создал).

## Что сделано

1. **Кэш у каждого vCPU (A1).** `SharedJitRegion` (`Sync`, `crates/od-host/src/jit_region.rs`) держит единственную `MAP_JIT` region и аренду; часть (`JitRegionPart`, `Send`, без исполняемых ручек) выдаётся один раз и в потоке vCPU становится `ActiveJitPart` (`Rc`, `!Send`). Сессия `PagedFetchedLoadSession::with_region_part` публикует блоки в слоты части. Блок, ручка и PC-map остаются у потока; `unsafe impl Send/Sync` только у внутреннего значения region (сырой указатель для адресов непересекающихся слотов). Цикл S3-38o вызывается из потоков теста (по потоку на vCPU, своя сессия и свой `PagedHostLoopControl`); механизма вызова из `parallel_run` нет (`pub(crate)` в `od-machine`, кванты интерпретатора).
2. **Инвалидация между vCPU (A3, D1).** Запись vCPU A поднимает поколение страницы (`commit_write`); на каждом входе B заново снимает tracked snapshot и сверяет байты, страницу и поколение с ключом допуска блока. Первый вход после записи видит новое поколение при синхронизации через замок (шина под `Mutex`) или канал; без замка не проверено (S6-42b). **A7 не выполнен (шина под `Mutex`); задержка обнаружения без замка не проверялась — S6-42b.** Шаг JIT в тестах идёт под `Mutex<MachineBus>` (`s6_42.rs`), поэтому сценарий A/B, свободный прогон и `stop_all` проверяют режим чередования с гранулярностью замка; D1 и G-XMC в параллельном режиме не доказаны. Проверка «байты и поколение блока равны странице» в свободном прогоне почти тавтологична: `report.fetched_code`/`fetched_generation` берутся из свежего снимка под тем же замком, а не из ключа исполненного блока (`admitted.generation`, `admitted.bytes`). Корректная формулировка: эффект шага равен эффекту байт, которые хранит страница в этот момент; ключ допуска блока напрямую не сверяется. Основание доказательной силы — эффекты (RAX, qword данных для load и store при пути только JIT). Отбраковка закэшированного блока по поколению сценарием A/B не проверена: каждый отказ (`push`, `ret`) обнуляет `admitted`, поэтому каждый native-шаг B компилируется заново (admissions 2 и 4); отбраковку по ключу проверяет только свободный прогон, а случай «поколение выросло, байты те же» отдельно не проверен. Тесты `s6_42_vcpu_a_changes_code_vcpu_b_executes_it_and_leaves_the_old_code` и `s6_42_free_running_vcpus_never_execute_stale_code`.
3. **Освобождение (A4).** Слот освобождается только при падении `PublishedCode` в потоке-владельце (тип `!Send`), без периода ожидания. Отложенное освобождение (слот занят заимствованием таблицы) реализовано как механизм, применяемый на safe point сессии, но его путь (`jit_region.rs`, `try_borrow_mut` с ошибкой) защитный: в текущем коде недостижим, тестами не покрыт, проверки `pending_release == 0` тривиальны. В тестовой сборке освобождённый слот заполняется `BRK` только в `cfg(test)` и только первые 64 байта из 4096 — ограничение доказательной силы. Тесты `s6_42_slot_is_released_by_the_owner_and_reused_with_a_new_generation`, `s6_42_release_under_load_never_runs_a_released_slot`.
4. **MAP_JIT для нескольких потоков (M1 - M6).** Слотовый перевод допуска сделан: отображения на допуск у сессии с частью нет, аренда за допуск не берётся; сессия без части получает `MappingAlreadyLive` (M6). После записи слота — `sys_icache_invalidate` и явный `ISB` (M4; относится к слотам: ветка `Owned` в `publish_with_metadata_in` идёт без `ISB`, как и раньше). Mapping и аренда живут, пока жив владелец или любая часть (`Arc<RegionShared>`), — уточнение M1 (use-after-unmap исключён). «Один держатель исполняемой памяти» ADR-0005 понимается как один держатель аренды, части — арены внутри него. Отклонение от M2: вытеснение собственных записей (FIFO) при нехватке части не реализовано — публикация отказывает, сессия уходит в интерпретатор (для сессии с одним блоком недостижимо). Тесты S3-38o повторены на слотовом backend (11 тестов `s6_42_slot_backend_*`; `s3_38o_the_map_jit_lease_ends_with_the_session...` не повторён — его предмет, аренда на допуск, при слотах другой). Тесты M1/M2/M6: `s6_42_region_parts_are_disjoint_handed_out_once_and_hold_the_process_lease`, `s6_42_session_publishes_into_a_slot_and_a_plain_session_falls_back_to_the_interpreter`; M3: `s6_42_threads_write_and_run_their_own_parts_concurrently`.
5. **Остановка всех vCPU с JIT (S1, S3).** `PagedVcpuGroup::stop_all`/`resume` и `PagedHostLoopControl::acknowledge_safe`/`withdraw_safe` реализуют протокол S6-34 для цикла S3-38o; тесты `s6_42_stop_all_with_jit_vcpus_acknowledges_on_safe_points_and_resumes`, `s6_42_stop_all_names_the_vcpu_that_does_not_acknowledge`. Это не `ParallelControl::stop_all` из `od-machine`.

Изменения общего кода: `PublishedCode.region` стал `CodeRegion { Owned, Slot }`; четыре `publish_*` получили варианты `*_in(block, part)` (старые имена — обёртки с `None`); цикл S3-38o вызывает `session.safe_point()` в начале каждой итерации (без части — пустая операция). `PagedHostLoopControl` получил флаг `safe`.

## Ограничения и что не закрыто

- Нет привязки к `ParallelControl` и потокам S6-34: `parallel_run` недоступен из `od-host`, а JIT-сессия и общий интерпретатор берут `&mut MachineBus`. Потоки теста делят одну шину под `Mutex`: шаги vCPU чередуются, общая `PhysicalMemory` с поколениями — одна; параллельны только записи слотов, `ISB` и native-вызовы разных частей. Одновременное исполнение гостевой RAM из двух native-вызовов не доказано. **A7 не выполнен (шина под `Mutex`); задержка обнаружения без замка не проверялась — S6-42b.** Нужен вариант paged-пути JIT над `&MachineBus` и привязка к `ParallelControl` — подсрез **S6-42b**.
- `PagedVcpuGroup::stop_all` может вернуть `Ok` по `safe`, оставшемуся с прошлой остановки; по порядку Дейкстры это корректно (поток перечитывает флаги до шага). При `Err` запросы остаются поднятыми, нужен `resume`.
- Фикстурные бэкенды (`PublishedArenaBackend`, `MultiEntryBlockCache`) на слоты не переведены (A5); пока region жива, они получают `MappingAlreadyLive`.
- Граница «≤31 инструкции» не проверяется (профиль одной инструкции); многоинструкционные блоки со store — S3-24; связи блоков (D2/D3) — S3-31.
- Закрыто на gate S3-38o (2026-11-18): выход `StopRequested` с `retired == 1` для store в собственную страницу кода переводится в `CodeInvalidated`, как `Complete` (`store_invalidates_active_code`).
- Размеры частей в тестах — не замер (S6-38). Пометки «по памяти» контракта S6-40 (Intel SDM, Arm ARM, правило Apple о `pthread_jit_write_protect_np`, `ISB` в `sys_icache_invalidate`) не сверялись.
- S6-41b (inline-формы `LOCK`/`XCHG`/`MFENCE`) не затронут и остаётся предусловием S6-43a.
- Graphify не обновлялся (коммита нет).
