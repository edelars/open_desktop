# S3-20aj — RSP/RBP data with a low-GPR direct displacement

## Scope

Added exact singleton qword MOV forms `48 8B/89 /r disp8` (length 4) and
`48 8B/89 /r disp32` (length 7), with ModRM `mod=01/10`, data register RSP or
RBP (`reg=4/5`), and direct base RAX..RBX (`rm=0..3`). No SIB, address-size or
other prefixes, other data/base registers, pairs, or V3 forms were added.
Effective-address behavior remains defined by the decoded `MemoryOperand`;
generic GPR admission, frame layout and ABI are unchanged.

## Evidence

- Descriptor tests cover both operations, all four low bases, both data
  registers, disp8 -128/-1/0/127 and disp32 MIN/-1/0/MAX/128. Direct V2 and
  shared-IR site metadata and source-byte identity match. Invalid data fields,
  SIB, and prefix variants reject.
- Host tests compare direct V2, shared IR and interpreter for loads and stores
  across the same base/data/width matrix. They compare full CPU/RAM state,
  callback targets/counts and retirement. Targets are independently checked
  as `entry_base.wrapping_add_signed(displacement)`.
- Noncanonical RSP/RBP payloads are accepted as data. A noncanonical effective
  address through any low base produces #GP before a backend callback, with
  state/accounting unchanged for either direction and both displacement
  widths. Injected load/store backend failures remain host errors and preserve
  architectural state. A successful store callback can request STOP; the
  full old data-register payload remains committed.
- Dispatcher tests cover low-base singleton→NOP fallback→existing pair for
  both data registers, widths and directions. Budget and callback STOP return
  at the singleton's actual next RIP; continuation executes the NOP and pair
  without repeating the first memory effect. Loading a noncanonical RSP or RBP
  commits the first load, then using that value as the next address raises #SS
  at the second RIP without another callback.
- Partial fixture windows (1..3 and 1..6 bytes) return `BoundaryReached`
  without publication, helper calls or state changes. Unsupported SIB,
  register and prefix forms return `Unsupported` with zero blocks/callbacks.
- The previous RSP-data/RBP-base displacement profile remains covered. Its
  existing IR form for RSP data with RBP disp32 required the block predicate to
  retain the RBP base case as well as add low-GPR bases. Existing RBP-data/RBP
  base, RSP-base SIB, and RIP-relative cases remain in the suite.
- The exact low-base form's cfg-gated x19 canary passed on the independent
  review host: Darwin ARM64 (`aarch64-apple-darwin`).
