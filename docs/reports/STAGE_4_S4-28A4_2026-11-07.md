# S4-28a4 — caller-driven periodic Local APIC timer

## Result

Extended the opt-in Local APIC timer with periodic mode using LVT bit 17. A
nonzero Initial Count starts or replaces the timer; zero cancels. Periodic
Current Count wraps over the programmed interval. Dispatch rearms the existing
capacity-one queue from the original arm epoch, so a late caller coalesces
missed expirations into at most one edge and does not shift the timer phase.
Masked expirations continue the phase without setting IRR. The timer keeps
running while its vector is in service; EOI remains an APIC state transition.

Mode changes require an idle timer. Vector and mask may change before expiry
without restarting it. A due event still blocks writable timer MMIO with
`Busy`, including cancellation, until the caller dispatches it. Reset cancels
the queued deadline and clears timer registers while preserving the clock.
Deadline overflow and event-generation failure leave the due queue and IRR
unchanged.

## Boundaries

Time advancement and timer dispatch remain explicit caller operations. The
slice does not add TSC-deadline mode, an automatic event pump, host scheduling,
or Linux timer-profile evidence. Existing one-shot behavior and shared-clock
HLT dispatch gate remain in place; a separate periodic-mode HLT-gate test was
not added. Tests exercise EOI after earlier timer delivery, but do not exercise
a further periodic expiry while the vector remains in ISR. Parent S4-28, S4-27
and Stage 4 remain open.

The register behavior follows Intel [SDM release 090, Volume 3A §13.5.4](https://cdrdv2-public.intel.com/874240/325462-090-sdm-vol-1-2abcd-3abcd-4.pdf).
