# S3-35c — cold direct-entry checked-memory comparison

**Status:** three release process runs completed and passed independent source,
run-level evidence, and cross-run manifest review. This is a bounded cold-path
measurement; it does not select a production default or establish a general
performance winner.

## Scope

The opt-in `od-bench two-site-memory-cold` profile used the exact two frozen
S3-34a sequence identities, three fixed seeds, and 400 generated cases per
sequence/seed combination: 2 × 3 × 400 = 2,400 unique inputs. Each report has
sequence counts `[1200, 1200]` and input digest
`b09478b556aa91234d8c453f20e70f637222c5de2d7369d305ffe7c78caae540`.
The existing shared `od-testkit` fixture provider supplied inputs; the third
S3-34a sequence was not included.

For each input, correctness preflight ran two trials per backend. It compared
full CPU state, RAM, exit normalization, retired count, remaining budget, and
the exact ordered callback trace (addresses and widths). This yielded 4,800
interpreter and 4,800 native preflight executions, with all 4,800 trial pairs
matching. Every timing result was validated against the preflight outcome.

The native timed interval includes IR block compilation, publication, direct
typed entry execution, and explicit drops of both `PublishedCode` and the IR
block for that input. The interpreter interval includes interpreter execution.
Input/state reset and result validation are outside both timers. This profile
does not use a dispatcher, VMHost, or cache reuse between inputs or repeats.

Each release process performed its own calibration. The 200 ms common-side
floor was first met at 1,024 repetitions. Each scored process retained 20
alternating interpreter/native pairs at that count; all 40 measured sides per
process passed the floor. No pair was trimmed. Runs 1 and 3 started with the
interpreter; run 2 started with native.

## Results

The ratio is calculated from each pair's raw `native_total_ns /
interpreter_total_ns` totals. Across all 60 retained pairs, the median ratio was
**71.4765**, with a range of **66.7736–93.9423**. Per-process medians were
70.0309 (run 1), 71.7841 (run 2), and 71.1482 (run 3). The run 1 high ratio
(pair 11) remains included. These statistics describe only this direct-entry
cold compile+publish+execute+drop fixture and its corresponding interpreter
execution.

## Load and limits

Point-in-time monitoring recorded Stage 2 test/compiler activity during sampled
intervals in all three processes. A Graphify activity sample was recorded in
run 1 and a brief `graphify hook-check` near the start of run 3. The monitoring
envelopes are reconstructed snapshots, not continuous accounting. Reports do
not include per-pair wall-clock timestamps, so the affected pairs and the
impact of concurrent work are unknown. No process was stopped, no samples were
removed, and no timing series was replayed. Run 1 has a retained high-ratio
pair; its cause is not established.

The cap-2048 calibration-only run met the timing floor at 1,024 repetitions.
The projection artifact estimates 16.7555 minutes for cumulative calibration
through the reserve cap of 2,048 repetitions plus 20 pairs at 2,048. This is a
linear estimate, not a measured full-process duration; it excludes setup,
teardown, and other overhead. The scored runs calibrated and measured at 1,024. An earlier calibration attempt with the previous lower repetition
cap failed the interpreter floor and is retained as diagnostic evidence.

This is one Apple Silicon ARM64, local fixture, direct-entry cold profile on
two accepted S3-34a sequences. It does not measure the third sequence, a
production dispatcher/cache, repeated resident execution, VMHost, owner/MMU,
other memory forms, broad ISA coverage, physical x86 equivalence, or general
guest workloads. It makes no production default or winner decision. Mac mini
checks remain deferred until the end of Stage 3.

monitoring envelopes. The scored invocations were:

```sh

    --process-run "$run" \
    --output "work/tmp/stage3/s3-35c/run$run.json"
```
