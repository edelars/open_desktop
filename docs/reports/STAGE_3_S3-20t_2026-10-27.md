# S3-20t — Address32 SIB disp32 through shared IR and bounded dispatch

## Scope

The checked singleton profile admits exactly `67 48 8B/89 /r sib disp32`:
ModRM `mod=10,r/m=100`, RAX..RBX data/base/index, scale 1/2/4/8, qword data,
dword effective address and exact length nine. The decoder's `MemoryOperand`
and `access_address_48` remain the only source of displacement and effective
address semantics. No alternate prefix, SIB special, pair, decoder, owner,
Stage2, Mini or benchmark work is included.

The singleton source metadata capacity is now the named
`MEMORY_SITE_SOURCE_BYTES_MAX = 9`. The Rust API
`source_bytes_storage()` changed from `([u8; 8], u8)` to `([u8; 9], u8)`.
The code validates instruction length before slicing/copying and preserves all
nine source bytes. This change does not alter qword data buffers, pair source
`[u8; 6]`, ActiveCodeV3 source `[u8; 23]`, or RuntimeContext/C ABI layout.

## Evidence

- The `od-jit` descriptor matrix checks both operations, all allowed
  data/base/index encodings and scales, and disp32 MIN/-1/0/MAX. It checks
  decoded displacement and next RIP, exact nine-byte storage and one-instruction
  PC maps. Partial windows 1..8, wrong prefix/ModRM/SIB, unsupported
  registers, and trailing bytes reject.
- Native direct V2, shared IR and interpreter comparisons cover both
  operations, all scales, disp32 MIN/-1/0/MAX, RAX as data/base alias, ignored
  upper address bits, one qword callback per retirement and full CPU/RAM parity.
  One qword callback begins at `0xffff_fffc` and crosses 4 GiB contiguously.
  Two source records differing only in byte nine retain different source and
  decoded displacement metadata.
- Shared-IR architectural faults preserve exact payload and leave CPU, RAM,
  budget and retirement unchanged. Backend errors remain host errors. A
  successful nine-byte store that raises STOP in its callback remains
  committed, retires once, and returns at `entry + 9`.
- Bounded dispatch composes the nine-byte singleton → bare NOP interpreter
  bridge → existing pair. Budgets 0..4 match interpreter state/RAM; explicit
  checks cover stop-RIP at the bridge, callback STOP after the singleton,
  continuation from the actual RIP without a duplicate read, and byte windows
  1..8 with no memory callback or retirement. Successful continuation also
  exercises release of the prior executable mapping before the next
  publication.
