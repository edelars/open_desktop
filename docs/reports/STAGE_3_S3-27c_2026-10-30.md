# S3-27c — ActiveCodeBlockV3 host-PC attribution map

## Scope

This bounded slice adds diagnostic PC attribution to the existing exact,
fixture-only `ActiveCodeBlockV3` (`MOV RDX,imm64; MOV [RBX],RAX;
MOV RCX,imm64`). It does not change emitted guest behavior, bytecode, ABI,
production ownership/MMU paths, or host-fault recovery.

## Implementation

The emitter converts checked ARM64 word positions to byte offsets and builds a
validated `PcMap` covering the complete generated code with contiguous aligned
ranges. Commit boundaries are `A+10` after one retired instruction, `A+13`
after two, and `A+23` after three; map instruction indices are zero-based
(`0`, `1`, `2`). Canonical state writes and accounting are marked
`CommitInProgress`; checked helper and post-write/pre-commit ranges are
inadmissible after an effect. The helper-failure stub is attributed to store
RIP `A+10`, while the typed helper result continues to distinguish architectural
faults and backend failures. CodeInvalidated maps to fixed `A+13`; Complete and
STOP-after-tail map to fixed `A+23`. Shared stop-RIP, STOP, and budget stubs use
canonical state.

The compiler artifact owns the map, and publication clones it into
`ActiveCodeMetadataV3` in the arena slot. The typed published handle returns the
map only for its live slot generation. The lifecycle regression drops the
compiler artifact, clears/invalidate cached code while the V3 handle stays
live, and checks that an old handle cannot read the map after its slot is
reused.
