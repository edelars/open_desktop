# S4-12c: CPU-owned CR3 translation handoff

## Scope

Adds `run_paged_cr3_probe`, a bounded opt-in machine quantum for CPU-owned
`CR3`. The CPU profile permits exact `MOV CR3,RAX` and `MOV RAX,[RBX]` only.
After a committed CR3 write, the machine checks the full typed effect against
both the active snapshot and CPU state, validates a replacement immutable
`Long64ProbeConfig`, then installs it before polling STOP or fetching again.
The existing `run_paged_probe` still rejects CPU-owned CR3.

The independent root A→B fixture maps the same code and data linear addresses
to disjoint physical table trees and different code/data pages. The second
instruction can only complete with root B's code and data mappings. A separate
case confirms a non-present next-code PTE under root B raises a precise fetch
fault while retaining the retired MOV CR3, updated CPU CR3/RIP and effect
report. One-instruction quantum handoff is also covered. Stores, other memory
forms, stack operations, PIO and HLT are unsupported in this profile.

No TLB, PCID, global pages, EFER transitions, exception delivery or startup
state provenance are included. Parent S4-12 remains open for those tasks.
