# S3-37g. Invalidation and first redispatch on FIFO16

This benchmark uses `MultiEntryBlockCache` with the FIFO policy,
the S0-09 dispatcher and a real `PublishedArenaBackend`. It starts
with either one or eight backing pairs resident. Each pair has two
guest RIPs in separate mappings with the same backing ID, backing
version and instruction bytes. The program is `MOV RAX, imm64` with
a distinct immediate per backing and two alternating values per pair.
Before timing, the interpreter supplies a full-state reference for each
address and both values. The driver verifies state, exit, budget and
retirement for both calls after each timed pair. Cache-counter deltas
cover the pair.

Each epoch starts with the oldest pair. At full occupancy the target
rotates through the eight backings. Removal and reinstallation move
that pair to the back of FIFO. The scope measures these intervals:

| Interval | Timed operation |
| --- | --- |
| Ready pair | One cache-hit dispatch at each of the two addresses. |
| Current-version notification | One `invalidate` call with the existing version. Both entries stay resident. |
| Backing invalidation | One `invalidate` call with the next version. Both inactive handles are dropped before it returns. |
| First redispatch | One dispatch at each address with the new version and new value. The interval includes lookup, compilation, publication and native execution. |
| Clock control | An adjacent clock interval around a `black_box` of a constant. |

All timers retain their clock overhead. At 16 entries, an extra untimed
pair of cache hits on the next backing checks that unrelated entries
survive. All state reset, dependency construction, correctness
verification and counter reads take place outside the recorded
intervals. The driver supplies the new source bytes and a between-call
backing notification.

Every epoch verifies zero evictions, exactly two removals and two
new publications. Each removal reduces resident code and logical
metadata and returns two arena slots. Redispatch restores the starting
footprint. The driver also checks that clearing the cache returns all
16 slots and zeroes resident accounting. The reserved arena length
remains 64 KiB while the backend is live.

## Results

A separate four-sample pilot of 8,192 epochs per sample found the fastest
per-epoch interval at each occupancy. Fixed counts targeted 12 ms on that
interval. Four rounds ran the same signed executable in two processes per
round, alternating occupancy order. Each process retained eight samples
on one arena. The 64 scored samples completed 33,187,872 epochs.
All 256 operation intervals reached the 6 ms aggregate floor. The
shortest was 11.225 ms. The clock interval is a separate diagnostic.

Times below are nanoseconds per epoch, with the median and full range
of 32 samples at each occupancy. The interval for each dispatch pair
includes both guest addresses.

| Interval | 2 resident entries | 16 resident entries |
| --- | ---: | ---: |
| Clock control | 17.161 [16.679, 25.411] | 17.392 [16.620, 26.754] |
| Ready pair | 1056.961 [999.035, 1285.195] | 1005.915 [956.748, 1167.081] |
| Current-version notification | 17.284 [16.734, 20.048] | 33.963 [31.942, 39.716] |
| Backing invalidation | 221.338 [210.909, 275.543] | 363.761 [341.476, 467.860] |
| First redispatch | 5255.984 [4991.771, 6628.677] | 5252.555 [4926.607, 6785.698] |

The current-version notification at two entries is close to the clock
control. Removing the oldest pair takes longer with the full cache
in the observed samples. At the two occupancies the paired ratio of first
redispatch time to ready-pair time was 5.019 [4.806, 5.319] and
5.228 [4.999, 5.814]. The redispatch interval includes both executions
and the work needed to republish them.

| Starting entries | Free slots before → after removal | Code bytes before → after removal | Logical metadata bytes before → after removal |
| ---: | ---: | ---: | ---: |
| 2 | 14 → 16 | 1232 → 0 | 3156 → 0 |
| 16 | 0 → 2 | 9856 → 8624 | 25248 → 22092 |

These values returned to the starting figures after each redispatch.
The scored epochs published 66,375,744 blocks with zero capacity
evictions. The reserved 65,536-byte arena length stayed the same.
The measurement covers between-call notifications for the oldest FIFO
pair. S3-37d contains the separate duration-based stress runs. Active
guest writes and production owner/MMU remain open. Physical x86 and
Mac mini checks are deferred.

## Reproduction and evidence

The host used Apple M3 Max with 14 cores, 36 GB RAM, macOS 26.7.1
(25G241) and rustc 1.99.0. The signed release driver links libraries
built from an isolated snapshot of `56a1be3` and uses the smoke JIT
entitlement with ad-hoc Hardened Runtime. The archive records the Rust
driver, build and link scripts, source and executable hashes, pilot
counts, process order, raw rows, and audit.

Extract the archive's `files` into a scratch directory and run
`audit.py` with Python to reproduce the statistics. To take new
measurements, copy the scripts and `measure.rs` to a separate empty
scratch directory. From the repository root run its `build.sh` with
`zsh` and revision `56a1be3`, then run `run.py` and `audit.py` using Python.
The archive SHA-256 is
`ab6e1c3fa5492466d1b1fb20ae98676ccf5216b1c6f746b764c7f184d015c7a6`.
