# Stage 4 S4-25e: закрытие Local APIC (spurious, LVT mask, reset, приоритет, EOI)

Ограниченный срез НЕ закрывает родителя S4-25: LINT0/LINT1/Error LVT, Version и ESR остаются открытыми и выносятся в S4-25f. Новый код в `local_apic.rs`
минимален: операции `spurious_vector()` и `acknowledge_or_spurious()` с типом
`InterruptAcknowledge`; остальной срез — тесты и документация, фиксирующие уже
существовавшее поведение.

## Что сделано

- Spurious-путь: если на момент acknowledge нет eligible запроса, возвращается
  `SVR[7:0]`, IRR/ISR/TMR/PPR не меняются.
- Матрица reset: один набор проверок читает все регистры у свежего устройства
  и после четырёх путей сброса.
- LVT mask: фиксация поведения Timer LVT; остальные LVT и Version остаются
  неподдержанными.
- Приоритет/EOI: таблица из 17 случаев и тест порядка EOI.
- Ошибочные обращения: перебор всех смещений, ширин и пространств, таблица
  reserved-бит и read-only регистров, отказ при global disable.

## Решения

- **Выбор вектора при гонке.** Acknowledge разрешается на момент вызова, как
  INTA: самый старший eligible вектор сейчас, иначе spurious. Это не заменяет
  `acknowledge_vector(выбранный)`, который при изменённом выборе отказывает без
  изменений; CPU-путь S4-27 (`InterruptSelectionChanged`) не менялся.
- **Spurious при software disable.** Разрешён при global enable: software
  disable между выбором и acknowledge — это снятие запроса. Запрос остаётся в
  IRR и снова становится eligible после повторного включения.
- **Spurious не в ISR.** Гость не должен посылать EOI; тест проверяет, что
  ISR/PPR уже обслуживаемого вектора не изменились.
- **Masked LVT: событие теряется.** Уже принятый контракт S4-28a1/a4: маска
  проверяется в момент expiry, deadline снимается/перезаряжается, IRR не
  меняется, снятие маски не воспроизводит событие. Изменений поведения нет,
  добавлены тесты (в т. ч. что IRR/ISR/TMR с тем же вектором не затронуты).
- **Другие LVT не добавлялись (сужение контракта, согласовано ревью).** План S4-25e требовал маски для всех LVT-записей; поддержан только Timer;
  поддержан только Timer. Добавление CMCI/Thermal/Perf/LINT/Error потребовало
  бы Version и ESR, т. е. спекулятивной модели вне manifest. Они остаются
  `UnknownOffset`, это зафиксировано тестом.
- **Reset-матрица** соответствует SDM: SVR `0xff` (disabled), LVT mask, TPR 0,
  IRR/ISR/TMR 0, ICR 0. `reset` по-прежнему отклоняется при Remote IRR.
- **Ширина >32 бит.** Шина усекает значение по ширине обращения (первая версия
  теста ошибочно ожидала отказ через шину); отказ проверяется напрямую на
  устройстве.

## Измеренные числа

- `cargo test -p od-machine --lib local_apic --offline -- --test-threads=1`:
  30 passed (22 прежних без изменения ожиданий + 8 новых).
- `--lib diagnostic_vcpu`: 34; `--lib uart`: 13; `--lib io_apic`: 11;
  `--test stage4_uart_irq_probe`: 10; все passed. `cargo fmt --all -- --check`
  прошёл.
- Инъекции (код возвращён после каждой): EOI без снятия ISR — 8 падений из 30;
  EOI снимает наименьший вектор — 2; маска игнорируется при expiry — 4;
  `>=` вместо `>` для класса — 6; фиксированный spurious-вектор — 1.

Источник: Intel SDM 093, Vol. 3A, Chapter 13.

## Ревью

- Независимое ревью (Claude Opus, high, read-only): срез принят условно. Spurious, маска Timer LVT, reset-матрица, приоритет/EOI и ошибочные обращения проверены по коду, по SDM и мутациями (падения подтверждены). Вердикт по LVT: S4-25 сейчас не закрывать — Linux probe APIC читает Version и пишет LINT0/LINT1/Error LVT и ESR, а это в срезе не реализовано. Нужен S4-25f.
- Исправлено по ревью: срез не заявляет закрытие родителя S4-25 (отчёт, контракт, план); сужение контракта (только Timer LVT вместо «всех LVT») записано явно; добавлен S4-25f в план.
- Мелочи, на потом: spurious не подключён к CPU-доставке (до гостя вектор не доходит, CPU-путь даёт InterruptSelectionChanged); acknowledge_or_spurious отдаёт Spurious и при пустом IRR; SVR принимает spurious 0..15; в тесте global-disable флаг снимается прямой записью.
- Срез S4-25e принят условно; родитель S4-25 открыт до S4-25f.
## Открыто

- Кроме Timer других LVT, Version и ESR нет; Version не может быть опубликован
  без них.
- Spurious реализован как операция состояния устройства; CPU-доставка spurious
  вектора (S4-27) не подключена.
- Полный `cargo test -p od-machine` в этом срезе не запускался; прогнаны
  затронутые наборы.
- x2APIC, multi-CPU startup, NMI, IOAPIC S4-26c, IDT/IF, HLT wakeup, JIT, Linux
  вне среза.
