# S4-19b: paged #PF delivery and handler entry

**Status:** implementation and behavior checks complete; independent code review
passed after corrections. S4-19 and Stage 4 remain open.

## Scope

The new CPU-owned CR0.WP MOV selector accepts the exact paged qword load and
store forms. The parent CR0.WP probe retains its MOV CR0 and exact store
allowlist. A present supervisor read-only page with
`CR0.WP=1` produces a real `#PF` for `MOV [RBX],RCX`: PFEC is 3, the faulting
instruction does not retire, its RIP and data remain unchanged, and CR2 takes
the faulting linear address. The report retains the page walk's A/D updates.

`od-isa` validates a same-CPL Long64 interrupt gate for vector 14 with IST=0,
reads the gate and target descriptor through the memory contract, and pushes
the six qwords through tracked implicit-stack writes. IA-32e stack alignment is
applied while the original possibly unaligned RSP is saved. The saved RFLAGS
image sets RF for this fault-class exception; live interrupt-gate flags clear
IF, TF, NT, RF, and VM. The adapter preserves callback order, page-table A/D
effects, any committed frame prefix, and both original and secondary fault
records. After successful entry, the guest executes one handler `MOV RAX,[RBX]`
and observes the unchanged sentinel. A later handler fetch fault is reported
after delivery rather than as a delivery failure.

The target code descriptor must already have Accessed=1, have a zero base and
4 GiB effective limit, and use a GDT selector. This slice does not synthesize
the descriptor Accessed-bit write. Delivery aborts on a secondary fault or
backend failure and does not classify #DF or shutdown. PTE repair, INVLPG,
IRETQ, retry, and full exception recovery remain in the open parent S4-19.
