# S3-35a — cold first run on the frozen register corpus

**Status:** three successful release process runs measured a bounded
interpreter/FIFO(16) first-run comparison on the frozen S3-17 register-only
corpus. This is partial S3-35 evidence. The pipeline component measurements,
warm-runtime/resource gates, physical x86/Mini checks, and full Stage 3
acceptance remain open.

## Results

The per-run time values below come from the report's integer-nanosecond
`median_ns_per_sweep`, `min_ns_per_sweep`, and `max_ns_per_sweep` summaries.
The runner normalizes each raw sample by `elapsed_ns / sweeps` before producing
those fields. The paired-ratio values come from the median of each report's
`paired_interpreter_over_fifo_ratios` array. The final two columns show the
median and range across the three process-run medians. Times are milliseconds
for one complete 1,010-case corpus sweep.

| Variant | Run 1 | Run 2 | Run 3 | Median across runs | Range across runs |
|---|---:|---:|---:|---:|---:|
| FIFO(16) cold block dispatcher, including fresh arena/runtime init | 6.694460 | 6.668069 | 6.639773 | 6.668069 | 6.639773–6.694460 |
| Interpreter | 0.165827 | 0.163570 | 0.163649 | 0.163649 | 0.163570–0.165827 |
| Paired interpreter/FIFO elapsed ratio | 0.024664 | 0.024435 | 0.024777 | 0.024664 | 0.024435–0.024777 |

On this exact cold register-only corpus, the FIFO block path took about 40.5×
the paired interpreter time per full sweep. This describes only the measured
workload and timer boundaries; it does not predict warm execution or other
guest programs. The cold path is slower here, and no speedup is claimed.

## Timing scope and limits

For each FIFO sample, every timed corpus sweep starts with fresh runtime/cache
and executable arena; timing includes initialization, dispatch, decode/key
work, compilation, publication, and native execution. Cache reuse for repeated
keys within a single corpus sweep is part of this workload. The interpreter
sample times the same case sequence and guest work. Both paths use the same
initial cases, state, budgets, and retirement checks; setup and validation run
outside timing.

Fixture/trace parsing and admission, interpreter oracle and native preflight,
state cloning/reset, post-execution validation, process startup, and
runtime/cache/arena teardown are excluded from timed intervals. Teardown is
included in whole-process wall time. Legacy fragment timing is omitted because
the same admitted shape and semantics were not established for this corpus.
No warm workload, helper/memory/fallback corpus, resource/churn suite, physical
x86 oracle, Mini, or Stage 2 measurement was run here. S3-35 remains partial:
this report gives the bounded end-to-end cold corpus comparison, but it does
not record separate pipeline component timings or cold process startup. Host
power, thermal, and background-load telemetry was not recorded.
