# S4-27d — explicit HLT wait and maskable APIC wake

## Result

Added `DiagnosticVcpuSession::into_halt_wait`, which uses the existing exact
Long64 bare-HLT profile and transfers ownership to `DiagnosticHaltWait` only
after a successful HLT retirement. A rejected profile, non-HLT opcode, guest
fault or memory error returns the original session without publishing the
candidate CPU.

`DiagnosticHaltWait::poll_apic` does not execute instructions. IF clear or no
eligible Local APIC vector leaves the CPU Halted and the request pending. With
an eligible vector, the existing maskable-delivery helper constructs the frame
on a candidate CPU; acknowledgement of that exact vector publishes CPU state
as Running. `into_running` only returns the session after that committed entry.
The saved frame contains post-HLT RIP. The caller separately executes the
handler, guest EOI and IRETQ, then resumes the post-HLT instruction.

STOP while Waiting prevents wake. STOP after successful entry preserves the
committed CPU state, frame and APIC acknowledgement, marks the session Stopped,
and prevents `into_running`, so the handler cannot run after stop. A delivery
abort may leave a written frame prefix but leaves CPU Halted and the APIC
request pending; the wait becomes terminal and cannot retry. Repeated polling
after success reports the same vector without acknowledging another request.

## Boundaries

This is synchronous caller polling on a flat identity diagnostic path. It does
not implement asynchronous wake sources, NMI/debug/MOV-SS wake, APIC timers,
general scheduling, JIT integration or automatic handler/EOI/IRET execution.
The parent S4-27 and Stage 4 remain open.
