## Bounded checked-memory dispatcher partial

Added `od_jit::memory_dispatch::run` and the host
`PublishedMemoryBlockExecutor` for only the two exact checked qword memory
pairs and their singleton MOV load/store forms. The caller borrows immutable
code bytes through `CodeView`, selects an explicit fixture execution boundary,
and exclusively borrows `GuestMemory` for the synchronous call. Each iteration
compiles the pair or current singleton from actual RIP, forwards remaining
budget, and validates retirement/progress. The host publishes and drops one
artifact mapping before returning to the next dispatch iteration.

The unsafe caller contract retains the current checked-memory requirements:
private synchronous ordinary RAM, all-or-nothing qword writes, no MMIO,
executable/code aliases, concurrency, DMA, re-entry, or unwind. The generic
`GuestMemory` trait does not verify these properties. `od-machine` currently has
only its scaffold and no production RAM/MMU owner, so owner-backed VMHost
integration and owner-provided fetch remain open. A fixture boundary can inject
an explicit byte-window end may split an instruction. Partial bytes return
`BoundaryReached { rip }` before publication/helper use; this is neither a guest
fetch fault nor a guest halt. Complete unsupported (`90`) and invalid (`0F 0B`)
tails preserve explicit classifications, while a lone `0F` at the byte-window
end is classified as truncation. Actual code-fetch fault delivery remains open
until a memory owner supplies code fetch.

Focused native checks compare independent RAM/state snapshots against the
interpreter for two consecutive pair blocks and budgets 1 through 4. They also
cover continuation after a budget exit, no duplicate first access after a
second-site fault, stop-RIP inside a pair and between blocks, second-memory
architectural fault, A+1/A+2 no-effect and A+4 prefix-only byte-window
boundaries, complete unsupported/invalid and true-truncation tails, unsupported
code after a committed pair, cooperative STOP before entry and from either
pair's first memory callback, STOP on the final pair callback suppressing the
next publication, exact continuation after clearing STOP, and a second-block injected publication
error that preserves the first pair effects as a host error. Successful
two-pair execution demonstrates sequential single-slot publication and release
on the supported macOS ARM64 test host.

Checks for this partial:
`cargo test -p od-host --offline bounded_memory_dispatch -- --nocapture` (2
passed), `cargo test -p od-host --offline` (61 unit tests, 12 integration tests
passed; 2 ignored), `cargo test -p od-jit --offline` (131 passed),
`cargo fmt --all -- --check`, `cargo check --workspace --all-targets --offline`,
and `cargo check -p od-host --target x86_64-unknown-linux-gnu --all-targets
--offline`. The Linux host check passed with existing platform-gated dead-code
warnings. This slice does not complete the full Stage 1 corpus, physical x86
comparison, general guest fetch/MMU integration, cache,
arbitrary interpreter fallback, or general S3-15 acceptance.
