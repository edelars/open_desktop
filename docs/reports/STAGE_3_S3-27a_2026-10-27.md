# S3-27a — precise architectural fault for the active-code store

## Scope

This slice exercises the existing bounded V3 artifact:

```text
48 BA imm64       MOV RDX, imm64
48 89 03          MOV [RBX], RAX
48 B9 imm64       MOV RCX, imm64
```

It adds fixture-only fault injection and host-result decoder coverage. No
production runtime or decoder code changed, and no `od-isa` files were edited.

## Evidence

At a valid mapped writable destination, the fixture's `GuestMemory::write`
returns a selected architectural #PF with error code and linear address before
changing RAM. The native call returns that exact `ArchitecturalFault`; the
prefix remains committed (`RDX=OLD`), RIP points at the store, the tail's RCX
remains unchanged, and budget/retirement show one completed instruction.
Independent interpreter state, RAM, and backing versions match. The fixture
counts one attempted helper call and zero successful writes; no notification
is emitted and bytes/versions/cache-facing callback state remain unchanged.
The fault remains the result even when the owner raises STOP as the failed
helper returns.

Budget 1 and stop-RIP at the store each preserve the committed prefix while
preventing any write-helper call. Direct host decoder cases reject an unknown
exit tag, inconsistent RIP/retired/budget accounting, and an invalid optional
fault-field presence flag. A valid architectural fault with absent optional
error-code and linear-address values is accepted. A helper-boundary status is
classified as a host error, not converted to a guest fault. Existing V3 backend
failure coverage continues to verify that backend errors remain host errors.

## Limits

This is fixture-only validation for one checked store artifact. It does not
cover faulting instruction fetch, general PC maps, every memory form, MMIO,
production MMU fault delivery, or the complete S3-27 acceptance. Physical Mac
mini checks and long benchmarks remain deferred to the final S3-21 gate.
