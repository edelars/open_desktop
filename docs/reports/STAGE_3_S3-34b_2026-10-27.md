## Saved replay case

Corpus mismatch reports now use a version-1 JSON envelope for the two existing
memory sequences. It stores the profile and exact six source bytes, initial
RIP/GPR/RFLAGS plus an explicit default marker for out-of-profile CPU state,
the full 128-byte private RAM image, both effective addresses, budget,
stop-requested value, optional stop-RIP, typed fault and site/operation trigger,
and optional first-budget/continuation protocol. The outer report records the
host OS/architecture, build revision, native/interpreter availability, reason,
both snapshots, equivalence, and mismatch classes.

The report decoder rejects unknown versions/profiles/fields, source-byte or
address inconsistencies, non-default CPU state, malformed RAM/result sizes,
unsupported STOP/fault/budget/continuation combinations, unpaired results, and
inconsistent stored mismatch classes before native publication. An unsupported
current native backend returns an explicit error and cannot create an
equivalence-success report. The ignored entry point
`replay_saved_case_from_environment` requires `OD_JIT_REPLAY_CASE`; explicit
execution with no variable fails with a diagnostic. It replays the original
protocol on independent native/interpreter snapshots, carries actual committed
CPU/RAM from the first call into continuation, compares every phase, and creates
a new `.replay-<pid>.json` file with `create_new`, preserving the original.
`reproduced_mismatch` reports whether fresh mismatch classes equal the saved
classes.

`crates/od-host/Cargo.toml` adds only dev dependencies already pinned and used
by this workspace:

- `serde` `=1.0.229`, crates.io, `MIT OR Apache-2.0`, `derive` plus default
  `std` features for typed case/report serialization and strict deserialization.
- `serde_json` `=1.0.151`, crates.io, `MIT OR Apache-2.0`, default `std` feature
  for stable JSON encoding/decoding.

They are test-only; `od-host` production dependencies are unchanged.
