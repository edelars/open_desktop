# S3-20ad — RSP as qword MOV data and signed-disp8 SIB base

## Scope and implementation

Admitted only singleton `48 8B/89 64 24 ib`: ModRM `mod=01/reg=4/rm=4`, SIB
exactly `0x24` (RSP base, no index, scale 1), signed disp8, qword data,
64-bit effective address and exact length five. No generic data-register range
was widened; frame layout, public ABI, pair profiles, V3 and decoder semantics
are unchanged. Address calculation uses the decoded `MemoryOperand` and
`access_address_48`.

## Evidence

- Descriptor and source validation cover load/store and disp8 -128/-1/0/127;
  malformed/truncated SIB, altered ModRM/SIB, disp32, address-size prefixes
  and trailing bytes are rejected. The former `[RSP+disp8]` negative was
  removed because this exact ModRM/SIB is the newly admitted profile.
- Direct V2/shared IR/interpreter parity compares complete CPU and RAM state,
  callback address/count and retirement. Effective address and store payload
  are derived from entry RSP; a successful load commits a distinct loaded RSP
  only after the memory read succeeds.
- Architectural noncanonical-RSP faults preserve CPU/RAM/retirement and make
  no data callback. A canonical start at `u64::MAX-3` with an 8-byte access
  retains the `AddressOverflow` diagnostic; backend errors stay host errors.
  Entry STOP and zero budget suppress callbacks. A store whose callback raises
  STOP remains committed. The ARM64/macOS x19 canary includes this five-byte
  profile across native success, budget guard and fault returns.
- Dispatcher entry STOP and budget zero return before any block publication or
  data helper. The continuation scenario executes
  `48 8B 64 24 FF` (`MOV RSP,[RSP-1]`) at `ENTRY`, with old RSP 33 and callback
  address 32. Budget-one and callback-STOP runs commit the noncanonical value
  once and stop at `ENTRY+5`; resuming faults #SS on the following `[RSP]`
  instruction, preserves the first commit, and leaves callback count at one.
  A separate exact store `48 89 64 24 FF` writes the old RSP value at address
  32, then the write callback raises STOP; the dispatcher returns at `ENTRY+5`
  with one native retirement, one write callback and all eight stored bytes
  intact. The incomplete four-byte prefix and invalid forms stop with zero
  blocks executed and no data callback.
