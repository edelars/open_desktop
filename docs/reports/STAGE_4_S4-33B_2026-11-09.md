# Stage 4 S4-33b — CPL3 SYSCALL → kernel store → SYSRETQ → user load

Статус: ограниченный системный кейс реализован; независимое ревью ожидает.
Кейс не закрывает родителя S4-33 и Stage 4.

## Что сделано

`Stage4Cpl3SyscallProbeV1` — строгий raw-image профиль собственного ядра
поверх принятого примитива S4-20c (`step_paged_syscall_profile`, семантика
SYSCALL/SYSRETQ не менялась). Fixture `tests/fixtures/guest/stage4/cpl3_syscall/`
(`entry.S`, `layout.ld`) собирается `tools/build/build_stage4_cpl3_syscall_probe.py`
в образ 0x9000 байт (GPA `0x1000..0xa000`, 128 KiB RAM, без устройств).

- Код: user GVA `0x400000` — `0F 05` (SYSCALL), `48 8B 03` (`MOV RAX,[RBX]`);
  kernel GVA `0x600000` (LSTAR, supervisor) — `4C 89 17` (`MOV [RDI],R10`),
  `48 0F 07` (SYSRETQ).
- Страницы: user code GPA `0x7000` (user RX), kernel code GPA `0x8000`
  (supervisor RX), data GPA `0x9000` дважды: GVA `0x800000` supervisor RW и GVA
  `0x801000` user RO. Хвосты code-страниц нулевые, лишние PTE отвергаются.
- Entry state задаёт loader: CS `0x23`/SS `0x1b` (CPL3), RIP `0x400000`, EFER
  `0xd01`, STAR `(0x10<<48)|(8<<32)`, FMASK `0x200`, RDI `0x800000`, RBX
  `0x801000`, R10 = store qword, RAX = sentinel `0x0123456789abcdef`, RSP
  `0x702027`, CR3 `0x1000`.
- Qwords (по умолчанию): initial `0x1122334455667788` (raw `0x8000`), store
  `0x8877665544332211` (raw `0x8008`); они обязаны различаться.
- Успех: 4 инструкции, CPL по шагам 0/0/3/3, RIP `0x400005`, RCX `0x400002`,
  R11 `0x202` (RFLAGS до маскирования по FMASK, как по SDM), RSP и CR3 не менялись, RAM `0x9000` = store, RAX = store.
  Committed writes: ровно 11 (page walk A/D и одна запись `0x9000`) в
  фиксированном порядке; D-бит только у supervisor RW alias.
- Runner: `od-runner --stage4-cpl3-syscall-probe IMAGE [--budget N]
  [--inject-kernel-no-write | --inject-sysret-cpl0]`; JSON содержит
  `guest_state` (RIP, RSP, CPL, CS, SS, RAX, RCX, R11, RFLAGS, CR3),
  `event_trace` по шагам, `committed_write_trace`, `budget`, `stop_reason`,
  `checks`, `failed_checks`. Коды выхода: 0 принято, 7 завершено, но oracle
  не принят, 5 остановка до конца, 3/4 ошибки аргументов/образа.
- OUT/HLT примитивом S4-20c не исполняются: наблюдаемый результат — user RAX и
  guest state, а не UART.

## Инъекции

| Инъекция | Результат |

| `--inject-sysret-cpl0` (после SYSRETQ восстановлены kernel CS/SS) | `stop_reason=unsupported`, `retired=3`, CPL 0, RIP `0x400002`, RAX = sentinel; провален `returned_to_cpl3`; код 5 |

Мутационная проверка: если loader по умолчанию направляет kernel store на
`0x9ff8`, падают 3 machine-теста (успех, budget, CPL0-инъекция); если
возврат в CPL0 применяется безусловно после SYSRETQ, падают 3 machine-теста
(успех, budget, misdirected-инъекция).

## Открыто

- Только uncached interpreter и четыре инструкции S4-20c; нет OUT/HLT,
  stack switch, TSS, exception delivery из CPL3, timer, IRQ, HLT wakeup,
  self-modifying code, huge pages, TLB-on/JIT, Linux, physical hardware.
- Инъекция `sysret_cpl0` меняет CS/SS после шага SYSRETQ в harness, а не
  моделирует аппаратный дефект; она проверяет, что oracle различает CPL.
- Родитель S4-33 открыт: остальные кейсы набора не выполнены.

- FMASK (бит IF в ядре) не проверяется: события не записывают RFLAGS после SYSCALL. R11 = 0x202 — это RFLAGS до маскирования, а не признак маски; итоговые RFLAGS восстанавливаются из R11 и тоже не доказывают маску. Проверка `rflags_after` — отдельная правка, не блокер кейса.
- Инъекция `--inject-sysret-cpl0` меняет состояние CPU после шага SYSRETQ (CS, SS, cs_cache), а не только регистры fixture; ss_cache остаётся DPL3 — состояние несогласованное. Ловится отказом профиля и проверкой `returned_to_cpl3`, а не RAX/RAM.
- Мелочи: комментарий в machine-тесте про байт 0x4d неверен (это MOV [R15],R10); в runner `checks` нет RCX, R11, SS и CR3.
## Ревью

- Независимое ревью (Claude Opus, high, read-only): блокеров нет; срез принимается. Тесты 5/1/3 проверены; кодировки, отображения и ожидания по SDM сходятся. Исправлено: формулировка про R11 и FMASK (R11 = RFLAGS до маскирования). Инъекция sysret_cpl0 признана частично тавтологичной — ловится отказом профиля и проверкой CPL, записано в «Открыто».
- Срез S4-33b принят. Родитель S4-33 открыт.
