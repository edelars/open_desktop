# Stage 3 S3-20bj: address32 direct RSI/RDI qword MOV

## Implemented profile

The bounded singleton profile admits `67 48 8B/89 /r [disp8|disp32]` with ModRM `mod=00/01/10`, `rm=110/111` (ESI/EDI), and data register RAX..RBP. Source lengths are 4, 5, and 8 bytes. Address calculation remains decoder-owned through `MemoryOperand::access_address_48`: `(low32(old_RSI_or_RDI) + signed_displacement) mod 2^32`. The instruction transfers a full qword, uses one contiguous eight-byte memory callback, and preserves the complete RSI/RDI register value.

The exact profile is checked in direct V2 compilation, shared IR validation, runtime metadata validation, source-byte matching, and bounded `memory_dispatch::compile_at`. No SIB, extra prefix, new data/index register, pair, V3, owner/MMU integration, or frame/ABI change was added.

## Evidence

- JIT descriptor tests cover both operations, both bases, all six data registers, no displacement/disp8/disp32, and signed displacement boundaries. They assert exact bytes, decoded metadata, supported profile, and source matching. Partial byte windows and unsupported SIB/address32-RSI-data/RDI-data neighbors reject.
- Host parity compares direct V2 and shared IR against the interpreter for loads/stores, both bases, all six data registers, and all displacement cases. It checks full CPU/RAM state, exact callback address and length, retirement, unchanged full RSI/RDI, and an independent low32 effective-address formula with high base bits set.
- Dedicated cases verify one contiguous qword callback at `0xffff_fffc`, successful store followed by STOP with the write committed once, entry stop-RIP/STOP/zero-budget guards, and budget-split dispatcher continuation at actual RIP with no repeated access.
- Backend read/write failures preserve CPU state and RAM and report one callback at the exact target.
