## Что сделано

- **`InterruptPump`** (`crates/od-machine/src/interrupt_pump.rs`): владеет `EventQueue` (ёмкость 16) и таблицей
  `key -> (вектор, срок)`. Публичный путь caller: `irq_generation`, `schedule_irq(generation, key, vector, due_ns)`,
  `cancel_irq`, `reset_irq_queue`, `irq_queue_len`, `irq_queue_next_deadline`, `coalesced_irqs`. Снятие на границе после
  dispatch таймера: `peek_due` -> `request_fixed_edge` -> `remove_due` только после успеха; при ошибке событие остаётся и
  `run` выходит `Rejected(QueueRequest{vector, error})` (возобновляемый отказ). Due-события с вектором, уже стоящим в IRR,
  схлопываются: событие трассы `Coalesced{vector}` и счётчик. Generation: `reset_irq_queue` вызывает `EventQueue::reset`,
  токен старой generation отвергается. Инъекция `PumpInjection::PopBeforeRequest`. Новые отказы `QueueRequest`, `QueueState`,
  `QueueRoute`; ошибка caller `PumpQueueError` (`Queue`, `InvalidVector`, `NoClock`).
- **ISSUE-070** (`idle_advance`): срок = минимум полезных сроков таймера и очереди; источник, чей вектор уже в IRR при
  `eligible() == None`, не ждётся. Нет полезного срока — `IdleHalt` без продвижения времени.
- **`LocalApicHandle::timer_vector()`** (`crates/od-machine/src/local_apic.rs`): read-only вектор LVT Timer, если таймер есть
  и не маскирован.
- **Загрузчик** `Stage4InterruptQueueProbeV1` (`crates/od-machine/src/stage4_interrupt_queue_probe.rs`), fixture
  `tests/fixtures/guest/stage4/interrupt_queue/` (`entry.S`, `layout.ld`), builder `tools/build/build_stage4_interrupt_queue_probe.py`
  (+ `test_build_stage4_interrupt_queue_probe.py`, 4 теста).
- **Тесты** `crates/od-machine/tests/interrupt_queue_pump.rs` (8 тестов).
- **Runner** `--stage4-interrupt-queue-probe IMAGE [--budget N] [--inject-pop-before-request]`
  (`tools/runner/src/stage4_interrupt_queue_probe.rs`, `main.rs`) + `tools/runner/tests/stage4_interrupt_queue_build_cli.rs` (3 теста).
  В runner-модулях S4-27i1 и S4-27i2 в `match` по `PumpTraceKind` добавлен вариант `Coalesced` (поведение не менялось).
- **Документы:** `docs/specs/MACHINE_CONTRACT.md` (раздел S4-27i3, пометка в разделе S4-27i2), `docs/testing/MACHINE.md` (пункт 67),
  этот отчёт, данные [`s4-27i3-interrupt-queue.json`](data/stage4/s4-27i3-interrupt-queue.json).

## Ожидания и источники (не вывод кода)

- **Правила очереди:** due-событие (срок <= время) снимается на ближайшей границе; future-событие доставляется, когда
  часы остановленного CPU достигают срока (idle advance), время после wake равно сроку (инструкции 0 нс); два due-события
  с одним вектором — один IRR-бит (SDM Vol. 3A 10.8.4: IRR хранит запрос одним битом), один вход.
- **Кадр (SDM Vol. 3A 6.14.2–6.14.3):** RSP `0x6FC8`, RIP после HLT `0x4012`, CS `0x8`, RFLAGS `0x202`, RSP `0x6FF0`, SS `0x10`;
  RFLAGS в handler `0x2`; EOI снимает ISR (10.8.3.1). Приём на границе при IF=1 перед HLT кладёт RIP самого HLT.
- **Таймер (ISSUE-070):** P = 625 × 16 / 100 МГц = 100000 нс (SDM Vol. 3A 10.5.4); первое срабатывание в P (доставлено),
  второе в 2P (IRR при ISR того же вектора без EOI не eligible).

## Отклонения и открытое

- `Rejected(QueueRequest)` — единственный возобновляемый отказ (исключение из финальности в `run`; остальные отказы S4-27i1/i2 не менялись).
- Ожидание inline-сценария «неудачный запрос» воспроизведено отключением APIC caller'ом (`set_global_enabled(false)` на свежем APIC):
  состояние APIC по умолчанию, поэтому гость не теряет SVR; в известных путях других прозрачных причин отказа `request_fixed_edge` без потери состояния не найдено; отказ по вектору, совпавшему с level-маршрутом IOAPIC (`apic_pair.rs`), в этом срезе не воспроизводится
  (вектор < 16 отвергается при постановке, а не при запросе).
- Источник с заблокированным вектором не ждётся, событие остаётся в очереди; событие с другим, более приоритетным вектором и более
  поздним сроком время не блокирует (учитывается по коду, тестом не покрыто: загрузчики допускают один gate, вариант с TPR не проверен).
- Сброс очереди не связан со сбросом APIC/CPU (S4-37a).
- В Running срабатывание из будущего наблюдаемо только через idle advance (инструкции 0 нс, S4-37a); due-событие из Running наблюдаемо.
- DRY-долг: загрузчик очереди повторяет часть загрузчика таймера.
- Тесты S4-27i1/i2 не менялись; в `PumpTraceKind` добавлен вариант (поэтому правились два `match` в runner-модулях).
- Не входит: реестр устройств, обобщённый IOAPIC, асинхронные producer, paged (i4), `run_boot` и плата, Linux.
