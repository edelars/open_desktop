# S3-31m. Warm dispatch and continuation memo on M1 Pro

## Workload

Both sides ran the current S0-09 controlled dispatcher on the same
signed ARM64 release, with fixed register homes, eager flags and a
warmed FIFO16 cache. The ordinary side used the normal dispatcher
without phase timers. The observed side recorded phase timestamps on
the same execution path. Each interval includes the adapter that
constructs the code view, dependency slice and control context, plus
the full dispatch call. Fixture setup, CPU state reset, cache counter
snapshots and result validation occur outside those intervals.

| Fixture | Native blocks per call | Guest instructions per call | Unique blocks | `cache.find` calls per dispatch | Memo resolutions per call |
| --- | ---: | ---: | ---: | ---: | ---: |
| `same_4096` | 4,096 | 8,192 | 1 | 1 | 4,095 |
| `two_64` | 127 | 191 | 2 | 2 | 125 |
| `two_4096` | 8,191 | 12,287 | 2 | 2 | 8,189 |
| `three_64` | 190 | 254 | 3 | 190 | 0 |

The four input byte sequences, initial states and work counts come from
the archived S3-31l driver. Preflight checked full CPU state against
the interpreter, the end address, each expected exit kind, guest
retirement, remaining budget and native block count. Both timed sides
require one cache hit for each native block and zero misses,
compilations, publications and evictions.

## Attribution boundary

The initial-lookup timer includes the snapshot and lookup phase. The
continuation-memo phase measures current or previous entry selection
after the budget, STOP, event and code-boundary checks. A selected
entry still needs snapshot validation and a recorded hit. The
unattributed time includes these checks, cache accounting, adapter
work, observer bookkeeping and other dispatcher work. Each phase
share uses the total from the same observed side.

## Decision

Keep transitions through the dispatcher with the current memo and
explicit hit arguments for these S0-09 register fixtures. The memo
resolves all continuation visits with one RIP and all but one with
two RIPs. The previous matched comparison against the pre-memo
dispatcher measured current/original warm ratios of 0.0814 and
0.0659 on the two alternating profiles.

The three-RIP control goes through `cache.find` for all 190 blocks.
Its 40.75% observed phase includes key snapshot work alongside
lookup. The difference identifies a cost in the three-RIP control
while leaving the price of removable lookup work in ordinary execution
unresolved. A linked transition would still need the correct
generation, lifetime, STOP, event and budget behavior. This comparison
supports keeping the current simpler dispatcher on the measured scope.
ISSUE-520 stays open for the small matched long same-RIP difference
from S3-31l.

## Build and selection

The signed release ran on Apple M1 Pro with 16 GiB RAM, macOS 14.6.1
(23G93), SDK 14.5 and Rust/Cargo 1.99.0. The archived opt-in patch was
applied to `eb314737664ad1dd40297db4b92e8e1a9de4b6ea` and built with
`cargo build --release --offline --locked -p od-bench --bin od-bench --target aarch64-apple-darwin`.
The executable targets macOS 14.0, passed strict ad-hoc Hardened Runtime
signature verification with `allow-jit`, and has SHA-256
`49ffac86ac074508c22a94bbf975cedee8fb9985621ad17020e79451a2b320fc`.

All three selected processes, PIDs 4093, 4327 and 4571, ran as UID 501
with effective nice −5. Rounds 1 and 2 passed at 83.6% and 83.0%
minimum overlapping CPU idle. Round 3 try 1 passed source, timing,
work, watcher coverage and scheduling replay. Its 79.0% minimum
overlap idle missed the automatic 80% floor. The user authorized its
inclusion. That was the only below-floor sample among 52 overlapping
samples. The archive retains the original load-rejection disposition
and selection receipt.

The already running retry for round 3 also passed. PID 4761 ran as
UID 501 at nice −5 and stayed at or above 83.8% overlapping idle.
Substituting that retry yields the separate automatic series. Its
pooled ordinary medians were 43.424, 57.504, 46.214 and 652.730 ns per
native block in fixture order. The difference between selections was
at most 1.36% on those medians, and key snapshot and lookup still
accounted for 40.56% of observed time on the three-RIP control.

Before the selected series, an earlier controller rejected the seven
phase rows because it expected only the three active rows. That
attempt also had idle down to 69.0%. The corrected controller permits
the four additional rows only as zero-work rows. The old attempt is
retained as diagnostic evidence and excluded from both analyses.
