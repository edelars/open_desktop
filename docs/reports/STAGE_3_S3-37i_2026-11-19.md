# S3-37i. Sustained cache pressure in the retained S0-09 Session

Two independent signed processes ran the real `od_host::session::Session`
from `ddf7444`. Each used the S3-37f pressure shape, 20 blocks with
`MOV RAX,imm64` and a terminating `JNZ +0` against the FIFO16 cache.
Workers alternate between distinct immediate ranges. Final RAX was
20 or 40 in worker 0 and 60 or 80 in worker 1. Both ZF values were
exercised with distinct initial registers. Every whole-program RUN and
tail hit checked full state against a precomputed interpreter result,
along with exit, retirement, remaining budget and native block count.

Between checkpoints each sweep published 20 blocks and then hit the
last one. The driver checked exact cache deltas, 16 residents, stable
code and logical metadata totals, and configured high-water limits.
At every checkpoint, a STOP request issued before RUN and an unadmitted
entry RIP preserved state and cache accounting. A second live lease in the same process was refused.
Clear set logical residency to zero, preserved lifetime counters, and
allowed another temporary Session to acquire the lease. The cleared
Session then republished all 20 blocks, evicted four, and was dropped
with the cache full. Each fresh Session started with zero counters.

## Results

Each process used 64 checkpoints over a minimum of 660 seconds. Elapsed
time includes fixture preparation, pressure sweeps, lifecycle checks and
RSS sampling. The supervisor observed 659.944 seconds between its first and last
polls that found both worker processes live. This measures process
overlap. Cache residency varies during clear and recreation.

Both current and high-water accounting stayed at 16 entries,
15,936 code bytes and 38,144 logical metadata bytes at full occupancy.
Across the two processes, 16,766,464 sweeps, 335,331,840 publications

passed. The unadmitted entry exercises a typed dispatcher refusal.

## Reproduction

The local host is Apple M3 Max running macOS 26.7.1 (25G241), with the
toolchain and SDK recorded in the archive. Both workers ran the same
ad-hoc-signed Hardened Runtime binary with the smoke JIT entitlement.
The initial pilot's `ps` invocation was denied by the sandbox. A
two-second, four-checkpoint pilot then passed with the Mach RSS adapter
and the same binary used for scoring.

Extract the archive's `files` into a fresh scratch directory. From the
repository root, run its `build.sh` with `zsh` and revision `ddf7444`.
Run the extracted `run.py` with an unused output-directory path followed
by `660 64`. Run the extracted `audit.py` with that output directory.
For the saved results, run `audit.py` on the extracted `scored`
directory directly. The archive holds the exact driver and helper,
signed binary and library identities, host and toolchain, schedule, and
individual observations for both pilot and scored workers.
