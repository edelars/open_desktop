# S4-28a2 — shared vCPU and APIC timer clock

## Result

The diagnostic vCPU session and opt-in one-shot Local APIC timer can now use
one caller-driven virtual time domain. Bare Long64 RDTSC, timer arm, Current
Count and due dispatch read the same `VirtualClockHandle`. Only the Runnable
session can advance a shared clock. The standalone S4-28a1 timer constructor
and its caller-driven advance path remain available.

## Ownership and locking

`VirtualClockHandle` is a cloneable reference around the existing value-type
`VirtualClock`. Its public methods create a clock and read a copied snapshot.
One non-cloneable advancement capability can be claimed for the handle's
lifetime; a second session receives `ClockAlreadyOwned`, including after the
first session is dropped. Advancement is crate-private and is called by
`DiagnosticVcpuSession` after its Runnable-state check. A caller creates the handle, passes a clone to
`LocalApic::with_shared_timer`, and passes the handle to
`DiagnosticVcpuSession::new_with_clock_handle`.

APIC registers, deadline queue and IRR retain their existing pair mutex. APIC
operations may take that mutex and then briefly snapshot the clock mutex.
Session RDTSC and explicit time advance take only the clock mutex; guest CPU
execution does not hold the APIC mutex outside the existing synchronous bus
access. There is no reverse clock-to-APIC lock acquisition in this slice.
If a deadline is due while the session is Paused, Stopped or Terminal,
`dispatch_timer` returns `Busy` without consuming it or setting IRR. Resume
allows the caller to dispatch it. Arm derives its deadline and elapsed-count
origin from one clock snapshot. Reset removes the APIC deadline and leaves the
session clock unchanged.

- `cargo check -p od-machine --all-targets --offline` — passed.
- `cargo test -p od-machine --lib --offline` — 190 passed, including 33 diagnostic session, 19 Local APIC and 6 virtual clock tests.
- `cargo fmt --all -- --check` — passed.
- `git diff --check` — passed.
- Graphify updated after the final implementation and documentation changes.
- Architecture review: independent `gpt-6-astra/high` approved the shared-clock direction, with guest MMIO time coherence, APIC lock scope, atomic event handling and lifecycle boundaries called out. The implementation follows those constraints.
- Independent code review: repeat `gpt-6.1-sol/high` review passed with no remaining findings. Three P2 findings were fixed: unique advancement ownership, dispatch blocked during Paused/Stopped/Terminal without consuming the event, and one timestamp snapshot shared by due-check/rearm.

The integration case arms timer vector `0x40` with count 4 at 1 GHz, advances
the session by 2 ns, executes RDTSC and reads Current Count as 2, then advances
by 2 ns, executes RDTSC as 4, reads Current Count as 0 and dispatches the due
event into IRR. It checks that `LocalApicHandle::advance_timer_ns` rejects the
shared-clock configuration, due dispatch is blocked while Paused and Stopped,
and a second advancer claim is rejected.

## Boundaries

This is one diagnostic vCPU and one explicit APIC timer. It does not provide
automatic expiry polling, CPU interrupt delivery, event scheduling, HLT time
progression or wakeup, pause/resume host-time integration, periodic mode,
TSC-deadline mode, or a Linux timer profile. Mutex snapshot cost was not
benchmarked, so no performance claim is made. The S4-22 and S4-28 parent tasks,
S4-27 and Stage 4 remain open.
