# S3-20ei — exact address-size-32 ESP-base dword store with signed disp8

## Scope

S3-20ei admits only the exact five-byte singleton `67 89 44 24 ib`
(`MOV [ESP+disp8],EAX`) through the shared typed-IR checked-store path. It uses
ESP as the SIB base, no index, scale 1, and signed 8-bit displacement. The
effective address is `(low32(RSP) + sign_extend(disp8)) mod 2^32`, then
zero-extended; high 32 bits of RSP are ignored. The store writes low32 RAX in
one contiguous checked four-byte access and advances RIP to `A+5`. A write
starting at `0xffff_fffe` continues through `0x1_0000_0001`; individual bytes
do not wrap at 4 GiB.

The bounded host fixture compares native and interpreter CPU state and RAM,
checks poisoned high32 RSP values and 32-bit address wrap, and verifies one
four-byte write. Entry STOP/budget exits and an injected backend write error
leave state/memory unchanged and allow a successful retry. Callback STOP is
reported after the write and architectural state commit; retrying the same
published block is rejected at the committed RIP without a second write.
These fixtures do not establish production owner/MMU, hardware, or performance
behavior.

## Limits

The full `od-host` suite was not run, and no separate PC-map, broad
performance, or hardware claim is made. The open [ISSUE-045](../KNOWN_ISSUES.md)
is the distinct S3-20eg test-coverage limitation; S3-20ei does not close it.
Stage 2 remained outside this slice’s evidence; concurrent runs were ignored
per user instruction. Mini/M1 checks remain deferred and Stage 3 remains
partial.
