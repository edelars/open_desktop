# S3-20ar report: indexed SIB with RBP base

## Scope

Added only 64-bit-address-size singleton `48 8B/89 /r sib disp8|disp32`
forms with ModRM `mod=01/10,r/m=100`, SIB base RBP, index RAX..RBX, scale
1/2/4/8, data RAX..RBP and qword transfer width. Exact lengths are 5/8 bytes.
The `mod=00,SIB.base=101` encoding remains a no-base operand and is rejected.
Existing RSP-base indexed and no-index SIB profiles remain unchanged.

The checked builder, shared IR, direct V2, runtime metadata/source validator
and bounded dispatcher agree on this profile. The decoder's `MemoryOperand`
and `access_address_48` remain the sole EA semantics.

## Evidence

The JIT descriptor matrix checks load/store, all six data registers, four low
index registers, all scales and signed disp8/disp32 boundaries. It rejects
mod00 no-base with an index and unsupported SIB fields. The host matrix
compares direct V2, shared IR and interpreter CPU/RAM state, exact callback
address/count and retirement, including data=RBP and data=index pre-state
aliases and 64-bit address wrapping.

Host fault cases check #SS at a noncanonical RBP start and qword end across
data/index choices, with no callback or state/RIP/budget commit. A same-address
RBX control yields #GP. A qword range overflow remains a host
AddressOverflow diagnostic; injected backend failures remain host errors.
The old RBP store payload is committed before callback STOP. Dispatcher
coverage publishes both the disp32 singleton and a disp8 store, then resumes
after budget exhaustion or callback STOP through NOP and the existing native
pair without repeating the store. Partial disp32 windows and the complete
mod00 no-base source have no publication or effects. The exact RBP-base path's
cfg-gated x19 canary passed on host `aarch64-apple-darwin`.
