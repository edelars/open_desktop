# S4-10c: PDPTE.PS → гостевой #PF RSVD, 2026-11-09

Статус: реализовано и проверено локально; ревью не проводилось, в плане не отмечено.
S4-10, S4-10b-полный и S4-33 остаются открытыми.

## Что сделано

- `crates/od-machine/src/page_walk.rs`: в `probe_long64_4k` и в tracked walker
  (`walk_long64_4k_with_writer`, общий для `access_long64_4k_ram`,
  `access_long64_2m_ram`, `step_paged_mov*`) present PDPTE с PS (bit 7) = 1 теперь
  добавляет bit 7 в `offending` (как PML4E bit 7 из S4-10a) и даёт
  `PageFaultReason::ReservedBits { level: Pdpt, .. }` с PFEC P|RSVD вместо
  `UnsupportedPageSize`. Ветка `UnsupportedPageSize` осталась только для PDE PS=1
  в 4 KiB API (в 2 MiB профиле PDE PS=1 — leaf, S4-10b). PT bit 7 и PML4 bit 7 не
  менялись.
- Остальные потребители (`paged_exception_delivery`, `translation_probe_cache`,
  CPU-адаптеры) изменений не потребовали: `ReservedBits` у них уже обрабатывается
  (A последней entry не ставится), а их тесты `UnsupportedPageSize` относятся к PDE.

## Значения (источник, не код)

PFEC для PDPTE.PS=1, supervisor / user: read `0x09` / `0x0d`; write `0x0b` / `0x0f`;
fetch при NXE=1 `0x19` / `0x1d`; fetch при NXE=0 `0x09` / `0x0d`. Биты: P=bit0
(всегда 1), W/R=bit1, U/S=bit2, RSVD=bit3 (всегда 1), I/D=bit4 только при NXE=1.
Источник: Intel SDM vol. 3, «Page-Fault Error Code» и принятое правило S4-10a для
PML4 bit 7 (тот же reserved-bit путь). CR2 = линейный адрес доступа, saved RIP =
RIP инструкции. A: ставится на PML4E (предок, пройденный успешно), на PDPTE не
ставится (reserved-проверка раньше A-записи), D нигде; walk останавливается на
PDPTE (trace из двух entries), PDPTE не меняется, операнд не трогается, retirement
нет. Совпадает с принятой моделью PML4 bit 7 и с планом.

## Инъекция

Временный возврат к S4-10a (PDPT PS → `UnsupportedPageSize` в tracked walker и в
pure probe), затем откат. Результат: 8 lib-тестов `page_walk` падают (7 переписанных
плюс новый `s4_10c_*`), оба `s4_10c_*` теста `paged_mov_step` падают с
`UnsupportedPageSize { level: Pdpt, .. }` вместо `Fault(#PF, 0x19 / 0x09)`. После
отката всё зелёное.

## Не проверено

TLB-on и JIT; 1 GiB позитивный путь (не объявлен); MMIO; запись через такую PDPTE
как отдельный случай (запись как доступ проверена, но до D-бита/операнда дело не
доходит); cross-page; delivery такого #PF в guest handler (на собственном ядре
кейс huge pages S4-33 — отдельно); физическое оборудование (не oracle: Intel SDM
по тексту, не сверка с CPU).

## Открытое

- Приоритет reserved-бита PDPTE.PS относительно других reserved-битов той же entry
  не заявляется (все в одном `offending_bits`); одновременное PS+NX при NXE=0 и PS+
  физические reserved дают один fault с объединённой маской.
- CPUID `DiagnosticV1` на лист 0x8000_0001 возвращает нули: `Page1GB = 0`. При Page1GB=0
  PDPTE.PS по Intel SDM — reserved, и реальный CPU с таким CPUID дал бы тот же RSVD
  `#PF`. На CPU с Page1GB=1 тот же бит — валидная 1 GiB страница; эта модель её не
  объявляет. Негативный кейс 1 GiB для S4-33 — отдельный срез.
- Тест-бинарники `paged_pio_u8_step` и `stage4_cpl3_syscall_probe` в этой среде не
  завершились за отведённое время (процесс висит с нулевым CPU; известное
  зависание полного `cargo test -p od-machine`); они не используют PDPT PS и в
  проверки не включены, `stage4_stack_probe`, `stage4_store_load_probe` и остальные
  stage4-бинарники не запускались.
