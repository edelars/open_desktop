# S4-11e — CPU-connected cross-page word read

## Scope

Adds an independent opt-in `PagedMovCrossPageWordReadLong64V1` profile for the
exact `66 8B 03` (`MOV AX,[RBX]`) form. It uses one vCPU, Long64,
canonical48/physical36/four-level/4 KiB uncached paging, CPL0 or CPL3, and
requires `RFLAGS.AC=0`. The instruction bytes reside on one code page. The
operand is either within one RAM page or begins at offset `0xfff` and spans two
non-contiguous RAM pages. This does not expand the existing qword/dword profiles.

## Results

- Same-page and crossing RAM reads succeed; AX receives the low word, upper
  RAX bits and unrelated CPU state are preserved, RIP advances by three and
  the instruction retires once.
- Both translation/permission walks and RAM admission precede operand reads.
  Second-page faults for CPL0 non-present and CPL3 supervisor-only mappings
  report the second byte's linear address and exact PFEC, preserve CPU/buffer
  state and retirement, retain prior A updates and do not set D.
- RAM holes and MMIO are rejected without device dispatch, including same-page
  MMIO. Alias behavior follows walk-then-sample. Unsupported encodings,
  CPL1/CPL2 and AC=1 are rejected by the bounded profile.
- No general split access, cross-page store, exception delivery/CR2, restart,
  REP/RMW, JIT/TLB, or Linux support is claimed.
