# S3-20fv: address32 RCX-base Dword load singleton `67 8B 01`

## Planned scope

This slice is planned for exactly three bytes, `67 8B 01`:
`MOV EAX,[ECX]`, with `67` as the only prefix, Dword data size, Dword address
size, RCX as the addr32 alias base, and no index or displacement. The effective
address is the zero-extended low 32 bits of the original RCX. High RCX bits do
not participate in the address, but full RCX remains unchanged after execution.

Execution should perform one contiguous checked four-byte read. The loaded
value zero-extends into full RAX; other GPRs, RFLAGS, and RAM remain unchanged;
the successful next RIP is `A+3`. The starting address is 32-bit, but bytes
after `0xffffffff` continue above 4 GiB without bytewise wrap. Existing
guest/backend faults, entry guards, retries, and callback STOP without replay
remain required. RCX disp8/disp32, SIB, other bases or destinations, and extra
prefixes are outside the slice.

## Proposed identities and acceptance coverage

Proposed Rust test identities:

- JIT: `memory_load_v2::tests::ir_dword_addr32_rcx_base_load_binds_exact_source_and_site`
- Host: `tests::s3_20fv_addr32_rcx_base_dword_load_uses_zero_extended_ecx`

Proposed harness identities:

- `s3_34dg_ir_addr32_rcx_base_dword_load_source_binding`
- `s3_34dg_host_addr32_rcx_base_dword_load_zero_extended_ecx`
- Fail-closed self-test: `test_s3_34dg_addr32_rcx_base_dword_load_gates_are_pinned_and_fail_closed`

The JIT fixture should pin the exact source bytes, address and operand widths,
RCX base, no index, scale one, zero displacement, and the `A+3` PC-map boundary.
It should reject forged metadata and preserve distinct source/site bindings for
the supported full-width `[8B,01]`, addr32 `[67,8B,00]`, and `[67,8B,03]` forms.
The existing `[67,8B,01]` compile-negative in the RCX singleton fixture should
become a successful compilation with bidirectional source/site mismatch checks
against `[8B,01]`.

The host fixture should use equal low32 RCX values with different high32 values,
including noncanonical full64 values, and a full64 decoy address with distinct
memory contents. It should cover zero and unaligned EAs, starts `FFFFFFFD`,
`FFFFFFFE`, and `FFFFFFFF` with contiguous reads across 4 GiB, payloads
`0`, `80000000`, and `FFFFFFFF`, full RCX preservation, and RAX zero-extension.
Guest/backend faults and each entry guard should preserve state and permit a
successful retry; callback STOP should not replay a committed read. Fetch
errors, compiled-block/`.site()` lifetime, and MAP_JIT publication ownership
must retain the existing contracts.

The exact form must be admitted through the compiler metadata whitelist, a
separate `CheckedDwordLoad` literal-byte gate, narrow decoded block and typed IR
addr32 RCX profiles, runtime site/source matching, and the existing host
publisher. RCX should not be added to the shared RAX or RBX addr32 profiles.
Unsupported neighbors include `67 8B 41 ib`, `67 8B 81 id`, repeated `67`,
REX, operand-size, segment and LOCK prefixes, another destination/base, and
indexed SIB.

Implementation, actual identity verification, and independent reviews are
pending. Expected harness totals are 292 Rust gates (282 acceptance plus 10
lifecycle), 310 local steps, and 130 self-test names, from a baseline of 290,
308, and 129. These are manifest targets, not execution results.
