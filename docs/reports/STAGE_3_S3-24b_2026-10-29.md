# S3-24b — bounded V3 tail-immediate invalidation

## Scope

This partial fixture slice permits one previously rejected case in the exact
23-byte V3 artifact:

```text
48 BA imm64       MOV RDX, imm64
48 89 03          MOV [RBX], RAX
48 B9 imm64       MOV RCX, imm64
```

The checked qword store may replace only the final instruction's immediate at
artifact byte offsets `[15,23)`. The active source lease is checked across the
complete 23-byte region before generated entry. The write plan must resolve to
the same backing identity and exact backing offset as that immediate, in one
segment. Tail opcode writes, shifted/partial qwords, store-instruction overlap,
and split-mapping targets remain rejected.

After all source, opcode, identity, and destination checks pass, the owner marks
the staged write plan dirty. A successful store commits once and the V3 entry
returns `CodeInvalidated` with RIP `entry+13`, two retired instructions, and one
instruction remaining from budget 3. After native return and result decoding,
the owner advances the backing version and notifies the cache while the typed
V3 handle is live. A fresh dispatch reads the new immediate; the stale native
tail cannot execute.

## Coverage

- Direct destination `entry+15` and same-backing guest alias `0x500f` both
  update the tail immediate and match an interpreter checkpoint over complete
  CPU state, backing bytes, generation, and write count.
- Four warmed entries (prefix and tail through direct and alias mappings) are
  invalidated by one `BackingContentChanged` notification. An unrelated
  backing entry remains resident and reuses its cached artifact.
- Direct and alias redispatch execute the new immediate. A captured native
  result from the old immediate is rejected by the tail-result comparator.
- STOP raised during a successful store does not suppress the dirty exit.
- Stale mutation of any byte in the complete source lease, writes into the
  executing store instruction, the tail opcode, qwords shifted by either one
  byte, and a same-backing target split across adjacent mappings are rejected.
- Backend failure and injected architectural write fault preserve the
  committed prefix but do not mutate bytes, advance the backing generation,
  increment the write count, or emit invalidation.

This proves only fixture-level backing identity, invalidation, and redispatch
for one exact tail immediate. It is not a physical Intel/AMD self-modifying
code oracle. General code rewriting, production MMU/writer integration,
arbitrary spans, SMP, and complete S3-24 remain open. Mini, performance,
Stage 2, and owner-backed checks were not run.
