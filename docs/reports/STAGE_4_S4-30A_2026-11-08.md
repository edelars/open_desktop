# Stage 4 S4-30a — PCI ECAM window и type-0 function model

Статус: ограниченный срез реализован, проверен и принят после ревью (Claude Opus, high; два раунда, замечания исправлены — см. раздел «Ревью»). Родительский S4-30 остаётся открытым.

## Что сделано

Модуль `crates/od-machine/src/pci_ecam.rs`: `PciEcam` (реализует `BusDevice`), `decode_ecam_offset`, трейт `PciFunction`, `Type0Config` (type-0 header, один 32-bit memory BAR0). Тестовый endpoint (диагностический Vendor `0xD1A6`, Device `0x0001`, class `0xFF0000`, BAR0 4 KiB) существует только в `#[cfg(test)]` и платой не объявляется.

## Адреса

ECAM: `[0xFC10_0000, 0xFC20_0000)`, сегмент 0, bus 0..0, 1 MiB. Не пересекает регистры дисплея `[0xFC00_0000, 0xFC00_1000)` и NVMe `[0xFC00_1000, 0xFC00_3000)` (проверяется `const`-assert на константах `DISPLAY_REGISTERS_*` и `NVME_MMIO_*`), верхняя граница `0xFEC0_0000` — из `FIRMWARE_BOOT.md`.

## Правила

- Ширины 1/2/4, выровненные; qword → `UnsupportedWidth`, невыровненный → `Misaligned`, bus вне диапазона → `UnknownOffset`. Ошибки возвращаются до любого изменения состояния.
- Absent: чтение — все единицы, запись игнорируется.
- Регистрировать можно только функцию 0 (`add_function` с fn ≠ 0 → `InvalidSlot`): type-0 header не задаёт multi-function bit, поэтому функции 1..7 не моделируются.
- Class code — 24 бита; большее значение → `Type0ConfigError::InvalidClassCode`.
- Command RW только биты 0..2; Status, BAR1..5, 0x100–0xFFF — RO 0. BAR sizing по маске `!(size-1) & 0xFFFF_FFF0`, биты 0..3 RO 0.
- Полный контракт: `docs/specs/MACHINE_CONTRACT.md`, раздел «PCI ECAM window and type-0 function model (S4-30a)».
