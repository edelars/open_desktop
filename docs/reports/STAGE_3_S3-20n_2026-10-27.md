# S3-20n — no-displacement SIB MOV in shared IR and bounded dispatch

## Scope

This slice adds the exact four-byte singleton forms `48 8B/89 /r sib` with
ModRM `mod=00,r/m=100`. Data, base and index encodings are RAX..RBX; operand
and address sizes are qword; scale is 1/2/4/8. SIB no-index/no-base forms,
RSP/RBP/R8+, displacement, address override, other prefixes, and trailing
bytes remain outside this shared-IR/dispatcher profile. The direct-base
disp8 instruction with the same four-byte length remains distinguished by
ModRM `mod=01`.

The decoded `MemoryOperand` remains the only effective-address semantics.
Raw bytes are checked against decoded operation, length, register, base, index,
and scale; the compiler and emitter add no SIB address arithmetic. Pair
sequences and the private synchronous ordinary-RAM caller contract are
unchanged. This remains a bounded borrowed fixture, not an `od-machine` owner
integration or a performance claim.

## Evidence

- `od-jit` compiles both directions for every data/base/index combination and
  each scale, and verifies that shared IR and direct V2 artifacts retain the
  same decoded site and exact four-byte source identity. Invalid/truncated
  SIB, no-index/no-base, RSP/RBP, extension bits, displacement, address
  override and tail bytes are rejected.
- Native direct V2 and shared IR are compared against the interpreter for all
  operations, register combinations and scales. The matrix includes data/base
  and data/index aliases, base/index aliases, and a zero-valued index. A
  scale-8 case uses index `0x2000_0000_0000_0001` and base `u64::MAX - 7`;
  multiplication wraps to 8 and addition wraps to address 0.
- SIB-derived shared-IR loads fault before commit for noncanonical start
  `0x0000_8000_0000_0000` and qword end crossing from
  `0x0000_7fff_ffff_fffc`; state remains unchanged and no data callback runs.
  SIB stores additionally check exact architectural #PF payload
  `(vector=14,error_code=2,linear_address=16)`, unchanged CPU/RAM, budget 2,
  zero retirement, and one failed write callback. A backend write failure is
  a host error with no CPU/RAM commit. A successful SIB store callback commits
  bytes, raises STOP, and returns at `entry + 4` with retirement 1 and
  remaining budget 1.
- Bounded dispatch composes SIB singleton → bare NOP interpreter fallback →
  existing pair at budgets 0..4, with full CPU/RAM parity and exact total
  accounting. It stops at the actual RIP after the singleton when STOP is
  requested before NOP, then resumes correctly after clearing STOP without
  repeating the load. Partial windows ending before the SIB byte classify as
  `BoundaryReached` without
  retirement or data callbacks.
