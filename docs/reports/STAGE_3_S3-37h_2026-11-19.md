# S3-37h. Active-code V3 store, invalidation and redispatch

The test driver measures the exact S3-24b future-tail case on the
tracked owner fixture. The 23-byte artifact executes
`MOV RDX,imm64; MOV [RBX],RAX; MOV RCX,imm64`. Each epoch changes the
pending tail immediate, alternating between two distinct 64-bit values.
In the direct profile the destination is `0x100f`. In the alias profile
it is `0x500f`, which exposes the same backing offset. The two tail
addresses, `0x100d` and `0x500d`, start cached. One unrelated block
remains resident throughout.

Each epoch compares full CPU state, backing bytes and versions with
the bounded interpreter fixture. The active call retires prefix and
store, returns `CodeInvalidated` at the tail, and preserves one unit
of budget. The single committed store produces one backing notification.
Its callback removes both stale tail entries. The old active handle
then rejects re-entry with `ActiveSourceMismatch`, leaving CPU state
and write attempts unchanged. Dropping that handle releases its slot.
The new direct and alias calls both retire exactly one instruction and
observe the changed immediate. Their next calls hit. An untimed
unrelated hit checks that another backing survives.

| Interval | Timed operation |
| --- | --- |
| Build and publish V3 | Compile the current 23-byte artifact and publish its typed handle. |
| Active write and notification | Execute the native prefix and store, return through the owner, and invalidate the two cached tails in the notification callback. |
| First tail pair | Resolve the source bytes, decode, admit, compile, publish and execute the updated tail at both addresses. |
| Warm tail pair | The same tracked dispatch helper at both addresses with resident entries. |

The oracle, state reset, stale handle probe, old active handle drop,
result validation and unrelated hit are outside the timed intervals.
The two tail intervals include the tracked helper's source lookup,
decode, admission, dependency construction and source/RIP assertions.
The active-write interval includes the notification callback and its
assertion. The interpreter supplies the correctness references.

## Results

The pilot used four batches of 4,096 epochs per destination and sized a
common count of 65,670 epochs from the fastest observed interval, with
a 30 ms target. Four rounds ran both profiles in separate, sequential
processes, reversing the order in rounds two and four. Each process
kept one arena for eight scored samples. The 64 samples completed
4,202,880 epochs. All 256 operation interval totals reached the 15 ms
floor. The smallest totaled 28.653 ms.

Times are microseconds per epoch, with the median and full range of 32
samples per profile. The last two dispatch intervals cover both addresses.

| Interval | Direct store | Aliased store |
| --- | ---: | ---: |
| Build and publish V3 | 1.572 [1.546, 1.671] | 1.571 [1.542, 1.635] |
| Active write and notification | 0.454 [0.436, 0.466] | 0.459 [0.446, 0.490] |
| First tail pair | 5.499 [5.393, 5.669] | 5.538 [5.422, 5.747] |
| Warm tail pair | 1.380 [1.356, 1.434] | 1.384 [1.356, 1.418] |

The ranges for direct and alias writes overlap in all four intervals.
The median per-sample first-tail/warm-tail ratios were 3.986
[3.890, 4.021] and 4.004 [3.906, 4.069]. The first-tail interval
includes preparation and native execution of both entries as well as
compilation and publication.

The four-slot arena has one free slot before building the active
artifact. During one epoch, publication consumes that slot, the
notification returns two slots, dropping the old active handle returns
a third, and the new tail pair consumes two slots. Clearing the cache
at the end leaves four slots available. The 16,384-byte arena remains
reserved while the backend lives.

Resident tail-cache accounting includes the unrelated block. Code
bytes and logical metadata go from 1,848 and 4,734 to 616 and 1,578
after each notification. Every redispatch restores the starting
values. The old V3 artifact uses its own arena slot outside those
cache totals. Scored epochs performed 4,202,880 committed stores and
the same number of stale-handle rejections. They included 8,405,760
tail cache publications and 4,202,880 separate active-artifact
publications, with zero capacity evictions. Each epoch records two
timed warm hits plus the untimed unrelated hit.

The measurements cover the existing exact future-tail fixture. The
process-wide RSS snapshots and duration-based stress results are
recorded separately in S3-37b/d. General active-code shapes, production
owner/MMU and the wider resource matrix remain open. Physical x86 and
Mac mini checks are deferred.

## Reproduction and evidence

The host used Apple M3 Max with 14 cores, 36 GB RAM, macOS 26.7.1
(25G241) and rustc 1.99.0. The build script extracts `626e582` into a
separate source tree. It adds the archived test driver and a test-only
include to access the existing tracked fixture. It compiles the
`od-host --lib` test binary in the release profile, then signs a copy
with ad-hoc Hardened Runtime and the smoke JIT entitlement. The runner
invokes one exact ignored benchmark test and verifies its result.

Extract the archive's `files` into a scratch directory and run
`audit.py` with Python to replay the statistics. For fresh scores copy
the scripts and `active_code_bench.rs` to a separate empty scratch
directory. From the Git repository root, run that directory's
`build.sh` with `zsh` and revision `626e582`, then run `run.py` and
`audit.py` with Python. The archive records the base and injected source
hashes, signed executable identity, both pilot logs and all eight scored
process logs. Its SHA-256 is
`8b38054ee9a20645e4d9cb7cdbc068608e27478498774b1e64dc436c71f28fe2`.
