# S4-16e: retired INVLPG resets inactive aliases after remap

**Status:** accepted after independent code and documentation review. Parent
S4-16 and Stage 4 remain open.

## Scope

One vCPU, fixed Long64 paging snapshot, one physical code page, two virtual
aliases, and inactive native blocks. This slice executes one bounded
`INVLPG [RBX]` through the tracked RAM fetch adapter. It connects a retired
canonical guest invalidation effect to the host session's idle cache and
admission state; it does not implement a production TLB.

## Implementation

- `od-machine::step_paged_invlpg` calls the existing exact
  `od-isa::step_invlpg` profile with RAM-only tracked fetch. It preserves the
  exact invalidated address/effect, committed A/D callbacks, page fault, and
  tracked walker error.
- `PagedCodeSession::execute_invlpg` validates the captured paging controls and
  reconciles committed fetch writes before returning. Instruction faults and
  ISA rejections are carried in `Ok(result).step.cpu.exit`; tracked fetch
  backend failures are carried in `Ok(result).step.access_error`. The `Err`
  path is reserved for adapter/session configuration errors. Exactly one
  retired canonical invalidation clears both idle alias entries and releases
  the fixed backing, code range, and alias binding.
- Any canonical retired effect conservatively resets both entries. A remap
  write alone, noncanonical retirement, rejected input, or instruction fault
  does not reset the admission binding. The guest still executes a separate
  INVLPG for each virtual alias.

## Evidence

The host fixture warms both aliases and confirms they execute the old
immediate. A separate INVLPG fetch commits an A-bit write into the warmed code
page and then receives #PF; both idle cache entries are cleared before the
error while the old backing, code range, and alias binding remain intact. The
fixture remaps the leaf PTE using `write_physical_ram`; the new backing is
rejected while the old binding remains. It then executes INVLPG for each
virtual alias. Fresh admission uses a different alias, code offset, and range
length, and executes the new immediate with exact retirement/RIP results.
Noncanonical retirement and rejected input preserve the warmed cache. Machine
tests cover successful fetch callbacks, noncanonical retirement,
reject-before-fetch, CPL3 #GP after fetch, and fetch #PF after committed A/D
effects.

Independent code review found no semantic defect in the execution path. Its
requests for host-level coverage of A/D writes before fetch faults and public
remap writes plus a changed alias/range after reset are addressed by the cases
above. Independent documentation reviews passed after clarifying the result
channels in the plan, machine contract, JIT contract, and report.

## Limitations

The session reset is bounded cache/admission handling after an architectural
invalidation effect, not production TLB behavior. Cross-page code, general
writers, MMIO/DMA, SMP, and active-block retirement remain outside this slice.
No performance measurements or speed claim are made.
