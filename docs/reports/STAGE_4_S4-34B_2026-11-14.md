# Stage 4 S4-34b — KVM identity and repeatability

Status: S4-34b was accepted after independent `gpt-6.1-sol/high` review and
merged to `main` in `1203ba7`. The S4-34 parent remains open. The method covers
three existing KVM fixtures only;
it does not establish page walks, fault delivery, descriptors, interrupts,
bare-metal execution, or Linux boot behavior.

## Implementation

- `tools/kvm-runner/kvm_runner.c` emits the complete CPUID entry list passed to
  `KVM_SET_CPUID2` from `KVM_GET_SUPPORTED_CPUID`. It also captures the host
  `microcode` field from `/proc/cpuinfo`.
- `tools/build/build_stage4_kvm_method.py` supports 1–100 invocations per case
  (default 3), records each result separately, hashes the raw CPUID model, and
  rejects malformed CPU identity, unstable outcomes, injection trace/UART
  mismatches, runner source/binary changes, or image hash changes. CPUID rows
  must have exactly seven required fields, all integer (not boolean) uint32
  values, include leaves 0 and 1, and number 2–256. Each attempt retains its
  complete raw CPUID model, raw hash, and normalized identity hash.
- Repeat comparison masks only the documented per-logical-processor APIC ID
  fields: CPUID leaf 1 EBX[31:24] and leaf 0xB EDX. Intel documents leaf 1's
  initial APIC ID and leaf 0xB's x2APIC ID as processor identifiers, which can
  differ when the runner is scheduled on another logical processor. All other
  CPUID fields remain in the normalized hash and must match exactly. See the
  [Intel SDM](https://cdrdv2-public.intel.com/874240/325462-090-sdm-vol-1-2abcd-3abcd-4.pdf)
  and the [Linux KVM API](https://www.kernel.org/doc/html/latest/virt/kvm/api.html).
- Scheduling counts (`run_count`, `intr_count`) are retained per invocation
  and are not compared for equality; exit, stop reason, UART, entry state and
  exit sequence must remain stable. Each injection has its own exact expected
  OUT/HLT trace; OUT bytes must agree with UART hex and decoded text. Runner
  source SHA-256 must match before compile; compiled runner and image SHA-256
  are checked before and after every KVM invocation.

## Limits and next step

This verifies repeatability within one KVM host session, not across host
reboots. It does not establish bare-metal behavior. S4-34b is accepted after
independent review. S4-34 still requires separate architectural KVM cases for page walks,
rights/A-D/CR2 and error codes, CR transitions, descriptors, delivery/return,
and the interrupt path.
