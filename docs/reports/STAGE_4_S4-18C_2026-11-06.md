# S4-18c: target descriptor Accessed update during paged #PF delivery

**Status:** implemented and independently reviewed; S4-18c accepted. S4-18,
S4-19, and Stage 4 remain open.

## Scope and behavior

The existing Long64/CPL0/same-CPL/IST=0 page-fault delivery path now accepts a
valid GDT target code descriptor with A=0. It performs the six tracked frame
qword stores, sets only bit 0 of the descriptor access byte through a tracked
one-byte RAM write, then commits CS cache, RSP, RIP and live flags. A=1 targets
do not trigger a descriptor write. The handler executes the profiled first
`MOV RAX,[RBX]` and observes the original sentinel.

The frame → descriptor write → handler-state commit sequence is an explicit
partial-effects choice for this bounded emulator profile. Intel SDM Vol. 1
§6.14.1 describes the same-CPL frame and target CS:EIP operations, while Vol.
3A §3.4.5 describes setting the descriptor Accessed bit when loading a
selector. Those sections do not establish this exact fault-visible ordering
under competing faults. Sources: [Intel SDM Vol. 1, version 090](https://cdrdv2-public.intel.com/874241/253665-090-sdm-vol-1.pdf),
[Intel SDM Vol. 3](https://cdrdv2-public.intel.com/782157/325384-sdm-vol-3abcd.pdf).

The adapter permits the existing explicit qword faulting store, aligned
implicit-stack qword stores, and only the descriptor-table byte write. Before
frame stores, a pure preflight checks all planned qword translations and
possible page-walker A/D write ranges. It checks frame operand ranges against
the target descriptor byte, GDT walk entries, and page-table entries used by
reachable stack slots. It checks stack-walk A/D writes against the descriptor
byte and GDT walk entries. It rejects direct aliases, frames that
would overwrite or redirect a GDT PTE, and earlier frame writes that would
remap later stack slots. It preserves the preflighted descriptor physical
mapping. Preflight stops at the first stack failure so an unreachable later
alias cannot replace its PF/backend result. Alias refusal has no frame write
effects and is a terminal backend/profile result, not a guest page fault.

If the descriptor A-bit write itself faults while delivering the original
`#PF`, architectural handling requires `#DF`. `#DF` and shutdown classification
are not implemented in this slice, so the result remains terminal and
undelivered. The retained state is diagnostic only, not resumable.

## Verification

- `cargo test -p od-isa --lib interrupt::tests:: --offline -- --test-threads=1` — 24 passed.
- `cargo test -p od-machine --lib paged_exception_delivery::tests --offline -- --test-threads=1` — 2 passed.
- `cargo test -p od-host --test stage4_exception_delivery --offline -- --test-threads=1` — 17 passed.
- `cargo fmt --all -- --check` — passed.
- `cargo check --workspace --all-targets --offline` — passed with existing `od-jit` and `od-host` warnings.
- `git diff --check` and local Markdown/JSON checks — passed after the final code changes.

The integration cases cover guest-loaded LIDT/LGDT with A=0, exact frame and
ordered writes, GDT PTE Accessed and Dirty effects, one-byte update, and handler
load. Negative cases cover A=1 on read-only GDT, invalid A=0 target, read-only
A=0 update fault with CR2/PFEC and retained frame, and a distinct-linear-address
physical alias and saved-RIP rewrites of the GDT leaf PTE to read-only and
redirected RAM mappings, an earlier slot that would remap a later frame slot,
and first-failure cases for a missing stack page, a read-only direct-linear
alias, and a physical RAM hole. All 17 system cases pass. This evidence is local to the project
implementation; it is not physical hardware acceptance or complete exception
recovery.

## Review and Graphify

- Architecture review: `gpt-6-astra/high` classified the chosen store order as
  an explicit emulator contract, not a guaranteed Intel fault-visible order;
  it also required preserving the `#DF` and nonrestartability caveats.
- Independent code review: gpt-6.1-sol/high found the linear-alias ordering
  issues and confirmed the fixes. Final review found no remaining code issues;
  both P3 documentation findings were corrected and confirmed closed.
- Full `graphify update .` remains unavailable because its Python 3.15
  `pathlib` scan stalls. The changed Rust, test, Markdown and JSON files were
  refreshed with Graphify's AST extractor and merged, then
  `graphify cluster-only .` completed. A graph query resolves the descriptor
  preflight, stack aliases and delivery symbols. The refreshed graph has
  27,436 nodes, 68,165 edges and 1,070 communities.
