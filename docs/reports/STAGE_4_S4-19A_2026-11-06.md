# S4-19a: architectural CR2 state

**Status:** accepted after independent code and documentation review. S4-19 and
Stage 4 remain open.

## Scope

Added optional `cr2` to `LongModeState`. Existing profiles initialize it as
`None`; state cloning preserves a populated value. The fragment adapter and the
testkit `IntegerState` snapshot reject a populated CR2 because those contracts
do not represent it. The v2 restore path initializes CR2 to `None`.

Compiler diagnostics identified 89 full struct initializers without update
syntax. They now explicitly initialize `cr2: None`; initializers that use
`..LongModeState::default()` continue to inherit the default unchanged.

## Limits

This foundation does not yet populate CR2 when a page fault occurs, expose a
`MOV CR2` instruction, or deliver/recover from guest exceptions. Page-fault
delivery and recovery are covered by S4-19b and later S4-19 work; `MOV CR2` is
not currently part of the Stage 4 plan. No page-fault delivery or recovery claim
is made here.
