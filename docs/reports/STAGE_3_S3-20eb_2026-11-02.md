# S3-20eb — exact RSP-based dword checked-memory load with signed disp8

**Status:** bounded implementation slice; S3-20 and Stage 3 remain open.

Runtime commit `d2ccbaa`, with the test-only coverage follow-up `43f9e58`,
admits only the exact four-byte singleton `8B 44 24 ib`
(`MOV EAX,[RSP+disp8]`) in the shared typed-IR Dword-load path. This is an
address64 SIB operand with full-width RSP base, no index, scale 1, and signed
disp8. The decoder-owned operand computes full-width RSP plus signed
displacement with wrapping u64 arithmetic. Successful loads read one
contiguous four-byte value, zero-extend it into RAX through EAX, and advance
guest RIP to `A+4`. The JIT fixture binds all 256 signed disp8 source-byte
values to their exact sites; this is not a separate PC-map phase claim.

The host fixture compares native execution with the interpreter. It checks
both displacement signs, including disp8 `-1` with RSP `0x1001` reaching EA
`0x1000`; the `+1` case is also covered. RSP `u64::MAX` plus `+1` wraps the
starting address to zero and reads four contiguous bytes. Each successful
case issues exactly one width-four read. Noncanonical RSP start and range-end
faults produce `#SS`, with the RBX-base `#GP` profile as a control. A
width-four range overflow at `u64::MAX - 1` and an injected read error leave
architectural state uncommitted; overflow makes no data callback. Budget and
STOP guards do not read. Callback STOP after a successful read leaves the
load and `A+4` commit visible. Retrying the same published block with
committed guest RIP `A+4` returns
`EntryRipMismatch { expected: A, actual: A+4 }`, preserves state, and does not
perform a second read.
