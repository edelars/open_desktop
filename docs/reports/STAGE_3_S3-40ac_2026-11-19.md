# S3-40ac STEP entry checks on M1 Pro

This diagnostic times pairs of predecoded STEP calls for `d24865d` and
`5275d67` on the same 2,400 S3-34a inputs. The original-pair arm retains
the exact S3-40ab source. The current build adds one out-of-line STEP
function with a selector for its predecode entry checks. The function
shares profile setup, the decoder callback and postdecode processing
between guards-enabled and guards-bypassed. Both historical selector arms
use the same historical STEP as an A/A control.
[Previous shared STEP measurements](STAGE_3_S3-40ab_2026-11-19.md)

Disassembly verified that the two current selector paths converge on the
same decoder call in the timed and fetch-recording memory instantiations.
The untimed checks matched CPU state, RIP, defined flags, RAM and exact
ordered data accesses with context after the first instruction and after
the full pair. All steps returned `Advanced`, and the single-step
prefixes and full pairs recorded zero FETCH on every input and arm.
The timed path uses the same fixture memory and checks outcomes outside
the intervals.
The flag-controlled bypass exists in the scratch benchmark only.

Six paired rounds alternated build and sequence order. Each process
covered all six variant permutations for each sequence. The two pilots
selected 812,400 and 813,600 calls per interval, respectively. The series
retained 432 intervals and 351,216,000 calls. The shortest interval was
80.281 ms, above the 45 ms floor.

Bypassing the selected entry checks changed the current pooled medians
by less than 1 ns. The current-minus-historical gap remained 167.4 ns
and 168.0 ns with the checks bypassed. The original pairs differed by
168.7 ns and 168.6 ns. The measured effect of the selected checks is small
relative to the revision gap on both sequences. The selector, decoder
callback and subsequent execution still contribute to the full paths.
The postdecode MOV path remains open for attribution.

## Environment and reproduction

MacBookPro18,3, Apple M1 Pro, eight logical CPUs, macOS 14.6.1 (23G93),
Xcode 15.4 (15F31d), Rust and Cargo 1.99.0. Standard `aarch64-apple-darwin`
CPU settings, minimum macOS 14.0 and SDK 14.5. Both release binaries
passed strict signature verification with Hardened Runtime and `allow-jit`.
The machine was on AC power. The two pilots and twelve scored processes
recorded UID 501, nice −5 and QoS `0x21`. The 24 preflight probes ranged
from 86.3% to 99.6% idle CPU. The nine scoring probes ranged from 73.5% to
87.2%, with a median of 86.9%.

Place the archived harness files under `work/tmp/s3-40-step-entry-boundary/`
in a repository with both pinned Git revisions and the S3-40m and S3-40w
input archives. Use an isolated Cargo home with the lockfile dependencies.
Build in the harness directory with the following settings.

```sh
export MACOSX_DEPLOYMENT_TARGET=14.0
unset RUSTFLAGS CARGO_ENCODED_RUSTFLAGS CARGO_BUILD_RUSTFLAGS
unset CARGO_TARGET_AARCH64_APPLE_DARWIN_RUSTFLAGS
zsh build.sh historical
zsh build.sh current
zsh check.sh
```

The archived `README.md` describes the monitored `python3 run.py run-NAME`
and packaging commands. `python3 offline_audit.py /path/to/evidence.json.gz`
reproduced the saved audit. The archive retains 84 files including the
original and compiled source bindings, untimed prefix and pair receipts,
