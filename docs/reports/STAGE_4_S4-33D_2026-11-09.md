# Stage 4 S4-33d — cross-page read и fetch на собственном ядре

Статус: ограниченный системный кейс реализован; ревью Opus проведено: срез
принимается; правки ревью учтены. Кейс не закрывает родителя S4-33 и Stage 4.

## Предусловие

Qword-путь S4-11b (`48 8B 03`) при NXE=1 сохраняет поведение. Существующие тесты
уже исполняют его при NXE=1: `paged_mov_step.rs` использует `EFER = LME|LMA|NXE`
(`0xd00`), в том числе `cross_page_qword_load_covers_all_offsets_with_two_noncontiguous_ram_pages`
(все смещения `0xff9..0xfff`); `cargo test -p od-machine --offline --test
paged_mov_step` — 37 passed. Профиль S4-32 тоже задаёт EFER `0xd00`. Дополнительно
добавлен явный тест `qword_read_keeps_its_behaviour_when_nxe_is_set_in_efer`
(лежит в `crates/od-machine/tests/stage4_cross_page_probe.rs`; `paged_mov_step.rs`
не менялся; NXE=0 и NXE=1 дают одинаковые RIP, RAX, committed writes и PTE; при NXE=0 PTE
данных без NX, потому что бит 63 при NXE=0 зарезервирован, SDM Vol. 3A §4.5).

## Что сделано

`Stage4CrossPageProbeV1` — строгий raw-image профиль (GPA `0x1000..0xe000`, 128 KiB
RAM, polling UART `0x3f8`) поверх принятых S4-11b/c/d/e/f и S4-32; семантика
примитивов и allowlist `PagedCpl0ProbeV1` не менялись.

- Страницы: code 0 GVA `0x400000` -> GPA `0x7000` (PTE `0x7001`), code 1 GVA
  `0x401000` -> GPA `0x9000` (PTE `0x9001`); data 0 GVA `0x800000` -> GPA `0xb000`
  (PTE `0xb003|NX`), data 1 GVA `0x801000` -> GPA `0xd000` (PTE `0xd003|NX`). Пары
  кадров несмежные; кадры `0x6000`, `0x8000`, `0xa000`, `0xc000` не отображены.
  Все leaf-записи supervisor, A и D сброшены.
- Данные: qword разрезан: байты 0..2 на GVA `0x800ffd..0x800fff`, байты 3..7 на
  GVA `0x801000..0x801004`. Same-page копия значения на GVA `0x800800`; decoy
  `0xa5`x8 в начале кадра `0xb000` и `0x5a`x8 в конце кадра `0xd000` (обнаруживают
  обмен кадров).
- Код: `66 8B 03` на GVA `0x400ffe` (`66 8B` в конце кадра `0x7000`, `03` в начале
  кадра `0x9000`), затем `48 8B 03` (`0x401001`), `8B 03` (`0x401004`), `66 8B 03`
  (`0x401006`), `EE` (`0x401009`), `F4` (`0x40100a`).
- Handoff (loader): CPL0 (контекст доступа), RFLAGS `2` (AC=0), CR0 `0x80010033`,
  CR3 `0x1000` явно (в `LongModeState` `None`, как в S4-32), CR4 `0x20`, EFER
  `0xd00` (NXE=1), RIP `0x400ffe`, RAX `0xdeadbeefcafebabe`, RBX `0x800ffd`, RDX
  `0x3f8`. CPL, AC и NXE выводятся в evidence отдельным блоком `handoff`.
- Sequencer из 6 шагов: `step_paged_mov_word_read_cross_page_fetch` (S4-11f) ->
  `step_paged_mov` (S4-11b) -> `step_paged_mov_dword_read` (S4-11c) ->
  `step_paged_mov_word_read` (S4-11e) -> `step_paged_pio_u8` -> quantum (`F4`,
  budget 1). Бюджет считается в шагах (runner: по умолчанию 16, максимум 1024).
- Файлы: fixture `tests/fixtures/guest/stage4/cross_page/`, builder
  `tools/build/build_stage4_cross_page_probe.py`, модуль
  `crates/od-machine/src/stage4_cross_page_probe.rs`, runner
  `--stage4-cross-page-probe`.

## Почему один RBX и порядок шагов

Профиль S4-11f отвергает word-операнд на смещении `0xfff` («профиль никогда не
режет операнд») и требует его целиком в одной странице; профиль S4-11d для `8B 03`
не заявляет cross-page операнд вместе с fetch-cross. RBX гостем не меняется (нет
разрешённой инструкции записи в RBX), поэтому операнд поставлен на `0x800ffd`: word
остаётся в data 0 (допустимо для S4-11f и S4-11e), qword и dword пересекают границу
(S4-11b, S4-11c). Первая инструкция — fetch-cross, потому что после неё ни одна
data-страница ещё не пройдена: при NX на второй кодовой странице A-биты данных
остаются сброшены, и это прямое доказательство, что operand walk не выполнялся.

## Не проверено и открыто

- Только uncached tracked walker: TLB-on не проверяется (S4-14 не принят). JIT:
  кейс `not_supported` в матрице.
- Не вошло: cross-page store, RMW, stack, REP, RAM/MMIO split; fetch-cross для
  `8B 03` (S4-11d) в кейсе не исполняется: при единственном RBX=`0x800ffd` любой
  dword пересекает границу данных, а контракт S4-11d такого операнда не покрывает
  («the dword operand lies entirely in a separate RAM page»); покрыт принятыми
  unit-тестами S4-11d;
  word-операнд на `0xfff` вместе с fetch-cross (примитив S4-11f отвергает); CPL3,
  delivery #PF и коммит CR2 (CR2 в состоянии CPU остаётся `None`, #PF-запись
  хранит значение, которое получил бы CR2); huge pages (после S4-10c).
- Шаг 4 (word `66 8B 03`) не меняет RAX: после шага 3 (dword `8B 03`, RAX
  `0x8877665544332211` -> `0x44332211`) word читает те же младшие 16 бит и оставляет
  RAX прежним. Шаг 3 RAX меняет. Шаг 4 подтверждают retirement, переход RIP
  `0x401006` -> `0x401009` и префикс бюджета 3 против 4; A-биты его не различают (все
  A к этому шагу уже стоят). Неизменный RAX не пустая проверка: он исключает zero-extend
  (дал бы `0x2211`) и чтение не того адреса или кадра. Различить шаг 4 по RAX нельзя
  (примитивы: RBX — база, RAX — приёмник, RBX не меняется, записей нет; word после
  более широкого чтения того же адреса оставляет RAX прежним при любом порядке).
  Принятое ограничение. Сохранённый sentinel на шаге 1 и RAX `0x44332211` после шага 4
  показывают, что word не обнуляет старшую часть.
- Control-прогон (`--same-page-control`) — смена RBX на same-page копию, а не
  отдельный образ; доказывает, что A на data 1 и committed write `0x5008` вызваны
  пересечением границы.
- Вопрос A-бита при отказе по правам (NX на втором code PTE ставит A на этот PTE)
  унаследован от S4-11d/f и S4-19b: SDM допускает, но не единственно возможное
  поведение; помнить для S4-34.
- Значения второй страницы различаются для двух образов (`0x4455667788` и
  `0xe5d4c3b2a1`); байты первой страницы (`112233`) совпадают специально, чтобы
  разница RAX шла только от второй страницы. UART-байт при этом одинаков (`0x11`).
- `cpl()`, `nxe()`, `efer()` в probe-модуле возвращают константы, а не состояние CPU;
  поле `cpl` по шагам тоже константа (ограничение модели). Что NXE=1 действует на деле,
  доказывают другие факты: S4-11f без NXE отказывает (тест
  `s4_11f_rejects_nxe_disabled_before_any_code_fetch`), инъекция NX даёт PFEC `0x11` с
  битом I/D.
- CR2 `0x801000` для доступа через границу страниц — выбор контракта модели, SDM
  однозначно не определяет; зафиксировать решение для S4-34.
- Loader и builder не отвергают значения, при которых инъекции становятся невидимыми:
  `0xa5a5a5a5a55a5a5a` (совпадает с decoy, обмен кадров не обнаружится) и значения с
  младшими 16 битами `0xbabe` (RAX шага 1 совпадёт с sentinel). Защита — в следующем
  срезе, сейчас не чинится.
- Список `STAGE4_CROSS_PAGE_STEP_RIPS` для runner берётся из machine-модуля (не
  дублируется); тест сверяет весь список с RIP-evidence шагов. Ручное дублирование
  адресов инструкций остаётся в builder/fixture.
- Hole: A на PTE второй страницы ставится до отказа RAM-admission (контракт S4-11b).
- Родитель S4-33 открыт.
