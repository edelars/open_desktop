# Stage 3 S3-28a: Cooperative event yield at register-dispatch boundaries

## Result

Added an invocation-local optional `AtomicBool` event request to host
`DispatchControl` and a distinct `DispatchExit::EventPending`. The event is
host-only: raw runtime exit tags and `RuntimeContextV1`/generated ABI are
unchanged. `run_cached_controlled`, `run_multi_cached_controlled`, and
`run_with_nop_fallback` check the event after stop-RIP, STOP, CodeEnd, and
budget guards, before entering the next unit. Cached dispatch checks before
cache binding and again immediately before native execution, so a request
raised during publication prevents native entry.

A request made while a bounded native block is executing is returned only
after that block's report, state, and accounting have been validated and
committed. The NOP fallback checks again before each interpreter step. The
event remains set when returned; the caller clears it and resumes at the
actual guest RIP. No runtime ABI event tag was introduced.

## Review finding and correction

The first independent review found that the pre-native-entry boundary after
publication checked only the event request. If the publication callback raised
STOP and event together, `EventPending` incorrectly took priority over
`StopRequested`. The boundary now re-runs the full stop-RIP → STOP → CodeEnd →
budget control check before sampling the event. A deterministic mock
publication hook raises STOP, event, or both; the matrix verifies STOP wins
when both are set and native execution remains zero. The event-only case still
returns `EventPending`.

## Acceptance coverage

- Pre-entry event: unchanged architectural state, budget, and retirement; no
  compile, publication, execution, or NOP fallback step. Covers single-entry
  cache, multi-entry cache capacities 1 and 2, and the published host arena.
- Event requested by the executor during a bounded block: exactly one block
  commits, no next block is entered, and the request remains set until the
  caller clears it. Covers cache miss and hit, and multi-cache capacity 1 and
  2.
- Event requested during publication: publication can complete, but native
  entry is skipped and guest state/budget remain unchanged.
- Resume after an event at a taken Jcc boundary: interpreter-computed prefix
  state is preserved, one bare NOP and the native suffix execute after clear,
  and final state/budget match uninterrupted interpreter execution without
  replaying the prefix.
- Simultaneous stop-RIP, STOP, CodeEnd, and budget priorities; terminal
  runtime exit; malformed accounting; and backend execution error.
- NOP/native transitions preserve the shared instruction budget and report
  native/interpreter retirement separately.
