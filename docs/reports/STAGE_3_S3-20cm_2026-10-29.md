# Stage 3 S3-20cm: Address64 direct RBP-base qword MOV with RSI/RDI data

## Scope

Implemented the eight singleton encodings `48 8B/89 /r disp8|disp32` with ModRM `mod=01/10`, data RSI/RDI (`reg=6|7`), and direct RBP base (`r/m=5`). The forms have lengths 4/7; `[RBP]` uses disp8 zero. `mod=00,r/m=5` stays RIP-relative. No SIB, address32, other data/base registers, pair, or V3 encoding was added to this profile.

Decoder-owned `MemoryOperand` remains the authority for signed displacement and the pre-instruction RBP value. The direct V2 and shared IR metadata/profile checks, exact source matcher, block admission, checked RSI/RDI load/store validation, and bounded dispatcher `compile_at` gate now agree on the forms. The dispatcher gate admits only ModRM `mod=01/10`, `r/m=5`, data `reg=6/7`, lengths 4/7; `mod=00,r/m=5` keeps its RIP-relative route. RSI/RDI load `WriteGpr` remains tied to the immediately preceding matching checked load; generic reads and arithmetic were not expanded. Host parity coverage extends the direct V2/shared IR/interpreter matrix to direct RBP-base disp8/disp32 and both RSI/RDI data registers. A dispatcher test covers both operations/data registers, callback STOP, partial windows, retirement, and continuation from actual RIP without replay.
