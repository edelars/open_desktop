# S4-24b: bounded CPL0 byte PIO instruction path

**Result:** accepted bounded slice after independent `gpt-6.1-sol/high` review.
The parent S4-24 and Stage 4 remain open.

## Implemented boundary

`DiagnosticCpl0PioU8V1` admits only bare Long64 `EC` (`IN AL,DX`) and `EE`
(`OUT DX,AL`), at CPL0, with CR0 and CR4 inputs both `None`. Each call executes
at most one instruction. Machine-side fetch uses flat identity RAM
(`linear == physical`) and PIO dispatch uses the existing `MachineBus` port
map.

`IN` reads one byte from `DX & 0xffff` into AL and preserves the upper 56 bits
of RAX. `OUT` writes AL to `DX & 0xffff`. Success performs exactly one PIO
callback, retires one instruction, advances RIP by one byte, and preserves
RFLAGS and `rflags_defined`. Admission, fetch, decode and PIO errors retire
nothing; CPU state and definedness remain unchanged on failure. Fetch/backend,
unsupported-instruction and PIO errors are distinct. The legacy `run` path
continues to reject these PIO instructions.

The connected COM1 model uses the existing bounded TX holding/shift stages and
the byte-wide shared THR/RBR offset `0` (THR on write, RBR on read when DLAB is
clear). RX consists of one byte injected through `Uart16550Handle`. `LSR.DR`
bit `0` is set while that byte is pending; reading RBR returns and clears the
byte and the bit. Injection while occupied returns `Busy`, while reading an
empty RBR returns `DeviceError::WriteOnly`. No FIFO or interrupt delivery is
implied.

## Verification and review

Reported implementation and independent-review results:

```text
cargo test -p od-isa --locked --offline                  # 2014 unit + 7 integration passed
cargo test -p od-machine --locked --offline              # 98 passed
cargo check -p od-isa --all-targets --locked --offline   # passed
cargo check --workspace --all-targets --locked --offline # passed
cargo fmt --all -- --check                               # passed
git diff --check                                          # passed
```

Tests cover admitted IN/OUT forms, bare-form rejection, CPL and CPU-state
admission, one callback/retirement, upper-RAX preservation, identity fetch,
unmapped-port and fetch failures, unchanged CPU state on failures, UART RBR
read-clear, `LSR.DR`, empty-RBR `DeviceError::WriteOnly`, and bounded TX.
The relevant tests are `in_al_dx_reads_one_uart_receive_byte_and_retires_once`,
`reads_do_not_advance_transmission_and_reset_discards_pending_bytes`, and
`unsupported_spaces_widths_and_register_directions_are_explicit` in the UART
and PIO integration targets. Independent `gpt-6.1-sol/high` review approved
the complete code slice with no P0–P3 findings. These are recorded
implementation and review runs; this documentation update did not rerun Rust
checks.

## Limits

This slice does not implement IOPL or TSS I/O-bitmap checks, other I/O widths,
immediate-port instructions, REP/string I/O, IRQ delivery, APIC integration,
Linux serial-driver compatibility or Linux boot. The UART is not a full
16550A model. Parent S4-24 remains open for complete device behavior,
interrupt integration and guest-visible acceptance. Stage 4 is not complete.
