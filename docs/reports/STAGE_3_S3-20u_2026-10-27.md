# S3-20u — RBP-base signed disp8 qword MOV

## Scope

This slice admits only singleton `48 8B/89 /r disp8` forms with ModRM
`mod=01,r/m=101`, RBP as the memory base, data register RAX..RBX, qword data,
64-bit effective address and exactly four source bytes. `MemoryOperand` and
`access_address_48` remain the sole displacement and effective-address
semantics. SIB, RSP, address-size override, disp32, extra/segment prefixes,
extended registers, pairs and decoder changes are excluded. This remains a
borrowed fixture API; it does not add the absent `od-machine` production RAM
owner integration.

## Evidence

- The exact IR descriptor matrix checks loads and stores for each allowed data
  register and disp8 `-128/-1/0/127`. It rejects truncated, disp32, SIB,
  address-override, extended-data and trailing forms. The old direct-profile
  negative was narrowed to keep RBP disp32 rejected while admitting only RBP
  disp8.
- Native direct V2 and shared IR are compared with the interpreter for both
  directions and all four displacement boundaries. The checks compare full
  guest state and RAM, callback address and count, retirement/budget, and verify
  that RBP/RSP are unchanged.
- RBP noncanonical start and last-byte-crossing accesses return architectural
  #SS (vector 12, error code 0, no linear address); equivalent RBX controls
  return #GP (vector 13, error code 0, no linear address). These checks make no
  data callback and preserve state, RIP, RAM, budget and retirement.
- A canonical high-half RBP access whose qword range overflows u64 returns the
  `MEMORY_ERROR_ADDRESS_OVERFLOW` host diagnostic, not synthetic #SS. A normal
  backend read failure returns `MEMORY_ERROR_BACKEND`. Entry STOP and zero
  budget make no helper call. A successful store whose callback raises STOP
  remains committed, retires once and returns at the next RIP.
- Bounded dispatch composes RBP disp8 → bare NOP interpreter bridge → existing
  pair for budgets 0..4 and compares complete state/RAM against interpreter
  stepping. A separate split run executes the RBP singleton first, then
  resumes from its returned RIP and completes NOP+pair without repeating the
  first access. The sequence preserves RBP and RSP.
