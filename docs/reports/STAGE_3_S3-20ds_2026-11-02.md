# S3-20ds — exact RBP-base dword checked-memory store with disp8

**Status:** bounded implementation slice; S3-20 and Stage 3 remain open.

Runtime commit `fc3151c` adds exactly the three-byte singleton `89 45 ib`
(`MOV [RBP+disp8],EAX`) to the shared typed-IR dword-store path. The decoded
memory operand is authoritative for full-width RBP plus signed disp8 with
wrapping. One successful helper call writes exactly four bytes from low32
RAX. Guest RIP advances to `A+3` and retirement commits after the successful
write. All 256 disp8 values bind distinct source/site identities.

The JIT test verifies exact source/site binding and the PC-map phase contract:
`HelperCall` and `AfterHelper` are `InadmissibleAfterEffect`, while
`CommitInProgress` is `InadmissibleDuringCommit`. The canonical successor
boundary `A+3` is separate and post-commit. The host fixture compares
published execution with the interpreter and checks CPU/RAM
state, write address/width/count, and retirement. RBP noncanonical-start and
four-byte range-end faults produce `#SS` without writes or commit; the
neighboring RBX-base case retains `#GP`. Address addition from
`u64::MAX + 1` wraps to zero. A checked width-four range starting at
`u64::MAX - 1` returns `AddressOverflow` before a write or architectural
commit. Architectural faults occur before a write callback; a backend-error
attempt leaves CPU state and RAM bytes uncommitted. Zero budget and entry STOP
perform no write; STOP raised from a successful write callback leaves exactly
one committed four-byte write and RIP `A+3`, while a second invocation at that
RIP is rejected without replay. The fixture uses bounded private RAM and does
not establish MMIO, SMC, owner notification, MMU integration, or hardware
behavior.
