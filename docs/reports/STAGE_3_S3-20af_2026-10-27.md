# S3-20af — RBP as qword MOV data and signed-disp32 base

## Scope and implementation

Admitted only seven-byte singleton `48 8B/89 AD id`: ModRM
`mod=10/reg=5/rm=5`, signed disp32 in bytes 3..6, qword data and 64-bit EA.
The decoded `MemoryOperand` and `access_address_48` remain the address
authority. This is an exact admission exception; generic GPR predicates,
source storage, pairs, V3, frame layout and ABI are unchanged. ModRM
`mod=00/rm=5` remains the distinct RIP-relative NextRip form.

## Evidence

- Descriptor/direct-V2/shared-IR checks admit both MOV directions at disp32
  MIN/-1/0/MAX, retain the exact seven-byte source and reject partial windows
  1..6 plus malformed SIB and prefix forms. Byte-six variants yield distinct
  decoded displacement metadata and host callbacks at independently expected
  `0x01000040`/`0x02000040` targets for initial RBP 64. Same displacement
  RBP-base and mod00/rm5 operands are passed to `access_address_48`; results
  are checked against the respective independent RBP+disp32 and NextRip+disp32
  formulas and asserted distinct.
- Host direct V2/shared IR/interpreter parity compares full CPU/RAM state,
  callback address/count and retirement for both operations and all signed
  boundaries. The effective address and store payload use entry RBP; the load
  commits its value only after successful access.
- Exact disp32 RBP noncanonical load/store accesses return #SS before the
  backend callback and preserve state, RAM, RIP, budget and retirement.
- A canonical upper-half start whose qword wraps u64 remains
  `AddressOverflow` with no callback; an unmapped store returns the host memory
  error with the exact address/length and leaves RAM/state uncommitted.
- Bounded dispatch with budget one commits a noncanonical RBP value at the
  first instruction's actual next RIP. Resuming faults #SS at the next
  RBP-relative instruction, preserves the first commit and does not repeat
  the read. The exact singleton also composes with bare NOP and the existing
  native pair across separate budgets: retirements are native 1, interpreter
  1, native 2, with one initial read and no replay. The macOS/ARM64 x19 canary
  exercises this exact disp32 profile on success, zero-budget and fault exits.
  Earlier RBP data-only/base-only, RSP data and dual-register profiles remain
  covered.
