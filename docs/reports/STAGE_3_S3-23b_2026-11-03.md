# S3-23b — MemoryPairCache invalidation between synchronous calls

**Date:** 2026-11-03. **Status:** bounded fixture slice implemented and focused
local ARM64 checks passed; independent review pending. This does not complete
S3-23 or S3-25.

## Scope and contract

`MemoryPairCache` now accepts the existing `CodeInvalidation` notifications.
Its invalidation path calls the same dependency matcher used by the
register-only single-entry and multi-entry caches. Backing content changes
match backing identity and changed version across aliases; mapping replacement
and removal use address-space/mapping identity; execute-permission changes
compare the notified permission with the dependency snapshot. A matching
inactive resident is dropped immediately and removed from lookup. An unrelated
notification preserves the resident handle. The next invocation remains
caller-owned and supplies the updated dependency snapshot.

Safe borrowing limits invalidation to the interval between completed
synchronous `MemoryPairCache::run` calls. The cache does not own or query a
guest-memory owner. The exact ARM64 `od-host` acceptance gate executes a
published two-site memory pair, invalidates after return, and republishes with
a changed backing version, fresh CPU state, and a fresh RAM fixture. The
successful republish under `od-host`'s single-live MAP_JIT rule proves the old
mapping was dropped before the new one was opened.

## Behavioral tests and harness gate

- `od-jit` tests cover all four notification variants, unrelated backing,
  backing-alias matching, immediate handle drop, and replacement using an
  updated dependency snapshot.
- The host acceptance test checks execution results from the first and fresh
  second CPU/RAM inputs, two successful publications, and an empty cache after
  notification.
- The Stage 3 harness pins the exact host test and includes a fail-closed
  self-test for gate identity, invocation, missing evidence, and failed runs.

Current pinned harness totals are 326 Rust gates (308 acceptance and 18
lifecycle), 344 local steps, 151 self-test names, and 18 local Rust source
pins. The harness self-test does not run the full Stage 3 suite.

```sh

PYTHONPATH=tests/cpu python3 -m unittest -v test_stage3_harness.Stage3HarnessValidationTests.test_s3_23_memory_pair_invalidation_gate_is_pinned_once_and_fail_closed
```

Results: 11 focused `od-jit` tests passed; the exact host gate and harness
self-test each passed 1/1. `od-jit` emitted its existing unused
`CodeMemory::one_instruction` warning; the `od-host` test build emitted two
existing test warnings (`scale` unused and `callback_stop` unnecessarily
mutable). No full crate/workspace suite, full Stage 3 harness, Mini check,
performance run, or Stage 2 check was run. Graphify refresh was not repeated:
the root task already tried it after S3-18g, and the tool refused the update
because six semantic nodes are folded together.

This is fixture-only between-call invalidation. It does not wire
`od-machine`, production MMU or writers, DMA/device paths, active SMC
retirement, or SMP reclamation. No production MMU or active-SMC completion is
claimed. See the [Stage 3 plan](../plans/STAGE_3.md#s3-23b-memory-pair-fixture-cache-invalidation)
