# S3-31b: cached NativeRegisterV1 observed-phase attribution

## Scope and method

This is a bounded phase-attribution experiment for the cached NativeRegisterV1
synthetic recurrence profile at source revision
`c2af2a3821a6c8c2e226d25ae7c391061e2ffef7`. It compares ordinary full-call
timing with the same cached dispatcher path under explicit phase observation.
The observed path includes observer begin/end work. State reset and `CodeView`
construction are outside both timed scopes.

Two fixed loop kernels (`a` and `b`) were measured at 1, 64 and 4,096
iterations, for six strata. Three release processes retained 20 alternating
ordinary/observed pairs per stratum: 60 pairs per stratum, 360 pairs overall.
Each side had the same calibrated call count within its pair and had to exceed
200 ms. No pair restarts were discarded.

The ratio is `observed elapsed_ns / ordinary elapsed_ns`. Reported medians and
ranges use the 60 stored raw paired ratios per stratum, without trimming.

All 720 measured sides passed the 200 ms floor. The paired delta is a net
difference between two complete ordinary/observed call paths, not an isolated
measurement of observer cost. In particular, the `b_64` raw ratio range
crosses parity even though its median is above 1.

## Observed-path phase breakdown

Shares are each phase's cumulative observed time divided by cumulative
observed full-call time for that stratum. Per-visit time is cumulative phase
time divided by that phase's invocation count across the same 60 samples. The
residual share is the signed unmeasured remainder divided by cumulative
observed full-call time.

| Stratum | Block build/admission: share / ns per visit | Key snapshot/lookup: share / ns per visit | Host execution boundary: share / ns per visit | Residual share |
|---|---:|---:|---:|---:|
| `a_1` | 21.02% / 174.75 ns | 42.80% / 355.77 ns | 4.42% / 36.77 ns | 31.76% |
| `a_64` | 21.76% / 175.58 ns | 44.18% / 356.53 ns | 4.53% / 36.59 ns | 29.53% |
| `a_4096` | 21.76% / 174.10 ns | 44.19% / 353.53 ns | 4.54% / 36.32 ns | 29.50% |
| `b_1` | 32.56% / 344.92 ns | 38.63% / 409.22 ns | 5.49% / 58.19 ns | 23.31% |
| `b_64` | 33.23% / 348.13 ns | 39.36% / 412.36 ns | 5.62% / 58.86 ns | 21.80% |
| `b_4096` | 33.20% / 350.06 ns | 39.40% / 415.42 ns | 5.60% / 59.01 ns | 21.81% |

Each of the three measured phases ran this many times across 60 samples in its
stratum: `a_1` 18,268,880; `a_64` 20,078,080; `a_4096` 20,070,400; `b_1`
14,823,340; `b_64` 15,352,320; and `b_4096` 15,728,640. The timed hit-only
samples had zero phase invocations for `IrLowering`, `Allocation`,
`EmissionAndFinalization` and `Publication`. Exact per-run phase counts, totals
and cache counters are in the [suite manifest](data/stage3/s3-31b-20261101/suite-manifest.json).

These are shares of the **observed path**, not production phase shares.
`KeySnapshotAndLookup` excludes repeated post-hit validation and
`matches_code_view`. `HostExecutionBoundary` includes its wrapper and result
decoding. The residual holds all work outside the named phases, including
observer hooks; it is not attributable to one component.

## Correctness, counters and resource bounds

Release preflight did not start timing. For every stratum, ordinary and
observed execution had matching full CPU state and retirement, and the phase
accounting envelope was valid. Preflight recorded a capacity-one resident
entry (one miss, compile and publication, no replacement). Each scored
ordinary and observed sample was hit-only: cache hits equalled `calls ×
iterations`, with zero misses, compiles, publications or replacements. Both
sides retired exactly `calls × guest_work_per_call` guest instructions.

Preflight resident sizes were 1,408 emitted code bytes / 7,193 logical bytes
for kernel `a`, and 2,188 emitted code bytes / 10,552 logical bytes for kernel
`b`; the sizes were constant across iteration-count strata. The only error
preflight was a code mismatch rejected before admission, with zero phase
calls. Cleanup for errors arising inside a measured phase was not tested.

## Environment and limits

- Host: Apple M3 Max, macOS 26.7.1, `aarch64-apple-darwin`.
- Build: release, `rustc 1.99.0 (b940084d7 2026-09-28)`.
- Source revision: `c2af2a3821a6c8c2e226d25ae7c391061e2ffef7`; source SHA-256:
  `7f1976afbe33a35c5ce3fb9082da4ae1234e35341223f5b38a2df8e9de0f82d0`.
- Captured build metadata has `source_tree_dirty: false`. Runtime
  `working_tree_dirty` is `null` because the runtime Git status check exceeded
  its two-second timeout; runtime cleanliness is unknown.
- Raw preflight, process reports, source fingerprints and their SHA-256 values
  are recorded in the suite manifest.

The observed/ordinary paired difference does not isolate observer cost and
does not justify a runtime or default-policy change. This covers only the two
synthetic recurrence kernels and this observer wrapper; it is not a production
phase-share estimate, a broad workload result, or Stage 3 acceptance. Mac mini
checks remain deferred until the end of Stage 3.
