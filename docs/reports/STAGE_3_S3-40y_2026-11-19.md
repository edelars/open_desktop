# S3-40y checked-memory JIT on M1 Pro

The same two S3-34a sequences ran on `d9ecaa2` and `5275d67`, which both
include exact-key cache reuse. The M1 Pro built both signed ARM64 release
executables from immutable Git exports with the same benchmark driver.
Six alternating paired process rounds compared cold JIT, warm JIT and
the interpreter. Each process used six triples per sequence. The audit
validated 432 intervals and 106,531,200 calls. The shortest interval was
60.126 ms, above the 35 ms floor. Pilots selected 248,400 calls per
interval for `store_then_load` and 244,800 for `load_then_store`.

The benchmark checks full guest state, RAM, ordered memory accesses,
retirement, budget and cache counters on the frozen 2,400 inputs. Each
cold call starts with an empty cache. Warm calls reuse the published
entry and require hits with zero new compiles or publications. The
retained entry used 4,782 logical bytes for both builds and sequences.
[S3-40v driver and corpus](STAGE_3_S3-40v_2026-11-19.md)

Every between-build raw and normalized JIT range crossed parity. On
`5275d67`, warm JIT took 0.8094 [0.7904, 0.8191] and 0.8205 [0.8104,
0.8304] of its paired interpreter time. Cold JIT took 30.6819 [29.3971,
31.8276] and 30.7262 [29.5347, 31.7374] times the paired interpreter time.
Exact-key reuse therefore still serves the two resident checked-memory
sequences on this M1 Pro. The measurements support retaining the current
path for these sequences. A broad workload decision and attribution of
the historical interpreter RUN gap remain open.

## Environment and reproduction

MacBookPro18,3, Apple M1 Pro, eight logical CPUs, macOS 14.6.1 (23G93),
Xcode 15.4 (15F31d), rustc and Cargo 1.99.0, Python 3.12.5. The target was
`aarch64-apple-darwin` with deployment target macOS 14.0 and the standard
Rust target CPU. Both executables carried Hardened Runtime and `allow-jit`.
The host was on AC power at preflight. All 14 processes, including the
two pilots, confirmed ordinary UID 501, nice −5 and QoS `0x21`. The 24
preflight probes had 64.6–90.8% CPU idle. Across 42 probes during scoring,
CPU idle ranged from 62.4% to 87.6%, with a median of 85.5%.

Extract the archived `files` and place the harness scripts under
`work/tmp/s3-40y-current-memory-jit/` in a repository containing the two
pinned revisions and the S3-40v input archive. Use an isolated Cargo home
with the lockfile dependencies and default target settings. From the
harness directory run the following build commands.

```sh
export MACOSX_DEPLOYMENT_TARGET=14.0
unset RUSTFLAGS CARGO_ENCODED_RUSTFLAGS CARGO_BUILD_RUSTFLAGS
unset CARGO_TARGET_AARCH64_APPLE_DARWIN_RUSTFLAGS
zsh build.sh baseline
zsh build.sh candidate
```

Use a fresh
`run-NAME` for `python3 run.py run-NAME` and monitor host load during the
series. `python3 offline_audit.py /path/to/evidence.json.gz` reproduced the
audit on M1 Pro and after transfer. The archive retains every scored
interval, build and launch records, and the load trace.
