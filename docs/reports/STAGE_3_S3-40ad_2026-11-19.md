# S3-40ad Final MOV dispatch on M1 Pro

This diagnostic runs predecoded STEP pairs on the same 2,400 S3-34a
inputs in `d24865d` and `5275d67`. The original-pair arm retains the
S3-40ac path. The two other arms use one shared STEP with an opaque
runtime selector immediately before the final operation dispatch.
Normal dispatch follows the original operation match. Direct MOV calls
the existing transfer helper for the exact three-byte Long64 Qword MOV
with a register and a plain base-register memory operand. The shared
STEP keeps the original entry checks, decoding callback, admission,
memory error handling, defined-flag handling and RIP commit.
[Previous STEP entry measurements](STAGE_3_S3-40ac_2026-11-19.md)

The untimed validation checks the one- and two-instruction prefixes.
It requires `Advanced` at each step, matching CPU state, RIP, defined
flags, RAM, ordered data accesses with context, and zero FETCH.
Disassembly checks cover both memory types used by timing and validation.
Each pair reaches the same STEP destination twice. The direct and
normal MOV call sites use the same transfer symbol for each memory
type.

The two pilots selected 679 sweeps, or 814,800 calls per interval, for
each sequence. Six matched rounds alternated build and sequence order.
Each process covered all six arm permutations for each sequence. The
series retained 432 intervals and 351,993,600 calls. The shortest
interval was 79.942 ms, above the 45 ms floor.

The current direct MOV path had median ratios of 1.0080 and 1.0147
against normal dispatch. The first sequence's range crossed 1.0.
The direct path retained a current-minus-historical gap of 170.3 ns
for store then load and 170.7 ns for load then store. These timings
cover the full paths, including the direct route's selector and
eligibility predicate. Earlier postdecode admission remained common
to both paths. The remaining gap is tracked in ISSUE-521.
[Open interpreter performance issue](../KNOWN_ISSUES.md#issue-521)

## Environment and reproduction

MacBookPro18,3, Apple M1 Pro, eight logical CPUs, macOS 14.6.1
(23G93), Xcode 15.4 (15F31d), Rust and Cargo 1.99.0, and Python 3.12.5.
The release builds used the standard Apple ARM64 CPU settings, minimum
macOS 14.0 and SDK 14.5. Both passed strict signature verification with
Hardened Runtime and `allow-jit`.

The machine was on AC power. Each of the two pilots and twelve scored
processes recorded UID 501, nice −5 and QoS `0x21`. The 24 preflight
probes ranged from 74.2% to 99.6% CPU idle, with a median of 99.3%.
The nine scoring probes ranged from 71.3% to 73.0%, with a median of
72.1%.

Extract the archived harness files to `work/tmp/s3-40-mov-postdecode/`
in a repository with both pinned revisions and the S3-40m and S3-40w
input archives. Use an isolated Cargo home with the lockfile
dependencies. Build and check from the repository root.

```sh
export MACOSX_DEPLOYMENT_TARGET=14.0
unset RUSTFLAGS CARGO_ENCODED_RUSTFLAGS CARGO_BUILD_RUSTFLAGS
unset CARGO_TARGET_AARCH64_APPLE_DARWIN_RUSTFLAGS
harness=work/tmp/s3-40-mov-postdecode
zsh "$harness/build.sh" historical
zsh "$harness/build.sh" current
zsh "$harness/check.sh"
```

The archived `README.md` gives the monitored run and packaging
commands. `python3 "$harness/offline_audit.py" /path/to/evidence.json.gz`
reproduced the saved audit on both machines. The archive contains
85 files, including build receipts, disassembly checks, untimed
fixture checks, every raw timing and the host load logs.
