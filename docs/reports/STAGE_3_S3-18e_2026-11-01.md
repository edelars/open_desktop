# S3-18e: bounded checked-memory cache implementation

## Scope

Commit `b1a6ccb130844c40a396155a8f84bda656bfa8c3` adds an opt-in
`MemoryPairCache` for exactly the frozen `StoreThenLoad` and `LoadThenStore`
checked-memory fixture profiles. The existing one-shot
`MemoryBlockExecutor` path keeps its release-before-return lifetime.

The cache retains at most one published entry. Its typed key includes the
profile, complete immutable source view and entry RIP, validated executable
dependency identities/generations and permissions, and a nonzero caller-owned
execution-context generation/profile. It admits at most six dependency spans
before key allocation and enforces a 512 KiB logical bound. A same-key request
revalidates the key; clear or replacement drops the prior inactive published
handle before a new publication. A failed replacement leaves the cache empty.

`od-host` owns the retained executable mapping and immutable artifact metadata.
Each synchronous run supplies fresh invocation-local CPU state, RAM, access
context, budget, STOP and event controls. The retained handle does not contain
those pointers. The fixture contract is private ordinary RAM with no code/data
alias, MMIO, DMA, concurrent observers, re-entry, or unwind through the helper;
writes are all-or-nothing.

## Focused evidence

- `cargo fmt --all -- --check` — passed.
- `cargo check -p od-jit -p od-host --all-targets --offline` — passed.
- Eight focused `od-jit` cache unit tests and two native `od-host` memory-cache
  integration tests passed in the implementation run. The integration cases
  compare frozen-profile execution with uncached dispatch and cover control,
  committed-prefix and lifecycle behavior.
- The host integration tests are gated to macOS ARM64. No Mini, physical-x86,
  benchmark, or production owner/MMU run is claimed here.

The unit coverage includes same-key reuse, changed dependency/context identity,
capacity-one replacement and release ordering, failed publication, dependency
limits, STOP/event/budget entry guards, and executor-error cleanup. The host
corpus checks two cached executions for each of 2,400 frozen inputs, exact
compile/publication/hit counts, clear, control exits, committed prefixes, and
fault parity.

## Boundaries

This implementation provides a local fixture cache, not production RAM,
backing, mapping or MMU ownership; committed-writer/SMC/DMA coherence; async or
concurrent execution; active-code retirement; other memory profiles; or a
general cache policy. The cache is correctness infrastructure for the bounded
fixture. No performance result or default-policy conclusion follows from these
tests. S3-18 and the broader Stage 3 gates remain open.

The checked-memory handle lifetime proposal is recorded in
[ADR-0004](../decisions/ADR-0004-capacity-one-memory-cache.md), with the
runtime boundary in the [JIT contract](../specs/JIT_CONTRACT.md#s3-18e-capacity-one-checked-memory-cache-fixture-partial).
