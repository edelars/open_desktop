# S3-38o: production host loop of one vCPU over `PagedFetchedLoadSession`

**Status:** implemented 2026-11-18; accepted with limits after the Opus high gate review (2026-11-18, see «Gate review» below). Does not close S3-38. One vCPU, one thread. S6-42 connects the loop to the vCPU threads.

## What was done

- **New module** `crates/od-host/src/paged_host_loop.rs` (public: `od_host::paged_host_loop`):
  - `PagedHostLoopControl`: owned by the caller, `Sync` (atomics only). It holds the STOP `AtomicU8` and the request flags `stop`, `finish`, `event`. `request_stop` / `request_finish` / `request_event` set the flag (`SeqCst`) and then the byte (`SeqCst`); `clear_*_request` withdraws only the flag. Only the loop takes the byte down.
  - `run_paged_host_loop(session, control, config, state, bus, rflags_defined, incoming_budget, committed_write) -> PagedHostLoopReport`.
  - Iteration (S6-40 section 5, S3, steps 1-2, single-thread form): on the S3-25c safe point take the byte down (`swap(0, SeqCst)`) and reread the flags (`SeqCst`), once per iteration (a JIT step or the fallback interpreter step; the flags are not reread between a JIT refusal and the interpreter step that follows it, which stays within the bound of one instruction); exit by priority STOP, finish, budget, event (a raised flag means no step runs; the loop never clears a flag); otherwise one step. The step is the session's native path (`execute_forms_with_stop`, the caller's byte passed as `RuntimeContextV1::stop_requested` of every native call); if the session refused without effects of the instruction, exactly one step of the shared paged interpreter, `od_machine::run_paged_probe` with a budget of one (the interpreter `FirmwareBoard::run_quantum` uses).
  - `StopRequested` of a single-instruction block is an ordinary result: retired 0 (before the instruction, no effect) or retired 1 (after it); the instruction is never repeated. `BudgetExhausted` / `StopAddress` of a one-instruction block stay `JitHostFailure(InvalidOutcome)`. A guest fault of either path ends the loop with `GuestFault` and the `#PF` record.
  - Shared budget: `retired_jit + retired_interpreter + remaining == incoming` (`budget_is_consistent`).
  - All RAM writes of both paths go through `commit_write` inside the bus (the page generation grows); the walk writes of the fetch and the operand are delivered to the caller's `committed_write`, native path after the call returned, interpreter path in order.
  - The loop owns no executable memory: the `MapJitLease` lives in the session's `PublishedCode` and is released by `reset` or drop (M6).
- **Changes in `crates/od-host/src/lib.rs`** (no behaviour change of existing entries): `PagedFetchedLoadSession::execute_forms_with_stop` and `*_with_stop` variants of the three internal native entries take the caller's STOP byte; `execute_forms`, `execute_paged_mov_rax_rbx_v2` and `execute_paged_mov_rbx_rax_store_v2` call them with a local zero byte as before; `JIT_TEST_LOCK` became `pub(crate)` so the new tests share the process-wide MAP_JIT lock with the existing ones. `od-isa/src`, `od-machine/src`, VMHost/ABI, `storage_abi_v1.rs` and the set of JIT forms are not touched. The loop uses the existing public `od_machine::run_paged_probe`; no new interpreter API was needed.
- **Documents:** STAGE_3 subsection S3-38o (status and result); JIT_CONTRACT: the *paged session* column of the S3-28c matrix filled by the new tests, and the section "S3-38o: the caller of `PagedFetchedLoadSession`".

## Tests (`crates/od-host/src/paged_host_loop.rs`, module `tests`, real native on macOS aarch64)

The reference is the pure interpreter (`run_paged_probe`) over identical RAM, 4-level paging with a writable code page and a data page. The mixed program is `mov rax,[rbx]` (native), `mov [rbx],rax` (native store), `push r12`, `ret` (interpreter): an endless guest loop with a balanced stack. The native store `48 89 03` has no interpreter counterpart, so the reference runs the alias `48 89 0B` with equal registers and the code page is excluded from the RAM comparison.

## Limits (recorded, not extended)

- One vCPU, one thread. The session, bus and CPU state are not `Send`/`Sync`; the loop introduces no thread. The STOP byte protocol is the single-thread form; S6-42 connects the loop to vCPU threads and adds `stop_all` and `split_owner` to the reread (the order of steps does not change).
- JIT profile: one instruction per block. A block is dropped by every unsupported form, so a mixed loop re-admits each native form (compile and map per step); no block reuse across interpreter steps. Performance was not measured.
- The admission still maps one region per session admission; slots of a region are S6-42.
- The shared interpreter is the board's narrow profile (`MOV RAX,[RBX]`, `MOV [RBX],RCX`, stack forms, `RET`, `HLT`, port I/O and a few exact firmware forms). The forms admitted only by the JIT (`48 89 03`, `8B 03`, displacement and RIP-relative loads) have no interpreter fallback and no oracle in this loop: when the session refuses such a form, the loop ends with `Interpreter(Unsupported)`.
- A native attempt that exits before its instruction has already committed the Accessed bits of the fetch walk (idempotent, reported in the write list); a reference that retired nothing has not fetched, so the stop-at-step-0 test clears only the Accessed bit of the four fetch-walk qwords and checks the write list explicitly; nothing else is normalised.
- The `StopRequested` exit with retired 1 (byte raised inside the helper) is accounted by the decoder and the loop counters, but no deterministic loop test raises the byte inside the helper.
- Recovery after a host fault in generated code (S3-27) is open. S3-38 is not closed.
- **S4-16i with an observed STOP: closed at the gate (2026-11-18).** The exit of a retired store into the active code page (`Complete`, or `StopRequested` with retired 1) is rewritten to `CodeInvalidated` and the block is marked retired (`store_invalidates_active_code`, unit test `a_retired_store_into_the_code_page_invalidates_even_when_stop_was_observed`). The STOP is not lost: the loop clears the byte and re-reads the flags at the next safe point; only `native_stop_exits` misses that exit.

## Gate review (Claude Opus, high, 2026-11-18)

Verdict: **accept with limits.** Reviewed at eaa83b2 (after the S6-42/42b/42c changes to `paged_host_loop.rs`). Items 1–7 of «Сделать» and all checks of «Проверить» are covered by real tests; the S6-40 §5 S3 order (`swap(0, SeqCst)` then the `SeqCst` flag reads, no step under a raised flag, only the loop clears the byte, STOP before the event, the event flag kept) holds; the budget identity holds on every exit, including `StopRequested` with retired 1; M6 holds; no «Не делать» item is violated.

- D1 (non-blocking, fixed in this commit): the S4-16i rewrite to `CodeInvalidated` fired only for `Complete`; it now also fires for `StopRequested` with retired 1 (`store_invalidates_active_code`, `lib.rs`), with a unit test on synthetic results.
- D2 (non-blocking, kept as a limit): no deterministic loop test raises the byte inside the helper; the shared branch with `Complete` and the decoder cases cover the accounting.
- Limits of the acceptance: one vCPU, one thread; one instruction per block, re-admitted at every native step, performance not measured; the board interpreter is narrow (JIT-only forms have no fallback and no oracle); S3-27 open; S3-38 not closed.
- Commands at the review: `cargo test -p od-host --offline --lib s3_38o` 13 passed; `--lib paged_host_loop` 66 passed, 1 ignored. After the D1 fix: `cargo test -p od-host --offline` all 14 test binaries ok (lib 482 passed, 1 ignored).
