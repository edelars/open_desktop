## Состав MADT (84 байта)

| Смещение | Содержимое |
|---|---|
| 0..36 | заголовок: `APIC`, Length `0x54`, Revision 5, checksum `0x4D`, OEM ID `OPNDSK`, OEM Table ID `ODFWAPIC`, OEM rev 1, creator `ODFW`, creator rev 1 |
| 36 | Local APIC address `0xFEE00000` (из записи кода 2) |
| 40 | Flags = 1 (`PCAT_COMPAT`) |
| 44 | Processor Local APIC: тип 0, длина 8, UID 0, APIC ID 0, flags 1 (Enabled) |
| 52 | I/O APIC: тип 1, длина 12, ID 1, резерв 0, адрес `0xFEC00000`, GSI base 0 (запись кода 3) |
| 64 | Interrupt Source Override: тип 2, длина 10, bus 0, source IRQ 0, GSI 2, flags `0x0000` |
| 74 | Interrupt Source Override: тип 2, длина 10, bus 0, source IRQ 9, GSI 9, flags `0x000F` |

Нет NMI-источников, x2APIC и Local APIC address override; тест проверяет, что список структур ровно `[0, 1, 2, 2]`. Один CPU: S4-25a (`LocalApic` — one-CPU, APIC ID 0), диагностические пути S4-26..S4-28 тоже «one vCPU».

## Выбор revision

**5.** Это значение Table 5.19 в ACPI 6.4 (`Revision | 1 | 8 | 5`), редакции, которая читалась через Context7. Ревизия 6 принадлежит ACPI 6.5, текст которого не читался; ревизия 5 принимается, и Linux обрабатывает 5 и 6 одинаково для этой таблицы. Валидатор отвергает любую другую (проверены 0, 3, 4, 6).

## Кодировка INTI flags (и расхождение с текстом задачи)

ACPI 6.4 Table 5.26 (= MPS 1.4 Table 4-10), прочитано через Context7: polarity — биты 0..=1 (`00` как у шины, `01` active high, `10` reserved, `11` active low); trigger mode — биты 2..=3 (`00` как у шины, `01` edge, `10` reserved, `11` level).

- IRQ 0: `0x0000` — «как у шины» по обоим полям, для ISA это edge, active high (решение задачи).
- SCI: level (`0b11 << 2`) | active low (`0b11`) = **`0x000F`**. Значение `0x000D`, названное в задании, — это trigger `11` (level) и polarity `01` (active **high**), то есть не то, что требует решение 4 («level, active-low»). Взято `0x000F`; расчёт зафиксирован в тесте `inti_flags_encoding_follows_table_5_26` вместе с декодированием `0x000D`.
- Для других комбинаций флаги SCI берутся из записи PM: level/low `0x000F`, level/high `0x000D`, edge/low `0x0007`, edge/high `0x0005` (тест).

## Эталон

Эталон собран вручную по раскладке (заголовок 36 байт, 8 байт Local APIC address и flags, затем записи) независимым скриптом `python3 -I` без кода Rust, зашит в `reference_madt` как hex и сверяется побайтно (`madt_matches_the_hand_assembled_reference`). Checksum `0x4D` пересчитан отдельно: сумма остальных 83 байт `0xAB3` (2739), остаток `0xB3`, `0x100 - 0xB3 = 0x4D`; сумма всей таблицы по модулю 256 равна 0. Offsets в тестах — литералы, не константы сериализатора.

## Валидация

`validate_madt`: сигнатура, Length, checksum, ревизия 5, flags ровно `PCAT_COMPAT`, Local APIC address ненулевой и выровнен на 4 KiB; обход структур (неизвестный тип, нулевая или неверная для типа длина и выход за таблицу — `BadEntryArea`); ровно один Local APIC (UID и APIC ID 0, `Enabled=1`, `Online Capable=0`, то есть flags ровно `1` для этого профиля по ACPI 6.4 Table 5.23) и ровно один I/O APIC (резерв 0, адрес ненулевой, выровнен, не равен адресу Local APIC); override только на bus 0 (`BadIsoBus`), source 0..=15 (`BadIsoIrq`), один на source (`DuplicateIso`), flags без зарезервированных битов и без значения `0b10` в полях (`BadIsoFlags`); override IRQ 0 обязателен и ведёт в GSI 2; GSI каждого override внутри `[gsi_base, gsi_base + 24)` (`GsiOutsideIoApic`); `gsi_base + 24` не переполняет 32 бита (`BadGsiBase`).

Сборка проверяет вход до первой записи (буфер не тронут при ошибке): запись Local APIC/I/O APIC присутствует, не PIO, окно ненулевое, выровнено на 4 KiB, длина `0x1000`, ниже 4 GiB; GSI base; GSI SCI в 0..=15 (как `SCI_INT` FADT); SCI не на IRQ 0 и не на GSI 2 (их занимает override таймера); GSI 2 и GSI SCI внутри диапазона IOAPIC; буфер не короче 84 байт.

## Follow-up независимого ревью

Ревью выявило, что валидатор принимал flags `3`: одновременно `Enabled=1` и `Online Capable=1`. Для поддержанного здесь one-CPU профиля ACPI 6.4 Table 5.23 требует `Online Capable=0` при `Enabled=1`. Валидатор теперь требует ровно `LOCAL_APIC_ENABLED` (`1`). Regression-тест `validation_rejects_online_capable_when_local_apic_is_enabled` меняет поле flags по смещению 48 на `3`, пересчитывает checksum, проверяет сумму таблицы `0` и подтверждает `BadField("Local APIC: flags")`.

Повторные проверки после исправления: `cargo fmt --manifest-path firmware/uefi/Cargo.toml -- --check` — успешно; firmware host suite — **154 passed, 0 failed**; `cargo check --manifest-path firmware/uefi/Cargo.toml --target x86_64-unknown-none --offline` — успешно. Из-за вложенного пути worktree Cargo ошибочно обнаруживает внешний workspace, поэтому эти три проверки выполнялись над точной временной копией `firmware/uefi` и необходимой ACPI blob fixture в `/private/tmp`; исходники в worktree служили источником копии и не менялись проверками.

## Отклонения и замечания

- **INTI flags SCI `0x000F`, не `0x000D`** — см. выше.
- **IOAPIC ID = 1 — решение прошивки, не манифеста.** Запись кода 3 несёт адрес, длину и GSI base; ID «читается из регистров устройства» (FIRMWARE_BOOT.md 6.3), но у модели `IoApic` (S4-26a) нет читаемого регистра ID. Выбрано 1, отличное от APIC ID 0 процессора, чтобы в ОС с единой таблицей APIC ID они не пересекались. Не сверено с чтением гостем.
- **Число входов IOAPIC = 24 — допущение прошивки** (размер 82093AA-совместимого IOAPIC). Манифест и модель его не сообщают (S4-26a: один маршрут INTIN4, Version не выставлен). Используется только для проверки GSI override (`[base, base + 24)`).
- **Источники.** Через Context7 (ACPI 6.4) подтверждены: Revision = 5, Local Interrupt Controller Address со смещения 36 и Flags 40, структуры с 44, бит `PCAT_COMPAT`, тип 2 и MPS INTI flags. Раскладки структур типа 0 (Processor Local APIC) и типа 1 (I/O APIC) в ответах поиска не вернулись; они взяты из известной структуры ACPI/ACPICA и закреплены только ручным эталоном. Текст ACPI 6.6 не читался.

## Ревью

Независимый reviewer подтвердил, что ACPI 6.4 Table 5.23 требует нулевой `Online Capable`, когда `Enabled` установлен ([официальная спецификация](https://uefi.org/htmlspecs/ACPI_Spec_6_4_html/05_ACPI_Software_Programming_Model/ACPI_Software_Programming_Model.html)). Исправленный валидатор допускает только `LOCAL_APIC_ENABLED`; regression-тест пересчитывает checksum после установки `Flags=3` и получает ожидаемый `BadField`. Повторное ревью — **PASS**, 15 MADT tests прошли в независимом harness; форматирование, 154 firmware host tests и сборка `x86_64-unknown-none` также прошли на точной временной копии из-за Cargo workspace discovery в nested worktree. `git diff --check` чистый.

S4-31 целиком пока нельзя принять: отдельный ACPI 6.4 контракт MADT требует matching processor device object в DSDT для каждой Local APIC записи. Текущая DSDT не объявляет CPU UID 0; это самостоятельный следующий срез, не исправление валидатора MADT. См. [ACPI 6.4 §5.2.12.2](https://uefi.org/htmlspecs/ACPI_Spec_6_4_html/05_ACPI_Software_Programming_Model/ACPI_Software_Programming_Model.html).
