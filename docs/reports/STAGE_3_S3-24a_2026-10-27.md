# S3-24a — bounded active native prefix invalidation

## Scope

This partial slice compiles one exact 23-byte artifact:

```text
48 BA imm64       MOV RDX, imm64
48 89 03          MOV [RBX], RAX
48 B9 imm64       MOV RCX, imm64
```

All three instructions are independently decoded by the existing long-mode
decoder. A distinct compiler flavor, V3 runtime context/entry, arena metadata,
and typed handle keep this artifact separate from V1 and the V2 load/store
entries. The V3 emitter owns guards, sequential commits, accounting, exits, and
tail execution; it shares only the checked-store helper call primitive.

The fixture owner reserves the next backing version before writing and binds an
invocation-local dirty word for the synchronous native call. A successful
store into the already executed prefix marks that word at the commit point.
The artifact then commits RIP `entry+13`, budget, and retirement once and exits
`CodeInvalidated` before its stale native tail. The host decodes the result,
releases its arena borrow, then applies the notification while the handle
remains live so invalidated cache slots can be reclaimed. A fresh dispatch runs
the tail from current bytes; re-entry observes the modified prefix. Stores to
the store instruction or not-yet-executed tail are rejected, including aliases.

## Coverage

- Same-entry native execution completes an unrelated store and executes all
  three instructions.
- Prefix-changing store exits before the native tail; fresh tail dispatch and
  re-entry observe the updated bytes.
- Interpreter checkpoint matches CPU state, RAM, backing version, and exact
  write count for the prefix-changing scenario.
- STOP-RIP, STOP, budget 0/1/2/3, STOP raised during write, alias write,
  noncanonical fault, backend write failure, and future-tail overlap through
  direct/alias addresses are covered.
- A stale 23-byte source lease is rejected before generated execution for
  budgets 1 and 3, preserving full CPU state, bytes, version, and write count.
- Dirty notification invalidation releases the prefix/tail arena slots before
  the next lookup; fresh tail and re-entry publications reuse those slots.
- Architectural fault leaves the first instruction committed and the store
  RIP faulting; RAM and version remain unchanged.
- Malformed source forms are rejected by the V3 compiler unit test.

## Limits

This is a bounded already-executed-prefix fixture case. It does not establish
behavior for modifying a not-yet-executed instruction, general multi-block or
IR/PC-map integration, production MMU/writers, or complete S3-24. No physical
Mac Mini checks or long benchmarks were run; physical execution remains at the
final S3-21 gate after local Stage 3 work.
