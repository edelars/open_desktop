# S3-30c allocator census on the measured S3-14 profile

The signed ARM64 release passed the untimed allocator census on an
Apple M3 Max, macOS 26.7.1, with Rust 1.99.0. The input list, trace
and accepted S3-36l archive are pinned by SHA-256. S3-36l measured
these same five cases through normal warm FIFO16 on M1 Pro.
[M1 Pro warm profile](STAGE_3_S3-36l_2026-11-19.md)

The census executes an ordinary untimed dispatch sweep into the empty
FIFO16 and checks the five cases against the interpreter. The sweep
retired 14 guest instructions in five native blocks. It compiled five
blocks on five misses. Each of the five recorded block visits enters at
guest RIP zero.

## Emitted allocator transfers

The census uses the validated dispatch lowering and production allocator
plan. Its re-emitted bytes must match the normal dispatch compiler
byte for byte. For the observed SP-relative 64-bit LDR and STR words,
it records the offset, register and PC-map attribution. It distinguishes
allocator-owned spill and helper capture offsets from the runtime
frame.

| Fixture | Homes | Spill slots | Helper boundaries | Emitted spill stores | Emitted spill reloads | Emitted helper saves / restores | Allocator sites |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| Four JZ/JNZ branch fixtures, each | 2 | 0 | 1 | 0 | 0 | 2 / 2 | 4 |
| `s3_14_live_through_helpers` | 4 | 10 | 5 | 10 | 17 | 3 / 3 | 33 |
| Across five trace visits | | | | 10 | 17 | 11 / 11 | 49 |

The live-through case accounts for 33 of 49 visit-weighted allocator
sites. Its plan contains ten spill loads, ten stores and three helper
save/restore pairs. The normal emitter produces 17 spill reload sites
in that block. The trace records block entries, so the output leaves
dynamic transfer counts unset. The census separately records 423
runtime-frame LDR/STR sites.

This identifies `s3_14_live_through_helpers` as the pressure case in
the measured profile. The next S3-30 comparison still needs paired
compile and warm timings, code size and correctness evidence for a
profile-guided allocator variant.

## Verification

An early native diagnostic stopped on the first skipping-tail branch
because generic lowering produced different bytes. The final census
uses the feature-gated observation entry to the same admitted lowering
as normal dispatch. All five byte comparisons and the ordinary FIFO
interpreter checks passed. An altered case list was rejected without
creating an output report. Formatting, the bench all-targets check
and the `od-jit` check with default features disabled passed.

Run the untimed census from the repository root after building and
signing `od-bench` for ARM64 macOS.

```sh
"$OD_BENCH" allocator-census-s3-36l \
  --case-list tests/fixtures/x86/stage3/s3_14_branch_helper_case_list.txt \
  --trace docs/reports/data/stage3/s3-36b/trace.json \
  --accepted-archive docs/reports/data/stage3/s3-36l-m1pro-20261119/warm-branch-helper.json.gz \
  --output "$OUT/census.json"
```

The archive binds the source diff on `a819705`, the signed binary
digest, host, build, detailed census and rejection evidence. Archive
