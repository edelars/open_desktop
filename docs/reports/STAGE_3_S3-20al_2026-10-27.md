# S3-20al — RSP/RBP data through indexed 64-bit SIB

## Scope and implementation

This slice extends the existing 64-bit indexed-SIB qword MOV profile to allow
RSP or RBP in the ModRM data field. It accepts only low-GPR base and index
(RAX..RBX), scales 1/2/4/8, and the already supported no-displacement,
signed-disp8 and signed-disp32 forms (lengths 4, 5 and 8). It does not add
address-size override, no-index/no-base special forms, new pairs, V3 or an
`od-machine` owner integration.

Admission is aligned across direct V2, shared IR and runtime host metadata.
Raw source-byte checks bind the exact form to decoded fields; the existing
`MemoryOperand`/`access_address_48` remains the only effective-address
semantics. The borrowed dispatcher now routes this exact singleton profile to
shared IR compilation while preserving other profile gates.

## Evidence

- Descriptor tests cover both MOV directions and RSP/RBP data with all
  scales, low base/index combinations including base=index, and no
displacement, disp8 -128/-1/0/127 and disp32 MIN/-1/0/MAX. Invalid and
  truncated source/profile combinations remain rejected.
- Host differential tests compare direct V2, shared IR and interpreter for
  CPU state, RAM, callback counts/targets, fault payload, and retirement. They
  include noncanonical low-GPR effective addresses (#GP before callbacks),
  architectural and backend fault paths, callback STOP after successful store,
  and noncanonical stack-register values as data.
- Dispatcher coverage compares budgets across each SIB width, validates
  partial byte windows without memory effects, resumes from actual RIP after
  budget/STOP, and checks a noncanonical loaded RSP/RBP followed by stack-base
  use: the first load remains retired and committed, while the next access
  raises #SS without repeating the first callback.
- A macOS/ARM64 x19 ABI canary exercises the exact indexed-SIB RSP-data load
  across success, budget-guard and backend-fault exits.
- The existing no-index RSP-base SIB profile and previous RSP/RBP data/base
  profiles remain covered by the surrounding host/JIT suites.
