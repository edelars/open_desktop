# Stage 4 S4-14a: cache lifecycle boundary

## Результат

Принят ограниченный S4-14a. Существующий opt-in `TranslationProbeCache`
проверен как host-controlled one-entry pure-probe cache: `clear()` удаляет
только resident value, а завершение immutable-borrow scope позволяет явно
изменить page table и создать новый cache над обновлённой памятью.

Проверены следующие границы:

- пустой и заполненный cache, повторный `clear()` и отсутствие изменений RAM/A-D;
- точная последовательность `Walk -> Hit -> clear -> Walk -> Hit`;
- failed replacement, после которого cache остаётся пустым;
- remap через завершение cache scope с наблюдением нового physical page;
- tighten/relax leaf RW с PFEC `0x07` и NX Fetch с PFEC `0x15`;
- явный PTE write callback `(PT, 8)` без callback или записи со стороны probe.

## Граница

Срез не реализует guest invalidation, INVLPG, CR3/EFER transitions,
generation counters, global/PCID/INVPCID, CPU/JIT hooks или concurrent memory
owner. Полный S4-14 остаётся открытым; cache остаётся экспериментом S4-13a,
а returned translations — диагностическими value snapshots.
