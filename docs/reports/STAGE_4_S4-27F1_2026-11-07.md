# S4-27f1 — bounded JIT event handoff

## Result

Added opt-in `DiagnosticVcpuSession::run_jit_nop`. The caller supplies a stable
guest code base and the complete expected byte range, an instruction budget,
dispatch control, a controlled executor and a caller-owned event flag. The
method constructs the exact `S0_09NopAdmission` internally from the bytes. The
machine validates the entire range on every call: it must be nonempty,
overflow-safe, fit within one guest 4 KiB page, be backed entirely by RAM, and
match every expected byte. The current RIP must be a valid admitted boundary
inside this full range. Reusing the same full range on resume preserves backward
branch context and avoids repeating an already executed prefix.

Dispatch now uses event-aware execution. An event noticed in the publication
window yields before entering native code. An executor result of
`Yield(EventPending)` is returned as an event exit after higher-priority exits,
without attributing extra guest progress. The session does not clear the event;
the owner decides when it has been handled and explicitly clears it before
resuming. Candidate CPU state is only published for a valid successful result.
Profile/range/byte/admission rejections occur before executor entry and preserve
the session. A dispatch error may follow executor entry; it preserves the
original CPU state, marks the session Stopped and leaves the event flag
caller-owned. The caller certifies a completed boundary, serializes machine
access, provides private synchronous RAM and keeps code bytes stable for the
duration of a call. The profile requires Runnable Long64/CPL0, Running
activity, Clear STI shadow, no configured CR0/CR3/CR4 snapshot and
`INTEGER_FLAGS` definedness.

The ARM64 host integration tests use the real `PublishedBlockExecutor`. They
prove publication-window yield without native entry, native prefix execution,
yield before NOP on a persistent event, explicit owner clear, and continuation
through NOP and the native suffix without repeating the prefix.

## Boundaries

This is cooperative handoff at dispatcher boundaries. It does not asynchronously
interrupt a native block, deliver the event through APIC, or compose JIT exit
with APIC entry, handler execution, guest EOI and IRETQ. It is not production
scheduling, paged JIT admission or Linux acceptance. Parent S4-27 and Stage 4
remain open.
