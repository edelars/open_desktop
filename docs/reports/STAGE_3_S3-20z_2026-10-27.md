# S3-20z — guest RSP as qword MOV data register

## Scope

This bounded slice admits only `48 8B/89 /r`, ModRM `mod=00`, data register
RSP (`reg=4`), direct memory base RAX..RBX (`r/m=0..3`), exact length three.
The data-register exception is deliberately local to checked memory load/store;
generic guest GPR reads and writes remain restricted to RAX..RBX. No SIB,
displacement, address override, extra prefix, other base or pair/V3 change is
included. Decoder `MemoryOperand` remains authoritative for effective address.

The IR frame stages GPRs at `SP+56..95`, flags at `SP+96`, RIP at `SP+104`,
and saves X19/X20 and X21/X22 at `SP+112` and `SP+128`. The minimum reserved
prefix is 144 bytes, keeping both callee-saved pairs beyond the complete staged
state. This avoids RSP/RFLAGS aliasing and does not change host SP, public
runtime context, or C ABI. A successful checked load commits its full
64-bit value to guest RSP; a noncanonical value is valid store data because
canonicality is checked for effective addresses, not payload data.

## Evidence

- The descriptor test admits only exact direct forms for load/store and rejects
  unsupported neighboring encodings; the special RSP admission does not widen
  generic `ReadGpr`/`WriteGpr`.
- Direct V2, shared IR and interpreter agree for both operations on full CPU
  state and RAM, including callback address/count and one-instruction
  retirement. Load destination and store source use guest RSP while host stack
  state is unaffected.
- Stores of noncanonical payload `0x0000_8000_0000_0000` commit all eight exact bytes to RAM. Faulting accesses do not commit state/RAM/counters. A native x19 canary passes on success, budget-guard and architectural-fault exits. Entry STOP and budget zero suppress callbacks; a budget-one split resumes at actual RIP without repeating the first load. The sequential dispatcher
  scenario executes `MOV RSP,[RAX]` with a noncanonical qword payload, commits
  guest RSP and RIP, then resumes at `MOV RCX,[RSP]`. That second access returns
  #SS at its own RIP, preserves the first instruction's effect, and makes no
  repeated callback. STOP/resume uses actual RIP.

Evidence is local ARM64 fixture only. Owner/MMU integration, physical x86
verification, Mini runs and performance measurements remain deferred.
Independent review initially found an overlap between staged RIP and saved
host callee-saved registers. The frame was corrected: guest state ends at
offset 111, X19/X20 save at 112 and X21/X22 at 128, with a 144-byte reserved
prefix. All six save/restore paths and every prefix consumer were updated. A
Darwin ARM64 canary now verifies X19 preservation on success, budget guard and
fault exits. Review also requested a noncanonical store payload and explicit
entry STOP/budget-zero and budget-one split cases; these were added and
independently rechecked. Final independent review completed cleanly with no
open findings.
