# Stage 4 S4-24d: guest UART RX→IN→OUT echo

The new strict `Stage4UartEchoProbeV1` image uses the existing Stage 4 board,
page tables and Long64/CPL0 handoff, with code bytes exactly `EC EE F4`:
`IN AL,DX`, `OUT DX,AL`, `HLT`. The legacy flat-probe loader remains strict and
rejects the echo profile. Session reset preserves the selected profile and
validates the replacement image before changing session state.

The runner accepts an independent `--rx-byte` and `--expect-byte`. It schedules
and dispatches the RX byte through the session's bounded generation-aware event
queue and UART, runs the guest quantum, and drains actual UART TX. Success
requires HLT, exactly three retired instructions, `RIP=0x400003`, RAX equal to
the expected byte, and TX exactly `[expected]`. The expected byte is not given
to the guest or used to create output. Empty RBR remains the existing PIO error.
JSON reports `observed_rax`; `observed_data_qword` stays null for this profile.

Verification passed: 13 `PagedVcpuSession` unit tests, 9 runner CLI tests,
2 builder→CLI tests (two builds matched both ELF and raw artifacts),
`cargo check -p od-runner --all-targets --offline`, `cargo fmt --all -- --check`,
and `git diff --check`. The CLI tests cover byte values `0x00`, `0x80`, `0xff`,
budget and STOP prefixes, empty RBR, mismatched/missing expectations, malformed
and duplicate options, and filenames equal to option names. Independent
`gpt-6.1-sol/high` review found no remaining P0–P3 findings.
