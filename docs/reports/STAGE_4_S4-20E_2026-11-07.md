# Stage 4 — S4-20e: paged CPL3 MOV CR0 after IRETQ

**Date:** 2026-11-07
**Status:** accepted after implementation checks, independent Sol code review,
and independent documentation review with no remaining findings. Parent S4-20
and Stage 4 remain open.

## Implementation

S4-20e adds the bounded `step_paged_cpl3_mov_cr0` machine entry. It derives
privilege from the committed CS selector/cache and CR3 from CPU state, and uses
the fixed Long64, canonical48, physical36, four-level 4 KiB profile with
`CR0=0x80010033`, `CR4=0x20`, and `EFER=0xd00`. Invalid user CS or controls,
live TF/RF/AC, and an active STI shadow are rejected before fetch. The
instruction offset bound admits `0xff1` and rejects `0xff2` before fetch.

After complete fetch/decode, bare `0F 22 C0` (`MOV CR0,RAX`) at CPL3 produces
`#GP(0)` for tested RAX values and IOPL settings. `F0 0F 22 C0` produces
`#UD` after complete fetch/decode. Injected fetch faults at each byte precede
these execution faults. The entry returns fault results; it does not deliver
them through the IDT or switch stacks. A fault does not retire or partially
commit CPU state; completed page-walk A effects remain visible.

## Evidence

The first-user-fetch system test invokes `step_paged_cpl3_mov_cr0` directly.
Its matrix covers supervisor-only fetch at each page-table level, NX fetch,
and a non-present user leaf. The latter asserts PFEC `0x14`, exact linear
address, CR2 and saved RIP, zero retirement, preservation of CPU state except
CR2, the three completed A-bit updates, exact PTE values and callback ranges,
and no D-bit update. A separate backend case reports `OperandPhysical` at GPA
`0x30000` and preserves successful earlier A updates. The IRETQ → user load →
store → MOV CR0 case confirms that the prior store remains committed after
`#GP(0)`.

The recorded baseline is 10 `cpl3_` ISA tests and 39 system test functions; one
additional non-present-fetch assertion case was added within the system suite,
so it is not counted as another test function. The direct first-fetch system
test was also run separately and passed. The page-walk A-write failure matrix
and the fetch-specific case pass through the internal tracked-walker writer
seam. They validate `TableWrite` classification, level/address/bit, retained
committed prefix and callbacks. That injection tests the shared page-walk
function and does not inject through the machine entry's report projection.

Recorded checks passed:

- `cargo test -p od-isa --lib cpl3_ --offline -- --test-threads=1` — 10 passed.
- `cargo test -p od-host --test stage4_exception_delivery --offline -- --test-threads=1` — 39 passed, with the additional assertion case noted above.
- Targeted `cpl3_mov_cr0_first_fetch_enforces_user_page_permissions` — passed.
- Targeted page-walk A-write failure matrix and fetch-specific failure test — passed.
- `cargo check -p od-machine --all-targets --offline`, formatting, and `git diff --check` — passed.
- Graphify was updated after code changes in the primary checkout: 27,555
  nodes and 69,202 edges.

Sol review identified that PFEC `0x14` needed direct coverage through the new
entry. The system test was extended accordingly and the targeted test passed.
The independent Sol code re-review after that correction passed with no P0–P3
findings. A separate documentation review also passed after corrections to
the test count, recorded page-table readbacks, Graphify snapshot, and links.
S4-20e is accepted.

## Boundaries

This slice generates #GP/#UD and page-fault results but does not deliver
exceptions. IDT/TSS stack switching, general CPL3 exception delivery, other
CR forms, and cross-page instruction fetch remain outside the slice. The
shared page-walk A-write injection is not an end-to-end failure injection
through `step_paged_cpl3_mov_cr0`.
