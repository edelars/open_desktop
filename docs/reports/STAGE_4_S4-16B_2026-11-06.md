# S4-16b: guest MOV store invalidates inactive aliased JIT code

**Статус:** срез принят после независимого ревью без замечаний. Родительский
S4-16 и Stage 4 остаются открытыми.

## Граница

Один vCPU, фиксированный Long64 paging snapshot, одна физическая RAM code page,
два virtual aliases и bounded register-only JIT cache из S4-16a. Между native
вызовами исполняется один machine-профиль `step_paged_mov`; проверенный store —
`48 89 0B` (`MOV [RBX],RCX`). Code range остаётся внутри одной guest page.
Срез не задаёт поведение cross-page operand, remap/TLB, SMP, MMIO/DMA, других
writer APIs или active-code mutation.

## Реализация

- `PagedCodeSession::step_guest_mov` проверяет CR0/CR3/CR4 против session
  snapshot, сохраняет CPL и передаёт CR3 отдельно в machine adapter. Для точного
  interpreter profile используется локальная копия CPU state с `cr3 = None`;
  исходный CR3 восстанавливается перед копированием результата вызывающему коду.
  При machine input error caller state не меняется.
- Session собирает фактические committed physical write callbacks из
  `step_paged_mov`, включая walker A/D writes. До возврата guest report или
  ошибки сверяет callback ranges с физической code page. При пересечении читает
  актуальное generation и синхронно инвалидирует обе idle alias cache entries.
- Сценарий успеха выполняет guest store по alias B в immediate уже
  закэшированного register-only блока. Оба alias исполняют обновлённые bytes;
  обе старые cache entries очищены до повторного lookup.
- Fault-сценарий использует CR3 page, физически совпадающую с code backing.
  CPL3 store commits PML4 Accessed update в этом backing, затем получает #PF на
  unmapped operand. CPU state и retirement не меняются, operand write не
  committed, callback приводит к invalidation обеих alias entries.
- Store в другую RAM page commits свои байты, не меняя generation code page и
  оставляя обе alias entries resident.
- Existing `step_paged_mov` может направить operand access в зарегистрированный
  MMIO; S4-16b проверяет только RAM. Reconciliation получает committed physical
  RAM write callbacks и не представляет device-side writes.

## Ограничения и измерения

Этот correctness slice связывает только существующий `step_paged_mov` guest
writer с инвалидацией cache внутри одной bus-bound session. Он не доказывает
универсальную интеграцию всех writer APIs, remap/TLB invalidation, cross-page
operand semantics, MMIO behavior или active-block retirement. Производительность не измерялась;
speed claim отсутствует. См. также [план S4-16](../plans/STAGE_4.md#s4-16-physical-aliases-и-инвалидация-исполняемого-кода).
