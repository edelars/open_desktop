# S3-28c / S3-28d: STOP/event matrix, shared budget, local STOP latency

**Status:** done as checks and documents; no product code changed. S3-28 itself stays open (closing belongs to the coordinator). One vCPU, JIT path without SMP. The latency measurement is local, not Mini, and promises no number of milliseconds.

## What was done

- **S3-28c matrix.** The case → test table (cached register, checked-memory, NOP fallback, paged session; cases STOP before entry, STOP at the k-th instruction of a 32-instruction block, STOP in a guest loop, STOP next to a helper/fault, budget exhaustion, STOP over event) is in `docs/specs/JIT_CONTRACT.md`, section "S3-28c / S3-28d". Every cell names an existing test or a new one; cells that cannot apply to a path are marked with the reason (artifact of at most two instructions; one instruction per call; no STOP/event input in `PagedFetchedLoadSession`).
- **Latency bound in guest work** (same section): STOP is one instruction, also inside a pair (for a two-site memory artifact it is polled on the boundary before the second site); the pair bound (at most two instructions) applies only to the event; an event is one bounded block (at most 32 instructions by contract), one memory artifact, or one bare NOP step. Found while measuring: the compile pipeline rejects emitted code above `MAX_EMITTED_BLOCK_BYTES = 4096`, the admitted instruction count depends on the instruction forms (ten MOV give 3868 bytes, `ten_mov_block_remains_inside_the_unchanged_code_size_limit`); the measured form (`NOT RAX` plus guards) fits up to 9 instructions; the 32-instruction block is exercised through the emitter directly.
- **Shared budget:** native blocks and interpreter NOP steps decrement one budget; existing `forwards_remaining_budget_*` and `rejects_invalid_counters_*` plus the new end-to-end test below.

## S3-28d: local measurement

Local only (development machine, Apple M3 Max, Darwin 25.6.0 arm64), not Mini, no millisecond promise. Ignored test `s3_28d_local_stop_latency_on_the_busy_cached_register_path` in `crates/od-host/tests/s3_28d_stop_latency.rs` (od-host, not od-jit, because native publication lives in od-host). Protocol: a worker thread runs the cached register dispatcher over an endless guest loop; the control thread waits until the worker has run at least 1000 more blocks, spins a pseudo-random 0 to 200 microseconds, takes `t0`, stores `stop_requested = 1`; the worker takes `t1` right after the dispatcher returns `StopRequested`. Latency = `t1 - t0` (includes the store, observation by a guard or the dispatcher boundary, frame unwind, result decode, one `Instant::now()`; excludes wake-up of an idle thread).

Commands:

```text
cargo test -p od-host --offline --test s3_28d_stop_latency -- --ignored --nocapture --test-threads=1
cargo test -p od-host --release --offline --test s3_28d_stop_latency -- --ignored --nocapture --test-threads=1
```

1000 runs per configuration; raw values (ns) are in `docs/reports/data/stage3/s3-28d/stop_latency_<config>_<profile>.txt`.

| Configuration | Profile | median | p95 | p99 | max |
| --- | --- | --- | --- | --- | --- |
| `loop2` (ADD; JZ, 2-instruction block) | release | 459 ns | 833 ns | 959 ns | 21458 ns |
| `blockmax` (8 NOT RAX + JZ, 9 instructions, largest block the compile pipeline accepts) | release | 1208 ns | 2416 ns | 5334 ns | 22709 ns |
| `loop2` | debug | 3084 ns | 6000 ns | 18583 ns | 29333 ns |
| `blockmax` | debug | 8500 ns | 15625 ns | 21666 ns | 54458 ns |

Clock tick about 42 ns. The maxima include scheduling noise. This is an observation on this machine and build, not a latency guarantee.

Unsafe: new `unsafe` only in test code of `crates/od-host/src/lib.rs` (block emit, `transmute` to the entry pointer, the entry call with a SAFETY comment); the integration tests add none. The `largest_compilable_block` probe in the ignored test now requires `BlockCompileError::EmittedCodeTooLarge` for every size that does not compile and panics on any other error. Limitation of the guest-loop test: the state is identical at every block boundary (the native register profile admits only RAX-based forms and `JZ` needs ZF set; `ADD RBX,1` and `NOT RDX` were tried and rejected by admission). The test relies on counters (blocks, retirement, publications) and the interpreter comparison for exactness.

**Warning:** the ignored measurement writes into `docs/reports/data/stage3/s3-28d/` (or `OD_S3_28D_OUT`) and overwrites the saved data on every re-run; do not run it in this repository without intending to replace the data.

## Limits

One vCPU; JIT path without SMP (the interpreter `StopAck`/`SafePoint` protocol is not claimed); no timer, APIC or event delivery; the paged session has no STOP/event input and no production host loop yet (S3-38 / S6-40); measured guest forms are register-only; the 32-instruction case (b) uses the emitter directly because of the 4096-byte compile cap; measurement is local and single-run per profile.
