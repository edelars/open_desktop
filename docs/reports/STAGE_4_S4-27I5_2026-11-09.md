# Stage 4 S4-27i5 — перевод UART-probe на pump, общий загрузчик, закрытие оговорок S4-27

Статус: срез реализован исполнителем, ревью не проводилось. В плане `[x]` не ставился: S4-27i5, S4-27i, S4-27 и
Stage 4 остаются открытыми (S4-27i4b тоже открыт). Данные: [s4-27i5-uart-pump.json](data/stage4/s4-27i5-uart-pump.json).

## Что найдено до реализации

- Планом предполагалось, что UART-probe просто работает на pump. Это не так: pump S4-27i1–i3 не умеет исполнять `LIDT [RSP+0]`
  и `IN`/`OUT` (обычный интерпретатор их не выполняет), не знает очередь RX и линию UART->INTIN4, ждёт сроки только при IF=1,
  а доставку на границе совмещает с первой инструкцией handler (старый UART-цикл входил отдельным шагом).
- Поэтому срез добавляет к pump аддитивные точки расширения (хост и режим входа без первой инструкции), а UART-специфика
  остаётся адаптером. Без хоста и флага pump не меняется.

## Что сделано

- **Pump** (`interrupt_pump.rs`): трейт `PumpHost` (`dispatch`, `next_deadline`, `step`, `as_any`), `PumpHostEvent`, `PumpHostStep`,
  `PumpTraceKind::Host`, `PumpRejection::Host`, поле `clock_ns` в `PumpTraceEvent`, `with_host`, `with_entry_only_delivery`, `host`,
  `host_mut`, `advance_time_ns`. Срок хоста ждётся и при IF=0 (нужно для S4-24e: байт RX при IF=0 фиксируется в IRR).
- **UART-probe** (`stage4_uart_irq_probe.rs`): цикл удалён; `Stage4UartIrqProbe` = `InterruptPump` + `UartOwner` (RX-очередь,
  линия UART->INTIN4, мгновенный TX, `LIDT`, `IN`/`OUT`) + отображение трассы и выходов. Публичный API сохранён; в
  `Stage4UartIrqProbeError` добавлен вариант `ClockState` (часы теперь принадлежат сессии).
- **Общий загрузчик** (`stage4_interrupt_probe_common.rs`): `FlatProbeSpec`, `validate_flat_image`, `build_flat_pump`,
  `flat_entry_state`, `flat_access_context`. Три загрузчика (`stage4_interrupt_{pump,timer,queue}_probe.rs`) стали обёртками
  по 70-80 строк (было 191, 206 и 204 строки); публичные константы, ошибки, функции и тексты ошибок сохранены. Загрузчик
  UART-probe использует только вход состояния и контекст доступа.
- **Runner:** в трёх модулях pump/timer/queue в `match` по `PumpTraceKind` добавлена пустая ветка `Host(_)`.
- **Документы:** `docs/specs/MACHINE_CONTRACT.md` (раздел S4-27i5; пометки в S4-24e, S4-27g, S4-27h, S4-27i1),
  `docs/testing/MACHINE.md` (пункт 70), этот отчёт и JSON.

## Что осталось адаптером и почему

| Часть | Где | Причина |
|---|---|---|
| RX-очередь `UartRxEventPump`, срок для idle advance | `UartOwner::dispatch/next_deadline` | не IRQ-очередь pump; доставляет байт в регистр UART |
| линия UART -> INTIN4 (`set_intin4` по смене уровня) | `UartOwner::sync_line` | pump не знает устройств |
| мгновенный TX | `UartOwner::drain_tx` | свойство профиля S4-24e |
| `LIDT [RSP+0]`, `IN AL,DX`, `OUT DX,AL` | `UartOwner::step` | нет в обычном интерпретаторе и в шагах pump |
| отображение `PumpExit`/`PumpTraceKind` в типы S4-24e | `map_exit`, `trace_kind`, `sync_trace` | публичный API S4-24e |

## Отклонения и ограничения

1. Тексты `Rejected(..)`/`IntegrationError(..)` строятся из отказов pump и могут отличаться от прежних; тип выхода сохранён, кроме п. 8.
2. CLI (`FA`) pump исполняет, старый цикл давал terminal `Unsupported`; частичный REP довершается (раньше `IntegrationError`).
   В образах S4-24e этих инструкций нет, не наблюдаемо.
3. `Cli` и `Coalesced` в UART-трассу не отображаются.
4. Расширение pump проверено только через UART-probe (отдельных тестов хоста нет); поведение без хоста подтверждено
   неизменными тестами pump.
5. Часы UART-probe теперь принадлежат сессии: `advance_time_ns` при остановленном или terminal CPU отказывает
   (`ClockState`).
6. STOP стал финальным — изменение поведения S4-24e. Старый цикл на STOP делал `break` с `Stopped` без `finished`: session
   не останавливалась, следующий `run` продолжал работу. Pump на STOP вызывает `stop_cpu()` и ставит `finished = Stopped`:
   все следующие `run` возвращают `Stopped`, `advance_time_ns` отказывает `ClockState`. Тесты и runner (`--cancel-after`,
   один `run`) этого не видят. Принята семантика pump (S4-27i1); возобновляемый STOP в адаптере не сохранён (кандидат
   ISSUE-072, если понадобится).
7. Доставка внутри STI-кванта (`step_sti_quantum`, `Delivered`): entry-only не действует, первая инструкция handler
   исполняется в кванте, `Entry.rip` = handler + длина инструкции. Старый цикл давал `Rejected("STI quantum: …")`.
8. Wake из HLT с ошибкой `into_running`: было `IntegrationError`, стало `Rejected(HaltEntry(ProfileRejected))`; тип выхода
   в этом случае не сохранён (уточнение к п. 1).
9. Уточнение к фразам «поведение S4-24e не менялось» и «публичный API сохранён»: публичный API сохранён; поведение
   сохранено для всех сценариев с тестами и runner, кроме финальности STOP (п. 6) и п. 7, 8.

## Оговорки S4-27: было и стало

- Было: «только плоская identity Long64/CPL0 без paged-входа и IRETQ; автоматического event pump и scheduler нет».
- Закрыто: paged вход и IRETQ одного вектора (S4-27h); paged STI/HLT и wake (S4-27i4a); flat pump с границей, STI/HLT/wake,
  таймером, очередью IRQ и арбитражем простоя (S4-27i1–i3); UART-probe на pump (S4-27i5).
- Остаётся: pump поверх paged-бэкенда (S4-27i4b); `run_boot`, плата, время по инструкциям, PIT/PIC/INTIN2, ISSUE-067 (S4-37a);
  общий paged-интерпретатор и Linux EOI `movl` с disp32 (S4-38); вложенные #PF/#NP/#DF, CPL3, IST != 0, TLB (S4-33);
  JIT внутри pump (`not_supported`, S4-33); MOV SS и её тень (задача этапа 2).
