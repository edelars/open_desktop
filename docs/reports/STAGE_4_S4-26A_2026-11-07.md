# Stage 4 S4-26a: fixed-edge IOAPIC route

S4-26a adds an opt-in `od-machine` IOAPIC at MMIO base `0xFEC00000` and one
programmable route, INTIN4 to physical Local APIC ID 0. The guest configures
the entry through Dword IOREGSEL/IOWIN accesses at offsets `0x00`/`0x10`, using
selectors `0x18` and `0x19` for the low and high halves of redirection entry 4.
The selected profile supports Fixed delivery, physical destination 0,
active-high edge mode, masking, and vectors `0x10..=0xFE`; reset leaves it
masked. The partial model does not expose an IOAPIC Version value.

The external input API tracks INTIN4's level. An unmasked low-to-high edge
requests a fixed vector from the existing Local APIC. A masked edge is ignored
and is not replayed by unmasking; high-to-high also does not create an edge.
Already pending requests remain in the Local APIC IRR when route settings
change, and equal vectors coalesce there. If the Local APIC rejects the
request, the input transition is not consumed and the caller can retry. The
caller must serialize operations on both controllers, including resets and
enable changes.

Register semantics follow Intel's [82093AA I/O APIC document 290566-001,
preliminary release](https://intel-vintage-developer.eu5.org/DESIGN/PCISETS/DATASHTS/29056601.PDF),
§§3.1–3.2.4. This historical device document grounds the selected register
subset; it is not a claim of full IOAPIC compatibility.

## Limits

Only redirection entry 4 and one active-high Fixed edge route are modeled.
Other selectors/entries, Version/ID/ARB registers, level trigger and Remote IRR
delivery, logical destinations, APIC bus, CPU interrupt acceptance or handler
execution, IDT/IF, HLT wakeup, default board wiring, and Linux discovery are not
implemented. Device errors are local host-side results, not guest exception
delivery. Parent S4-26 and Stage 4 remain open.
