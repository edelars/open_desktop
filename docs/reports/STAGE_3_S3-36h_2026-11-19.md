# S3-36h. One warm lookup on an S0-09 cache hit

The ordinary S0-09 dispatcher uses the resident index returned by
`record_hit`. That index reflects the entry's position after an LRU touch.
The dispatcher saves an index for the next iteration only after a completed
block returns to its own entry RIP and passes the continuation checks.
Snapshot validation and the borrowed publication boundary apply on each
host entry. The A, A, B, B test checks the publication identities and hit
counters under both FIFO and LRU.

## Matched release measurement

The comparison uses the archived S3-36g driver on the same six one-RIP and
two-RIP countdown profiles. Both executables link release `od-host` and
use the same local hardened-runtime signing options. The baseline uses
`06bb39a`. The candidate applies the two dispatch changes above. The timer
covers a full warmed `Session::run` or synchronous interpreter call. State
cloning, initial publication and parity checks are outside the timer. Every
scored JIT call verifies full state, exit, retirement and work, and each
sample checks that all cache activity consists of hits.

Three process rounds ran the executables sequentially. The candidate ran
first in the middle round. Each profile retained eight alternating
JIT/interpreter pairs per executable and round. Both engines and both
builds used identical fixed calls per profile. The per-side floor was 50 ms.
The call counts are half the S3-36g counts, rounded up.
[S3-36g profiles and comparison boundary](STAGE_3_S3-36g_2026-11-19.md)

## Results and decision

The audit verified 576 timed sides. The shortest lasted 69.588 ms. The raw
ratio compares median JIT times within each process round. The normalized
ratio compares the per-round medians of paired JIT/interpreter ratios.
Both columns give the median and full range across three rounds. The last
column pools the 24 candidate JIT/interpreter ratios per profile.

| Profile | Candidate / baseline raw | Candidate / baseline normalized | Candidate / interpreter |
| --- | ---: | ---: | ---: |
| `same_1` | 0.9627 [0.9468, 0.9707] | 0.9721 [0.9541, 0.9751] | 1.4255 [1.3937, 1.4861] |
| `same_3` | 0.9664 [0.9610, 0.9930] | 0.9715 [0.9692, 0.9762] | 0.6241 [0.6091, 0.6853] |
| `same_64` | 0.9730 [0.9725, 0.9806] | 0.9867 [0.9828, 0.9892] | 0.1132 [0.1110, 0.1163] |
| `same_4096` | 0.9826 [0.9800, 0.9844] | 0.9925 [0.9875, 0.9979] | 0.0867 [0.0853, 0.0913] |
| `two_64` | 0.9672 [0.9611, 1.0080] | 0.9718 [0.9634, 0.9815] | 1.7529 [1.7287, 1.8791] |
| `two_4096` | 0.9863 [0.9636, 0.9928] | 0.9698 [0.9683, 0.9755] | 1.7581 [1.7262, 1.7909] |

Keep the single search and continuation-time index selection in the S0-09
dispatcher. The combined change improved normalized medians in every round
for every profile. The raw `two_64` range crosses parity. The two-RIP loops
and one-pass case still favor the interpreter. The measured warm loops
retain the same guest work, cache hit counts, resident code and logical
metadata. Broader workloads and cold behavior with this patch remain open.
Physical x86 and Mac mini checks are deferred.

## Reproduction and evidence

The host was Apple M3 Max with 14 CPU cores and 36 GB RAM, macOS 26.7.1
build 25G241 and rustc 1.99.0. Both builds used
`cargo build --release --offline -p od-host --lib --message-format=json`.
