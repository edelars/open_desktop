# Этап 4 — S4-19e2: retry faulting MOV и commit данных

## Результат

Сквозной guest roundtrip после настоящего #PF теперь заканчивается повторным
исполнением исходной `MOV [RBX],RCX` с RIP, восстановленного гостевым IRETQ.
В paged MOV profile live RF очищается после fetch/decode/admission и до
проверки адреса операнда/доступа к памяти. Это происходит для разрешённых
точных load/store форм; clear сохраняется при operand #GP/#PF и backend error.
Fetch/profile exits и ограниченный cross-page store refusal сохраняют RF.
`rflags_defined` не меняется.

Guest store ретируется один раз. Tracked page walk устанавливает Dirty в leaf
PTE `0xe023 → 0xe063`, сохраняя Accessed и supervisor-only U/S=0; notification
порядок — сначала PTE, затем единственная восьмибайтовая запись данных.
Следующий guest `MOV RAX,[RBX]` читает новое значение. Соседний qword canary
остаётся прежним после store и readback. После исполнения retry live RF равен
нулю; CR2, control registers и исходный RSP сохраняются.

Реализация опирается на Intel SDM Vol. 3B §20.3.1.1 revision 090US для RF
clear timing. Условия и ошибки outside bounded same-CPL Long64/CPL0/WP=1
private-RAM profile не заявляются. Tracked path не содержит TLB, поэтому
необходимость INVLPG и eviction stale translation не проверяются.
