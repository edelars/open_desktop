# S3-37b — process-wide RSS snapshots for FIFO16 churn

**Status:** three local release processes completed the bounded 128-sweep
S3-17 register-only churn workload and recorded pre-runtime, pre-drop, and
post-drop process RSS. The snapshots are process-wide observations; they do
not attribute memory to the FIFO cache or establish leak-free lifecycle.
S3-37 remains partial.

## Scope and method

The S3-37a `od-bench cache-churn` workload was rerun with report schema 2.
Each process admitted the same frozen 1,010-case S3-17 corpus and completed
128 sweeps using one retained FIFO16 runtime/cache/arena. The runner sampled
RSS after corpus preparation and before runtime creation, after all sweeps and
before dropping the runtime, and after explicitly dropping the runtime. RSS
sampling occurs outside timed dispatch intervals. On macOS, `/bin/ps -o rss= -p
<pid>` returns KiB, which the runner converts to bytes. Each snapshot records
its method and either a value or an unavailable reason.

RSS covers the entire benchmark process, including the runner, fixtures,
runtime, allocator state, and other live allocations. A lower post-drop RSS
does not prove runtime-owned memory was released; a higher post-drop RSS does
not prove the cache retained it. Runtime teardown correctness, leak-free
behavior, independent-instance isolation, SMC invalidation, and memory
workloads remain outside this bounded observation.

## Results

RSS is shown in KiB (JSON stores bytes). All nine snapshots were available and
used the same macOS `/bin/ps` method.

| Measure | Run 1 | Run 2 | Run 3 |
|---|---:|---:|---:|
| RSS before runtime creation | 5,056 | 5,024 | 5,040 |
| RSS after sweeps, before runtime drop | 5,808 | 6,000 | 5,904 |
| RSS after runtime drop | 5,744 | 5,936 | 5,840 |
| Post-drop minus pre-drop | -64 | -64 | -64 |
| Post-drop minus pre-runtime | +688 | +912 | +800 |
| Cumulative cache hits | 256 | 256 | 256 |
| Cumulative misses / compiles / publications | 168,960 each | 168,960 each | 168,960 each |
| Cumulative evictions | 168,944 | 168,944 | 168,944 |
| Resident entry / code / logical metadata high-water | 16 / 21,640 B / 50,124 B | 16 / 21,640 B / 50,124 B | 16 / 21,640 B / 50,124 B |
| Published arena reservation | 65,536 B | 65,536 B | 65,536 B |

The process-wide RSS decreased by 64 KiB between the pre-drop and post-drop
snapshots in every run. After dropping the runtime, RSS remained 688–912 KiB
above its pre-runtime snapshot. This pattern is observed only for these three
processes; it cannot distinguish allocator retention, other benchmark-process
allocations, or runtime-owned memory. The counters and bounded resident
high-water match the S3-37a workload, but this does not extend to other
workloads or resource lifetimes.

## Verification and limits

The runner implementation passed `cargo fmt -p od-bench -- --check` and
`cargo check -p od-bench --all-targets --offline` before these measurements.
Three release runs completed successfully; raw JSON hashes and source/input
fingerprints are recorded above. Host power, thermal, and background-load
telemetry was not recorded. No Mini/physical x86 or Stage 2 checks were run.
RSS snapshots do not close the S3-37 lifecycle/resource gate.
