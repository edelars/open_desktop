## Scope

This report covers only the existing two typed V2 memory entries:

- `48 89 03 48 8B 0B`: `MOV [RBX], RAX; MOV RCX, [RBX]`.
- `48 8B 03 48 89 02`: `MOV RAX, [RBX]; MOV [RDX], RAX`.

The test uses the public compiler, host publication/execution API, and
`od_isa::execute` interpreter. Each backend receives an independent complete
CPU and private synchronous RAM snapshot. The fixture's instruction bytes are
separate from its data RAM; qword writes are all-or-nothing and no asynchronous
or concurrent observers exist.

## Corpus and comparisons

`crates/od-host/tests/memory_corpus.rs` defines three fixed seeds and generates
400 inputs for each seed and each sequence: 2,400 unique successful inputs in
total. Uniqueness uses the complete sequence, 16 GPRs, flags, effective access
addresses, and all RAM bytes. Every input is executed twice by both backends.
Generated inputs vary qword register/RAM contents, initial destination values,
alignment, same/different ranges, and safe partial overlaps in load→store.
Store→load retains the exact artifact's same-range accesses. Comparisons check
the complete `LongModeState`, every RAM byte, exit, remaining budget, retirement,
and callback sequence/count.

The test has separate named cases for an architectural memory fault, entry
STOP, one-instruction budget exhaustion, and continuation from the second
instruction. Continuation begins from the actual CPU and RAM snapshots returned
by each backend's first budget-limited entry. The comparator self-check injects
wrong GPR, RIP, RAM byte, retirement, and missing-fault outcomes through the
same comparison function used by corpus checks. A diagnostic serialization
check verifies named-case JSON includes its seed, case ID, original input, and
both result snapshots. These named cases do not contribute to the
generated-success count. On mismatch, the test prints seed/case ID and writes
JSON with the original input and both backend observations to the system
temporary directory.
