# S3-34dn — create-only mismatch artifact and validated replay for S3-34dm

## Scope and status

This bounded slice adds one persisted mismatch artifact and a replay path for
the exact S3-34dm profile `67 89 04 24` (`MOV [ESP],EAX`). Runtime commits
`f858b7a`/`10447f0` and harness commits `89c5e28`/`13b7790` are integrated.
Runtime and harness diffs passed independent static Sol/high review. The exact
artifact-protection self-check and its fail-closed harness self-test have now
passed; full S3-34.2 runtime/replay acceptance remains open.

Follow-up commit `ee2af23` adds self-check assertions for create-only
no-overwrite behavior plus invalid-version and invalid-RIP rejection. The
follow-up diff also passed independent static Sol/high review. The exact Rust
self-check passed 1/1, and the pinned Python fail-closed harness self-test
passed.

The differential corpus creates an artifact only on a detected mismatch.
Artifacts are written with create-new semantics under
`work/stage-3/s3-34dn/run-<pid>-<timestamp>/mismatch.s3-34dn`; an existing
artifact is not overwritten. The versioned 15-field record includes all GPRs,
flags, effective address, 12 fixture RAM bytes, seed and case index, fixed RIP,
profile and exact instruction bytes, fixed RAM layout, RAM digest, both backend
observations, and comparator mismatch details.

Replay validates the schema/version, exact profile/source/RIP, seed/index
domain, input state constraints, sparse RAM layout, and FNV-1a 64-bit digest
of the saved RAM layout and bytes before compiling or publishing code. It
starts from the captured CPU/RAM state; seed and index are provenance and do
not regenerate the input. Interpreter and JIT each run twice from reset copies
of that saved state.

`reproduced` requires deterministic observations across the two repetitions
and recurrence of the recorded comparator mismatch and captured observations.
For a valid artifact where the mismatch does not recur, replay reports
`not_reproduced`; this is diagnostic evidence, not a passing regression gate.
When the optional replay test has no artifact environment variable or the
named file is absent, it also reports `not_reproduced` without replaying; this
must not be treated as replay evidence. Invalid artifacts fail with a distinct
validation error.

The Rust self-check
`s3_34dn_replay_artifact_self_checks_roundtrip_and_fail_closed` uses explicitly
labeled synthetic mismatch data. It checks serialization, classification,
and fail-closed validation for profile/source/address/digest/layout mutations;
it does not execute either backend or establish runtime mismatch evidence. The
separate optional replay Rust identity is
`replay_saved_s3_34dn_mismatch_artifact`. Harness gate
`s3_34dn_replay_artifact_self_check` and fail-closed self-test
`test_s3_34dn_replay_artifact_self_check_gate_is_pinned_and_fail_closed` are
pinned. These checks validate the labeled synthetic artifact and harness
registration; they do not run interpreter/JIT parity or replay a persisted
runtime mismatch artifact.

The self-check now directly exercises the filesystem create-new/no-overwrite
path by preserving a pre-existing sentinel file, and checks parser rejection
after version and RIP mutations. These assertions are accepted for this
synthetic self-check; they do not establish runtime artifact replay.
