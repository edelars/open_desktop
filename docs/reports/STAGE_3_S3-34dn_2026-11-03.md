# S3-34dn — create-only mismatch artifact and validated replay for S3-34dm

## Scope and status

This report records a bounded documentation plan for the existing S3-34dm
exact profile `67 89 04 24` (`MOV [ESP],EAX`). Implementation and independent
static review are pending. Execution is deferred. No runtime code or harness
implementation is included in this change.

The planned path creates one persisted artifact only when the deterministic
interpreter/JIT differential check detects a mismatch. Artifact creation is
create-only and never overwrites an existing path. The record captures the
complete initial CPU state, fixture RAM bytes and layout, instruction
address/RIP, exact profile and source bytes, S3-34dm seed/case index as
provenance, both backends' repeated observations, and mismatch classification
and details.

Replay must validate schema/version, profile/source, RIP relationship, CPU
state and RAM layout/lengths, and a digest over the captured initial input and
observations before executing. It uses the saved CPU/RAM state directly; seed
and case index are provenance and do not regenerate the case. Interpreter and
JIT execute twice from independent reset copies of the saved state, with
repeat observations compared deterministically.

`reproduced` means the recorded mismatch identity recurred. `not_reproduced`
means a structurally valid artifact replayed without that mismatch; it is
diagnostic evidence and does not pass a regression gate. Invalid or
incompatible artifacts return a separate validation error and are not
classified as `not_reproduced`.

Self-checks are planned around explicitly labeled synthetic mismatch data.
They cover create-only behavior, serialization/replay, repeat determinism,
and fail-closed rejection of version, profile, source, RIP, layout, and digest
mutations. Synthetic self-checks must not be reported as runtime mismatch or
replay evidence.

## Boundaries and counts

The scope excludes a generic replay framework, reducer (broader S3-34.2 work
remains pending), new runtime APIs, dependencies, and opcodes. No runtime
semantics change is planned. ISSUE-028 remains open until S3-20eg execution
acceptance.

The integrated S3-34dm baseline is 303 gates (293 acceptance + 10 lifecycle),
321 local steps, and 136 self-test names. The target delta is exactly +1 gate,
+1 step, and +1 self-test name, for targets of 304 gates (294 acceptance + 10
lifecycle), 322 steps, and 137 self-test names. These are planning targets
only: exact identities, the static diff, and the recount await implementation
and review.
