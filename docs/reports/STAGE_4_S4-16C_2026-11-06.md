# S4-16c: physical loader writes invalidate inactive aliased code

**Status:** accepted after independent review. Parent S4-16 and Stage 4 remain
open.

## Scope

One vCPU, fixed Long64 paging snapshot, one captured physical RAM code page,
two virtual aliases and the existing bounded register-only native cache. This
slice adds one privileged physical RAM loader write between native calls. It
does not add a mutable bus handle, arbitrary writer callback, guest permission
check, remapping, cross-page code, MMIO/DMA, SMP or active native-code mutation.

## Implementation

- `MachineBus::patch_physical_ram_with_callback` forwards the exact committed
  range reported by `PhysicalMemory::write_bytes`. The existing
  `patch_physical_ram` method delegates with a no-op callback.
- `PagedCodeSession::write_physical_ram` accepts a typed physical address and
  byte slice and collects committed ranges. It reconciles those ranges before
  returning success or an error.
- Guest-store and physical-loader paths share one reconciliation helper. If a
  committed range overlaps the captured code page, the session reads the
  current per-page generation and applies `BackingContentChanged` to both alias
  caches. This applies to a write outside the admitted instruction bytes but
  inside the same physical code page. A different page does not invalidate the
  code aliases.
- The `code_invalidated` result flag means the operation detected an overlapping
  committed range and applied invalidation to both caches. It does not assert
  that an entry was resident or removed.

## Evidence

The `s4_16c_physical_loader_write_invalidates_only_committed_code_page`
scenario verifies:

- Exact callback range and generation update for physical replacement of the
  eight-byte immediate in a cached `MOV RAX, imm64`, then one retired native
  instruction and the expected immediate through each alias.
- Conservative invalidation for a physical write elsewhere in the same code
  page, outside the admitted instruction range.
- A neighboring guest page write updates its generation while preserving the
  code generation and both cached alias entries.
- A RAM/ROM boundary-crossing write and a ROM write fail without modifying RAM
  or code generation, without emitting a callback, and without evicting either
  alias entry.
- Existing S4-16a and S4-16b regressions remain green.

## Checks and review

- `cargo test -p od-host --lib --offline s4_16c_ -- --test-threads=1` — 1 passed,
  0 failed.
- `cargo test -p od-host --lib --offline s4_16 -- --test-threads=1` — 4 passed,
  0 failed (S4-16a/b/c).
- `cargo check -p od-host --all-targets --offline` — passed with existing
  warnings in `od-jit` and `od-host`.
- `cargo fmt --all -- --check` and `git diff --check` — passed.
- Graphify updated after the implementation; node and edge totals are recorded
  in the accompanying manifest.
- Independent `gpt-6.1-sol/high` review found three test/documentation precision
  issues. The alias checks now seed a sentinel and verify native retirement; the
  bus callback is directly observed on failed writes; and the result-field
  contract describes invalidation rather than claiming a resident entry was
  removed. A second independent review confirmed these fixes and found no code
  defects. The missing report and manifest were added after that review finding.

## Limitations

This slice covers one physical RAM loader writer only. General writer
notifications, page-table remap/TLB invalidation, cross-page code,
MMIO/DMA-originated changes, SMP, and active-block retirement/lifetime remain
open under S4-16. The loader and cache path are correctness work; no performance
measurement or speed claim is made.
