# Stage 3 S3-20bh: direct RSI/RDI qword memory bases

## Scope

Added exact singleton `48 8B/89 /r` with ModRM `mod=00`, `rm=110` (RSI) or `rm=111` (RDI), data RAX..RBP, qword transfer and exact length three. RSI/RDI are accepted only as direct bases for this profile; no SIB, displacement, address override, added prefix, pair or V3 profile was introduced. Effective address and canonicality checks continue to come from the decoded `MemoryOperand::access_address_48` path.

## Evidence

- JIT descriptor tests cover load/store × six data registers × both bases, assert the exact decoded metadata/source shape, and reject displacement, SIB, address32, partial-window and RSI/RDI-as-data neighbors.
- Host tests compare direct V2, shared IR native execution and interpreter state/RAM for all 24 operation/base/data combinations. Each operation retires once and makes exactly one 8-byte callback at the independently computed old RSI/RDI target. Loads update only the destination after success; stores preserve the full 64-bit payload; each base remains unchanged.
- Noncanonical first-byte and last-byte load/store addresses produce guest #GP before any callback and preserve CPU state, RAM and retirement (zero retired). Address overflow remains a distinct host diagnostic with no callback. Backend load/store failures remain host errors; the attempted address/count are asserted and no state or RAM is committed.
- Entry STOP, zero budget and stop-RIP guards perform no callback. Store+STOP commits once and returns at the next RIP. Dispatcher budget split resumes from actual RIP, reads the second RSI/RDI-based instruction once, and does not replay the first read.
