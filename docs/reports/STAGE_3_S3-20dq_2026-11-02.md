# S3-20dq — address-size-32 SIB dword stores with signed disp32

**Status:** bounded partial implementation evidence; S3-20 and Stage 3 remain
open.

Runtime commit `2636e6c` adds exactly four eight-byte shared typed-IR store
singletons:

- `67 89 84 0B id` — `MOV [EBX+ECX*1+signed disp32],EAX`
- `67 89 84 4B id` — `MOV [EBX+ECX*2+signed disp32],EAX`
- `67 89 84 8B id` — `MOV [EBX+ECX*4+signed disp32],EAX`
- `67 89 84 CB id` — `MOV [EBX+ECX*8+signed disp32],EAX`

The decoder-owned address-size-32 effective address adds low32 EBX, low32 ECX
times the SIB scale, and signed disp32, wraps to 32 bits, and zero-extends
before canonical checking. The high halves of RBX and RCX do not contribute.
Each instruction performs one contiguous checked four-byte write of low32 RAX
and has guest boundary `A+8`.

The JIT source/site test covers all four scales and a set of signed disp32
values, including each encoded displacement-byte mutation and rejection of
neighboring forms. It verifies exact source/site binding and the eight-byte
boundary. Host cases compare published native execution with the interpreter,
including address wraparound and high register halves, and check write/fault,
budget, STOP, and committed-write stop behavior. Their memory fixture is
private synchronous RAM with one checked write callback. It does not test
MMIO, guest self-modifying code, owner notification, or MMU integration.
