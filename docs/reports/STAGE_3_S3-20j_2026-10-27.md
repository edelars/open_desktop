# S3-20j / S3-26c / S3-20k / S3-26d — exact two-site memory entries

**Date:** 2026-10-27. **Status:** bounded implementation and local native
ARM64 verification complete; independent review pending. Physical x86 remains
part of the later S3-21 gate.

## Scope

The new opt-in profile accepts exactly `48 89 03 48 8B 0B`:
`MOV [RBX], RAX` followed by `MOV RCX, [RBX]`. One `BasicBlock` and typed IR
carry both instructions and their independent commits. The verifier binds each
memory effect to its active guest instruction and requires the store to be
immediately followed by its own commit. The dedicated emitter creates one
entry with a two-element helper-site table. The second site and all second
instruction state-map ranges identify the load instruction.

The typed artifact, compile flavor, publication metadata, and host execution
method are separate from the existing singleton V2 load/store APIs. Those APIs
retain their index-zero checks. This artifact executes only synchronous
private ordinary RAM under the same all-or-nothing write and no-concurrency
preconditions as the existing checked-store path. Branches, executable/code
aliases, MMIO, atomics, and general multi-site blocks are not admitted.
The public unsafe host entry and pair helper document the private synchronous
RAM, all-or-nothing write, alias, concurrency, re-entry/unwind, and lifetime
preconditions.

## Local evidence

- Builder test accepts the exact pair, stops at the pair even when source bytes
  follow, and rejects a wrong second instruction.
- Lowering and verifier tests cover two instruction records, store→commit→load
  order, wrong commit index, missing store commit, and early load commit.
- Native ARM64 host test verifies callback order `write, read`, exact RCX/RAX
  equality, two retirements, and full-state/RAM agreement with two interpreter
  steps on independent copies.
- Store architectural fault preserves CPU/RAM and returns the exact payload.
  Load architectural fault retains the store, leaves RCX unchanged at the
  second RIP, and retires only the store. Resuming at the load RIP yields a
  second read callback without repeating the write.
- A second architectural load fault during continuation is decoded as the
  same guest fault with zero continuation retirements. A continuation backend
  read error is decoded as a backend `MemoryError`; both callback traces remain
  `write, read, read`, proving the store was not repeated.
- STOP raised by the write callback preserves the store and prevents the load.
  Zero budget, entry STOP, and stop-RIP at entry call neither helper. Budget 1
  commits the store and a later invocation at the load RIP performs only load.
- Simultaneous stop-RIP and exhausted one-instruction budget at the load
  boundary returns `StopAddress`; STOP raised by the write callback with the
  same stop-RIP also returns `StopAddress`, preserving guard order
  stop-RIP → STOP → budget.
- PC map contains distinct helper and planned-failure ranges for instruction
  indices 0 and 1; the successful store helper/commit path is non-replayable.
  The typed artifact is rejected by V1 and singleton V2 execution APIs.

## S3-20k / S3-26d extension: exact load→store

The shared typed two-site artifact and emitter now also admit exactly
`48 8B 03 48 89 02` (`MOV RAX, [RBX]; MOV [RDX], RAX`). Sequence metadata is
explicit and host publication validates the sequence bytes, decoded operation,
operand registers, site indices, and `A`, `A+3`, `A+6` boundaries. The shared
emitter commits loaded RAX at the first boundary, then runs the store site.
Singleton V2 APIs keep their original index-zero checks; the legacy named
store→load typed API rejects a load→store sequence.

The native ARM64 host fixture verifies `read, write` callbacks; a loaded value
that differs from initial RAX; two retirements; and full-state/RAM agreement
against two interpreter steps on independent copies. Load fault preserves the
complete initial CPU/RAM state with no store. Store fault after load preserves
loaded RAX, leaves destination RAM unchanged, returns at the second RIP with
one retirement and the exact fault payload. Repeated and resumed store faults
perform no reread; after changing source RAM, successful continuation writes
the already committed RAX. Backend store error remains a host memory error.
STOP raised by successful read and budget 1 stop at the second RIP after one
retirement with no store; zero budget and entry STOP call no callbacks.
Second-boundary stop-RIP wins over budget and over STOP raised by the read
callback. A backend read error also remains a host error with no load/store
commit.

The same private synchronous ordinary RAM, all-or-nothing write, no executable
aliases, no MMIO/atomics/concurrent access, no re-entry/unwind preconditions
apply. No arbitrary memory pair support or performance claim is introduced.
The focused `od-jit`/`od-host` tests passed 131 and 59 cases respectively on
the local ARM64 host. `cargo fmt --all -- --check`, workspace all-targets
offline check, Linux `od-host` all-targets check, `git diff --check`, and
`graphify update .` passed. Linux emitted existing dead-code warnings for
macOS-only mapping code. Graphify emitted its existing header parser warning
for `include/open_desktop/host_abi.h` and no-symbol manifest warnings. No
benchmark was run. Independent review signed off with no open findings;
the reviewer independently passed the same scoped tests, formatting,
workspace/Linux checks, and diff check.
