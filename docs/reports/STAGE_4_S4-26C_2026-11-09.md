# S4-26c — IOAPIC ID/Version, окно регистров и недопустимые записи

## Что сделано

`IoApic` отвечает на регистры ID (`0x00`), Version (`0x01`), Arbitration ID
(`0x02`) и все 24 redirection entries (селекторы `0x10..=0x3F`) через
IOREGSEL/IOWIN `0xFEC00000`. Состояние лежит в `Route` (`apic_pair.rs`): добавлены
`id` и `pins` (low dword входов, кроме INTIN4). Логика окна переписана в
`io_apic.rs` (`Register`, `register`, `valid_low`); вход 4 по-прежнему идёт через
`PairState::set_low`, поэтому проверки конфликтов, Remote IRR, EOI S4-26a/b не
менялись.

## Решения

- **ID:** reset = 1 (то же, что `IOAPIC_ID` в MADT S4-31f); биты 27:24 RW,
  запись reserved-битов — `UnsupportedConfiguration`; reset (`IoApicHandle::reset`,
  `reset_pair`) возвращает 1; на маршрутизацию не влияет.
- **Version:** `0x00170020` (версия `0x20`, MRE 23), read-only, запись —
  `UnsupportedConfiguration`.
- **Arbitration ID:** `ID << 24`, read-only (82093AA загружает его из ID; шины и
  арбитража нет), запись — `UnsupportedConfiguration`.
- **Неизвестный select:** IOREGSEL хранит любой байт (> 0xFF — отказ); IOWIN на
  чтение и запись при неизвестном select — `UnknownOffset`, состояние (снимок
  `PairState`) не меняется, политика S4-26a/b.
- **Polarity (правка по ревью):** на входах без линии (все, кроме INTIN4) под маской
  допускается бит 13 = 1 (SCI GSI 9 level/active-low в MADT); запись без маски с
  этим битом — UnsupportedConfiguration без изменений. INTIN4 не менялся.
- **Redirection:** входы 0..23, high dword принимает только 0 (physical
  destination 0), low — Fixed, physical, active-high, mask/trigger/vector.
  Вход 4 маршрутизирует, остальные 23 хранят конфигурацию (reset masked), линии
  и Remote IRR у них нет.
- **Отказы без изменения:** unmasked vector < 16 и `0xFF`, любой delivery mode
  кроме Fixed (все семь значений, в том числе зарезервированные `011`/`110`),
  logical destination (бит 11), polarity (кроме masked на входах без линии), reserved-биты, ненулевой high dword.
- **Masked-политика (расширение):** masked entry допускает любой vector: reset
  уже masked с vector 0, и Linux маскирует входы с vector 0. Прежние отказы S4-26a
  (vector 0/15/0xFF без маски) сохранены.
- **Logical destination:** отказ; routing не реализован (граница, риск для Linux
  при logical flat mode, см. S4-25f «Открыто»).

## Согласование с MADT

MADT живёт в отдельном crate прошивки, `od-machine` от него не зависит. Тест
`model_agrees_with_the_firmware_madt` читает ID и адрес I/O APIC из байтов MADT
реального blob-фикстуры (`tests/fixtures/guest/stage4/acpi_blob/stage4_acpi_blob.bin`,
после `validate_acpi_blob`), а число входов (в MADT его нет) — из
`IOAPIC_PIN_COUNT` в `firmware/uefi/src/acpi/madt.rs` через `include_str!`.
Сверка: ID = 1, MRE = 23, вход 23 существует, вход 24 нет. Комментарий в
`madt.rs` («NOT checked against a guest read of the device») по-прежнему текстово
устарел; MADT/blob не менялись (граница задачи).

## Изменённые ожидания старых тестов

Один: `reset_registers_and_rejected_accesses_are_atomic` брал селектор 1 как
«неизвестный» (ожидал `UnknownOffset`) — теперь это Version. Тест использует
селектор 3, а чтение IOREGSEL ожидает 3 вместо 1 (дважды). Остальные 10 прежних
тестов без правок.

Правки по ревью Opus: недостижимые ветки `pin >= 24` удалены (селекторы 0x10..=0x3F дают pin 0..=23
по построению); цикл по структурам MADT в тесте защищён `assert_ne!(len, 0)`;
комментарий про Version исправлен.

## Ревью

- Первое независимое ревью (Claude Opus, high, read-only): принято с условием. Отказы, снятие маски и согласование с MADT проверены; обходов не найдено. Замечание принято: MADT объявляет SCI на GSI 9 как level/active-low, модель отвергала polarity на любом входе — исправлено: masked active-low хранится на входах без линии, unmask с polarity — отказ без изменения состояния.
- Повторное ревью правок (тот же ревьюер): код и тесты в порядке; три мелочи формулировок в контракте и json исправлены (код UnknownOffset на 0x40; перечень расширений; оговорка про polarity).
- Срез S4-26c принят. Родитель S4-26 закрыт с оговорками из «Открыто».

## Открыто

- SCI GSI 9 (level/active-low) принимается только маскированным; разблокировка —
  отказ. Риск для S4-29/S4-38 (включение SCI).
- EOI-регистра IOAPIC (смещение `0x40`) нет; регистр `0x03` — UnknownOffset. Version
  `0x20` как у ICH/QEMU-style IOAPIC.
- Polarity из «Сделать» S4-26 покрыта только для active-high на INTIN4 и для
  маскированных входов без линии; родитель S4-26 закрывать только с этой оговоркой.

- Тексты 82093AA/SDM в срезе заново не перечитывались: ID RW 27:24, Arbitration
  ID RO и раскладка entry взяты из принятой политики S4-26a/b, не проверены по
  тексту.
- Logical destination, lowest priority, SMI/NMI/INIT/ExtINT не маршрутизируются
  (только отказ); Linux при logical flat mode упрётся в отказ (S4-38).
- Входы кроме INTIN4 не имеют линий; GSI-маршруты (SCI GSI 9, PIT GSI 2) не
  подключены.
- Один IOAPIC, PCI MSI нет; Linux acceptance — S4-38.
