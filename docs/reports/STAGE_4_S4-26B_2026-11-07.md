# S4-26b — bounded fixed-level IOAPIC route

## Result

Added active-high Fixed level-triggered delivery to the existing single
INTIN4 → physical Local APIC ID 0 route. Accepted level requests set Local
APIC IRR/TMR and IOAPIC Remote IRR together. A matching EOI clears the in
service vector and Remote IRR atomically, then accepts one further request if
the input remains asserted and the route is unmasked. TPR gates eligibility,
not acceptance. Acceptance requires APIC global enable and SVR software enable;
the configured level vector is reserved from edge/self-IPI use even when the
route is masked or inactive. An assert/unmask that cannot be accepted fails
before publishing the line or route change when it would immediately deliver
a request; masked assertion may record the high level without delivery. Global
or software disable is vetoed while Remote IRR is outstanding.

The IOAPIC and Local APIC now share one narrow state owner and mutex. There are
no callbacks or nested locks. Vector/trigger changes that could confuse an
outstanding level request are rejected before mutation. Existing edge-to-edge
vector reprogramming remains supported, preserving a previously pending edge
at its original vector.

Independent device resets preserve the other controller. Both are vetoed
without mutation while Remote IRR is outstanding; `reset_pair` explicitly
clears both devices. The APIC-base CPU helper executes against a candidate CPU
state and publishes it only after the paired Local APIC transition succeeds.
A host-side veto is not guest `#GP` and does not retire the instruction. Fetch
and page-walk effects already committed are not rolled back. Callers serialize
the full CPU helper and pair operations; guest fetch is not performed under the
pair mutex.

## Sources and boundaries

TMR acceptance and EOI follow Intel SDM 253668-093US, September 2026,
Volume 3A §§13.8.4–13.8.5. Route behavior is bounded by Intel 82093AA I/O APIC
document 290566-001, preliminary release, §3.2.4. See the
[Intel SDM](https://cdrdv2.intel.com/v1/dl/getContent/671190) and
[82093AA datasheet](https://intel-vintage-developer.eu5.org/DESIGN/PCISETS/DATASHTS/29056601.PDF).

Only one physical route, active-high polarity, Fixed delivery, and the selected
Dword registers are implemented. This does not establish APIC bus operation,
guest CPU interrupt/handler delivery, IDT/IF semantics, default board wiring,
other IOAPIC routes, Linux discovery, or full interrupt-controller reset
semantics. Parent S4-26 and Stage 4 remain open.
