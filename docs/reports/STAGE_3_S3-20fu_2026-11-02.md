# S3-20fu: RCX-base Dword store signed disp32 `89 81 id`

## Planned scope

This slice is planned to admit only the six-byte form `89 81 id`:
`MOV [RCX+disp32],EAX`, with a Dword operand, Qword address size, RCX base,
no index, and no prefix or SIB. The displacement is a signed little-endian
`i32`, sign-extended into site metadata. The effective address is computed
from the full original RCX with signed displacement modulo 2⁶⁴. The payload
is the low 32 bits of the original RAX.

Execution is planned as one contiguous checked four-byte write. All GPRs,
including full RAX and RCX, and RFLAGS remain unchanged; successful next RIP
is `A+6`. Canonicality and range preflight apply to the computed EA and full
write range. Existing guest/backend faults, entry guards, retry, and callback
STOP without replay remain in scope. Address32, SIB, other bases or source
registers, and prefixes are excluded.

Planned JIT coverage binds each displacement byte to its site, checks signed
metadata and the `A+6` PC-map boundary, and forges site fields. Supported
neighboring forms remain distinct sites. Two existing compile-negative cases
for `89 81 00000000`—in the RAX disp32 store and RCX singleton store fixtures—
must become successful compilation with bidirectional source/site mismatch
checks. The Load compiler's rejection of Store opcodes and the addr32
ECX-base negative `67 89 81 ...` must remain unchanged.

The host fixture should distinguish full RCX from a low32 decoy and keep the
low32 RAX payload independent from the effective address. It should cover
zero and unaligned EAs, canonical upper-half addresses, signed wrap, the
largest valid range, and preflight failures without calling the write
callback. Guest/backend write errors must preserve CPU/RAM and allow retry;
each entry guard must have its own successful retry; callback STOP must not
replay the committed write. Displacement-byte fetch errors must propagate
without a substitute value or fallback.

Before this slice the harness has 288 Rust gates (278 acceptance and 10
lifecycle), 306 local steps, and 128 self-test names. Target totals are 290
gates (280 acceptance and 10 lifecycle), 308 steps, and 129 self-test names.
Runtime and harness implementation, actual Rust identity verification, and
independent review are pending. These target counts are not execution results.
