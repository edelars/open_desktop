# S3-20cu — exact dword checked-memory store with disp32

**Status:** bounded implementation slice; S3-20 and Stage 3 remain open.

Runtime commit `c9a9587` adds only the six-byte singleton `89 83 id`
(`MOV [RBX+disp32],EAX`) to the shared typed-IR dword-store path. The decoded
memory operand supplies the signed disp32 effective address from full-width
RBX. The helper performs one checked four-byte write from the low 32 bits of
EAX. RIP and retirement commit only after a successful write, before STOP is
observed. The descriptor binds the source bytes and the PC map has one guest
instruction boundary at `A+6`.

This is an additional exact address form alongside `89 03`, `89 00`, and
`89 43 ib`; it does not open a general dword-store family. The host fixture
does not contain a separate noncanonical-end or 64-bit range-overflow case.
The decoded `access_address_48` path remains the shared authoritative
effective-address implementation. The missing cases are a bounded test
coverage limitation, not evidence of a runtime defect. No production
owner/MMU, SMC, cache, dispatcher, Mini, M1, Stage 2, physical-x86, or
performance conclusion is claimed.
