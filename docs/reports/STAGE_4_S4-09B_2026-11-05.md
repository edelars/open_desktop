# S4-09b — injected page-table write failures

## Result

Added a private writer seam to the tracked Long64 page walker. Production A/D
updates still call `PhysicalMemory::write_u64`; no public fault-injection API or
general framework was added.

Four A-write failures are injected independently at PML4, PDPT, PD and PT. Each
case checks the exact `TableWrite` level, entry, bit and physical error; the
writer attempt sequence stops at the failed level; the RAM entries preserve
only the successfully committed A prefix; the report contains exactly that
prefix of `AdUpdate`, followed by `None` in every unused slot of the fixed-size
journal; and callbacks list exactly those committed writes in order. The
operand remains unchanged.

A separate D-write failure after all four A writes checks the exact PT/entry/D
error, all five writer attempts, the four-entry committed A prefix, callback
order, all five `ad_updates` slots (four expected updates followed by `None`),
unchanged leaf D bit and unchanged operand. The injected failed write does not
mutate RAM or call the commit callback. Existing `PhysicalMemory` rejection
tests continue to cover atomic writer failure and absent callback.

The initial independent review requested complete fixed-array assertions and
updated parent-plan status. Both findings are addressed: both failure tests now
compare every `ad_updates` slot, and the parent entry closes injected table
write failure while retaining its other open criteria. The independent
`gpt-6.1-sol/high` review rerun found no remaining P0—P3 findings. Parent S4-09
stays open for the full permission-level matrix, CPU integration and system
acceptance.
