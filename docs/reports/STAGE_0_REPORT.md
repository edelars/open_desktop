# Этап 0 — отчёт технической приёмки

**Дата:** 22 октября 2026 года. **Статус:** ревью ISSUE-005–007 принято владельцем как пройденное после исправлений и успешных регрессионных проверок. Этап остаётся не принятым до проверки выбранного режима подписи/поставки.

## Решение

**Дополнение по ревью от 22 октября:** отдельная проверка текущего рабочего дерева обнаружила три воспроизведённых дефекта control lifecycle (ISSUE-005–007). Все три исправлены; [новая регрессионная проверка](../../tests/system/vmhost_control_race_smoke.py) прошла. По прямому решению владельца ревью отмечено как пройденное после этих исправлений и проверок. Это решение закрывает результат ревью, но не проверку режима поставки; положительная приёмка этапа в целом пока не подтверждена.

Текущий результат подтверждает жизнеспособность ограниченного headless CPU/JIT-прототипа и локального VMHost smoke path на M3 Max, а также минимальный JIT smoke на MacBook Pro с M1 Pro. Fault в сгенерированном ARM64-коде завершил дочерний процесс; protocol-level fault helper через VMHost control framing завершился по `SIGSEGV`, который launcher распознал и передал вызывающему процессу. Новая control-race smoke проверила ранний STOP, неполные кадры и естественное завершение до таймера. Локальный ad-hoc `.app` bundle smoke также прошёл. Владелец сообщает, что у него есть Developer ID certificate, но членство Apple Developer Program не активно. На доступных M3 Max и M1 Pro нет обнаруженной Developer ID Application identity; сертификат с закрытым ключом не доступен для проверки подписи на этих машинах. Apple notary service недоступен при неактивном членстве, поэтому notarization не проверена. Этап 0 нельзя объявить завершённым до проверки выбранного режима поставки.

Загрузка Windows/Linux средствами Open Desktop в объём этапа 0 не входит. Владелец подтвердил, что Windows ISO рабочий; отдельная проверка ISO не блокирует этап и не включена в его критерии. По прямому запросу владельца минимальный JIT smoke на M1 Pro был выполнен до внешнего Windows запуска; этот запуск не является технической зависимостью Open Desktop и сам Open Desktop не проверяет. S0-12/E03 был перенесён за пределы Stage 0 и позже закрыт в Stage 1 для ограниченного register-only профиля; это не меняет оставшиеся условия поставки Stage 0.

S0-12/E03 больше не является открытым carry-over: он закрыт для оговорённого профиля в Stage 1. Stage 0 остаётся не принятым из-за незавершённой проверки режима подписи/поставки.

## Открытые обязательные условия

1. **Подтвердить режим поставки в доступной конфигурации.** Локальный ad-hoc `.app` bundle smoke прошёл. Владелец сообщает о наличии Developer ID certificate, но ни сертификат с соответствующим private key, ни signing identity не обнаружены в keychains тестовых Mac; Developer ID signing поэтому не проверен. Членство Apple Developer Program не активно, и Apple указывает, что доступ к notary service при истёкшем членстве прекращается. Notarization потребует возобновить членство; до этого можно проверить Developer ID signing без notarization, если владелец установит действующую identity на тестовый Mac. Критерий выбранного режима поставки остаётся открытым.

По решению владельца S0-12/E03 перенесён за пределы Stage 0 и позднее подтверждён в Stage 1. Установка гостевой ОС средствами Open Desktop и производительность полной VM не заявляются.

## Ограничения измерений и backlog

- CPU и integration данные — короткие серии на одном M3 Max; нагрузка, температура и питание не контролировались. Они подтверждают только зафиксированные узкие сценарии.
- Для S0-13 неизвестными оставлены размер JIT executable mapping, пакетное ABI-сравнение (такого API пока нет), длительная нагрузка и бюджет нескольких полноценных VM. Ни одно решение о полной VM на этих данных не принималось.
- S0-13 измерил peak RSS smoke helpers: 5.94 MiB на процесс и 11.88 MiB как сумма peaks двух helper processes; это не оценка памяти работающих гостевых ОС.
- Известная 50 ms задержка ожидания worker завершения устранена completion pipe; результат и ограничения сравнения описаны в [ADR-0003](../decisions/ADR-0003-event-driven-vmhost-completion.md). Реестр проблем обновлён.

Подробный статус задач и критериев находится в [плане Stage 0](../plans/STAGE_0.md); условия будущих guest boot проверок — в [матрице требований ОС](../specs/GUEST_REQUIREMENTS.md) и [проекте виртуальной платы](../specs/VIRTUAL_BOARD.md).
