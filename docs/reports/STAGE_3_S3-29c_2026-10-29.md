# S3-29c: exact INC RAX partial-flags handoff

## Result

Added separate `S0_09NopIncRaxAdmission` and eager/candidate compile and dispatch
entry points for the S0-09 register subset, exact bare NOP, and exact `48 FF C0`
(`INC RAX`). Existing NOP-only admission continues rejecting INC. The new
admission validates the full immutable code view and all branch boundaries;
truncated, prefixed, wrong-width/register/opcode, DEC, and branch-into-INC forms
are rejected.

Native prefixes stop at the admitted INC boundary. The dispatcher invokes the
existing interpreter with a bounded immutable three-byte fetch window, requires
RIP to advance exactly three bytes, and accounts for exactly one interpreter
retirement. The eager and demand-flags candidate routes share the existing
uncached dispatch control/accounting loop. The candidate PC-map witness
observes pending flags in the native prefix; dispatch only reaches the
interpreter after the completed executor call has returned and released its
mapping. The following Jcc/suffix executes natively from the updated state.

Host coverage compares complete CPU state and accounting against eager and
interpreter execution for `CMP → MOV RAX,imm64 → INC RAX → JZ/JNZ → native
suffix`. It checks both CF inputs, both branch outcomes, and literal
OF/SF/ZF/AF/PF results for zero, signed qword extrema, `u64::MAX`, nibble and
parity boundaries. It checks budgets 0..6 and stop/resume at every reachable
instruction boundary without replay. An event raised after the native prefix
remains pending and yields before INC; clearing it and resuming reaches the
interpreter-equivalent final state. Simultaneous stop-RIP and atomic STOP with
an event preserve STOP priority. A synchronous single interpreter step has no
deterministic executor callback after its retirement; event-after-step
injection is not claimed. STOP-RIP at the post-INC boundary verifies no Jcc
executes before the caller resumes.
