# S3-20ea — exact RSP-based dword checked-memory store through SIB

**Status:** bounded implementation slice; S3-20 and Stage 3 remain open.

Runtime commit `9c03a54` adds only the exact three-byte singleton `89 04 24`
(`MOV [RSP],EAX`) to the shared typed-IR Dword-store path. Its decoded
address64 SIB operand uses full-width RSP as base, with no index. A successful
checked write transfers exactly four contiguous bytes from low32 RAX, commits
guest RIP to `A+3`, and preserves the other architectural state. The fixture
makes no separate PC-map phase claim.

The host fixture exercises an unaligned address above 4 GiB and compares
native execution with the interpreter for state and RAM. Noncanonical RSP at
the first byte and a width-four range extending beyond the canonical boundary
produce `#SS`; the non-stack RBX control produces `#GP`. A width-four range
overflow at `u64::MAX - 1` returns before the writer callback. An injected
backend error records one attempted width-four write and leaves CPU state and
RAM unchanged. Entry STOP and zero budget do not write. A successful write
callback that requests STOP leaves its single write and the `A+3` commit
visible; retrying the same published block with committed guest RIP `A+3`
returns `EntryRipMismatch { expected: A, actual: A+3 }`, preserves state, and
does not attempt another write.
