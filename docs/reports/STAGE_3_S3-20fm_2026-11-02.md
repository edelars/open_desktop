# S3-20fm: exact address32 RAX-alias Dword store with signed disp8

## Scope and semantics

This bounded runtime slice admits only `67 89 40 ib` (`MOV [EAX+sign_extend(ib)],EAX`).
The effective address is computed from the original low32 RAX:
`zero_extend((low32(RAX) + sign_extend(ib)) mod 2^32)`. The store payload is
the low32 of that same original RAX, independently of the displacement. The
operation is one contiguous checked four-byte write. Full RAX, other GPRs, and
RFLAGS remain unchanged; successful retirement advances RIP to `A+4`. Only the
starting EA wraps modulo 2^32. A transfer starting at the end of the 32-bit
address range continues contiguously above 4 GiB.

Admission is limited to the exact source form across compiler metadata, the
`CheckedDwordStore` literal-byte gate, decoded and IR address profiles,
runtime source/site matching, and the host store publisher whitelist. Addr32
disp32, SIB, other source/base forms, and additional prefixes remain outside
this slice.

replaces the stale global rejection of `67 89 40 00` with a provenance
comparison against the singleton form. The neighboring addr32 disp32 negative
is preserved. JIT test identity:
`memory_load_v2::tests::ir_dword_addr32_alias_disp8_store_binds_all_signed_source_bytes_to_its_site`.
Host test identity:

## Verification status and limits

The JIT and host test cases are present in the runtime change. No behavioral
tests, builds, formatting, Cargo checks, or Python harness checks were run for
this slice. Mini checks remain deferred until the end of Stage 3, and the M1
regression was deferred by the user. This slice does not establish production
owner/MMU integration, physical hardware behavior, or performance. Stage 2 is
excluded; Stage 3 remains partial. See the [S3-20fm plan entry](../plans/STAGE_3.md#s3-20fm-address32-rax-alias-disp8-dword-store-67-89-40-ib)
