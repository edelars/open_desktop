## Выбранные адреса и архитектура

- Один блок портов `0x0600..0x0610`: `PM1a_EVT_BLK = 0x0600` (4 байта), `PM1a_CNT_BLK = 0x0604` (2), `PM_TMR_BLK = 0x0608` (4), `RESET_REG = 0x060C` (1 байт, SystemIO), `RESET_VALUE = 0x06`, `SMI_CMD = 0`, `\_S5 SLP_TYP = 5`. Реальные PIO платы: COM1 `0x3F8..=0x3FF` и conf1 `0xCF8..=0xCFF` (остальные устройства — MMIO). Блок целиком ниже `0xCF8`, `0xCF9` остаётся `UnknownOffset`.
- Одно устройство — одна привязка: регистры делят состояние (`SLP_TYP`, причина остановки), как `PciEcam` делит таблицу функций; адреса — внутри блока, лишние зазоры — `UnknownOffset`.
- Остановка: устройство защёлкивает причину, цикл `run_boot` опрашивает её после каждой инструкции (существующий механизм STOP). Это не требует новых путей в CPU и сохраняет сброс (S7-26) отдельной операцией.
- Таймер: 24 бита (`TMR_VAL_EXT = 0`), `floor(now_ns * 3_579_545 / 10^9)` по virtual clock; время не идёт без `advance_time_ns`.
- `SCI_EN` — константа 1 (нет `ACPI_ENABLE/DISABLE`, `SMI_CMD = 0`); события `PM1` без источников, SCI-маршрута нет; `SLP_EN` для `SLP_TYP != 5` игнорируется (другие состояния сна не объявлены).
- Дефолтный handoff не менялся, handoff не меняется и с флагом: у v1.0/v1.1 нет кода устройства для PM-блока, а новый код — изменение контракта. Адреса идут через `ACPI_PM_DESCRIPTOR`, как ECAM через `PCI_ECAM_DESCRIPTOR`. Флаг `acpi_pm` выбран по образцу `pci_ecam`: без него поведение платы прежнее.

## Отклонения и API

- `LoadedFirmwareBoard::clock()` возвращает снимок `VirtualClock` (значение) вместо `&VirtualClock`; внешних вызовов в репозитории нет (`cargo check --workspace --all-targets` чист). Причина: таймер PM должен читать те же часы, что двигает плата.
- `FirmwareRunReport` получил поле `stop_reason`.

## Результаты проверок

- `cargo test -p od-machine --offline`: 564 passed, 0 failed (было 537 после S4-30c; +27: 17 в `acpi_pm`, 10 в `firmware_board`).
- Регистры: `SCI_EN = 1` с сброса и без выключателя; S5 + `SLP_EN` (слово и один старший байт) → `Shutdown`; другой `SLP_TYP` — нет остановки; `RESET_VALUE` → `Reset`, другие значения — нет; причины различаются, первая сохраняется; `PM1_STS` W1C; `PM1_EN` по маске; таймер: 1 с = 3 579 545, +1 мс = +3579, 24-битный wrap (5 с = 17 897 725 − 2^24), запись — `ReadOnly`; ошибки доступа без побочного эффекта.
- Через `MachineBus::read_port`/`write_port` (реальная `PortRegionBinding`): регистры доступны, ошибки устройства — `BusAccessError::Device`, порты за блоком — `UnmappedPort`.
- Плата: handoff с флагом и без байт в байт одинаков и равен golden-эталону (golden-тест не менялся); без флага порты — `UnmappedPort`; на плате со всеми опциями (second screen, NVMe, ECAM, PM) COM1 и conf1 отвечают, `0xCF9` — `UnknownOffset` и машину не останавливает; карта памяти с флагом и без совпадает.
- Часы и таймер: `the_pm_timer_follows_the_board_clock` (через `advance_time_ns`) и `run_boot_advances_the_clock_by_retired_instructions_and_pm_tmr_sees_it` (после `run_boot` с одним `HLT` часы +1 нс, `PM_TMR` 3 579 544 → 3 579 545).
- Гостевой код через `run_boot`: `OUT` в старший байт `PM1_CNT` → `Stopped`/`Shutdown`, `OUT` `0x06` в `0x60C` → `Stopped`/`Reset`, retired = 3, `HLT` не исполняется; остановка на последней бюджетной инструкции — не `BudgetExhausted`; повторный `run_boot` не исполняет инструкций; без флага `OUT` в `0x60C` — `PortIo`, а не остановка.
- `cargo fmt -p od-machine -- --check`: чисто. `cargo clippy -p od-machine --all-targets`: замечаний в `acpi_pm.rs` и в новом коде `firmware_board.rs` нет (в файле единственное давнее — `validate_config`, `is_multiple_of`). `cargo check --workspace --all-targets --offline`: чисто. `firmware/uefi` не трогался, его тесты не запускались.

## Открытое

- Нет SCI-маршрута и событий PM1 (`TMR_STS` и другие не взводятся), GPE0/GPE1, PM1b, `ACPI_ENABLE/DISABLE`, состояний сна S1–S4. Передача S4-31: в `Flags` FADT `PWR_BUTTON = 1` и `SLP_BUTTON = 1` (источников кнопок нет; ноль означал бы «кнопка есть как fixed feature»), `FIX_RTC = 1` (`RTC_STS`/`RTC_EN` не поддержаны), `TMR_VAL_EXT = 0`, `RESET_REG_SUP = 1`; нули в `PM1b_*`, `PM2_CNT_BLK`, `GPE0/1_BLK`; `SLP_TYP = 5` в `\_S5`; выбрать `SCI_INT` (S4-31). Проверка ACPI mode и SCI в Linux — S4-38.
- ISSUE-067: PM-таймер стоит внутри кванта. Часы платы двигаются только между квантами (`advance_time_ns(instructions_executed)`), квант заканчивается на записи COM1 THR, doorbell NVMe, остановке PM, `HLT` или конце бюджета; гость, опрашивающий `inl(0x608)` без этих событий, видит одно значение до конца бюджета, ожидание по `PM_TMR` (UEFI `Stall`, калибровка Linux) не завершится. Исправление — закрывать квант на чтении `PM_TMR` или на опросе; решение за S4-37/S4-38. Механизм квантов не менялся.
- Сам сброс машины и снятие защёлки остановки — S7-26; сейчас остановка необратима.
- Флаг `acpi_pm` по умолчанию выключен: S4-31/S4-38, которым нужен PM-блок в плате, должны включать его; смена дефолта golden handoff не затронет, так как handoff от флага не зависит.
- Не сделано по плану: `HW_REDUCED_ACPI`, RTC/CMOS, HPET, PIC/PIT/8042, FADT, MADT/MCFG.
