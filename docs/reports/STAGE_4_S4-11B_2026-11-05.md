# Stage 4 S4-11b: bounded CPU-connected cross-page qword read

## Результат

Принят bounded срез на baseline `5e1804b`. Профиль допускает только одну
Long64 instruction `MOV RAX,[RBX]` (`48 8B 03`) с qword operand, пересекающим
одну границу guest 4 KiB страниц. Проверены все семь начальных offsets
`0xff9..0xfff`; соседние GVA pages могут отображаться в несмежные RAM pages.

Новый CPU-connected path переводит и проверяет обе части в возрастающем
linear-address порядке и допускает только полностью RAM-backed physical
ranges. Ни один MMIO device не вызывается для пересекающего границу operand.
Cross-page store остаётся на прежнем раннем отказе. A-bit writes и callbacks
коммитятся при каждом обходе и остаются видимыми после fault; чтение не ставит
D. Операнд читается после обоих обходов, сначала из первой части, затем из
второй, во временный 8-byte buffer. Caller buffer и RAX меняются только при
полном успехе; ошибка второй страницы сохраняет точный fault record и исходный
RIP, не retire-ит instruction и оставляет уже committed A effects.

Alias contract задаёт явный порядок: A updates обоих walks завершаются до
operand sampling. Поэтому PTE bytes, физически совпадающие с частью operand,
наблюдаются после этих writes; обновление из первого walk может влиять на
таблицы второго walk. Это deterministic API contract uncached adapter, а не
заявление об универсальном hardware ordering. Intel SDM Rev. 090 Vol. 3A
§§5.7–5.8 задаёт page-fault и A/D semantics; §11.1.1 указывает, что split
accesses across page boundaries generally не гарантируют atomicity ([official
PDF](https://cdrdv2-public.intel.com/874240/325462-090-sdm-vol-1-2abcd-3abcd-4.pdf)).

## Проверки и review

В основном checkout прошли:

```text
cargo test -p od-machine --test paged_mov_step --locked --offline
cargo test -p od-machine --lib --locked --offline
cargo check -p od-machine --all-targets --locked --offline
cargo fmt --all -- --check
git diff --check
```

Результат: **15 integration tests и 82 unit tests passed**. Coverage включает
семь offsets, две непоследовательные physical pages, обе формы second-page
page fault (not-present и supervisor protection), PFEC/address/RIP/access
context, отсутствие D, ordered A callbacks, неизменность CPU и caller buffer,
RAM+hole/RAM+MMIO отказ без device dispatch и alias visibility. Same-page RAM и
S4-06c MMIO tests остались зелёными.

Независимое `gpt-6.1-sol/high` review завершилось финальным **approve**, без
P0—P3 замечаний. Исходное P3 о слишком общей проверке fault был исправлен
точными assertions для vector 14, PFEC 0/5, адреса второй страницы, saved RIP
и `Read / Long64 / Explicit` context; финальный reviewer повторно проверил
затронутую часть.

Graphify query выполнен до чтения исходников, затем Graphify обновлён после
изменений в worktree реализации (24,667 nodes, 63,593 edges, 887 communities)
и в основном checkout (26,028 nodes, 65,344 edges, 877 communities).

## Границы

Срез не реализует cross-page stores, иные operand widths, RAM/MMIO или MMIO/MMIO
splitting, instruction fetch across pages, stack/REP/RMW restart, exception
delivery/CR2 commit, TLB/JIT, IRQ, SMP или Linux. Родительский S4-11 и этап 4
остаются открытыми; ISSUE-054 остаётся открытой для этих общих границ и других
`GuestMemory` consumers.
