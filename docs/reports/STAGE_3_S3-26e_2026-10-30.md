## Scope

The existing checked two-site path now admits exactly
`48 8B 03 48 8B 0B` (`MOV RAX,[RBX]; MOV RCX,[RBX]`). The builder, typed
lowering, metadata validation, emitter, publication path, and bounded memory
dispatcher preserve two separate reads from `[RBX]` and independent commits
for RAX and RCX. The same generated entry accepts the first instruction RIP or
the second-instruction continuation at `A+3`; all unrelated pair forms remain
rejected. Existing store→load and load→store profiles retain their checks.

## Local evidence

The native host fixture records two qword reads at the same guest address and
compares complete CPU state and RAM with two interpreter steps. It covers
first-site and second-site architectural faults, partial RAX commit at the
second-site fault, second-site backend failure, and a singleton checked-load
retry at `A+3` with no replay of the first read. It also checks budgets 0/1/2,
pre-entry STOP, stop-RIP at the second instruction, STOP raised by the first
read callback, and S3-28b event polling after the pair: with remaining budget,
both reads retire before `EventPending` is returned ahead of a following NOP.
The event remains set.
