# Stage 4 S4-25f: Local APIC для Linux probe (Version, LINT0/LINT1, Error LVT, ESR)

Ограниченный срез. Linux-подобный probe APIC (чтение Version, запись LINT0/LINT1/
Error LVT, DFR/LDR и ESR) больше не получает `DeviceError`. Все новые регистры
только хранят состояние: источников LINT-пинов и ошибок нет, доставки нет.
Родитель S4-25 закрывается только после ревью этого среза.

## Что сделано

- `local_apic.rs`: Version `0x30` = `0x00030014`, LINT0 `0x350`, LINT1 `0x360`,
  Error LVT `0x370`, ESR `0x280`, DFR `0xe0`, LDR `0xd0`. Поля `State`:
  `lint0`, `lint1`, `error_lvt`, `dfr`, `ldr`, `esr`, `esr_pending`; reset
  идёт через `State::default()`, как у остальных регистров.
- Software disable (SVR bit 8 = 0) ставит mask в трёх новых LVT.
- Perf `0x340`, Thermal `0x330`, CMCI `0x2f0` не добавлялись.
- Тесты: 9 новых, 30 прежних. Документы: `MACHINE_CONTRACT.md`, `MACHINE.md`,
  manifest `docs/reports/data/stage4/s4-25f-lapic-linux-probe.json`.

## Решения

- **Version `0x00030014`.** Версия `0x14` (integrated), Max LVT = 3 (4 LVT:
  Timer, LINT0, LINT1, Error; SDM: число LVT минус 1), bit 24 = 0. Совпадает со
  SDM; расхождений нет. Запись `ReadOnly`. Доступен и без opt-in таймера:
  Version описывает профиль APIC.
- **LINT0/LINT1.** Reset `0x10000`. Пишутся vector, delivery mode (Fixed, SMI,
  NMI, INIT, ExtINT), polarity, trigger, mask. Delivery Status (12) и Remote IRR
  (14) при записи отбрасываются (Linux пишет значение, прочитанное из регистра,
  отказ сломал бы его). Это отличается от Timer LVT, где запись этих битов
  отклоняется; различие зафиксировано в контракте. Reserved bits и delivery mode
  `001/011/110` — `UnsupportedConfiguration` без изменений. Vector не
  валидируется: доставки нет, проверка принадлежит срезу с доставкой.
- **Error LVT.** Reset `0x10000`; пишутся vector и mask, bit 12 отбрасывается.
- **Mask и software disable.** Как у Timer LVT (S4-25e): software disable
  ставит mask; снятие mask при software disable отклоняется без изменений
  (SDM §13.4.7.2 говорит «игнорируется»; принятая модель Timer отклоняет,
  чтобы не было молчаливой потери записи). Linux включает SVR раньше, чем
  снимает mask LVT, и на старте пишет только masked значения.
- **ESR.** Модель SDM §13.5.3: `esr` (защёлка) и `esr_pending` (лог).
  Запись переносит лог в защёлку и очищает лог; значение игнорируется (любой
  32-битный). Чтение не очищает. Источника ошибок нет, `esr_pending` всегда 0,
  ESR читается 0; ошибки не выставляются. Тесты заполняют лог напрямую в
  `State` (проверка механизма).
- **DFR/LDR: нужны.** `setup_local_APIC` вызывает `init_apic_ldr`
  (flat/cluster driver пишет DFR и LDR и читает LDR); логика выбора драйвера
  зависит от версии ядра и Kconfig, поэтому безопасный минимум — хранение. DFR
  reset `0xffffffff`; хранится только model (31:28), допустимы `0xf` и `0x0`,
  bits 27:0 читаются единицами. LDR reset 0; хранится только ID (31:24). Logical
  destination routing не реализован.
- **Perf/Thermal/CMCI не добавлены.** Условие: CPUID не объявляет PMU, TM и
  CMCI, Max LVT = 3, поэтому Linux не обращается к ним. Зафиксировано тестом
  `UnknownOffset` и в контракте.

## Изменённые ожидания прежних тестов

Только там, где прежний тест закреплял отсутствие регистров, которые срез
по плану добавляет:
- `unsupported_accesses_are_atomic`: запись в `0x30` была `UnknownOffset`, теперь
  `ReadOnly` (Version есть и read-only).
- `reset_matrix_is_identical_...`: чтение `0x30` ждало `UnknownOffset`, теперь
  `0x00030014`; в матрицу добавлены `0x350/0x360/0x370 = 0x10000`, `0x280 = 0`,
  `0xd0 = 0`, `0xe0 = 0xffffffff`; `dirty()` пачкает новые регистры, чтобы
  проверить все пути reset.
- `lvt_entries_other_than_timer_and_version_...` переименован в
  `lvt_entries_other_than_timer_and_s4_25f_set_...`: из списка `UnknownOffset`
  убраны `0x30`, `0x280`, `0x350`, `0x360`, `0x370` (теперь реализованы);
  остались `0x2f0`, `0x330`, `0x340`.
- `erroneous_accesses_are_rejected_without_state_change`: `supported()` расширен
  новыми смещениями (иначе их ждали бы как `UnknownOffset`); в таблицу
  rejected добавлены reserved-случаи новых регистров.
Остальные ожидания прежних тестов не менялись.

## Ревью

- Независимое ревью (Claude Opus, high, read-only): блокеров нет; срез принимается. Изменения старых ожиданий признаны расширением модели, проверки не ослаблены. Мутации (7 штук) пойманы. Версия 0x00030014 верна; LINT-маски и биты 12/14 соответствуют SDM; ESR соответствует SDM §13.5.3.
- Оговорка по DFR/LDR (внесена по ревью): не сверено с исходником Linux 7.0. По памяти в 6.9–6.10 на x86_64 убран logical flat mode; тогда Linux 7.0 работает в physflat и DFR/LDR не трогает. Хранение безвредно в обоих случаях. Если ядро выберет logical flat mode, IOAPIC RTE с bit 11 = 1 и dest = 0x01 сейчас отклоняется (`io_apic.rs`) — риск для S4-26/S4-38.
- Срез S4-25f принят; родитель S4-25 можно закрывать.

## Открыто

- Доставка с LINT-пинов, NMI/SMI/INIT/ExtINT, доставка Error LVT и выставление
  ESR не реализованы; validation vector < 16 для Fixed LINT — в срезе с
  доставкой.
- CPUID гостя ещё не проверен на согласие с отсутствием PMU/TM/CMCI (S4-38).
- DFR/LDR не участвуют в logical destination routing.
- x2APIC, multi-CPU, IOAPIC S4-26c, CPU delivery, Linux acceptance (S4-38) вне
  среза. Источник: Intel SDM release 093, Vol. 3A, Chapter 13.
