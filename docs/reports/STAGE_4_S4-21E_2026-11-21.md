# Stage 4 S4-21e: restart of the firmware board processors after a stop

Remaining S4-21 work needed by S7-26 (reset as a machine operation) and S8-30:
a stopped board could not be restarted without rebuilding it. The CPU-complex reset of S6-24
(`reset_cpu_complex`) existed but was test-only, kept no entry state, and the stop
latch of the ACPI PM block ("the reset operation (S7-26) is the only thing that will clear it")
had no way to be acknowledged.

## What was added

- `LoadedFirmwareBoard` records the boot processor's entry state at load
  (`None` for the Linux direct assembly).
- `AcpiPmHandle::take_stop_request` acknowledges the latch (crate-private).
- `LoadedFirmwareBoard::restart_vcpus() -> Result<Option<MachineStopReason>, FirmwareBoardError>`:
  `reset_cpu_complex(entry, FIRMWARE_EFER)` then acknowledge the stop. Errors change nothing.
- `reset_cpu_complex` lost its test-only attribute.

## SDM check (Vol. 3A 12.1.1, Table 12-1, text of 671200)

Power-up/RESET/INIT columns compared with the existing state models: EFLAGS `2`, EIP `FFF0`,
CR0 `60000010H` (INIT keeps CD/NW), CR2-4 0, CS `F000`/`FFFF0000`/`FFFFH`, other
segments 0/`FFFFH`, EDX = processor signature, other GPR 0 and EFER 0 are covered by the S6-13
application-processor tests (power-up and INIT). GDTR/IDTR, DR0-DR7 and the other registers
of the table are not modelled by the real-mode model and are not claimed.
INIT leaves x87/MMX/XMM/MXCSR/MSRs unchanged (kept by `Vcpu::apply_startup`).
Known gap, unchanged: on power-up/RESET the x87 control word is `0040H` and the tag word
`5555H`; the model resets to the `FNINIT` values (`037FH`/`FFFFH`). The firmware and kernels run
`FNINIT` before using x87. The boot processor restarts at the direct Long64 entry, not the
reset vector (the board's boot contract); BSP INIT through the Local APIC is still refused
(S6-15/S6-16).

## Tests (od-machine, narrow)

`cargo test -p od-machine --offline --lib restart` (10 filtered, 4 new: reset, shutdown/halt/no-PM,
host STOP flag, no-entry board), `... acpi_pm` (26), `... vcpu` (170), `cargo check -p od-machine
--offline --all-targets`, `cargo fmt --all -- --check`. The reset test runs a two-vCPU
board: after a guest reset write the processors move, a fixed interrupt, an NMI and INIT are queued,
`restart_vcpus` returns `Some(Reset)`, state equals the recorded entry, the AP waits for SIPI,
no Local APIC has a pending event, the latch is clear, RAM hash and clock are unchanged, and a second
`run_boot` retires the same three instructions and stops with Reset again.

## Not claimed

RAM clearing/restoring (cold/warm), ROM re-read, device, NVRAM and TPM handling, `--reboot-cycles`,
BSP INIT, hardware-reset x87 values, VMHost wiring. S4-21 and S7-26 stay open. Review: pending
(coordinator, Opus/high).
