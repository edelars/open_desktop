# Stage 4 S4-21d: runner completion and cancellation

`--stage4-probe` runs the fixed image through `PagedVcpuSession`. HLT is
`guest_completed` only with an expected decimal or hexadecimal nonce, three
retired instructions, matching RAX and exactly one UART byte equal to the
nonce's low byte. HLT without expectation is `guest_halted`; a failed check
is `completion_mismatch`. Both return code 5. A deterministic `--cancel-after`
counts permitted instruction polls: zero stops before fetch, one after load,
two after OUT. STOP preserves the committed prefix and returns `host_cancelled`;
budget exhaustion returns `work_limit`. Guest fault, backend, PIO, loader and
invalid input categories remain separate. The session's `drain_tx` consumes
committed output without exposing the UART handle.

CLI tests cover completion, missing and wrong nonce, cancellation at each
prefix, budget, invalid input and loader refusal (8 passed); the reproducible
artifact CLI test passed (1), and the session drain-after-STOP unit test passed
(1). `cargo check -p od-runner --all-targets --offline`, workspace formatting,
and diff checks passed. Independent `gpt-6.1-sol/high` review found no code
issues; it identified a README wording mismatch, which was corrected. Graphify
code update passed (27,622 nodes, 69,379 edges); semantic documentation extraction was not run. Fault/backend/PIO paths cannot be induced by the
validated fixed image through this CLI and are not claimed as CLI fault-injection
evidence. The fixed image allowlist and CPU/MMU semantics are unchanged.
