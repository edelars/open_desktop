# S3-20w — RSP-base no-index SIB qword MOV with signed disp8

## Scope

The bounded singleton profile admits only `48 8B/89 /r sib disp8`, ModRM
`mod=01,r/m=100`, exact SIB `0x24`: RSP base, absent index, scale 1, signed
disp8, data RAX..RBX, qword data, 64-bit effective address and five-byte
length. Decoder `MemoryOperand::access_address_48` remains the only effective
address implementation. The earlier no-displacement `[RSP]` profile is kept
separate. Disp32, indexed RSP, `67`, segment/extra prefixes, extended registers,
pairs and V3 are outside this change.

## Evidence

- The descriptor test validates both opcodes, all four supported data-register
  encodings and disp8 -128/-1/0/127 across direct V2/shared IR metadata. It
  rejects partial encodings and unsupported index, disp32, prefix, RSP-data and
  trailing-byte variants.
- Direct V2 and shared IR match interpreter load/store behavior for all four
  displacements. Comparisons include full guest state and RAM, effective
  callback address/count, retirement/budget, and unchanged RSP, RBP and flags.
- A positive wrap case sets RSP to `u64::MAX - 100` and disp8 to `+101`, so the
  decoder-derived address wraps to canonical zero. Direct V2, shared IR and
  interpreter all issue one qword callback at address zero and match full state,
  RAM and retirement.
- Noncanonical RSP start/end-of-qword checks retain #SS; corresponding RBX
  controls retain #GP. Architectural faults make no data callback and commit
  no CPU/RIP/RAM/budget/retirement state. AddressOverflow and ordinary backend
  failures remain host errors. Entry STOP and budget zero prevent access;
  successful store+STOP remains committed.
- Dispatcher composes the five-byte singleton → bare NOP interpreter bridge →
  existing native pair. Budgets 0..4 match interpreter state and RAM. A split
  run resumes at the actual next RIP without replay; STOP-RIP at the bridge
  prevents further work. Windows 1..4 return `BoundaryReached` with no effects;
  unsupported forms retire nothing and make no memory callbacks. The prior
  `[RSP]` dispatch scenario remains covered independently.
