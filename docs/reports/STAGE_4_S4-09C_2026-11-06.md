# S4-09c — tracked permission-level A/D matrix

## Result

Added test-only coverage for the existing `access_long64_4k_ram` path. No
production walker, public API or CPU behavior changed. All cases use
`Long64ProbeConfig`, a four-level 4 KiB page walk, RAM-backed tables and
`AccessOrigin::Explicit`.

At each of PML4, PDPT, PD and PT, with all other entries permissive, the tracked
matrix verifies:

- Non-present Read/Write/Fetch for CPL0 and CPL3. Expected PFECs are respectively
  `0/4`, `2/6`, and `0x10/0x14`. The failed entry remains byte-for-byte intact;
  only eligible predecessor A updates appear in the complete five-slot report
  and committed callback sequence.
- U/S clear: CPL3 Read/Write/Fetch faults with PFEC `5/7/0x15`; CPL0, CPL1 and
  CPL2 can access the mapping as supervisor for all three access kinds.
- R/W clear: Read/Fetch remain allowed for CPL0/CPL3. Supervisor writes with
  CPL0/CPL1/CPL2 succeed at WP=0 and fault with PFEC 3 at WP=1. CPL3 writes
  fault with PFEC 7 at either WP setting.
- NX set with NXE enabled: Fetch faults with PFEC `0x11` for CPL0/CPL1/CPL2 and
  `0x15` for CPL3. Data Read/Write remain allowed for CPL0/CPL3.
- NX set with NXE disabled: Fetch raises a reserved-bit page fault with PFEC
  `9/13` for CPL0/CPL3. Only predecessor A entries are updated because reserved
  validation precedes A on the faulting entry.

For non-present/reserved faults, the faulting entry and lower entries remain
unchanged, with only eligible predecessor A bits committed. Protection checks
occur after all four levels have been walked, so A can be set on the denied
entry as part of the complete eligible prefix. These faults commit neither D
nor the operand.

Fault assertions compare the full `PageFaultRecord` (vector 14, error code,
linear address, saved RIP, access kind and context), all page-table entry values,
the complete `ad_updates` array, callback order, and unchanged operand bytes.
Successful writes verify A updates followed by leaf D and exactly one
operand commit. Preset A/D bits produce no redundant table callbacks. A separate
pure-probe test checks Read/Write/Fetch for CPL0/CPL3 and confirms no A/D change.

A same-memory regression uses read-only entries with WP=1: a Read installs A at
all four levels, followed by a Write that completes the walk and faults with
PFEC `0x03`. Because A is already present, that second call returns an empty
five-slot A/D journal and emits no callbacks; D, all entries and operand bytes
remain unchanged. The full suite below predates this added regression; its
focused follow-up result is recorded separately.

The slice does not implement CPU exception delivery or CR2 update, CPU execution
integration, system acceptance, cross-page operations, other paging modes,
cached A/D semantics or a production TLB. Full S4-09 remains open for CPU
integration and system acceptance.
