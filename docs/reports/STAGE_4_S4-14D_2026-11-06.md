# S4-14d: CPU-owned CR3 invalidation in the mutable session

**Date:** 2026-11-06  
**Scope:** bounded feature-gated integration of the existing exact
`MOV CR3,RAX` CPU effect with `MutableTranslationProbeSession`. Full S4-14 and
Stage 4 remain open.

## Behavior

`execute_mov_cr3` first requires the CPU CR0/CR3/CR4 state to match the
session's validated Long64/canonical48/physical36/four-level/4 KiB snapshot.
It executes the existing `MovCr3Long64V1` step using a pure instruction-fetch
adapter that bypasses the resident translation entry. A rejected instruction,
privilege fault or fetch fault leaves the snapshot and entry unchanged.

After one retired `Cr3Write`, the machine verifies the effect's old CR3,
committed CPU CR3 and retirement count, validates a replacement
`Long64ProbeConfig`, installs it and clears the capacity-one cache before
returning. This also invalidates on a write of the same CR3 value, so a PTE
change followed by same-value `MOV CR3` cannot reuse the stale translation.
Before the retired invalidation effect is consumed, a matching probe may still
hit the resident translation; `write_pte` itself does not invalidate. Fetch
and effect consumption do not perform tracked A/D writes or memory callbacks.

If an effect cannot be reconciled after CPU retirement or the replacement
snapshot fails validation, the session keeps its old snapshot, clears the
stale entry and becomes poisoned. Later `probe`, `write_pte`, `execute_invlpg`
and `execute_mov_cr3` calls return `SessionPoisoned`; callers must stop the
session because CPU state may already have advanced.

## Limits

This remains a one-entry diagnostic session over one exclusive RAM owner. It
does not implement cached tracked A/D accesses, production TLB behavior,
reset/CR0/EFER transitions, generations, huge pages, PCID/global semantics,
JIT invalidation, DMA or SMP. INVLPG and `MOV CR3` invalidation are only the
bounded guest effects covered by this diagnostic path; full S4-14 remains open.
