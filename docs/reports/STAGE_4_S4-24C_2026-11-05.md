# S4-24c: bounded paged CPL0 byte PIO

**Result:** accepted bounded code slice after independent `gpt-6.1-sol/high`
review. Parent S4-24 and Stage 4 remain open.

## Implemented boundary

`od_isa::execute::step_paged_pio_u8` uses profile `PagedCpl0PioU8V1`. It admits
only bare Long64 `EC` (`IN AL,DX`) and `EE` (`OUT DX,AL`) at CPL0. CR3 and EFER
are not inputs to this CPU entry. It accepts an already-selected `GuestMemory`
and validates CPU-side admission, including CR0/CR4. The machine entry validates
CR3 and EFER through the existing `Long64ProbeConfig` four-level, 4 KiB profile
and supplies the CPU entry with the real page-aware memory adapter. Instruction
fetch follows guest page tables and uses `AccessOrigin::Explicit`.

The machine path joins paged fetch with the existing byte PIO bus and UART. The
end-to-end test executes `MOV RAX,[RBX]` followed by `OUT DX,AL` without host
mutation between steps and transfers definedness from the first result to the
second. UART output bytes match the guest-loaded data. Tests cover not-present
PFEC `0x10` and NX protection PFEC `0x11`. If PIO fails after a successful
fetch, CPU state and definedness remain unchanged while page-table A/D writes
and callbacks already performed by the fetch remain visible.
