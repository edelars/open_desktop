# S3-35f. Cold Session after the cache-index change

This release comparison repeats the six S3-35e countdown profiles after
S3-36h. The baseline is `06bb39a` and the current build is `2b0f598`.
The only runtime source change between those revisions is in the S0-09
dispatcher. Both builds use the archived S3-35e driver and the same
interpreter, workload bytes, initial states and budgets. [S3-35e inputs](STAGE_3_S3-35e_2026-11-19.md)
[S3-36h warm comparison](STAGE_3_S3-36h_2026-11-19.md)

The JIT timer spans construction of a fresh `Session`, two empty-cache
probes and the first RUN. A timestamp inside this interval separates
construction from the probes and RUN. State reset, correctness checks and
session drop occur outside timing. Each JIT call verifies an empty initial
cache, one or two misses, compiles and publications, the expected hit
count and zero evictions. Both engines verify the full resulting CPU state,
exit and retirement. The JIT also verifies remaining budget and the number
of executed blocks. Published code and logical metadata sizes match across
all rounds and builds for each profile.

The four unscored calibration pairs per build set common per-profile
counts targeting 40 ms on the fastest observed side. Each scored process
ran eight pairs per profile with alternating JIT/interpreter order. The two
executables ran sequentially in each of four rounds, with reversed
execution order in rounds two and four. All 768 sides passed the 20 ms floor. The
shortest side took 32.954 ms.

## Results

Total times are medians in microseconds per call from the current build.
The two build ratios summarize the four per-round ratios of medians with
full ranges. The normalized column first divides the JIT time by the
paired interpreter time. The last column summarizes 32 paired ratios
from the current build.

The first two processes took 27.2 and 25.0 seconds wall time. Later
processes took 16.0–18.0 seconds. The workload counts stayed fixed and all
rounds are included. The normalized ranges for `same_1`, `same_3` and
`same_64` cross parity. The normalized medians were lower in every round
for `same_4096` and the two-RIP loops. The current JIT beat the interpreter
in every pair at 64 and 4096 iterations with one RIP. The other four
profiles favored the interpreter in every pair. The cold result supports
retaining the dispatcher change on this profile alongside the warm
evidence. It leaves the broader workload matrix and individual compiler
phase costs open. Physical x86 and Mac mini checks are deferred.

## Reproduction and evidence

The host used an Apple M3 Max with 14 cores, 36 GB RAM, macOS 26.7.1
(25G241) and rustc 1.99.0. `build.sh` extracts each revision with
`git archive`, builds `od-host` with a separate release Cargo target and
links the unchanged Rust driver. Both executables use ad-hoc Hardened
Runtime signatures with the smoke JIT entitlement. The archive retains
the driver, dispatch diff, build and signature identities, pilot samples,
fixed counts, process order, scored samples and audit.

Extract the archive's `files` into a fresh scratch directory. Run `audit.py`
with Python to reproduce the saved results. To take new measurements, from
the Git repository root run `zsh <scratch>/build.sh baseline` and
`zsh <scratch>/build.sh current`, then run `pilot.py`, `run.py` and
`audit.py` from that scratch directory. The archive SHA-256 is
`5ffcf01d348cbfafcb61ec41810efdaae7cf22b16e2dee4620e7dfb842c0661c`.
