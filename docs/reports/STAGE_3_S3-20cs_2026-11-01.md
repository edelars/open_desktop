# S3-20cs — exact dword checked-memory load with disp32

**Status:** bounded implementation slice; S3-20 and Stage 3 remain open.

Implementation commit `1db3afa` adds only the six-byte singleton `8B 83 id`
(`MOV EAX,[RBX+disp32]`) to the shared typed-IR Dword-load path. The decoded
memory operand supplies the signed disp32 effective address from full-width
RBX. A successful checked read transfers four bytes and zero-extends EAX into
RAX. The source/site contract binds all six instruction bytes and the PC map
has one guest instruction boundary at `A+6`.

The descriptor tests exercise signed displacement values and reject changed
source bytes and neighboring encodings. The host fixture checks the decoder-
owned effective address, four-byte read, zero-extension, and no architectural
commit on failed reads. This remains one exact RBX-base form: it does not open
other dword bases/addressing forms, prefixes, SIB forms, or a general dword
memory family. It adds no production owner/MMU, SMC, cache, or performance
claim.
