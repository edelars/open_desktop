# S3-20ah — RBP data with signed RSP-base SIB displacement

## Scope and implementation

Added exact singleton forms `48 8B/89 6C 24 ib` (disp8, length 5) and
`48 8B/89 AC 24 id` (disp32, length 8). ModRM is `mod=01/10, reg=5, rm=4`
and SIB is exactly `0x24`: RSP base, no index, scale 1. Decoder-provided
`MemoryOperand` remains the address authority. Generic register predicates,
existing pair/V3 forms, source storage, frame layout and host ABI are unchanged.

## Evidence

- Descriptor tests cover both opcodes and widths, signed displacement
  boundaries, decoded RSP/no-index/unit-scale metadata, exact instruction
  lengths and source bytes. Partial windows and wrong SIB/ModRM/prefix/data
  register variants reject. Earlier no-displacement RBP-data/RSP-base and
  RBP-base profiles remain supported; their stale negative cases were changed
  to reject genuinely unsupported near-matches.
- Host direct V2/shared IR/interpreter parity covers load/store at disp8
  -128/-1/0/127 and disp32 MIN/-1/0/MAX/128. Independent test setup asserts
  `target = entry_rsp.wrapping_add_signed(displacement)`. Load updates RBP
  only after success; store uses the full entry RBP payload. Full CPU/RAM,
  callback address/count and retirement are compared.
- Noncanonical RSP returns the expected #SS before a memory callback and
  preserves CPU state and accounting. Noncanonical RBP is valid store data;
  successful store callback STOP preserves all 64 bits for both widths.
  AddressOverflow and backend failures remain host errors with no CPU commit.
- Bounded dispatch exercises both singleton widths followed by NOP and the
  existing pair, checking native/interpreter/native retirement counts,
  callback STOP, continuation from actual RIP and no repeated access. A
  displaced singleton load followed by `[RBP]` commits the loaded RBP and
  resumes at that next instruction; the second callback uses the newly loaded
  RBP address.
- On macOS/ARM64, an x19 ABI canary covers exact-profile success, zero-budget
  guard and guest-fault return.
