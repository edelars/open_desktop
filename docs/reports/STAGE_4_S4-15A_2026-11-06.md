# S4-15a: one tracked Published V2 qword load

**Date:** 2026-11-06  
**Status:** implementation, verification and independent review complete; S4-15a accepted.
Parent S4-15 and Stage 4 remain open.

**Scope:** exact `MOV RAX,[RBX]` through the existing direct V2 published
memory-load entry and the production `MachineBus` owner.

## Implementation

`od-machine::with_paged_mov_memory` lends a temporary read-only `GuestMemory`
adapter to one synchronous callback. It uses the existing uncached tracked
Long64 four-level/4 KiB RAM walker. Only same-page qword reads are admitted;
fetch, write, cross-page qword and MMIO dispatch are refused. The result keeps
the callback result, precise page-fault or tracked backend detail, and any A-bit
updates/write ranges already committed before failure. Existing
`step_paged_mov` wrappers retain their prior direct write callback path; the
effect collectors are enabled only for this scoped API.

`od-host` now depends on `od-machine` and exposes
`PublishedCode::execute_paged_mov_rax_rbx_v2`. It verifies direct V2 artifact
metadata for exact bytes `48 8B 03`, Long64 mode, CPL0/CPL3, runnable activity,
clear interrupt shadow, entry RIP and an admitted paging snapshot before
opening the memory scope. It invokes the published block with budget one. The
memory borrow is invocation-local and is not retained in the JIT mapping or its
metadata.

## Verification

Verification results:

- `cargo test -p od-host --lib --offline s4_15a_paged_v2_qword_load_uses_tracked_ram_and_refuses_out_of_slice_inputs` — **1 passed, 0 failed**.
- `cargo test -p od-machine --lib --offline` — **103 passed, 0 failed**.
- Successful CPL0 and CPL3 access assert each exact physical A-bit update (entry address and before/after value), the exact eight-byte physical write ranges, and page-table readback. All four entries acquire A, while D remains clear.
- The real missing-leaf #PF asserts the exact three committed ancestor updates/ranges and readback: those ancestors acquire A, the absent leaf remains byte-for-byte unchanged and not-present, D remains clear, and CPU destination/RIP remain unchanged.
- A dedicated CPL3 access through user-readable ancestors and a present supervisor-only (U/S=0) leaf produces a real protection `#PF` with PFEC `0x5`, exact saved RIP and CR2, zero retirement, and an unchanged full CPU state including RAX/RIP. It asserts all four exact A updates/ranges and readback, with D clear and the leaf still U/S=0. Because the mapping is present and writable, accidentally downgrading this access to Ring0 would make it succeed and fail this test.
- Cross-page and unsupported-block preflight snapshot all four walk entries and compare them after rejection; both preserve the complete CPU state and dispatch no device callbacks. Unsupported privilege (Ring1), halted activity, and blocking STI shadow are also rejected with unchanged CPU and walk entries, with no device callbacks.
- An unsupported-mode rejection cannot be exercised through the current API: `InstructionMode` contains only `Long64`. No mode was fabricated or added as part of this verification-only correction.
- The earlier `cargo check --workspace --all-targets --offline` completed with exit 0. It reported existing warnings for `od-jit::CodeMemory::one_instruction` and unused `scale`, unnecessary `mut callback_stop`, and unused `MEMORY_CORPUS_SEQUENCES` in `od-host` tests.
- `cargo fmt --all -- --check` and `git diff --check` — passed.
- `graphify query` for the test and entry point — passed before source inspection. `graphify update .` — passed; refreshed graph contains 26,851 nodes, 67,219 edges, and 1,063 communities. Independent review passed with no remaining findings. Three P3 verification findings were resolved by adding exact A-bit snapshots, preflight walk checks, and the CPL3 supervisor-only fault case.

## Limits

Only the exact direct V2 `MOV RAX,[RBX]` form is admitted. JIT stores, other load
forms, cross-page/device access, interpreter fallback dispatch, TLB caching,
executable aliases/invalidation and system acceptance are outside this slice.
Unsupported cross-page/MMIO paths remain host/backend errors, not guest page
faults. This slice does not accept parent S4-15.
