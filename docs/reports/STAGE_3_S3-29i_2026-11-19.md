# S3-29i carry handoff to the interpreter

The host regression runs a published native `ADD RAX, RCX` prefix
followed by an interpreter `ADC RDX, 0x10` or `SBB RDX, 0x10`.
It covers both carry values with the incoming CF set to the opposite
value. After ADD, the eager PC map records a canonical boundary and
the demand-flags PC map records pending flags at the consumer RIP.

The native call returns the unsupported-instruction exit at the consumer
RIP after one retirement and with one instruction left in the budget.
Both strategies must return the same full state and CF as the interpreter
after ADD. The interpreter then retires exactly one consumer. Starting
from RDX = `0x20`, the expected ADC outcomes are `0x30` and `0x31` for
CF = 0 and 1, respectively. The SBB outcomes are `0x10` and `0x0F`.
The test compares the completed state and RIP with a fully interpreted
run of both instructions.

Both carry consumers in this test execute in the existing interpreter.
The test covers the state handoff from the published block. S3-29 still
needs accepted M1 Pro latency measurements. Physical x86 checks remain
deferred.

On local ARM64 macOS, the focused test passed with the linker signature
and with Hardened Runtime and `allow-jit`. The hardened binary passed
all seven tests selected by `demand_flags_candidate_` in a serial run.
