# S3-25a — synchronous published-entry lifetime partial

**Date:** 2026-10-27  
**Status:** implementation complete; independent review pending.

## Scope

This slice checks the existing one-vCPU synchronous dispatch lifetime. The
cached entry's verified block metadata and published handle remain borrowed
through the backend call and dispatch result/counter validation. The host arena
keeps its slot metadata borrowed through generated execution and raw-result
decoding. Eviction, clear, and slot reuse are therefore confined to the safe
point after the backend returns and the result is checked, before a later
lookup. Execution errors remove an entry only after backend return. STOP before
entry does not execute or release a resident mapping; STOP observed after an
execution leaves the mapping resident.

Tests exercise A→B→A churn at cache/arena capacities 1 and 2, publication/drop
and resident code/metadata accounting, STOP before and after backend execution,
and an injected executor error followed by safe removal and republication. The
host arena tests also cover a live neighboring slot and the existing
backend-before-handle / final-handle-reopens-arena lifetime case.

## Limits

This does not implement active-code invalidation or self-modifying-code
retirement, SMP reclamation, a deferred deletion queue, or the complete S3-25
retirement framework. It establishes only the existing synchronous
single-vCPU borrow/drop boundary and its fixture/native regression coverage.
