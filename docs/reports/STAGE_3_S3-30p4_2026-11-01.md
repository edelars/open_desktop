# S3-30p4 — pending flags with allocator pressure at JZ/JNZ

**Status:** bounded test-only correctness slice completed and independently reviewed. S3-30 allocator selection and broader correctness remain open.

## Scope

The existing `ADD RAX,RCX → MOV RAX,7 → JZ/JNZ` demand-flags fixture now crosses `register_homes` budgets 0..4. Four inputs exercise taken and non-taken results for both JZ and JNZ. The nonzero ADD input is `RAX=1`, `RCX=u64::MAX-6`; it is not-taken for JZ and taken for JNZ. After `MOV RAX,7`, recomputing flags from current RAX would incorrectly produce zero. The instrumented materialization helper therefore checks that the original ADD operands and initial flags are retained and read at materialization.

For each homes budget, candidate and eager execution are compared with the interpreter at the emitted block prefix for budgets 0..4. A dispatcher continuation is compared with the full interpreter result after budget-exhausted prefixes and the conditional branch's fallthrough boundary. STOP-RIP is checked after ADD and immediately before Jcc; resuming must reach the same final CPU state and additive retirement count without replaying the prefix. An entry STOP leaves state and accounting unchanged and does not invoke the helper. The non-taken suffix is an admitted flag-preserving `MOV RBX,imm64` with a distinct state effect.

The allocator evidence inspects the four temporaries in the block ending at Jcc: two `ReadGpr` values, the ADD result, and the MOV-immediate constant. Homes0 places all four in spills; intermediate budgets mix homes and spills; homes4 assigns all four homes. Helper-call counts and captured `(ADD, lhs, rhs, initial RFLAGS)` are asserted for each branch input and budget; the budget-zero and entry-stop paths assert no helper call. PC-map checks require the candidate's Jcc-rip `HelperCall` and matching `AfterHelper`, and the eager reference's ADD-rip helper site, while permitting static exit-stub helper sites.

Only test code changed in `crates/od-host/src/lib.rs` (commit `3ac1751`, `Cover pending flags across allocator budgets`). No runtime allocator, compiler API/policy, default strategy, or guest semantics changed.
