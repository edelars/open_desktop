# Stage 4 S4-34cde — independent KVM system fixtures

## Result

**Accepted for this slice after independent review and Mini KVM execution.** The
parent S4-34 remains open because its S4-00 and S4-01 prerequisites are still
open.

Fourteen project-authored freestanding x86-64 images were assembled and linked
on the Mac, each below 4 KiB. The Linux Mini host compiled `kvm_runner.c` with
`gcc -O2 -Wall -Wextra -Werror -std=c11` and ran every image in three fresh KVM
VM invocations. All 42 invocations passed host validation. The raw result block
and normalized hardware identity were stable across all three repeats for each
case.

The cases cover 4 KiB page walks and successful A/D updates, not-present and
write-protection page faults, CR0.WP behavior, NX instruction-fetch faults,
CR3 root switching, INVLPG remapping, CR0/CR3/CR4 transitions, GDTR/IDTR/GDT/TSS
state, same-CPL interrupt frame and IRETQ restoration, CPL3 interrupt entry and
return, CPL3 privileged-instruction #GP recovery, and a vector 0x41 delivered
after HLT with user-space `KVM_INTERRUPT`.

## Hardware and evidence

- Host: Intel Core i5-3210M, microcode `0x21`, VMX enabled, KVM API 12; Linux
  host kernel `7.0.0-42-generic`.
- Environment: `senya@192.168.1.14:/home/senya/od-kvm`; no reboot, guest OS,
  system-file changes, or execution of the Open Desktop MMU/CPU.
- All per-attempt raw KVM JSON, result-block bytes, CPUID entries, CPU snapshots,
  exit traces, source/image/runner hashes, and tool versions are preserved in
  [`s4-34cde-kvm-system.json`](data/stage4/s4-34cde-kvm-system.json).
- Case image sizes range from 281 to 870 bytes. Runner source SHA-256 matched
  before compilation and after the run matrix; remote runner binary SHA-256
  remained stable. Image hashes matched before and after each of the 42 runs.
- CPUID identity comparison masks only per-CPU APIC ID fields
  `CPUID.1:EBX[31:24]` and `CPUID.0B:EDX`; raw CPUID entries are retained.

## Limits

This is VT-x guest execution through Linux KVM, not bare-metal execution and not
an Open Desktop CPU/MMU test. Case 0x31 uses the userspace `KVM_INTERRUPT` API;
it demonstrates delivery and IRETQ behavior in this runner configuration, not
physical APIC/IOAPIC/PIT/timer topology. Only the runner's 2 MiB guest RAM and
KVM exits were involved. No host reboot repeats were performed. The S4-00 and
S4-01 prerequisites remain open, so this report does not accept parent S4-34.
