# S3-20an — address32 indexed-SIB qword MOV with RSP/RBP data

## Scope and contract

Admitted exact singleton forms `67 48 8B/89 /r sib [disp8|disp32]` with
ModRM `mod=00/01/10,r/m=100`, data register RSP or RBP, and SIB base/index
RAX..RBX at scales 1/2/4/8. Address size is Dword, operand size Qword, and
encoded lengths are 5/6/9 bytes. No-index/no-base SIB forms, RSP/RBP base or
index, extra prefixes, pairs and V3 remain excluded. Effective-address and
displacement semantics remain owned by the decoded `MemoryOperand` and
`access_address_48`; this slice does not add address arithmetic or an emitter.

## Evidence

- Descriptor coverage checks both MOV directions and both stack data registers
  across no displacement, disp8 and disp32, all scales, low-GPR base/index
  combinations including base=index, signed displacement bounds, full source
  lengths and matching direct V2/shared IR metadata. Special SIB, stack
  base/index, truncation and prefix-order variants reject.
- Host parity compares direct V2, shared IR and interpreter state/RAM,
  callback addresses/counts and retirements. Matrices include both data
  registers, all scales, base=index, signed d8/d32 cases, ignored upper base
  bits and modulo-2^32 address wrapping. A qword beginning at `0xffff_fffc`
  is one contiguous callback through `0x1_0000_0003`.
- For the new stack-data disp32 profile, sources differing only in byte nine
  execute at independently expected callback addresses `0x20` and
  `0x0100_0020`. Architectural and backend failure cases preserve the
  instruction state/data and retirement. A store of noncanonical RSP data
  preserves all eight payload bytes when the successful callback requests
  STOP.
- Bounded dispatch composes the stack-data addr32 SIB disp32 singleton, bare
  NOP and existing pair. Separate RSP and RBP cases load noncanonical values,
  commit one retirement, then raise #SS on `[RSP]` / `[RBP+0]` with no second
  RAM callback. Partial byte windows do not perform data access.
