# S4-28b — guest periodic timer: N interrupts in virtual time

## Что сделано

Добавлены 12 тестов `crates/od-machine/src/diagnostic_vcpu/periodic_timer_tests.rs` (подключён как `#[cfg(test)] mod` в `diagnostic_vcpu.rs`) и один тест `od-isa` (`cpuid::tests::diagnostic_v1_does_not_declare_tsc_deadline`). Код устройств и сессии не менялся; поведение S4-28a1–a4 не изменено, старые ожидания не правились.

- `periodic_guest_handler_counts_every_period_with_eoi`: N=8, цикл advance → `dispatch_timer` → `run_apic_quantum` → handler (`inc qword [r8]`, EOI записью в MMIO `0xFEE000B0`) → IRETQ → resume. Счётчик 8, RAX = 8+3 после трёх добавочных квантов, RIP/RSP/RFLAGS основного потока восстановлены на каждом шаге, `vector_state` (IRR, ISR) = (0,1) в handler и (0,0) после EOI.
- `periodic_timer_wakes_halt_wait_repeatedly`: три wake подряд из HLT через `poll_apic`, таймер перевзводится сам; на половине периода dispatch даёт `false`.
- `expiry_while_in_service_is_one_edge_delivered_only_after_guest_eoi`: три dispatch всего, при vector в ISR две доставки и третий возвращает false: одна IRR-запись, до EOI не eligible, после EOI eligible; всего два прерывания.
- `large_time_jump_coalesces_to_one_interrupt_and_keeps_phase`: скачок 10,5 периода даёт одно прерывание; следующая граница на полпериода дальше (фаза от момента взвода).
- Долг a3, пути gate: `halt_gate_if_clear_…`, `halt_gate_tpr_blocked_…`, `halt_gate_masked_lvt_…` (periodic и one-shot, без replay при размаскировании), `halt_stop_in_waiting_…`, `halt_gate_reopens_after_outside_profile_…`.
- `pause_due_resume_delivers_exactly_once`.
- `tsc_deadline_mode_is_not_available_to_the_guest` и тест `od-isa`: бит 18 LVT отвергается, CPUID.01H:ECX[24] = 0.
- `clock_operations_do_not_take_the_apic_pair_lock`: lock-order инвариант на уровне API.

## Выбор guest-профиля

Профиль собран напрямую из CPU-state в тесте (как в тестах S4-27/S4-28a3): плоская identity-память, gate вектора 0x40, handler 8 байт, основной поток `inc rax` / `hlt; inc rax`. Kernel fixture с build-скриптом (путь S4-24e) не взят: он тяжелее, а `Stage4*Probe` владеет собственным циклом без shared clock; тестам нужен прямой контроль над IF, TPR, IDTR и временем между квантами. Следствие: handler исполняется с IF=0 (interrupt gate), а вариант handler с IF=1 моделируется записью IF в состояние CPU (STI-профиль недоступен для сессии с clock). Вложенный IRETQ на CS=0x20 профилем не поддерживается (`IretqUnsupported`), поэтому второе прерывание доставляется после возврата в основной поток.

## Injected regression

Временные мутации откатены (`git status` без правок `local_apic.rs`):
- EOI-запись в MMIO заменена на no-op — красные 5 из 12 тестов.
- `dispatch_timer` перевзводит periodic на `now` (burst вместо coalescing) — красные 6 из 12.
- Убран возврат gate при IF=0 в `poll_apic` — красный `halt_gate_if_clear_…`.

## Долг a3

Закрыто: IF=0, TPR, masked LVT, STOP в Waiting, `OutsideProfile` с последующим wake, повторное открытие gate (каждый раз проверено, что dispatch не `Busy`). Lock order pair → clock: инвариант проверен тестом (clock-операции не берут pair lock) плюс чтение кода `dispatch_timer`; обратный порядок в коде отсутствует. Не закрыто: прямая проверка недопустимости порядка clock → pair доступна только чтением кода, потому что замок clock берётся замыканием внутри `with_dispatch_guard`.
