# Stage 4 S4-30c — ECAM и conf1 в карте платы и на шине (opt-in, без host bridge)

Статус: ограниченный срез реализован и проверен локально; независимое ревью (Opus, high) ожидает. Родительский S4-30 остаётся открытым.

## Что сделано

- `crates/od-machine/src/pci_ecam.rs`: типизированный дескриптор `PciEcamDescriptor { segment, start_bus, end_bus, base, size }`, константы `PCI_ECAM_DESCRIPTOR` (`0, 0, 0, 0xFC10_0000, 0x10_0000`) и `PCI_ECAM_SEGMENT`, compile-time проверка `size == (end_bus - start_bus + 1) << 20`; экспорт в `lib.rs`.
- `crates/od-machine/src/firmware_board.rs`: opt-in поле `FirmwareBoardConfig::pci_ecam: bool` (по умолчанию `false`). `board_devices(nvme, pci_ecam)` с флагом заменяет запись кода 7 на `PRESENT` MMIO из дескриптора (`param0` = сегмент, `param1` = `start_bus | end_bus << 8`). Загрузчик с флагом добавляет на `MachineBus` одно устройство `PciEcam` с `MmioBinding` на ECAM и `PortRegionBinding` на `0xCF8` (8 портов), общий `device_index`. Ни одна функция платой не регистрируется.
- `firmware/uefi/src/acpi/dsdt/tests.rs`: один тест — точные 48 байт записи 7, как их выдаёт машина, принимаются DSDT-builder (`PCIE_ECAM`); других правок в `firmware/uefi` нет.
- Документы: `KNOWN_ISSUES.md` (ISSUE-065), `VIRTUAL_BOARD.md`, `MACHINE_CONTRACT.md` (раздел «ECAM и conf1 на плате (S4-30c)»), `FIRMWARE_BOOT.md` (код 7), `docs/testing/MACHINE.md` (пункт 47); evidence — [s4-30c-board-ecam.json](data/stage4/s4-30c-board-ecam.json).

## Выбранная архитектура и почему

- Код 7 уже лежит в слоте v1.0 таблицы устройств, поэтому флаг не повышает `version_minor` и не требует `handoff_minor_max ≥ 1` (в отличие от NVMe, кода 8). Меняются только запись 7 и один регион таблицы регионов.
- Регион карты порождается существующим общим циклом `board_map` по MMIO-записям (как LAPIC/IOAPIC/дисплей/NVMe): вариант `MemoryRegionKind::Mmio` — не RAM и без backing-хранилища; отдельного пути в карте нет, а запись таблицы устройств остаётся единым источником карты, шины и handoff.
- Флаг — `bool`, а не `Option<Config>`: у ECAM нет настроек, дескриптор фиксирован. Образец `nvme: Option` сохранён по смыслу (opt-in, выключен по умолчанию, шина и карта строятся из записи с `PRESENT`).
- Тестовый endpoint вводится через приватную `load_firmware_image_with_pci(image, config, PciEcam)`; публичный `load_firmware_image` всегда передаёт пустой `PciEcam`. Подставляемое устройство без флага не регистрируется (тест).
- Окно в том же 2 MiB-блоке страниц, что регистры дисплея `0xFC00_0000`, поэтому число boot page tables `N` не меняется (тест).

- `cd firmware/uefi && cargo test --offline`: 78 passed (+1, `ecam_entry_emitted_by_the_board_with_the_pci_flag_is_accepted`); firmware — отдельный проект вне workspace.
- Handoff по умолчанию: golden-тест `handoff_block_is_byte_identical_to_the_reference` проходит без изменения эталона; дополнительно `pci_ecam_is_off_by_default_...` (запись 7 `PRESENT = 0`, окна и портов нет).

- Карта: нет пересечений с RAM (в т. ч. максимальным `0xF_F400_0000`), ROM, двумя framebuffer, регистрами дисплея, NVMe, IOAPIC, LAPIC; окно ниже 4 GiB и внутри physical36. `patch_physical_ram` на ECAM (3 смещения) → `ReadOnlyRegion(Mmio)`, окно не меняется.

- Diagnostic endpoint (`#[cfg(test)]`, 00:03.0): vendor/device/Command/BAR0-sizing через conf1 видны через ECAM и обратно.
- `cargo fmt --all --check` и `cargo fmt --check` в `firmware/uefi`: чисто. `cargo clippy -p od-machine --all-targets`: новых замечаний в моём коде нет (в файлах среза единственное — `firmware_board.rs:289`, `validate_config`, давнее); в `firmware/uefi` — только давние (`dsdt/tests.rs:21 entry`, `main.rs`).

## Открытое

- `pci_sanity_check` Linux (S4-30b, задача S4-31/S4-38): conf1 отвергается, пока нет DMI-года BIOS ≥ 2001, функции на bus 0 класса 0x0600/0x0300 или vendor Intel/Compaq (обход — `pci=nochecks`); плата с флагом это не решает.
- С флагом `0xCF9` отвечает `UnknownOffset`, без флага — `UnmappedPort` (reset control — S7-14a).
- Не сделано по плану: MCFG и PNP0C02/`_CRS` (S4-31), E820 и loader (S4-37), host bridge и любые функции, BAR→MMIO и PCI MMIO aperture, MSI/MSI-X, ACPI PM, S7-14a; дефолтный handoff не менялся.
