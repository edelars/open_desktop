# Этап 4 — S4-20c: paged SYSCALL/kernel store/SYSRETQ/user load

**Дата:** 2026-11-06
**Объём:** ограниченный CPL3→CPL0→CPL3 machine roundtrip; родительский S4-20
и Stage 4 остаются открытыми.

## Реализация

Добавлен CPU-owned bounded syscall state для EFER/STAR/LSTAR/FMASK и
definedness сохранённых RFLAGS. `step_paged_syscall_profile` принимает только
четыре точные кодировки: `0F 05`, `4C 89 17`, `48 0F 07`, `48 8B 03`.
`run_paged_syscall_roundtrip` выполняет их подряд через tracked four-level
page walker, выводя CPL из committed CS и используя CR3 из CPU state.

Сценарий проходит CPL3 SYSCALL, kernel-only CPL0 qword store, SYSRETQ и CPL3
qword load через user RO alias. Начальные данные и RAX отличаются от nonce,
сохранённого ядром, поэтому итоговый read наблюдаем. Проверяются selector
caches, STAR-derived selectors, RCX/R11, FMASK, SYSRETQ flags mask `0x3c7fd7`,
definedness и неизменность RSP/CR3. Каждый fetch и operand находится в одной
guest page.

Все отдельные шаги отвергают live TF или RF до fetch. SYSRETQ дополнительно
отвергает сохранённый `R11.TF` после SCE/CPL/canonical checks без частичного
изменения CPU; завершённые fetch A updates и callback writes сохраняются.
Проверены точные A/D updates, реальные PTE readbacks и упорядоченные
`committed_write` callbacks на успешном пути, kernel-store #PF/backend abort и
поздних user fetch/read ошибках. Уже выполненные SYSCALL и kernel store
сохраняются при последующем отказе. Отдельный machine-level probe в ходе
независимого review (не входит в 33 системных теста) подтвердил точную запись
fetch A-bit и callback при отказе SYSRETQ из-за сохранённого `R11.TF`.

## Границы

Это не общая реализация syscall ABI. В профиле нет WRMSR, TSS/IST и stack
switch, SWAPGS, compatibility SYSRET, async events, CPL3 exception delivery,
cross-page fetch/operand или Linux entry/boot. Начальный CPL3 state задаётся
внешней fixture; S4-21 stop/resume и родительский S4-20 остаются открытыми.
