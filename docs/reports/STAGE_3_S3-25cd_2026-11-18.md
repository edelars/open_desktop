## What was done

**S3-25c (normative section).** `docs/specs/JIT_CONTRACT.md`, new section "S3-25c: block lifecycle for one vCPU (normative)":

- four states: unavailable for new entries, active execution, referenced (handles and generation-bound PC-map copies; no references through block links because no linking exists, S3-31 is open), physically freed (slot or `pending_release`; munmap after the last handle);
- transitions performed by the cache/backend/session only at the safe point "after the native call returned and its result was checked, before the next lookup"; destroying the last handle is a separate step that can happen at any moment (in the fixture arena it only records `pending_release` under a borrow), and the slot is returned (state 4) only at the next mutating arena access (`drain_pending_releases` in `publish_*` or in a drop), never under a borrow; `pending_release` is a mechanism of the fixture arena only, `PagedFetchedLoadSession` has no such path;
- both implementations mapped onto the scheme, with the function and the test (by name) for every transition; `PagedFetchedLoadSession` is declared the normative implementation, the fixture `MultiEntryBlockCache` + `PublishedArenaBackend` is a bounded model whose evidence covers the arena mechanisms (generation, `pending_release`, lease);
- reuse rule: every publication raises the slot generation; a stale handle or PC-map copy is rejected before any CPU or memory effect; the error name depends on the handle type (V1 cached: `StaleHandle`; V2 `pc_map()`: `StaleHandle` or `InvalidBlockMetadata`; V2 and V3 at execution: `InvalidHandle` for an older generation, `InvalidMetadata` for a freed slot); for a typed V3 artifact after `CodeInvalidated` the handle stays alive with the current generation and is not in the cache, and re-entry is refused by `validate_active_code_source_v3` as `Preflight(ActiveSourceMismatch)` before the native entry; the slot is freed only when the owner drops the handle;
- a rule (not a premise) for any future link or backward transition: it must check the target's generation, otherwise the detection delay of a retired target is unbounded (S6-40 item 3);
- explicit limits: one vCPU; current block profile (block up to 32 instructions, no linking, memory blocks up to two sites); no cross-thread release; DMA/NVMe/display writers outside; SMC of shared multi-instruction blocks containing a store stays with S3-24 (open).

**S3-25d (stress).** One new test in `crates/od-host/src/lib.rs`, next to the arena cache tests:
`s3_25d_small_capacity_lifecycle_stress_matches_interpreter_and_frees_everything`.

- Capacity 1 and 2, 8 rounds each, deterministic (fixed-seed LCG, no clock, no threads).
- Per round: cached-block churn (A/B/C with an alias), guest write into the aliased backing (invalidation of resident entries), STOP and EventPending before entry; publication of a V3 active-code artifact; injected helper fault (`ArchitecturalFault`); committed STOP during a store; invalidation of the active artifact by its own store; stale-artifact probes (rejected before any CPU/RAM effect); a neighbour handle dropped by the owner hook in `preflight_code_store` (under the arena borrow, before the native code is entered; capacity 2, `pending_release`); cache clear; backend drop with live handles (`MappingAlreadyLive`), last-handle drop, reopen.
- Every native execution is compared with the interpreter (`od_isa::execute::step` on a lock-step reference owner): in the cached runs the CPU state and `retired_instructions` are compared (exit is not checked; the interpreter continues on the same owner after the native run, which is sound because those blocks are register-only moves and `run_multi_cached` borrows the owner); in the V3 runs `backings[0]` (bytes and version) and `backings[2]` (variant 3) are compared fully, for `backings[1]` (variant 1) only `bytes[..8]` without the version.
- Counters from the last run: steps=532, native executions=237 (all 237 compared), live-generation checks=84 (slot generation and metadata verified before every direct V3 execution), stale attempts=84 (all 84 rejected: 48 forged handles of an old generation, rejected as `InvalidHandle` if the slot was reused or `InvalidMetadata` if it was freed, and 36 handles with the live generation rejected by the source check, `Preflight(ActiveSourceMismatch)`; `StaleHandle` does not occur in the stress), invalidated entries=30, deferred releases=6, faults=12, stops=33, event-pending=21, reopens=15, publications=64.
- Final asserts: `available_slots() == capacity` after every phase and after the last drop; `pending_release_count() == 0` at each safe point; a fresh backend opens with all slots free. "Freed code was not executed" is evidenced by: every execution equals the interpreter result, every stale or released-handle attempt is rejected with CPU state, RAM and write count unchanged. There is no separate hook that counts executions per generation.
- Debug run time: about 0.03 s.
- Sanity mutation (not kept): removing `drain_pending_releases()` from `publish_cached_block` makes the test fail with `CachePublish(CapacityFull)`.

**Getters.** None added. `available_slots()` and `capacity()` already exist; `ArenaInner::pending_release_count()` is reachable from the in-crate test module. No production code changed (the diff of `lib.rs` is the new test only).

## Limits

One vCPU, synchronous only. Current block profile (up to 32 instructions, no linking, memory blocks up to two sites). The stress runs on the fixture arena only, on macOS aarch64 (MAP_JIT); elsewhere the test returns at once and passes without checks; production evidence for `PagedFetchedLoadSession` is the existing `s4_15f_*` and `s4_16i_*` tests, not the stress. No cross-thread release or retirement with a grace period (SMP). Writers DMA/NVMe/display are outside; they rely on the key check at the next lookup (S4-16h). SMC of shared multi-instruction blocks with a store: S3-24 (open). Block linking and its generation check: S3-31 (open). No performance claim.
