# S3-23g — bounded qword write across distinct adjacent backings

## Scope

The fixed-RAM tracked owner accepts one qword guest write split across at most
two adjacent mappings, including mappings with distinct ordinary RAM
`BackingId`s. Before mutation it builds a fixed two-segment plan containing
backing index, backing offset, segment length, source-byte offset, and next
version. Both ranges, permissions, versions, active-source overlap and fixed
notification capacity are checked before any byte is copied. With the exclusive
single-vCPU fixture borrow held, both checked slices are copied without a
callback or re-entry; each distinct backing version is advanced once. The owner
returns a fixed notification batch, which the host applies after native result
decoding and before the next lookup.

## Evidence

The native V2 store test warms entries on each backing and on both aliases, plus
unrelated C. One store crossing the mapping boundary updates four bytes in each
backing, emits two notifications, invalidates all affected entries, retains C
as a cache hit, and redispatches the second backing to observe its newly written
MOV immediate. The native state/RAM/version result matches an independent
interpreter step. A control write through the same fixture transaction produces
the same bytes and versions and invalidates the same four entries.

Negative native cases cover a missing, read-only, or non-executable second
mapping, exhausted version on either backing, injected backend failure,
active-source alias overlap through the second segment, a canonical endpoint
overflow, and a range that would require three mappings. They preserve CPU
state and retirement, backing bytes and versions, notification count, and cache
residency. Failures before the copy leave both segments unchanged.

## Limits

This is a single-vCPU fixture transaction over ordinary fixed RAM. The two
slice copies have preflighted bounds and no callback/re-entry between them, but
this does not establish hardware atomicity, SMP synchronization, MMIO/DMA
behavior, a production MMU, or support for ranges spanning three or more
mappings. Stage 2 files are not modified. Physical Mac Mini validation and long
benchmarks remain deferred to the final S3-21 gate.
