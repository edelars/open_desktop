# S4-18d: bounded paged LTR AX, 2026-11-08

Статус: реализовано и проверено локально; независимое ревью без P0–P1, замечания P2/P3 исправлены (см. «Ревью»).
S4-18 и этап 4 остаются открытыми.

Перенесено из линии `stage4` (серия S4-18h) и переписано поверх дизайна `main`
(`PagedProbeResult`/`PagedProbeExit`, `PagedDescriptorMemory`, `walk_long64_4k_with_writer`).
Тяжёлая инфраструктура `stage4` (deferred RAM writes, owner-exclusive descriptor transform)
не переносилась: в `main` `&mut MachineBus` уже даёт единственного владельца RAM, а
уведомления о записи идут через существующий callback.

## Что сделано

- `od-isa`: `TaskRegisterCache`, `LongModeState::tr`, `validate_tss_descriptor`,
  `prepare_paged_ltr_ax`, `prepare_paged_ltr_commit` / `PreparedPagedLtrCommit`;
  `FragmentAdapterError::UnsupportedTaskRegister`.
- `od-machine`: `step_paged_ltr_ax` (+ `PagedLtrReport`, `PagedLtrRejection`, `PagedLtrError`)
  и транзакция `commit_paged_ltr_descriptor` в `page_walk.rs`; `WalkTranslation` теперь
  хранит `table_pages` для проверки alias.
- Порядок: exact fetch `0F 00 D8` внутри страницы RIP → проверки селектора → read walk
  (supervisor) → alias-проверка → валидация → write walk (WP) → согласованность
  трансляций → D leaf → запись дескриптора с busy → commit TR/RIP.

Источник: Intel SDM Vol. 2 (`LTR`) и Vol. 3A §7.2.3 (64-bit TSS descriptor). Не физический oracle.

## Тесты

- `od-isa`: валидатор TSS (границы, порядок отказов, G-бит, #NP раньше битого upper type,
  игнорирование прочих reserved-бит upper dword), commit-preparation, fragment adapter.
- `tests/paged_ltr_step.rs` (14 тестов): успешный путь (TR, busy-образ, порядок A/D/descriptor
  writes, неизменность остального состояния); уже dirty leaf; RPL в селекторе; G=0; 7 отказов
  дескриптора без изменений CPU/памяти; #NP раньше битого upper type; CPL3, LOCK, другие
  кодировки; fetch у границы страницы (0xffe/0xfff без walk, 0xffd допустим) и non-canonical RIP;
  non-canonical/wrapping адрес дескриптора (#GP(0)); отказ профиля до любого walk; read-only GDT
  (`#PF` W, CR2, RIP) и not-present; alias с page-table страницей (в т.ч. запись A-бита в байты
  дескриптора); дескриптор через границу страницы.

## Не входит и открыто

Чтение содержимого TSS, task/stack switching, IST, TLB/JIT, дескриптор через границу страницы,
2 MiB GDT, MMIO-дескриптор, CR0.WP=0 профиль, SMP/DMA-атомарность. Нет тестов на ошибку записи
leaf/descriptor (ROM-leaf) и на дескриптор в MMIO/ROM на уровне шага. `TranslationChanged`
недостижим с текущим walker (A-биты не меняют трансляцию) и не тестируется. Alias проверен только
для PT-уровня. Код ошибки `#GP(0)` для non-canonical базы и порядок проверок не сверены с текстом
SDM/железом (QEMU/Bochs, по замечанию ревью, дают `#GP(selector)` для базы).

## Ревью

Независимое ревью выполнено агентом Claude Opus (effort medium) по `AGENTS.md`. P0–P1 не найдено;
транзакция и порядок записей корректны в рамках профиля. P2: проверка верхнего dword была строже
SDM (теперь только type-поле, биты 12:8) и порядок «type → P → upper type» приведён к QEMU/Bochs;
код ошибки non-canonical базы помечен как несверенный. P3: формулировка про alias уточнена (A-биты
walk остаются committed и могут попасть в байты дескриптора), `table_pages` стал `Option` (нет
ложного alias для физической страницы 0 при 2 MiB leaf), добавлены недостающие тесты. Оставшееся
P3: поведение `LOCK 0F 00 D8` на `RIP&0xfff == 0xffd` — `Unsupported` вместо `#UD`, укладывается в
границу «только внутри страницы».
