# S3-20ej — exact address-size-32 ESP-base dword load with signed disp32

## Scope

S3-20ej admits only the exact eight-byte singleton `67 8B 84 24 id`
(`MOV EAX,[ESP+disp32]`) through the shared typed-IR checked-load path. It uses
ESP as the SIB base, no index, scale 1, and a signed 32-bit displacement. The
effective address is `(low32(RSP) + sign_extend(disp32)) mod 2^32`, then
zero-extended. High RSP bits do not participate. The checked load reads four
contiguous guest-address bytes, writes the result to EAX (zero-extending into
RAX), and advances RIP to `A+8`. A read starting at `0xffff_ffff` continues
above 4 GiB without per-byte wrap.

## Evidence

- JIT gate `memory_load_v2::tests::ir_dword_addr32_rsp_sib_disp32_load_binds_all_source_bytes_to_its_site`: passed 1/1 on the author branch and after integration. It covers ten representative signed displacements, mutates each encoded displacement byte, and checks exact source/site identity plus the `A+8` boundary.
- Host gate `tests::s3_20ej_addr32_rsp_disp32_dword_load_uses_wrapped_esp`: passed 1/1 on the author branch and after integration. The fixture checks `-128` and `+127`, wrap-to-zero, high32-poisoned RSP, interpreter CPU/RAM parity, contiguous reads across 4 GiB, and entry STOP/budget exits followed by successful retry. Callback STOP commits the load and retry is rejected without a second read.
- On runtime source commit `d649bd4`, `od-jit` passed 348/348; `cargo check`, formatting, and Graphify update passed. Exact S3-20ej JIT/host gates and adjacent S3-20da/S3-20dx host gates passed 1/1. The Sol runtime review passed after adding the signed-byte edges and retry coverage.
- Runtime source `d649bd4` was integrated as `4e4fec2`. Harness source `00430e9` was integrated as `4790e76`. At root revision `4e4fec2`, the exact JIT/host gates passed 1/1 and the full Python Stage 3 harness passed 94/94. The harness manifest has 216 Rust gates (206 acceptance, 10 lifecycle) and 234 local steps.

## Limits

The full `od-host` suite was not run. No broad PC-map, performance,
owner/MMU, or physical-hardware claim is made. The open [ISSUE-028](../KNOWN_ISSUES.md)
is the distinct S3-20eg test-coverage gap; S3-20ej does not close it. Stage 2
remained outside this slice’s evidence; concurrent runs were ignored per user
instruction. Mini/M1 checks remain deferred and Stage 3 remains partial.
