# Stage 3 S3-33a: exact native INC RAX

## Result

Added an opt-in, uncached native lowering path for the exact admitted bare
`48 FF C0` (`INC RAX`) form. Admission reuses `S0_09NopIncRaxAdmission` and
`is_exact_inc_rax`; other registers, DEC, memory forms and prefixed encodings
remain rejected. The normal compiler, shared translation cache and
S3-29c interpreter-bridge entry points are unchanged.

Lowering reads RAX, adds constant one at W64 width and writes `FlagEffect::WriteMask`
for PF/AF/ZF/SF/OF. The runtime uses the existing Add flags helper and merges
only those bits into staged RFLAGS, preserving CF and all bits outside the
mask. In the demand-flags candidate, any pending full arithmetic writer is
materialized before INC. Its live allocator homes are saved across that helper
call and restored before INC proceeds; INC then materializes its partial flags
eagerly. No broader pending descriptor or helper ABI was added.

Both eager and demand-flags native dispatch APIs use the existing uncached
bounded coordinator. The latter retains its pending-state PC-map annotations
and shares its budget, STOP-RIP, and accounting behavior. Native INC can be
followed by native JZ/JNZ consumers. The previous S3-29c interpreter bridge
continues to compile INC as `NoNativePrefix` and interpret exactly that
instruction.
