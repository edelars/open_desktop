# S3-40c — предварительная оценка single-block flags comparison

**Статус:** добавлено новое S3-29f evidence в decision ledger. Это
предварительный локальный результат, не выбор production strategy и не
завершение S3-29/S3-40.

## Измеренные факты

[S3-29f](STAGE_3_S3-29f_2026-10-30.md) провёл три release-process runs на
фиксированных семи S0-09 single-block случаях. Медианы 20 paired
candidate/eager ratio samples по каждому процессу были объединены медианой
между тремя процессами:

- Cross-run median ratios составили 1.003352–1.085941 по case; все семь
  значений выше 1, а alias ADD был близок к parity.
- Наибольшая разница наблюдалась на заменённом ADD→CMP флаговом writer chain:
  1.085941, примерно 8.6% больше elapsed для candidate в этой выборке.
- Candidate emitted block был на 40–47% больше для каждого case.
- Execution timing включает `execute_block` safe wrapper, runtime state
  materialization/snapshot и arithmetic-flags helper; compile и publication
  учтены отдельно, но в ratios не включены.

Повторы не записывали power, thermal или background-load telemetry. Между
process-level и paired samples есть разброс; различия около 0.3–1.5% не
позволяют утверждать устойчивое замедление или выигрыш на этих случаях.
Самое заметное case-level различие ограничено одной цепочкой на одной машине
и не представляет multi-block dispatcher или guest workload.

## Предварительное действие

Eager остаётся reference/default; demand-driven candidate сохраняется как
явный uncached вариант. По этой single-block выборке нет оснований менять
production default. Это не оценка полной стоимости стратегии: dispatcher,
shared cache, interpreter fallback, memory helpers, wider flags patterns,
compile/publication tradeoffs под representative workload и физическая x86
проверка остаются вне S3-29f.

Следующий полезный measurement должен держать одинаковыми guest work, cache и
publication policy, correctness gate, состояние и timing boundaries при
сравнении полных dispatcher variants. Пока такого сравнения нет, данные S3-29f
не объединяются с S3-35/36 или benchmark lookup evidence в общий break-even.
ADR не нужен: архитектура и default не менялись. S3-29, S3-40 и S3-41 открыты.
