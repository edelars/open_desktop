# Stage 4 S4-21a: bounded diagnostic vCPU session

## Результат

Принят ограниченный S4-21a. `DiagnosticVcpuSession` синхронно владеет одним
`LongModeState` и `MachineBus`, выполняет guest bytes только из `Runnable` и
возвращает управление после конечного instruction budget.

Проверены:

- реальный fetch/load/store через `IdentityMemoryAdapter`;
- эквивалентность одного бюджета и трёх квантов, включая `rflags_defined`;
- pause/resume без изменения CPU state и идемпотентный STOP;
- STOP до fetch и на poll point во время исполнения;
- отдельные halted/fault/unsupported/backend/stop-address terminal causes;
- отсутствие автоматического продолжения после `WorkLimit`;
- доступность `DiagnosticTerminalExit` внешнему crate caller через integration test.

## Проверки и ревью

- `cargo test -p od-machine --locked --offline`: 55 unit tests, 1 integration
  test и doctests прошли;
- `cargo check -p od-machine --all-targets --locked --offline`: успешно;
- `cargo fmt --all -- --check` и `git diff --check`: успешно;
- независимое ревью `gpt-6.1-sol/high`: первоначально найден P2 — отсутствовал
  public re-export `DiagnosticTerminalExit`; после исправления и повторного
  ревью: **approve**, новых P0—P2 нет.

## Граница

Срез не реализует полный vCPU lifecycle: HLT wakeup, reset, IRQ, MMU, JIT,
VMHost/IPC, worker threads и REP continuation semantics остаются открытыми.
Budget exhaustion и STOP не означают успешное завершение гостя.
