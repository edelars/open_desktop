# S4-18a: bounded paged LIDT

**Date:** 2026-11-06  
**Status:** implementation, verification, and independent review complete; S4-18a is accepted. Stage 4/S4-18 remain open.

## Scope and behavior

Added the separate `PagedLidtLong64V1` / `step_paged_lidt` CPU entry and the
`od-machine` tracked RAM adapter. The CPU path admits only bare
`0F 01 5C 24 ib`, with Long64, CR0=`0x80010033`, CR4=`0x20`, CR3 physical36,
EFER=`0xd00`, and an existing IDTR. It reuses the existing decoder and
`load_idtr`; the SS-based source is RSP plus signed disp8. Success commits only
IDTR and RIP and retires once. The loaded IDT base is not walked.

The adapter performs a single ten-byte RAM read within one 4 KiB guest page
through the tracked walker. It preserves committed fetch/operand A-bit updates
and callback order, does not set D, reports exact page-fault records separately
from backend failures, rejects crossing before operand translation, and does
not route descriptor reads to MMIO/PIO. Exact LOCK raises #UD after full fetch;
CPL1–3 raises #GP(0) before operand access; a truncated fetch fault retains
priority. The full SS-based source span is checked for canonicality before the
operand walk.

## Earlier failing tests

The two reported failures shared the same boundary: the CPU profile had not
reached `load_idtr`. `Unsupported { opcode: 15 }` meant the exact decoded
`LoadIdtr` was not admitted by the profile bridge; because operand reading was
never entered, the machine test then had no descriptor page-fault record to
unwrap. The current entry performs one decoder fetch sequence and passes its
decoded `LoadIdtr` operand to the existing `load_idtr`; no fetch replay occurs.
Both original machine cases pass. The first failure could not be reproduced
against the current partial edits, so the exact transient source state that
caused that classification is unavailable. The second failure was the
consequent absence of an operand walk, not a page-table fault conversion
failure. During this completion, CPL privilege enforcement was added to the
direct CPU entry, and crossing refusals now retain a typed
`TrackedAccessError::CrossesPage` diagnostic instead of an unclassified
backend string.

## Coverage and limits

Tests cover nonidentity code/data translations, positive and negative disp8,
full-state atomicity, exact operand #PF after fetch, actual callback ranges and
page-table A/D snapshots, LOCK #UD versus a byte-six fetch #PF, a machine fetch
fault with exact record and completed A notifications, CPL1–3 #GP, page
crossing, a noncanonical complete source span, a physical RAM hole, registered
MMIO with zero device callbacks, a RAM-starting read with an unmapped tail and
unchanged sentinel destination, an aliased descriptor observing the committed
A bit, the last fitting offset `0xff6` through a read-only mapping, and an
unsupported form. Profile rejection and the `0xff2`–`0xfff` instruction-start
boundary assert zero fetch/memory accesses. No MMIO/PIO width was added.

Cross-page descriptor reads, LGDT, descriptor caching, IDT gate checks,
exception delivery, production paging ownership, and hardware/Linux acceptance
remain outside this slice. ISSUE-056 was inspected and remains open: it concerns
the unrelated unmapped root `smoke/` directory and layout checker.
