# Документация проекта

- `ROADMAP.md` — глобальные этапы. `ARCHITECTURE.md` — предложение/принятые границы архитектуры. `PROJECT_LAYOUT.md` — нормативная карта каталогов.
- `plans/` — планы задач и критерии будущей приёмки. `specs/` — контракты CPU, платы, ABI и обзоры требований. `policies/` — постоянные политики. `testing/` — стенд и методики. `decisions/` — архитектурные решения с данными. `reports/` — фактические результаты; `reports/data/` — небольшие долговечные доказательства измерений.
- Не отмечать план или подготовленный шаблон как выполненный эксперимент. Каждый отчёт должен различать факты, гипотезы и непроверенные условия.
- Не заводить параллельные roadmap/architecture с другим смыслом. Сначала искать существующий документ.
- Нормативные wire formats находятся в `protocols/`; C headers — в `include/`. Спецификация в docs ссылается на единственный источник вместо копирования противоречащих деталей.
- В `reports/data/` хранить только нужные воспроизводимые данные без секретов/пользовательских материалов; большие временные трассы — в `work/`.
- При добавлении/переименовании пути обновлять карту и ссылки. Не менять исходные правила для сокрытия незакрытого критерия.
