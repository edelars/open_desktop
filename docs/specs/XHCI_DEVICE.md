# Контракт xHCI-контроллера и USB HID-устройств платы (S8-41)

**Статус S8-41: контракт написан; сверка с текстами xHCI 1.2, USB 2.0 и HID 1.11 выполнена 2026-11-21 (разделы 1 и 14), найденные противоречия исправлены; ожидает приёмки (решение HCIVERSION применено; чекбокс ставится после повторной проверки), чекбокс S8-41 не отмечен.** Кода модели нет: реализация — S8-42 (контроллер) и S8-43 (HID-устройства), потребитель прошивки — S7-34, потребитель Windows — S8-44. Решение о владельце модели (этап 8) принято по рекомендации Opus high 2026-11-21 и записано в [STAGE_8.md](../plans/STAGE_8.md#s8-01-инвентаризировать-предпосылки-с-владельцами); подтверждено владельцем проекта 2026-11-21. Документ описывает версию v1 — минимальный профиль для прошивки и inbox-драйверов Windows, а не полный xHCI.

Слова «реализовано» и «наблюдалось» к этому документу не применимы: всё ниже — требования к будущей реализации. Места, где требование опирается на непроверенное утверждение, перечислены в разделе 14.

## 2. Размещение

| Параметр | Значение |
|---|---|
| PCI-функция | `00:05.0` (шина 0, устройство 5, функция 0); слоты 0:3 (тестовый endpoint) и 0:4 (NVMe) заняты ([NVME_DEVICE.md](NVME_DEVICE.md) §2). Многофункциональность не используется. |
| Идентификаторы | Vendor `0xD1A6` (зарезервированный проектный идентификатор, как у NVMe-endpoint), Device `0x0010`, Revision `0x01`, Subsystem ID `0`. Драйверы привязываются по классу, не по vendor. |
| Класс | `0x0C0330`: base class `0x0C` (serial bus), subclass `0x03` (USB), programming interface `0x30` (xHCI). |
| BAR0 | **64-битный non-prefetchable memory BAR (BAR0/1), размер `0x4000` (16 KiB), запрограммирован при создании платы на `0xFC00_8000`: окно `[0xFC00_8000, 0xFC00_C000)`.** Остальные BAR — RO 0. |
| Почему этот адрес | Карта платы ([FIRMWARE_BOOT.md](FIRMWARE_BOOT.md) 2, [MACHINE_CONTRACT.md](MACHINE_CONTRACT.md) «ECAM и conf1 на плате», [NVME_DEVICE.md](NVME_DEVICE.md) §2) занимает: регистры дисплея `[0xFC00_0000, 0xFC00_1000)`, окно NVMe `[0xFC00_1000, 0xFC00_3000)`, BAR NVMe `[0xFC00_4000, 0xFC00_8000)`, ECAM `[0xFC10_0000, 0xFC20_0000)`. Окно `[0xFC00_8000, 0xFC00_C000)` вплотную за BAR NVMe не пересекает ни одно из них, лежит в том же блоке 2 MiB (число страниц `BOOT_PAGE_TABLES` не меняется, S8-42 это проверяет). Он находится внутри диапазона `[0xFC00_3000, 0xFEC0_0000)`, который [FIRMWARE_BOOT.md](FIRMWARE_BOOT.md) не назначает: окна HPET и ACPI fixed hardware выбирает S7-14 вне перечисленных диапазонов, S8-42 сверяет итоговую карту на отсутствие пересечения. Адрес — решение v1, не требование xHCI. |
| Декодирование | Как у NVMe PCI endpoint: Command.MSE (бит 1) включает MMIO, если BAR0 равен запрограммированному адресу; запись другого адреса в BAR0 выключает декодирование (модель не перемещается). Command.BME (бит 2) разрешает DMA; без BME модель не читает и не пишет гостевую RAM, doorbell запоминается и исполняется после включения BME. Command.IO (бит 0) не реализован (RO 0). |
| Прерывание | Interrupt Pin = INTA, level, active-low, фиксированный маршрут **INTA → GSI 17** (у NVMe — GSI 16). Значение вносится в `_PRT` вместе с окном BAR0 в `PCI0._CRS` (ACPI, [ACPI_SMBIOS_TABLES.md](ACPI_SMBIOS_TABLES.md)) в S8-42. Command.INTx Disable (бит 10) снимает линию; Status.Interrupt Status (бит 3) отражает её состояние. |
| Capabilities | **Список capability пуст** (Capabilities Pointer = 0, Status.Capabilities List = 0). MSI и MSI-X в v1 не объявляются (раздел 11). |
| Handoff block | Нового кода устройства в handoff v1 **нет**: прошивка находит xHCI перечислением PCI через ECAM (код 7, [FIRMWARE_BOOT.md](FIRMWARE_BOOT.md) 6.3), как и любую PCI-функцию. Требуется `pci_ecam = true`. Нужен ли регион `MMIO` для BAR0 в таблице регионов handoff и в `MachineMemoryMap`, решает S8-42 по образцу PCI-режима NVMe; в любом случае окно обязано входить в единую карту платы и в `_CRS`. |
| Включение | `FirmwareBoardConfig::xhci: Option<XhciConfig>` (подключено 2026-11-22), требует `pci_ecam`. По умолчанию (`None`) функции нет, чтение конфигурации `00:05.0` даёт все единицы, handoff, карта и хеш ACPI-манифеста не меняются. С конфигом плата собирает контроллер на board-часах, ставит клавиатуру на порт 1 и указатель на порт 2 (`attach_hid_devices`), регистрирует функцию в ECAM и окно BAR0 в `MachineMemoryMap` (`Mmio`, без записи в таблице устройств handoff; запись есть в таблице регионов handoff как `MMIO` без владельца). |
| Сброс PCI-функции (FLR) | Не реализован (как у NVMe). |

## 3. Модель обслуживания (DMA, время)

Как у NVMe ([NVME_DEVICE.md](NVME_DEVICE.md) §3): `BusDevice::read/write` не имеют доступа к гостевой RAM. Запись в doorbell и в регистры кольца только запоминает состояние и выставляет флаг. Команды, трансферы и события исполняются вызовом `service(&mut MachineBus, committed_write)` **между квантами гостя**; один вызов обрабатывает не более 256 TRB на кольцо и не более 64 событий ввода, остаток — в следующем вызове. Следствия:

- завершение видно гостю не сразу после doorbell, а после ближайшего `service`; драйвер, опрашивающий фазовый бит события (прошивка), это допускает; прерывания INTx приходят после `service`;
- DMA разрешён только в RAM (`MemoryRegionKind::Ram`); любой указатель на MMIO, ROM, framebuffer, вне карты или в окно самого xHCI — ошибка раздела 12, а не доступ и не паника;
- записи в RAM сообщают диапазон в `committed_write`;
- время — virtual clock этапа 4: от него зависят `MFINDEX` и задержка сброса порта (раздел 6). Реального времени и `sleep` в модели нет.

## 4. Capability- и Operational-регистры

Адреса — смещения от BAR0. Capability-регистры читаются с шириной 1, 2, 4 байта (`CAPLENGTH` — байт, `HCIVERSION` — слово), остальные регистры — шириной 4; 64-битные регистры (`CRCR`, `DCBAAP`, `ERSTBA`, `ERDP`) — шириной 4 (две половины, младшая первой) или 8. Запись шириной 1 или 2, запись 8 байт в не-64-битный регистр, невыровненный доступ — ошибка шины (`DeviceError::UnsupportedWidth` или `Misaligned`) до любого изменения состояния. Чтение неопределённого смещения внутри BAR даёт 0, запись игнорируется. Запись в RO-регистр и в зарезервированные биты игнорируется; чтения без побочных эффектов.

|---|---|---|

| `0x04` | HCSPARAMS1 | `0x0200_0108`: MaxSlots = 8, MaxIntrs = 1, MaxPorts = 2 |

### 4.2. Operational (база `0x20`)

| Смещение | Регистр | Доступ, reset, поведение |
|---|---|---|
| `0x20` | USBCMD | Реализованы биты: R/S (0), HCRST (1, самоочищающийся, читается 0), INTE (2), HSEE (3). Остальные (LHCRST, CSS, CRS, EWE, EU3S, CME, ETE и пр.) — RO 0. Reset `0`. R/S: 0→1 включает обработку колец и сбрасывает USBSTS.HCH; 1→0 останавливает обработку (команды и трансферы не исполняются), сбрасывает CRCR.CRR и выставляет HCH сразу (в том же доступе). Запись R/S = 1 при USBSTS.HSE = 1 игнорируется до HCRST. |
| `0x24` | USBSTS | HCH (0) RO, reset 1; HSE (2) RW1C; EINT (3) RW1C; PCD (4) RW1C; SSS, RSS (8, 9) RO 0; SRE (10) RW1C, никогда не выставляется; CNR (11) RO, всегда 0 (сброс мгновенный); HCE (12) RO 0. Reset `0x0000_0001`. |
| `0x28` | PAGESIZE | RO `0x0000_0001` (4 KiB). |
| `0x34` | DNCTRL | RW биты 15:0, хранятся, на поведение не влияют (Device Notification не доставляются). Reset 0. |
| `0x38` (64) | CRCR | Запись: RCS (0) и Command Ring Pointer (63:6) принимаются **только при CRR = 0**; CS (1) и CA (2) в v1 не реализованы (читаются 0, запись игнорируется, раздел 13). Чтение: бит 3 CRR, остальные 0 (указатель при чтении 0). CRR выставляется первым doorbell 0 при R/S = 1 и сбрасывается R/S = 0 и HCRST. Reset 0. Правила записи — xHCI 1.2 §5.4.5, §4.6.1; CS и CA в спецификации обязательны, в v1 не реализованы (раздел 14, пункт 11). |

| `0x58` | CONFIG | MaxSlotsEn (7:0), U3E и CIE (8, 9) RO 0. Запись только при HCH = 1. Эффективное число слотов — `min(MaxSlotsEn, 8)`; Enable Slot при `MaxSlotsEn = 0` даёт No Slots Available. Reset 0. |

## 5. Runtime, Interrupter 0 и Doorbell

| Смещение | Регистр | Доступ, reset, поведение |
|---|---|---|
| `0x1000` | MFINDEX | RO, 14 бит: `floor(virtual_ns / 125_000) & 0x3FFF`; MFINDEX Wrap Event не формируется. |
| `0x1020` | IMAN | IP (0) RW1C, IE (1) RW; reset 0. IP выставляется при записи в кольцо событий (кроме событий от TRB с BEI = 1), если ERDP.EHB = 0; вместе с ним выставляются EHB и USBSTS.EINT; пока EHB = 1, новые события IP не выставляют (xHCI 1.2 §4.17.2). |
| `0x1024` | IMOD | IMODI (15:0) reset `0x0FA0`, IMODC (31:16) RW; значения хранятся, замедления доставки в v1 нет. |
| `0x1028` | ERSTSZ | Биты 15:0. Запись значения > 1 игнорируется (ERST Max = 0). Принимается только при HCH = 1. |
| `0x1030` (64) | ERSTBA | Биты 63:6. Запись только при HCH = 1; запись загружает единственную запись ERST (16 байт: база сегмента 64 бита, размер в TRB 32 бита) и инициализирует кольцо: enqueue = начало сегмента, cycle = 1. Размер сегмента вне `[16, 4096]`, база не кратна 64 или не в RAM — **HSE** (раздел 12). |
| `0x1038` (64) | ERDP | DESI (2:0) RW (0 — единственный допустимый сегмент), EHB (3) RW1C, указатель (63:4). Запись нового dequeue освобождает место в кольце. EHB выставляется вместе с IP (§4.17.2, §5.5.2.3.3) и очищается драйвером записью 1. |
| `0x800 + 4*n` | Doorbell n, `n = 0..8` | Только запись, чтение 0. n = 0 — командное кольцо (DB Target = 0, иначе игнорируется). n = 1..8 — слот n: DB Target (7:0) = Endpoint ID (DCI) 1..31, DB Stream ID (31:16) обязан быть 0. Doorbell при HCH = 1, в выключенный слот или на DCI не из `{1, 3}` игнорируется со счётчиком диагностики. Без Command.BME doorbell запоминается и исполняется после включения BME. |

**Кольцо событий.** TRB пишутся в сегмент с текущим cycle bit; при достижении конца сегмента cycle инвертируется и enqueue возвращается в начало. Для событий резервируется последний свободный TRB: когда остаётся один слот, модель пишет в него **Event Ring Full Error** (Host Controller Event, тип 37, код завершения 21; сверено: xHCI 1.2 §4.9.4, §6.4.2.6, табл. 6-90 и 6-91) один раз и перестаёт обрабатывать команды, трансферы и сообщать о портах, пока драйвер не продвинет ERDP. Внутренней очереди событий нет: события формируются на месте из состояния (команда в кольце, TRB в кольце трансфера, бит изменения PORTSC), поэтому ничего не теряется, кроме отложенного исполнения. Прерывание INTx: пока выставлены IMAN.IP, IMAN.IE и USBCMD.INTE и не выставлен Command.INTx Disable, линия удерживается; запись 1 в IMAN.IP снимает её (EINT очищается записью 1 в USBSTS.EINT независимо).

## 6. Порты и корневой хаб

Два порта USB 2.0 (MaxPorts = 2, оба в одной Supported Protocol, раздел 7), без внешних хабов: **порт 1 — клавиатура, порт 2 — абсолютный указатель**. Устройства подключены с момента сброса платы; горячее подключение и отключение в v1 нет. Порты `PORTSCn` — `0x420 + 0x10*(n-1)`: PORTSC, PORTPMSC (+4), PORTLI (+8), PORTHLPMC (+0xC). PORTPMSC, PORTLI, PORTHLPMC — RO 0.

PORTSC (по Linux `xhci-port.h`):

| Бит | Поле | Поведение в v1 |
|---|---|---|
| 0 | CCS | RO; 1 всегда (устройство подключено). |
| 1 | PED | Читается 0 до сброса порта и 1 после; запись 1 отключает порт (PED = 0, PLS = 7 Polling; PEC не выставляется — для USB2-порта он выставляется только при Port_Error, §5.4.8, §4.19.2), порт требует нового сброса (§4.19.1.1.6). |
| 3 | OCA | RO 0. |
| 4 | PR | Запись 1 при CCS = 1 и PR = 0 запускает сброс: PR = 1, PED = 0, PLS = 7 (в состоянии Reset значение PLS не определено, §4.19.1.1.4; модель держит 7); запись PR = 1 при PR = 1 игнорируется (§5.4.8). Через **50 мс virtual clock** (константа `USB_PORT_RESET_NS = 50_000_000`: USB 2.0 §7.1.7.5, TDRSTR корневого порта не менее 50 мс; в тестах допускается 0 по явной настройке) модель завершает сброс: PR = 0, PED = 1, PLS = 0 (U0), PRC = 1, устройство возвращается в состояние Default (адрес 0, не сконфигурировано, протокол по умолчанию, idle 0, очередь отчётов очищена; слоты, привязанные к порту, не отключаются, их трансферы завершаются **USB Transaction Error (4)**, пока Device Address слота не совпадёт с адресом устройства: слот из Addressed/Configured переводится в Default командой Reset Device (срез B, раздел 9.1), затем повторяется Address Device; из Addressed Address Device даёт Context State Error). |
| 8:5 | PLS | Чтение: 0 (U0) при PED = 1, 7 (Polling) до сброса (состояние Disabled подключённого порта, §4.19.1.1.2–3); 5 (RxDetect, состояние Disconnected) и 4 (Disabled) не используются, потому что отключения нет. Запись с LWS (бит 16) = 1: значение 0 принимается как no-op; **U2, U3 и Resume игнорируются** (порт остаётся U0; приостановка устройств вне v1). LWS читается 0. |
| 9 | PP | RO 1 (PPC = 0). |
| 13:10 | Port Speed | RO; **1 (Full Speed)** при CCS = 1 (PSIC = 0: значение 1 — Full-speed, табл. 7-13; по §5.4.8 поле действительно после первого сброса порта, модель отдаёт 1 всегда). Оба устройства — Full-speed, 12 Мбит/с. |
| 15:14 | PIC | RO 0 (индикаторов нет). |
| 17 | CSC | RW1C; reset после HCRST — 1 (подключение, ещё не отчитанное). |
| 18 | PEC | RW1C; в v1 не выставляется (USB2-порт: только Port_Error, §5.4.8, §4.19.2). |
| 21 | PRC | RW1C; 1 по завершению сброса. |
| 19, 20, 22, 23 | WRC, OCC, PLC, CEC | RW1C, никогда не выставляются. |
| 24 | CAS | RO 0. |
| 25–27, 30, 31 | WCE, WDE, WOE, DR, WPR | RO 0 (пробуждение и warm reset не поддерживаются). |

**Port Status Change Event.** Для каждого порта модель хранит «событие выдано» (PSCEG, xHCI §4.19.2): USBSTS.PCD выставляется при переходе 0→1 любого бита изменения (CSC, PEC, PRC) независимо от R/S; Port Status Change Event (тип 34, Port ID в DW0 31:24, код Success в DW2 31:24; §6.4.2.3) публикуется один раз, когда OR всех битов изменения порта переходит 0→1, при R/S = 1 и настроенном кольце; пока не очищен какой-либо бит изменения порта, новые события этого порта не публикуются. Если событие нельзя записать (R/S = 0, кольцо не настроено, кольцо заполнено), флаг остаётся и событие публикуется при первой возможности. Запись 1 в бит изменения очищает его («событие выдано» снимается, когда очищены все биты изменения порта). Драйвер, опрашивающий PORTSC, события не обязан читать (прошивка).

## 7. Extended Capabilities

С смещения `0x2000` (xECP = `0x800`) единственная запись — **Supported Protocol Capability** (ID 2, 16 байт, Next = 0):

| Смещение | Значение |
|---|---|
| `0x2000` | `0x0200_0002`: ID = 2, Next = 0, Revision Minor = `0x00`, Revision Major = `0x02` (USB 2.0) |
| `0x2004` | `0x2042_5355` — строка «USB » |
| `0x2008` | `0x0000_0201`: Compatible Port Offset = 1, Compatible Port Count = 2, PSIC = 0 (скорости по умолчанию), Protocol Defined = 0 |
| `0x200C` | `0x0000_0000`: Protocol Slot Type = 0 |

Раскладка сверена с xHCI 1.2 §7.2 (табл. 7-6…7-9, 7-13, §7.2.2.1.4: Protocol Slot Type = 0); биты HLC и BLC слова 2 (табл. 7-15) равны 0: аппаратный LPM не поддержан. USB Legacy Support (ID 1) и BIOS-владение **не объявляются**: передавать управление прошивки ОС через USBLEGSUP не нужно, остановку контроллера прошивкой описывает раздел 12, потребителя — раздел 15. Диапазон `0x2010–0x3FFF` читается 0; `0x3000–0x3FFF` зарезервирован под таблицу MSI-X и PBA на случай расширения (раздел 11).

## 8. Структуры данных в гостевой RAM

Все структуры — в гостевой RAM по физическим адресам, которые пишет драйвер. Адрес должен быть в RAM, кольца и контексты — выровнены (ниже), иначе раздел 12.

- **DCBAA** (Device Context Base Address Array): 64-битные указатели, элемент 0 не используется (scratchpad нет), элемент n — Output Device Context слота n. Выравнивание 64, размер `9 * 8` байт.
- **Контексты по 32 байта** (CSZ = 0): Device Context = Slot Context + 31 Endpoint Context (1024 байта, выравнивание 64); Input Context = Input Control Context (32 байта) + Device Context (1056 байт, выравнивание 64 по табл. 6-1; поле указателя в TRB 63:4 допускает 16, модель принимает только кратный 64). Endpoint Context для DCI n — индекс n в Device Context (DCI 1 — EP0, DCI 3 — EP1 IN).
- **Поля, которые использует модель.** Slot Context: DW0 — Route String (19:0, должна быть 0), Speed (23:20) — в xHCI 1.2 поле устарело и зарезервировано (табл. 6-4): модель его не читает и не проверяет, при копировании переносит как есть; Context Entries (31:27); DW1 — Root Hub Port Number (23:16), Max Exit Latency (15:0); DW2 — Interrupter Target (31:22, должен быть 0); DW3 — USB Device Address (7:0), Slot State (31:27: 0 Disabled/Enabled, 1 Default, 2 Addressed, 3 Configured). Endpoint Context: DW0 — EP State (2:0: 0 Disabled, 1 Running, 2 Halted, 3 Stopped, 4 Error), Mult и MaxPStreams (должны быть 0), Interval (23:16, показатель степени: период `2^Interval` × 125 мкс; допустимо 0..15, для Full-speed interrupt 3..10; сверено: табл. 6-12, §6.2.3.6 — bInterval 10 мс = 80 × 125 мкс округляется вниз до 2^6, поэтому 6); DW1 — Error Count (2:1), EP Type (5:3: 4 Control, 7 Interrupt IN), Max Burst (15:8, 0), Max Packet Size (31:16); DW2:DW3 — TR Dequeue Pointer (бит 0 — DCS); DW4 — Average TRB Length. Остальные поля хранятся как записаны и не интерпретируются.
- **TRB** — 16 байт, выравнивание 16; сегмент кольца трансфера выровнен по 16, сегмент командного кольца и кольца событий — по 64, ни один не пересекает границу 64 KiB (табл. 6-1, §4.9). Общая раскладка: DW0:DW1 — параметр; DW2 — статус; DW3 — управление: Cycle (0), ENT/TC (1), ISP (2), CH (4), IOC (5), IDT (6), BSR/DC (9), TRB Type (15:10), DIR (16), Slot ID (31:24), Endpoint ID (20:16). Командное кольцо и кольца трансферов — сегменты по 256 TRB рекомендуемо, ≥ 2 TRB, один сегмент не пересекает границу 64 KiB; кольцо замыкает **Link TRB** (тип 6) с Toggle Cycle. Цепочки из нескольких сегментов через Link допустимы; Цепочки TRB (CH = 1) поддерживаются (раздел 9.3); Event Data TRB (7) и Transfer No-Op (8) не поддерживаются (**TRB Error**; в xHCI 1.2 они допустимы в кольце трансфера, табл. 6-91, то есть это отклонение; для Windows это риск, раздел 14, пункты 10 и 11).
- **Кольцо событий** — единственный сегмент через ERST (раздел 5), 16–4096 TRB.

## 9. Команды, трансферы и события

### 9.1. Команды v1

Командное кольцо исполняется при doorbell 0 в порядке кольца до первого TRB, чей Cycle ≠ RCS (кольцо пусто). Каждая команда порождает один **Command Completion Event** (тип 33): DW0:DW1 — физический адрес TRB команды, DW2 — код завершения в 31:24 и параметр 0, DW3 — Slot ID (31:24), VF ID 0, тип 33, Cycle. Link TRB в командном кольце обрабатывается без события. Типичный порядок драйвера: Enable Slot → Address Device → (Configure Endpoint) → Evaluate Context при необходимости.

| Команда (TRB Type) | Поведение и коды завершения |
|---|---|
| **Enable Slot (9)** | Выбирает наименьший свободный Slot ID в `1..min(MaxSlotsEn, 8)`, Slot Type (20:16) должен быть 0. Нет свободного — **No Slots Available (9)**. Иначе **Success (1)** с Slot ID, слот в состоянии Enabled; Output Context не пишется до Address Device. |
| **Disable Slot (10)** | **Принята в v1** (решение Opus high 2026-11-21; в списке постановки S8-41 её не было): без неё слот не освободить (восьми слотов хватает на два устройства, но порт-сброс и повторное перечисление требуют освобождения). Слот не включён — **Slot Not Enabled (11)**; иначе слот Disabled (все эндпоинты, включая EP0, — Disabled, §4.8.3), DCBAA[n] не трогается (RAM драйвера), Success. |
| **Address Device (11)** | Параметр — указатель на Input Context (выравнивание 64, иначе **TRB Error (5)**), BSR (9), Slot ID (31:24). Слот не включён — **Slot Not Enabled (11)**. Состояние слота не Enabled/Default (BSR = 0) или не Enabled (BSR = 1) — **Context State Error (19)**. Input Control Context: A0 = A1 = 1, остальные A и все D равны 0, иначе **Parameter Error (17)**. Slot Context: Root Hub Port Number ∈ {1, 2}, Route String = 0, Interrupter Target = 0, Context Entries = 1 (§6.2.2.1); EP0 Context: тип 4, Max Packet Size ≥ 8, TR Dequeue Pointer ≠ 0 и кратен 16, DCS = 1, MaxPStreams = 0 (§6.2.3.1), иначе **Parameter Error (17)**. Порт без подключённого устройства, не включён (PED = 0) — **USB Transaction Error (4)** (так в §4.6.5 отвечает неуспешный SET_ADDRESS); состояние слота при этом не меняется (§4.5.3: неуспешная команда перехода не вызывает; примечание §4.6.5 говорит «Default» — текст спецификации непоследователен; драйверы после этой ошибки выполняют Disable Slot). DCBAA[slot] = 0 или не в RAM — HSE (раздел 12). BSR = 0: устройству посылается SET_ADDRESS (адрес = Slot ID), Slot State = Addressed, Address в Slot Context = Slot ID; BSR = 1: адрес 0, Slot State = Default, SET_ADDRESS не посылается. Модель копирует Slot и EP0 Context в Output Device Context (EP State = Running; прочие поля, включая Speed, Root Hub Port Number и Context Entries, — из входа). Success. |
| **Configure Endpoint (12)** | Слот не Addressed/Configured — **Context State Error (19)**; Slot Not Enabled — (11). D0, D1 и A1 обязаны быть 0, A0 = 1 (§4.6.6; при A0 = 0 — Parameter Error, требование модели). Input Endpoint Context добавляемого DCI: EP State = 0 (§6.2.3.2). Поддерживается добавление только DCI 3 (Interrupt IN) с теми же проверками, что у EP0 (тип 7, Max Packet Size ≥ длины отчёта устройства — 8 для клавиатуры, 6 для указателя; Interval 3..10 (показатель степени, раздел 8); TR Dequeue Pointer ≠ 0, кратен 16); добавление другого DCI, второе добавление уже запущенного DCI (без Drop) и Max Burst/Mult/MaxPStreams ≠ 0 — **Parameter Error (17)**. Drop DCI 3 допустим; **Drop и Add DCI 3 в одной команде** (повторная конфигурация) допустимы: контекст эндпоинта переинициализируется из входного, EP State = Running, TR Dequeue Pointer и DCS берутся из входа (сверено: xHCI §4.6.6 и рис. 4-5 — D = 1 и A = 1 заменяют ресурсы, EP State = Running; D = 0 и A = 1 для не-Disabled эндпоинта — неопределённое поведение, модель отвечает Parameter Error; D = 1 для Disabled эндпоинта игнорируется). Бит **DC** (Deconfigure, 9) возвращает слот в Addressed, отключает DCI 3 и задаёт Context Entries выходного Slot Context = 1; Input Context Pointer при DC = 1 игнорируется (§4.6.6, табл. 6-64); в слоте Addressed без DCI 3 команда с DC = 1 — Success без действий. Успех: слот Configured (или Addressed при пустой конфигурации), DCI 3 Running, Success. Учёт пропускной способности отсутствует: **Bandwidth Error (8)** и **Resource Error (7)** не формируются. |
| **Evaluate Context (13)** | Слот Default, Addressed или Configured, иначе **Context State Error (19)**. Применяются A0 (Max Exit Latency, Interrupter Target = 0) и A1 (Max Packet Size EP0); D ≠ 0 — **Parameter Error (17)** (требование модели: §4.6.7 велит D = 0); флаги A для DCI ≥ 2 игнорируются (§6.2.3.3: Endpoint Context 2–31 не оцениваются); A для DCI больше Context Entries входного Slot Context — Parameter Error (§4.6.7). Success. |
| **No Op (23)** | Success без других действий, Slot ID в событии = 0 (§6.4.2.2). |
| Любой другой тип | **TRB Error (5)**, состояние не меняется; тип, не допустимый в командном кольце (табл. 6-91, примечание), — Slot ID = 0; неподдерживаемая команда, допустимая в кольце, — Slot ID из TRB. К ним относятся Force Event, Negotiate Bandwidth, Set Latency Tolerance Value, Get Port Bandwidth, Force Header, Get/Set Extended Property (раздел 13); до среза B такой ответ получают и четыре команды восстановления. |

**Срез B: команды восстановления (решение Opus high 2026-11-21).** Описаны сейчас и **входят в v1**; реализуются **вторым срезом S8-42**, до S8-43 и S8-44 (первый срез S8-42 их может не включать, тогда эти типы дают TRB Error). Состояния эндпоинта — раздел 8.

| Команда (TRB Type) | Поведение и коды завершения |
|---|---|
| **Stop Endpoint (15)** | Slot ID (31:24), Endpoint ID (20:16); SP (23) принимается и игнорируется. Слот не включён — **Slot Not Enabled (11)**; слот не Default/Addressed/Configured — **Context State Error (19)**; EP State ≠ Running (в том числе Disabled, а значит любой DCI вне {1, 3}, а также Halted и Error) — **Context State Error (19)**: **Endpoint Not Enabled (12)** командам не выдаётся, это код для doorbell (§4.7, табл. 6-90); для Halted и Error событие Stopped не формируется (§4.6.9, примечание). Иначе EP State = Stopped, в Output Endpoint Context записываются TR Dequeue Pointer и DCS, **Success (1)**. **Перед** Command Completion Event модель всегда пишет Transfer Event (Force Stopped Event, §4.6.9, табл. 4-2): если TRB по TR Dequeue Pointer действителен (Cycle = DCS), но данных для него ещё нет (Interrupt IN без отчёта) — код **Stopped (26)**, TRB Pointer = этот TRB, остаток = его длина; иначе (кольцо пусто; TD исполняются целиком внутри `service`) — **Stopped - Length Invalid (27)**, TRB Pointer = TR Dequeue Pointer, остаток 0; Slot ID и Endpoint ID — из команды. Кольцо событий должно вместить оба события, иначе раздел 5. |
| **Reset Endpoint (14)** | Слот не включён — **Slot Not Enabled (11)**; слот не Default/Addressed/Configured — **Context State Error (19)**; EP State ≠ Halted (включая Disabled и DCI вне {1, 3}) — **Context State Error (19)** (§4.6.8: код 12 здесь не используется). Иначе Halted → Stopped, **Success (1)**; TR Dequeue Pointer и DCS не меняются (следующий doorbell повторит последнюю транзакцию; для EP0 драйвер обязан затем выполнить Set TR Dequeue Pointer, §4.6.8); TSP (9) принимается, сброса data toggle в модели нет. Halt устройства (SET_FEATURE) не снимается: это CLEAR_FEATURE(ENDPOINT_HALT) драйвера. |
| **Set TR Dequeue Pointer (16)** | Slot ID, Endpoint ID; DW0:DW1 — новый указатель (63:4) и DCS (0); SCT (3:1) обязан быть 0 (иначе **Parameter Error (17)**, требование модели), Stream ID (DW2 31:16) ≠ 0 — **TRB Error (5)** (MaxPStreams = 0, §4.6.10). Слот не включён — **Slot Not Enabled (11)**; слот не Default/Addressed/Configured — **Context State Error (19)**; EP State не Stopped и не Error — **Context State Error (19)**; указатель 0, не кратен 16 или не в RAM — **Parameter Error (17)** (в спецификации проверка не задана, требование модели). Иначе кольцо продолжается с нового указателя и DCS (состояние частично выполненного TD отбрасывается), TR Dequeue Pointer в Output Endpoint Context обновляется, **Success (1)**; EP State: Stopped остаётся Stopped, Error → Stopped (§4.8.3). |
| **Reset Device (17)** | Slot ID. Слот не включён — **Slot Not Enabled (11)** (код 11 определён для Disabled; псевдокод §4.6.11 для не Addressed/Configured называет Context State Error, модель выбирает 11); слот Enabled или Default — **Context State Error (19)**. Иначе слот переходит в Default, Device Address в Output Slot Context = 0, Context Entries = 1, Route String и Root Hub Port Number сохраняются (§6.2.2.4); все эндпоинты кроме EP0 — Disabled; EP0 сохраняет Max Packet Size, EP Type, CErr, TR Dequeue Pointer, Average TRB Length и переходит в **Running** (§6.2.3.7, §4.8.3), остальные поля 0. **Success (1)**. Устройству ничего не посылается (его состояние сброшено сбросом порта). После этого допустим Address Device. |

Doorbell на эндпоинт в состоянии Stopped переводит его в Running; на эндпоинт в Halted, Error и Disabled — игнорируется. Doorbell на эндпоинт, кроме EP0, принимается только в слоте Configured (§4.5.3.4–6). Переходы состояний и предусловия сверены с xHCI 1.2 §4.5.3, §4.6.3–4.6.11, §4.8.3 (раздел 14, пункт 1).

DMA-ошибка при чтении Input Context или записи Output Context — HSE (раздел 12), а не код завершения. Каждая строка таблицы — отдельный обязательный тест S8-42, как и каждый отказ.

### 9.3. Трансферы

Doorbell слота n с DCI 1 (EP0) или 3 (EP1 IN) запускает исполнение кольца этого эндпоинта, если слот Addressed/Configured и эндпоинт Running. TR Dequeue Pointer и DCS берутся из контекста эндпоинта. TRB Cycle ≠ DCS — кольцо пусто. Stream ID, Interrupter Target и Block Event Interrupt обрабатываются: Stream ID ≠ 0 и Interrupter Target ≠ 0 — **TRB Error (5)**, эндпоинт переходит в **Error** (§4.8.3; восстановление — Set TR Dequeue Pointer). Doorbell на DCI 3 принимается только в слоте Configured.

**Control (EP0, DCI 1).** Транзакция состоит из TD: **Setup Stage (тип 2)**, необязательный **Data Stage (3)**, **Status Stage (4)**. Setup: IDT = 1, длина 8, байты запроса в DW0:DW1 (bmRequestType, bRequest, wValue, wIndex, wLength), TRT (17:16): 0 — без данных, 2 — OUT, 3 — IN; IDT = 0 или Transfer Length ≠ 8 — **TRB Error (5)** (проверка допустима, но не обязательна, §4.11.2.2). TRT определяет наличие и направление Data Stage; несоответствие TRT, DIR Data/Status Stage и wLength и несоответствие суммарной длины Data Stage и wLength xHC **не проверяет** (§4.11.2.2: «shall NOT check»). Data Stage: первый TRB типа 3 и, при CH = 1, следующие за ним **Normal TRB (тип 1)** того же направления — **цепочка** (не более 64 TRB, может проходить через Link TRB; драйвер `usbxhci` разбивает буфер по границам страниц, так выглядит и чтение конфигурации на 34 байта); DIR первого TRB задаёт направление всей цепочки (по табл. 4-7 равно TRT; не проверяется), суммарная длина цепочки T — сумма полей Length (не более 65535), с wLength не сверяется (длины определяют поля Length TRB); CH = 1 у Setup или Status Stage — **TRB Error**; Status Stage: DIR по табл. 4-7 — противоположен данным, IN, если данных нет (не проверяется). Запрос исполняет устройство (раздел 10): IN-данные записываются в буферы цепочки по порядку ровно `min(T, wLength, длина ответа)` байт. Короткий ответ (данных меньше T): TRB, на котором данные закончились, порождает событие **Short Packet (13)** с остатком этого TRB, если у него ISP = 1 **или IOC = 1** (при обоих флагах — одно событие); остальные TRB TD пропускаются, но каждый из них с IOC = 1 порождает событие с тем же кодом и тем же остатком; если короткий пакет пришёлся на TRB только с ISP = 1, второе событие (Short Packet, тот же остаток) формируется для последнего TRB с IOC (§4.10.1.1.2). Исполнение идёт к Status Stage. Без короткого ответа каждый TRB с IOC = 1 даёт Success (1) с остатком 0 (Setup Stage по IOC; Status). Ответ устройства STALL — **Stall Error (6)** для TD, EP0 переходит в **Halted (2)**, восстановление — Reset Endpoint и Set TR Dequeue Pointer (срез B, раздел 9.1). Буфер вне RAM — **Data Buffer Error (2)**, эндпоинт Halted. Слот, чьё устройство не находится в состоянии, соответствующем контексту (после сброса порта) — **USB Transaction Error (4)**, эндпоинт Halted. Любая ошибка кольца трансфера, кроме TRB Error, переводит эндпоинт в Halted (§4.10.2), TRB Error — в Error (§4.8.3, §4.10.2.2), в том числе запрос SET_ADDRESS в Setup Stage (§4.11.2.2 требует лишь, чтобы это не было stall).

**Interrupt IN (DCI 3).** Кольцо из **Normal TRB (тип 1)**: адрес буфера, длина, IOC, ISP, BEI; допускается цепочка (CH = 1, не более 64 TRB) с суммарной длиной ≥ длины отчёта, отчёт записывается в буферы по порядку. Если у устройства установлен halt (SET_FEATURE ENDPOINT_HALT, раздел 10.1), TRB не потребляется, формируется **Stall Error (6)**, EP State = Halted. Пока у устройства нет отчёта, TRB не потребляется (аналог NAK, события нет). Когда отчёт готов, модель записывает его в буфер, потребляет TRB и формирует Transfer Event: полный TD — Success (1), остаток 0; короткий отчёт — по правилам Data Stage (§9.3, §4.10.1.1.2, §4.10.3.4): **Short Packet (13)** при ISP = 1 или IOC = 1, остаток — по TRB, в котором кончились данные. Суммарная длина TD меньше длины отчёта — **Babble Detected Error (3)**, эндпоинт Halted (восстановление — Reset Endpoint, срез B). Интервал опроса (Interval) и `SET_IDLE` не используются для задержек: отчёт отдаётся при ближайшем `service` после его появления, не чаще одного отчёта на TRB.

### 10.1. Стандартные запросы (оба устройства)

Через control EP0: **GET_STATUS** (устройство и интерфейс — 0x0000; эндпоинт `0x81` — бит 0 = halt); **GET_DESCRIPTOR** — устройство (1), конфигурация индекса 0 (2, весь комплект 34 байта), строка (3), HID descriptor интерфейса (0x21), Report descriptor интерфейса (0x22); **GET_CONFIGURATION**, **SET_CONFIGURATION** (0 — нет конфигурации, 1 — настроено, иначе STALL), **GET_INTERFACE** (0), **SET_INTERFACE** (только alt 0), **SET_ADDRESS** (выполняет контроллер по Address Device; control-TRB с этим запросом — **TRB Error**). **Halt для Interrupt-эндпоинта обязателен по USB 2.0 §9.4.5; CLEAR_FEATURE и SET_FEATURE (ENDPOINT_HALT) для эндпоинта `0x81` в состоянии Configured выполняются:** SET_FEATURE устанавливает halt устройства (следующий опрос Interrupt IN завершается STALL), CLEAR_FEATURE снимает его. **Строка с неизвестным индексом (включая 0xEE, запрос Microsoft OS String)** — **STALL** (Request Error): EP0 переходит в Halted, восстановление — Reset Endpoint и Set TR Dequeue Pointer (срез B, раздел 9.1). Всё остальное — **STALL**: Device_Qualifier (6), Other_Speed_Configuration (7), BOS (15), Physical (0x23), SET_DESCRIPTOR, SYNCH_FRAME, CLEAR_FEATURE/SET_FEATURE для устройства (DEVICE_REMOTE_WAKEUP), интерфейса и эндпоинтов кроме `0x81`, неизвестные запросы. Запросы в состоянии Default (адрес 0) допустимы после Address Device с BSR = 1. **Состояния устройства (USB 2.0 §9.4):** в состоянии Address (после SET_ADDRESS, до SET_CONFIGURATION(1)) GET_CONFIGURATION возвращает 0, а GET_STATUS, CLEAR_FEATURE и SET_FEATURE для интерфейса и конечной точки `0x81`, GET_INTERFACE и SET_INTERFACE — **STALL** (§9.4.1, 9.4.4, 9.4.5, 9.4.9, 9.4.10); SET_CONFIGURATION(0) в состоянии Configured возвращает устройство в Address. SET_CONFIGURATION и SET_INTERFACE сбрасывают halt конечной точки `0x81` (§9.4.5). Device_Qualifier (6) — STALL: Full-speed-only устройство с bcdUSB `0x0200` обязано ответить Request Error (§9.6.2); Other_Speed_Configuration (7) — STALL. HID-дескрипторы запрашиваются GET_DESCRIPTOR с bmRequestType `0x81` (интерфейс), wIndex = номер интерфейса (HID 1.11 §7.1.1); комплект конфигурации — Configuration, Interface, HID, Endpoint в этом порядке (HID §7.1).

Отчёты формируются только пока выполнены оба условия: SET_CONFIGURATION(1) и DCI 3 Running (порядок Configure Endpoint и SET_CONFIGURATION произвольный). Внутреннее состояние (нажатые клавиши, координаты) обновляется всегда; очередь отчётов существует только пока эндпоинт запущен. После SET_CONFIGURATION/Configure Endpoint отчёт автоматически не отправляется: первый отчёт — по следующему изменению состояния.

### 10.3. Клавиатура: дескриптор отчёта и отчёт

Report descriptor (Usage Page Generic Desktop, Usage Keyboard, Application Collection) состоит из элементов, в порядке: Usage Page(0x07) → Usage Min 0xE0 / Max 0xE7 → Logical Min 0 / Max 1 → Report Size 1, Count 8 → **Input** (Data, Var, Abs) — модификаторы; Report Count 1, Size 8 → **Input** (Const) — зарезервированный байт; Report Count 5, Size 1, Usage Page LEDs(0x08), Usage Min 1 / Max 5 → **Output** (Data, Var, Abs); Report Count 1, Size 3 → **Output** (Const) — добивка; Report Count 6, Size 8, Logical Min 0 / Max 0xE7, Usage Page(0x07), Usage Min 0 / Max 0xE7 → **Input** (Data, Array); End Collection. Элементы Logical Min/Max знаковые: Logical Max 0xE7 кодируется двухбайтовым элементом `26 E7 00` (однобайтовый `25 E7` читается как −25); Usage Min/Max беззнаковые, `29 E7` допустим. Это **64 байта**; значение wDescriptorLength = 64 (`0x0040`). Тест S8-43 сверяет кодированные байты и структуру с HID 1.11 Appendix B и фиксирует результат. **Сверка 2026-11-21:** порядок элементов соответствует HID 1.11 прил. B.1 и E.6; отличие — Logical Maximum и Usage Maximum массива равны `0xE7` вместо 255 (B.1) и 101 (E.6): допустимо, так как boot-дескриптор «не обязан быть зашит» (прил. B), а первые 8 байт отчёта совпадают. Знак: явной фразы «Logical Minimum/Maximum знаковые» в 1.11 не найдено; найдено: поля с неотрицательными пределами беззнаковые, иначе дополнение до двух (§5.8, §6.2.2.7), Local items беззнаковые (§6.2.2.8), E.6 кодирует `19 E0` и `29 E7`; косвенно: B.2 использует Logical Minimum −127, который в одном байте (`0x81`) возможен только как знаковый. Отсюда `26 E7 00` для Logical Maximum и `29 E7` для Usage Maximum. Длины 64 и 63 байта пересчитаны вручную по таблице элементов; префиксы (`05`, `09`, `15`, `25`, `26`, `75`, `81`, `91`, `95`, `A1`, `C0`) — по §6.2.2.2, §6.2.2.5, §6.2.2.7 и E.6. Номера Usage Page `0x01`, `0x07`, `0x08` и Usage Keyboard `0x06` подтверждены в E.6; номера для указателя (Mouse, Pointer, X, Y, Wheel, Button) и ErrorRollOver `0x01` — в HID Usage Tables, не читались (раздел 14, пункт 7).

**Отчёт IN (8 байт):** байт 0 — модификаторы (бит 0 LeftCtrl 0xE0 … бит 7 RightGUI 0xE7), байт 1 — 0, байты 2–7 — Usage ID нажатых немодификаторных клавиш в порядке нажатия, свободные — 0. **Отчёт OUT (1 байт):** бит 0 NumLock, 1 CapsLock, 2 ScrollLock, 3 Compose, 4 Kana, биты 5–7 — 0.

**События ввода → отчёт.** Источник — очередь событий ввода машины (раздел 16); событие `Key { usage: u8, pressed: bool }`, где `usage` — **USB HID Usage ID страницы Keyboard/Keypad (0x07)**, не PS/2 скан-код: допустимы `0x04..=0xDD` (клавиши) и `0xE0..=0xE7` (модификаторы); `0x00..=0x03`, `0xDE..=0xDF`, `> 0xE7` — отбрасываются со счётчиком. Повторное нажатие уже нажатой и отпускание не нажатой клавиши — без отчёта. Каждое изменение множества нажатых клавиш формирует один отчёт (полный снимок состояния). Если одновременно нажато более 6 немодификаторных клавиш, байты 2–7 содержат `0x01` (ErrorRollOver) до тех пор, пока их не станет ≤ 6, байт 0 при этом сохраняется. Таблица соответствия клавиш окна Usage ID принадлежит S10-16; редакция HID Usage Tables здесь не фиксируется (раздел 14).

### 10.4. Абсолютный указатель: дескриптор отчёта и отчёт

**Выбор:** Generic Desktop → **Mouse** (application collection) → Physical collection **Pointer**, три кнопки, оси X и Y **абсолютные 0..32767** по 16 бит, колесо относительное. Альтернатива — Digitizer (usage page 0x0D). Выбор сделан без документации Microsoft «HID over USB»; пригодность для inbox `mouhid` и точность координат проверяет S8-44 (раздел 14, пункт 4); при отказе документ переиздаётся с Digitizer. Элементы в порядке: Usage Page(Generic Desktop), Usage(Mouse), Collection(Application); Usage(Pointer), Collection(Physical); Usage Page(Button), Usage Min 1 / Max 3, Logical 0..1, Size 1, Count 3, **Input** (Data, Var, Abs); Count 1, Size 5, **Input** (Const); Usage Page(Generic Desktop), Usage(X), Usage(Y), Logical 0..32767, Size 16, Count 2, **Input** (Data, Var, Abs); Usage(Wheel), Logical −127..127, Size 8, Count 1, **Input** (Data, Var, **Rel**); End Collection ×2. Всего 63 байта; Logical Max 32767 — `26 FF 7F`, Logical −127..127 — `15 81 25 7F` (знак проверен).

**Отчёт IN (6 байт):** байт 0 — кнопки (бит 0 левая, 1 правая, 2 средняя; биты 3–7 — 0), байты 1–2 — X (little-endian), 3–4 — Y, байт 5 — колесо (знаковый, приращение с момента прошлого отчёта). События: `PointerAbs { x: u16, y: u16 }` (значения > 32767 — отбрасываются со счётчиком), `Buttons { mask: u8 }` (биты 3–7 игнорируются), `Wheel { delta: i8 }`. Колесо накапливается и выдаётся порциями −127..127, остаток переносится; после отчёта накопление 0. Каждое изменение формирует отчёт. **Относительная мышь в v1 не реализуется**; захват курсора и relative mode — вне v1 (S10-16 использует абсолютный указатель). Производитель событий обязан сам перевести пиксели гостя в 0..32767 по формуле `x_logical = round(x_px * 32767 / (width − 1))` (и так же y): соответствие этого диапазона отображению Windows на пиксели экрана не сверено (S8-44, допуск ≤ 1 гостевого пикселя).

### 10.5. Переполнение очередей отчётов

Очередь отчётов устройства — не более 16. Отчёты — снимки состояния, поэтому при переполнении новый снимок **заменяет последний** в очереди: промежуточные нажатия теряются (счётчик `reports_coalesced`), итоговое состояние сохраняется. Очередь событий ввода машины — раздел 16.

## 11. Прерывания и опрос; MSI и MSI-X не в v1

В v1 есть два способа получения событий: **опрос** (фазовый бит событий и `ERDP`; прошивка S7-34 работает только так, ставит Command.INTx Disable и USBCMD.INTE = 0) и **INTx** level по GSI 17 (раздел 5) для драйверов, которые используют линию. **MSI и MSI-X не реализуются и не объявляются в списке capability** — решение v1 (рекомендация Opus high 2026-11-21, MSI-X отложен с условием): прошивке они не нужны. Для Windows это **не сверено**; **условие:** если S8-44 видит отказ `usbxhci` на INTx (драйвер требует MSI/MSI-X или не работает на линии), MSI-X добавляется **до повторного прогона S8-44**, и контракт получает версию v1.1 с MSI-X: capability `0x50`-стиля как у NVMe ([NVME_DEVICE.md](NVME_DEVICE.md) §3.1), таблица и PBA в зарезервированных страницах BAR0 (`0x3000`, раздел 7), вектор Interrupter 0 = вектор 0. Дозированное прерывание (IMOD) в v1 не моделируется.

### 12.2. HCRST

Запись USBCMD.HCRST = 1 (при любом R/S; HCH к моменту ответа = 1): **всё состояние Operational, Runtime и контекстов сбрасывается** (разделы 4–5, все слоты Disabled, кольца и указатели забываются; DCBAA, ERST и RAM гостя не изменяются), **все порты возвращаются в состояние «подключено, не сброшено»** (CCS = 1, PED = 0, PLS = Polling, CSC = 1), устройства — в Default (адрес 0, не сконфигурированы, idle 0, protocol report, очереди отчётов очищены; состояние нажатых клавиш и координат сбрасывается: все клавиши отпущены, кнопки отжаты, координаты не меняются). HCRST и CNR — мгновенно: HCRST читается 0, CNR = 0 после той же записи. PCI-конфигурация (BAR, Command) не меняется. Сброс платы выполняет то же и возвращает PCI-конфигурацию к значениям при создании.

### 12.3. Остановка при выходе из Boot Services (S7-34)

Прошивка перед передачей управления ОС: R/S = 0, ожидание HCH = 1, HCRST, ожидание HCRST = 0 и CNR = 0, USBCMD.INTE = 0, восстановление Command, прочитанного до начала работы (раздел 15). После этого модель **не читает и не пишет гостевую RAM** (нет кольцевой обработки, нет DMA), регистры в состоянии reset (HCH = 1, CRR = 0, IMAN.IE = 0, DCBAAP = 0); BAR0 неизменен. Тест S7-34/S8-42 проверяет эти значения через регистры модели и счётчик обращений к RAM. ОС (Windows) инициализирует контроллер с reset-состояния; USB Legacy Support не используется.

## 13. Не входит в v1

Явные границы; расширение — отдельные задачи или версия контракта:

- **MSI и MSI-X** в v1 нет (раздел 11): отложены с условием, добавляются до повторного прогона S8-44, если `usbxhci` откажет на INTx. Команды, кроме перечисленных в 9.1, — TRB Error. **Stop Endpoint, Reset Endpoint, Set TR Dequeue Pointer и Reset Device входят в v1** (срез B, раздел 9.1), Disable Slot принята в v1 (решения Opus high 2026-11-21; отступления v1 приняты владельцем проекта 2026-11-21).
- **Command Abort и Command Ring Stop** (CRCR.CA, CRCR.CS): команды исполняются целиком внутри `service`, прерывать нечего; Command Ring Stopped/Aborted не формируются.
- USB 3 / SuperSpeed (в том числе PORTSC Port Speed ≥ 4), SuperSpeed-порты и Supported Protocol USB 3; High-speed и Low-speed устройства; **streams**; **isochronous**; bulk; **mass storage** и прочие классы кроме HID; **внешние хабы** (Route String ≠ 0), TT; **passthrough** USB с host.
- Горячее подключение и отключение, suspend/resume, remote wakeup, Link Power Management, USB 3 Link, управление питанием портов.
- Save/Restore State (USBCMD.CSS/CRS), Light Host Controller Reset, Virtualization/Debug/Legacy Support capabilities, scratchpad-буферы, Device Notification, MFINDEX Wrap Event, Bandwidth Request, Doorbell Event, Force Event, Get Port Bandwidth, Extended Property, Latency Tolerance.
- Event Data TRB, Transfer No-Op, 64-байтовые контексты (CSZ = 1), несколько Interrupters, несколько сегментов ERST.
- Относительная мышь, Digitizer, multi-touch, Feature reports, периодическая повторная отправка по idle, повтор клавиш (typematic) — повторы делает ОС или прошивка.
- Снимки состояния: состояние xHCI не входит в snapshot ([VM_STATE.md](VM_STATE.md)); задача этапа 9.
- Копирование моделей и дескрипторов QEMU/Bochs/VirtualBox и других сторонних реализаций.

GET_REPORT указателя отдаёт колесо 0 и накопление не трогает; (е) SET_REPORT клавиатуры сохраняет биты 0–4 байта LED (биты 5–7 обнуляются), GET_REPORT(Output) возвращает его; LED сбрасываются сбросом устройства; (ж) `XhciHandle::attach_hid_devices` подключает клавиатуру к порту 1 и указатель к порту 2 и возвращает `HidHandle` (`leds`, `reports_coalesced`, `dropped_events`, `queued_reports`); по умолчанию порты держат заглушку, подключает плата.
19. **Подключение к плате (2026-11-22), контрактом прямо не заданное:** (а) окно BAR0 — регион `Mmio` карты платы и таблицы регионов handoff без владельца и без записи в таблице устройств (нет кода устройства, версия handoff и хеш ACPI-манифеста не меняются); таблицы страниц загрузки не растут (то же окно 2 MiB, что регистры дисплея и ECAM); (б) INTA → GSI 17: вход IOAPIC INTIN17 (level, active low, Remote IRR и повтор по EOI, как у NVMe и SCI) и источник `XhciIoapicIrqSource` поверх цепочки NVMe/UART в Linux-профиле; в профиле прошивки прерываний нет (опрос); (в) цикл прошивки (`run_boot`) вызывает `service` между квантами и заканчивает квант при записи в регистр xHCI (`XhciHandle::wakeup_pending`, флаг без блокировки, сбрасывается `service`); `service_pending` остаётся истинным, пока опрашивающий Interrupt IN ждёт отчёта, поэтому для остановки кванта используется `wakeup_pending`. **Linux-профиль с xHCI отклоняется конфигурацией** (`linux_profile` и `xhci` несовместимы): цикл CPL0-набора не открывает окно BAR0, у сброса порта нет дедлайна пробуждения (`next_deadline_ns`/`wake_ns` источника прерываний), многопоточный путь vCPU контроллер не обслуживает; их подготовка — условие для Windows (S8-44); вход IOAPIC 17 обрабатывается как уровневый вход INTA независимо от наличия контроллера, как 16 для NVMe; (г) цикл прошивки (`run_paged_firmware_probe`) обслуживает окна регистров точечно: к ним добавлены окно BAR0 xHCI и окно ECAM (через `SharedPciEcam` — одна таблица функций с шиной); порт-ввод конфигурации conf1 `0xCF8/0xCFC` прошивка выполнить не может (профиль ЦПУ прошивки не знает `out dx, eax`/`in eax, dx`), поэтому перечисление PCI в прошивке — через ECAM; (д) сброс платы (`platform_reset`) сбрасывает контроллер как HCRST, устройства (клавиши отпущены), очередь ввода и возвращает PCI-конфигурацию (Command = 0, BAR0 = `0xFC00_8000`); (е) **не сделано:** записи `_CRS`/`_PRT` в DSDT для `00:05.0` (окно BAR0 и INTA → GSI 17). DSDT строит прошивка (`firmware/uefi/src/acpi/dsdt.rs`, `PciRoot`) из таблицы устройств handoff (`PciNvmeRoute` из записи кода 8); у xHCI записи в таблице нет, значит источником маршрута нужно сделать новый код устройства (подъём `version_minor`, правка машины и прошивки, golden DSDT) либо константы прошивки; выбор — отдельное решение (пока Windows и Linux получают xHCI перечислением PCI, но без маршрута INTx).

## 15. Потребитель: прошивка (S7-34)

Минимальный срез S7-34 ([STAGE_7.md](../plans/STAGE_7.md#s7-34-usb-hid-клавиатура-прошивки-для-conin)), полностью определяемый этим контрактом. Ничего сверх списка в S7-34 не входит.

1. **Обнаружение.** Перечисление PCI по ECAM (handoff код 7): шина 0, устройства 0..31, функция 0; xHCI — первая функция с классом `0x0C0330`. Читает BAR0 (64 бита, запрограммирован платой; прошивка его не переназначает, проверяет, что размер `0x4000`), сохраняет Command, пишет Command = MSE | BME | INTx Disable. Функции нет — USB отсутствует, `ConIn` остаётся COM1, без ошибки и без сообщения на каждый опрос (одна диагностическая строка в COM1).
2. **Драйвер xHCI.** Чтение HCSPARAMS1/HCCPARAMS1 и проверка значений раздела 4 (CSZ = 0, MaxPorts ≥ 1); R/S = 0 → HCRST (ожидания — ограниченное число опросов, затем отказ без зависания); память: DCBAA, командное кольцо, кольцо событий (один сегмент) и ERST, Input/Output Contexts и кольца трансферов — в памяти `EfiBootServicesData`, выровненной по 64; CONFIG = 2 слота; DCBAAP, CRCR (RCS = 1), ERSTSZ = 1, ERSTBA, ERDP; USBCMD.R/S = 1; все ожидания — опросом, прерываний нет.
3. **Перечисление.** Для каждого порта с CCS = 1: очистить CSC, записать PR = 1, дождаться PRC = 1 и PED = 1 (сброс занимает 50 мс virtual clock, раздел 6; ожидание ограничено временем), очистить PRC; Enable Slot; Address Device (BSR = 0, EP0 Max Packet Size 64, Context Entries = 1, DCS = 1; поле Speed устарело, модель его не читает); GET_DESCRIPTOR device (18 байт) и configuration (34 байта, запрашивая сначала 9 байт, затем wTotalLength). Устройство подходит, если интерфейс имеет класс 3, subclass 1, protocol 1; иначе (указатель) слот освобождается (Disable Slot) и порт пропускается. Далее Configure Endpoint (добавить DCI 3, Context Entries = 3, тип 7, Max Packet Size 8, Interval 6 — период 2^6 × 125 мкс = 8 мс при bInterval 10 мс) и SET_CONFIGURATION(1); порядок двух операций произвольный (раздел 10.1); SET_PROTOCOL(0) (boot), SET_IDLE(0), SET_REPORT(Output) с LED = 0. Только корневой хаб, без внешних хабов.
4. **HID → ConIn.** Interrupt IN TRB (8 байт, IOC = 1) ставится в кольцо, doorbell; опрос кольца событий на фазовый бит — по таймеру/при `ReadKeyStroke`/`WaitForKey`; после каждого события TRB переставляется. Отчёт переводится в `EFI_INPUT_KEY` (ScanCode/UnicodeChar) и `EFI_KEY_STATE` (RightShift/LeftShift, Ctrl, Alt, Logo; KeyToggleState — NumLock/CapsLock/ScrollLock с записью LED SET_REPORT) и публикуется через **`EFI_SIMPLE_TEXT_INPUT_PROTOCOL` и `EFI_SIMPLE_TEXT_INPUT_EX_PROTOCOL`**. Новая клавиша = Usage в массиве отчёта, которого не было в предыдущем; автоповтора в прошивке нет. Таблица Usage ID → клавиша — в `UEFI_PROFILE.md` («Консоль»).
5. **Объединение источников `ConIn`.** COM1 (S7-07) и USB пишут в одну ограниченную очередь клавиш (256), `WaitForKey` сигналит при непустой очереди; опрос — COM1, затем USB, в одном цикле. Нет USB — только COM1.
6. **Остановка при выходе из Boot Services.** Обработчик события группы выхода из Boot Services выполняет раздел 12.3 и восстанавливает Command.
7. **Проверка (S7-34).** Runner вставляет HID-события в очередь ввода; приложение `echo` печатает нажатые клавиши; после выхода из Boot Services значения регистров — раздел 12.3.

**Срез A (2026-11-22, `firmware/uefi/src/usb/`): перечисление и опрос, без `ConIn`.** Сделаны пункты 1–3, опрос Interrupt IN и перевод boot-отчёта в очередь `EFI_INPUT_KEY` (`hid_keyboard.rs`, Usage ID страницы 0x07, раскладка US, CapsLock, без автоповтора), остановка контроллера при выходе из Boot Services с восстановлением Command (пункт 6). Не сделаны: `ConIn`/`ConInEx` и `KEY_STATE` (пункты 4–5, срез B), запись LED при смене CapsLock (срез B; при перечислении LED = 0 записывается; допустимость повторного входа `next_key` во время трансфера — [ISSUE-647](../KNOWN_ISSUES.md#issue-647)), проверка через runner и по регистрам модели после выхода из Boot Services (пункт 7, срез C, обязательно — [ISSUE-648](../KNOWN_ISSUES.md#issue-648)). Сбой остановки при выходе печатается строкой `OD-FW xhci: stop at exit failed step=… detail=0x…`. Перед HCRST драйвер ждёт CNR = 0 (xHCI 1.2, 4.2). Решения среза, контрактом прямо не заданные:

- Перечисление идёт по портам 1.. и останавливается на первой boot-клавиатуре; устройство не-клавиатура (указатель) получает Disable Slot. Прошивка требует bMaxPacketSize0 = 64 (значение из Address Device), иначе ошибка, а не молчаливая подстановка.
- Ожидания ограничены по времени через `stall` (виртуальные часы платы: рабочая TSC): регистры 20 мс, команда или трансфер 100 мс, сброс порта 200 мс при 50 мс контракта. Часы контроллера внутри кванта гостя стоят (раздел 14, п. 19в), поэтому каждый опрос ожидания пишет USBSTS = 0 (бит RW1C, ничего не снимает): запись в регистр xHCI заканчивает квант, плата двигает время и вызывает `service`. Без этого сброс порта не завершается.
- Центральный процессор профиля прошивки не исполняет инструкции чтения-изменения-записи с операндом в памяти (`and $imm, (mem)`) и BSR/LZCNT: чтения регистров и RAM идут через `black_box`, степень Interval считается циклом.
- Контроллер без функции xHCI (нет ECAM или нет функции класса 0x0C0330) не печатает ничего, чтобы COM1-транскрипты плат без xHCI остались байт в байт прежними (пункт 1 допускал строку). Успех — строка `OD-FW xhci: keyboard enumerated`; сбой — `OD-FW xhci: enumeration failed step=<шаг> detail=0x<8 hex>` (шаги и смысл detail — `Step` в `usb/mod.rs`), загрузка при сбое продолжается, контроллер остановлен, страницы DMA возвращены (если контроллер остановился).
- Размер BAR0 проверяется зондированием (запись всех единиц и восстановление при выключенных MSE и BME).
- В срезе A опрос `next_key` пока никто не вызывает: путь Interrupt IN → очередь покрыт модульными тестами декодера и колец, но не прогоном в ROM (нет источника HID-событий в runner, срез C).

**Срез B (2026-11-22): `ConIn`/`ConInEx`.** Пункты 4–5 раздела выполнены: ключи USB (Usage ID → `EFI_INPUT_KEY`, `EFI_KEY_STATE`) и COM1 идут в одну очередь на 256 ключей (`console/key_queue.rs`); `EFI_SIMPLE_TEXT_INPUT_PROTOCOL` и `..._EX_PROTOCOL` (на одном handle, EX публикуется, только если клавиатура перечислена) читают её; `WaitForKey` и `WaitForKeyEx` сигналятся при непустой очереди; `Reset` очищает очередь и состояние нажатых клавиш (замки сохраняются). Решения среза, контрактом прямо не заданные:

- **Порядок.** Один цикл опроса (таймер 10 мс, `ReadKeyStroke`, `WaitForEvent`): сначала кольцо событий xHCI и отложенная запись LED (`usb::service`), затем байты COM1, затем накопленные клавиши USB. Внутри источника порядок сохраняется; между источниками — порядок опроса (общих временных меток нет). Полная очередь не теряет ввод: байты COM1 остаются в UART, отчёты USB — в кольце событий (отчёты берутся, пока в промежуточной очереди драйвера есть место на 6 клавиш); потеря возможна только если драйвер ждёт управляющий трансфер, а промежуточная очередь (256) заполнена (счётчик `dropped`).
- **KEY_STATE.** `KeyShiftState` = VALID плюс биты модификаторов HID (левые и правые Shift, Ctrl, Alt, Logo); `KeyToggleState` = VALID плюс Scroll/Num/Caps Lock. Ключи COM1 несут нулевое состояние. Нажатия одних модификаторов ключа не дают. Для печатного символа биты Shift не передаются (Shift уже учтён в символе; UEFI 2.11 12.3.3, как в EDK2), у клавиш без символа (F-клавиши, стрелки, Enter) и у управляющих кодов Ctrl+буква они сохраняются. KEY_STATE_EXPOSED не выставляется. Ctrl+буква даёт коды 1–26; Alt и Logo символ не меняют.
- **Замки и LED.** Нажатие CapsLock, NumLock, ScrollLock (Usage 0x39, 0x53, 0x47) переключает замок и ставит запись LED (SET_REPORT Output: бит 0 NumLock, 1 CapsLock, 2 ScrollLock); `SetState` (EX) заменяет замки и ставит ту же запись; без бита VALID или с KEY_STATE_EXPOSED — `EFI_UNSUPPORTED`, при занятом драйвере (вложенный вызов) состояние не меняется и возвращается `EFI_NOT_READY` (в списке кодов 12.2.5 его нет: это отметка временного отказа). Начальное состояние замков — все выключены (LED = 0 из перечисления). Блок клавиш Usage 0x59–0x63 — цифры при NumLock, навигация (End, Down, PgDn, Left, —, Right, Home, Up, PgUp, Insert, Delete) без него. Запись LED не повторяется при ошибке (ошибка в `Keyboard::led_failure`).
- **ISSUE-647 (повторный вход).** Драйвер выдаётся через `Exclusive::with`: вложенный вызов (таймер консоли, который `stall` диспетчеризует внутри ожидания управляющего трансфера) получает `Busy` и пропускает опрос; запись LED выполняется только из `usb::service`, вне других трансферов; консоль вызывает `service` до того, как берёт своё состояние. Выход из Boot Services при занятом драйвере печатает `OD-FW xhci: stop at exit failed step=exit-busy …`.
- **Не поддержано.** `RegisterKeyNotify`/`UnregisterKeyNotify` — `EFI_UNSUPPORTED`. Опрос пишет USBSTS = 0 при каждом вызове (раздел среза A: заканчивает квант модели).
- **Проверка.** Host-тесты: очередь (порядок, 256, обратное давление), COM1 и USB в одной очереди, Usage ID → ключ, модификаторы и `KEY_STATE`, замки и очередь LED, `Exclusive`. Прогон в ROM с подачей HID-событий (Shift+a, CapsLock, стрелка, Enter через `ConInEx`) выполнен один раз на временном приложении и временной подаче событий в runner (клавиши дошли с правильными `KEY_STATE`); в CI этого не было: постоянная подача и приложение `echo` — срез C (ниже).

**Срез C (2026-11-22): проверка в ROM.** `tests/system/firmware_xhci_smoke.py`: (1) runner подаёт HID-события (`--xhci-keys`: Usage ID в hex, `HH` — нажатие и отпускание, `HH+`/`HH-` — одно ребро; первое событие после 60·10⁶ инструкций, шаг 2·10⁶, то есть после перечисления) через `XhciHandle::push_input` из наблюдателя цикла запуска; приложение `echo` (загрузка с ESP на NVMe, `ConIn`) печатает на COM1 принятое: `h e l l o`, пробел, Shift+w, `1`, стрелка вверх, CapsLock, `a`, CapsLock, `a` дают строку `hello W1[UP]Aa` (CapsLock дважды проходит через запись LED); (2) после выхода из Boot Services (приложение `ebs`) снимок модели (`XhciHandle::snapshot`, блок `xhci` отчёта runner) показывает состояние раздела 12.3: USBCMD.R/S = 0, USBSTS.HCH = 1, CRCR.CRR = 0, DCBAAP = 0, ERSTBA = 0, IMAN.IE = 0, BAR0 = `0xFC00_8000`, PCI Command = 0 (как до драйвера), и счётчик обращений контроллера к RAM на остановке равен конечному; контроль — `hello`, где контроллер остаётся запущенным. Ограничения: указатель в ROM не проверяется (прошивка его не использует); после выхода `ebs` сразу останавливает прогон, длительной работы гостя при остановленном контроллере нет (это проверяет тест модели); `RegisterKeyNotify` не поддержан.

## 16. Потребители модели, тесты и API

**Очередь событий ввода машины** — ограниченная (256 событий), принадлежит `od-machine`: производитель (тестовый API runner; после S10-16 — host-путь из окна, [STAGE_10.md](../plans/STAGE_10.md)) вызывает `push_input(InputEvent)`, при переполнении получает `InputQueueFull`, событие не теряется молча. Модель только потребляет очередь в `service` и не вызывает host-API ввода. Для тестов — чтение LED клавиатуры, чтение счётчиков отбрасываний/слияния и счётчика обращений к RAM. Имена API ориентировочные, фиксирует S8-42.

**Обязательные тесты S8-42** (каждый отказ контракта — отдельный тест): значения всех регистров разделов 4–7 и ширины доступа (в том числе HCIVERSION = `0x0100` и HCCPARAMS1 = `0x0800_0001` по разделу 4); BAR, MSE, BME, INTx Disable; HCRST из любого состояния; Enable/Disable Slot (включая No Slots Available, Slot Not Enabled); Address Device (BSR 0/1, каждый Parameter/Context State Error, порт не сброшен); Configure Endpoint (добавление DCI 3, отказы, DC); Evaluate Context; No Op; неподдерживаемый тип (Force Event и прочие → TRB Error); срез B — Stop Endpoint (с Transfer Event 26 или 27 перед Command Completion), Reset Endpoint, Set TR Dequeue Pointer, Reset Device (каждый отказ) и восстановление после STALL; цепочки TRB в control и Interrupt IN; CLEAR/SET_FEATURE(ENDPOINT_HALT); Link TRB и перенос cycle; кольцо событий (wrap, Event Ring Full); Port Status Change (отложенное событие, повторный сброс порта); control GET_DESCRIPTOR device/configuration/string (в том числе 0xEE) с драйвером-тестом на Rust через гостевую RAM и MMIO; interrupt IN: отчёт после события ввода; все пути раздела 12 (HSE при DMA-ошибке, буфер вне RAM, остановка при выходе из Boot Services с проверкой отсутствия обращений к RAM).

**Обязательные тесты S8-43:** последовательности событий → байты отчётов (клавиатура: модификаторы, порядок, ErrorRollOver, повтор/лишний release; указатель: X/Y/кнопки/колесо, границы), байты дескрипторов и HID-запросы раздела 10, boot protocol клавиатуры по Appendix B, SET_PROTOCOL/IDLE/REPORT, переполнение очередей.

**S8-44 (Windows):** inbox `usbxhci`, `usbhub3`, `hidusb`/`kbdhid`/`mouhid` находят оба устройства; закрывает пункты раздела 14 (2–7).
