## 2. Правила

1. **Заголовок** не содержит кода, цифр и путей. Код и путь — только в «Подробностях».
2. **Объяснение** — одно-два предложения; **действие** — что сделать пользователю. Тексты — ключи локализации `<ключ>.title`, `<ключ>.explanation`, `<ключ>.action` и русские значения по умолчанию. Английских значений в коде нет.
3. **Неизвестный код** (в том числе код `ERROR` вне закрытого списка 12.1, [6.7](../../protocols/control/CONTROL_PROTOCOL_V2.md#67-error-32--detail_length-байт)): заголовок «Неизвестная ошибка», «Подробности» с числом кода. Приложение не угадывает смысл.
4. **Сигнал VMHost** — «Процесс машины аварийно завершился». Это не «ошибка гостя»: гостевой код в этом этапе не исполняется, а паника или сбой процесса протокол не выдаёт за ошибку гостевой системы ([раздел 11](../../protocols/control/CONTROL_PROTOCOL_V2.md) протокола, «Панику Rust…»).
5. **Повтор.** Если состояние ресурсов после отказа неизвестно (`failed`, `host_failure`, сигнал, потеря связи, `io_error`, `unsupported_durability`), действие не говорит «повторите», «попробуйте снова», «ещё раз»; оно говорит «перезапустите приложение» или «проверьте машину». Колонка «Повтор безопасен» — единственное место, где разрешён совет повторить; тест проверяет слова.
6. **`unsupported_durability` — не временная ошибка.** Текст прямо говорит об этом и называет причину (надёжность хранения, этап 9, [ISSUE-055](../KNOWN_ISSUES.md#issue-055-s9-host-durability-guarantee-unconfirmed)); он не скрывается за «попробуйте позже».
7. **Stack trace не показывается.** Текст `detail` из `ERROR` не влияет на логику и попадает только в «Подробности» (протокол запрещает ему содержать пути вне bundle).
8. **Степени серьёзности.** `сведение` — не отказ (`ACK`, штатное завершение); `предупреждение` — запрос отвергнут, ничего не потеряно, состояние машины прежнее; `ошибка` — операция не выполнена, нужно действие пользователя; `критично` — процесс машины завершился аварийно или состояние неизвестно, перед следующим запуском машину надо проверить.

### 2.1. «Подробности»

Предлагаются, если в колонке «Подробности» стоит «да». Содержат строки:

| Строка | Когда |
|---|---|
| `Код:` имя и число (`pause_timeout (10)`), либо `статус N`, `сигнал N`, `неизвестный (N)` | всегда, кроме ошибок библиотеки |
| `Запрос:` Request ID | ошибка машины; `не определён`, если событие или ответ его не несёт |
| `Журнал:` путь к `logs/vmhost.log` внутри bundle | ошибка машины, если файл существует; иначе `vmhost.log пока не ведётся` |
| `Время:` местное время со смещением | всегда |
| технические строки: `Статус процесса`, `Сигнал`, `errno`, `Состояние процесса при ошибке`, `Числа ошибки` (`aux0`, `aux1`), `Сообщение процесса` (`detail`), `Поле конфигурации`, `Путь` | по случаю |

Пример (отказ паузы):

```text
Код: pause_timeout (10)
Запрос: 3
Журнал: vmhost.log пока не ведётся
Время: 2026-11-06 12:00:00 +0300
Состояние процесса при ошибке: 2
```

Запись журнала `vmhost.log` в VMHost на момент написания документа не реализована ([VM_BUNDLE, раздел 2](VM_BUNDLE.md) задаёт только его место); до тех пор «Подробности» честно говорят, что журнала нет, и не показывают несуществующий путь.

Если машина не отвечает, перезапустите приложение». Severity — ошибка, «Подробности» — да, повтор безопасен — нет.

## 4. Коды `ACK`

`ACK` — только успех ([6.2](../../protocols/control/CONTROL_PROTOCOL_V2.md#62-ack-12-байт)); отказы идут в `ERROR`. Записи нужны, чтобы каждый код провода имел слова и чтобы неизвестный код `ACK` показывался как «Неизвестная ошибка».

| Код | Заголовок | Объяснение | Действие пользователя | Severity | «Подробности» | Повтор безопасен |
|---|---|---|---|---|---|---|
| `0` (`ok`) | Готово | Запрос выполнен. | Действий не требуется. | сведение | нет | нет |
| `1` (`in_progress`) | Операция выполняется | Процесс машины уже получил этот запрос и выполняет его. | Дождитесь результата. | сведение | нет | нет |

Статус 0 после `STOP` или `SHUTDOWN` и EOF в `stopped` без запроса — штатное завершение: сообщения нет (запись `stopped` существует для полноты и не показывается). Отсутствие статуса (клиент над готовым сокетом, процесса нет) сообщения тоже не даёт (`ErrorPresentation.exit` возвращает `nil`); запись `unavailable` есть для полноты каталога.

## 7. Мастер создания машины

**Мастер — S11-08.** Мастера создания машины в коде ещё нет, поэтому его ошибок в каталоге нет и придумывать их заранее запрещено. Когда S11-08 появится, он добавляет записи сюда и в `ErrorCatalog`, а тест полноты расширяется перечислением его ошибок. Из плана S11-08 уже известно, что отказ `PREPARE_DISK` объясняется кодами раздела 3: `invalid_name`, `disk_exists`, `insufficient_space`, `invalid_state`, `unsupported`, `io_error`; предупреждение «ёмкость больше свободного места» и отмену на последнем шаге определяет сам мастер.

## 10. Локализация и расхождения с планом

- Тексты — пары «ключ и значение по умолчанию» в `ErrorCatalog`. Файла `Localizable.strings` в этой задаче **нет**: в SwiftPM-цели `OpenDesktop` нет ресурсов, а их добавление без `.process`/`resources:` ломает сборку. Подключение `Localizable.strings` (ru и en) — следующий шаг; ключи уже заданы (`titleKey`, `explanationKey`, `actionKey`). План S11-09 называет `apps/macos/Resources/Localizable.strings`; это расхождение с планом.
- Request ID. Событие `ERROR` без запроса несёт его; при отказе запроса клиент передаёт приложению только `ControlV2ErrorReport` без ID запроса, поэтому в «Подробностях» стоит `не определён`. Передача ID в завершение запроса — отдельное изменение `ControlClientV2`, не сделано.
- Журнал `vmhost.log` не ведётся (раздел 2.1).
- Колонка «Повтор безопасен» (`retrySafe`) добавлена к полям плана ради правила «не писать „попробуйте снова“ там, где повтор небезопасен».
- Мастер — S11-08 (раздел 7).
- Строка с `BundleConfigIssue.description` («поле: правило») под названием повреждённой машины в `MachineRowView` остаётся технической строкой на английском; её замена — отдельное изменение.
- Тексты написаны без проверки на пользователях; ручной чеклист раздела 9 не выполнен.
