# Host ABI канала агента, версия 1

**Задача:** [S11-21](../plans/STAGE_11.md#s11-21-устройство-канала-агента-в-od-machine-и-abi). **Объявления:** [`agent_abi_v1.h`](../../include/open_desktop/agent_abi_v1.h). **Реализация:** [`agent_abi_v1.rs`](../../crates/od-host/src/agent_abi_v1.rs). **Устройство:** [AGENT_CHANNEL_DEVICE.md](AGENT_CHANNEL_DEVICE.md). **Решение о канале:** [ADR-0007](../decisions/ADR-0007-agent-channel-transport.md) (ждёт подтверждения владельца).

ABI не расширяет `host_abi.h`, `session_abi_v1.h` и `display_abi_v1.h`. Это опциональный C ABI: VMHost читает байты, которые гость записал в COM2, и пишет байты, которые гость прочтёт. Формат кадров — [AGENT_PROTOCOL_V1.md](../../protocols/guest/AGENT_PROTOCOL_V1.md); ABI передаёт байты и не разбирает их.

## 1. Версия

`OD_AGENT_ABI_VERSION_V1 = 0x00010000` — идентификатор точного совпадения, не арифметика. Только структура статистики несёт `abi_version` и `struct_size` (оба задаёт вызывающий до вызова). Новые коды статусов добавляются в конец; существующие не меняются и не переиспользуются. Расширение — новые символы и новые структуры с новой версией; структуры v1 не меняются.

## 2. Handle, владение и потоки

- `od_agent_channel *` — непрозрачный идентификатор из процессной таблицы, не указатель; значение 0 не выдаётся, идентификаторы не переиспользуются. Устаревший, подделанный или освобождённый handle даёт `INVALID_HANDLE`, а не неопределённое поведение.
- Handle — **ссылка host** на канал. Канал принадлежит сессии `od-host`, которая исполняет гостевой код с шиной и устройствами (S10-09); `od_agent_channel_release_v1` снимает ссылку host, а не устройство.
- Любой поток может вызывать любые функции с одним handle: канал сериализует вызовы собственной блокировкой, статуса `BUSY` нет. Вызов, начатый до `release` на другом потоке, завершается нормально.
- Паника Rust не пересекает границу C: она даёт `INTERNAL_ERROR`.
- Буферы принадлежат вызывающему на время вызова; ABI не хранит указатели.

## 3. Привязка к сессии (состояние на 2026-11-22)

Сессии «CPU + устройства» (S10-09) ещё нет. Привязка заложена так: сессия, построив машину, вызывает Rust-функцию `register_agent_channel(AgentChannel)` и отдаёт handle VMHost; будущая функция C для получения handle у сессии — решение S10-09 и S11-22 (открытый вопрос, здесь не определена). До этого ABI проверяется:

1. тестовым конструктором `od_agent_channel_test_create_v1` (канал без сессии, устройство отсоединено от шины; гостевая сторона — `test_inject`);
2. unit-harness в `od-host`: устройство на шине по `0x2F8` без CPU, гостевая сторона — обращения к портам, host — ABI (тест `bytes_cross_between_port_accesses_of_the_guest_and_the_abi`).

## 4. Функции

Все возвращают `uint32_t` статус.

| Функция | Назначение |
|---|---|
| `od_agent_channel_read_v1(channel, buf, len, out_read)` | гость → host, не блокирует; копирует до `len` байт, число — в `*out_read` (0 — очередь пуста, статус OK); перед копированием выполняет pump |
| `od_agent_channel_write_v1(channel, buf, len, out_written)` | host → гость, не блокирует; принимает сколько влезло, число — в `*out_written`; остаток отвергнут и учтён в `rx_overflow_bytes`; короткий счёт — не ошибка |
| `od_agent_channel_stats_v1(channel, out_stats)` | ёмкости, заполнение, счётчики (структура 88 байт, выравнивание 8) |
| `od_agent_channel_release_v1(channel)` | снимает ссылку host |
| `od_agent_channel_test_create_v1(out_channel)` | **TEST-ONLY.** Канал без сессии, ёмкости по умолчанию; `*out_channel` должен быть NULL |
| `od_agent_channel_test_inject_v1(channel, buf, len, out_injected)` | **TEST-ONLY.** Байты «от гостя» без CPU; правило переполнения TX как у настоящего байта; не часть контракта продукта |

`len = 0` допустим (тогда `buf` может быть NULL). Порядок байтов сохраняется в обоих направлениях.

## 5. Статусы

| Код | Имя | Когда |
|---|---|---|
| 0 | `OK` | успех |
| 1 | `INVALID_ARGUMENT` | NULL handle, NULL или невыровненный указатель результата, NULL `buf` при `len > 0`, `len > PTRDIFF_MAX`, буфер пересекается с указателем результата, непустой слот `out_channel` |
| 2 | `ABI_MISMATCH` | `abi_version` или `struct_size` структуры статистики отличается от заголовка |
| 3 | `INVALID_HANDLE` | неизвестный, подделанный или освобождённый handle |
| 4 | `INTERNAL_ERROR` | сбой host (пойманная паника) |

Порядок проверки: форма аргументов (`INVALID_ARGUMENT`, `ABI_MISMATCH`), затем handle (`INVALID_HANDLE`).

## 6. Очереди и потери

Ёмкости RX и TX — 65 536 байт каждая (гипотеза до замера, [AGENT_CHANNEL_DEVICE.md](AGENT_CHANNEL_DEVICE.md), раздел 4). Переполнение — потеря с учётом: `rx_overflow_bytes` (host → гость, вызывающий видит принятое число) и `tx_overflow_bytes` (гость → host). Протокол агента переносит потерю байтов. Счётчики только растут.

## 7. Что не проверено

- Работа с настоящим гостем (CPU-путь PIO к `0x2F8` в сессии S10-09 и probe S11-23).
- Скорость канала: pump и стоимость PIO-обращения не измерены (порог перехода — ADR-0007).
- Вызовы из Swift/C: заголовок проверен только текстовым тестом соответствия констант Rust-зеркалу; компиляция C-клиента не выполнялась.
