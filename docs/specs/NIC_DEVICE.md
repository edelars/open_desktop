# Контракт модели NIC, совместимой с Intel 82540EM (S11-32)

**Статус S11-32: модель реализована в `crates/od-machine/src/nic_e1000.rs` (+ `nic_e1000/`), подключена опцией платы `FirmwareBoardConfig::nic` (по умолчанию `None` = `network = none`, поведение платы не меняется); проверена unit-тестами модели, тестами платы и тестом подключения к `NatBackend` с синтетическими кадрами (раздел 13). Драйвер Linux или Windows эту модель не видел: «имеет шанс распознать устройство» — цель, а не результат; подтверждение — S11-33. Ревью Opus high — отдельным шагом, в этот документ не записано.** Документ описывает то, что есть в коде; расхождение кода и текста — дефект одного из двух. Граница «NIC ↔ backend» — [NETWORK.md](NETWORK.md) раздел 4 и `net_backend.rs`; плата — [VIRTUAL_BOARD.md](VIRTUAL_BOARD.md) («Network»).

## 1. Источники и статус сверки

Источник по регистрам и дескрипторам — публичный Intel «PCI/PCI-X Family of Gigabit Ethernet Controllers Software Developer's Manual» (семейство 8254x, 82540EM). **Редакция и дата издания в этой сессии не сверены с первоисточником** (PDF не открывался; редакция 4.0 названа по памяти и не подтверждена): точная редакция и дата записываются при ревью. Имена и положения битов регистров взяты по памяти из этого руководства и **не сверены построчно**; места, где модель принимает решение сама или опирается на поведение драйвера, перечислены в разделе 14. Таблицы и код чужих эмуляторов не копировались; модель написана по описанию регистров. Поведение Linux-драйвера `e1000` для этого чипа (чтение EEPROM побитово через EECD, ожидание `EE_GNT`, обращения к PHY через MDIC, контрольная сумма EEPROM `0xBABA`) учтено по памяти, исходный код драйвера не читался.

## 2. Размещение

| Параметр | Значение |
|---|---|
| PCI-функция | `00:06.0` (слоты 0:3 тестовый endpoint, 0:4 NVMe, 0:5 xHCI заняты). Многофункциональность не используется. |
| Идентификаторы | Vendor `0x8086`, Device `0x100E`, Revision `0x02`. Subsystem ID/Vendor в PCI-конфигурации читаются как 0 (заголовок `Type0Config` их не имеет); в EEPROM слова `0x0B`/`0x0C` содержат `0x001E`/`0x8086`. |
| Класс | `0x020000` (Ethernet). |
| BAR0 | 32-битный non-prefetchable memory BAR, **128 KiB**, запрограммирован при создании платы на `0xFC02_0000`: окно `[0xFC02_0000, 0xFC04_0000)`. BAR1…BAR5 — RO 0: **I/O BAR (BAR2 настоящего чипа) и BAR flash отсутствуют**. Механизм (upstream-драйвер Linux `e1000`, по памяти, исходник в этой сессии не читался): `e1000_is_need_ioport()` для 82540EM возвращает true, драйвер находит I/O BAR; `e1000_reset_hw()` записывает CTRL.RST не через MMIO, а через `outl` в порт `io_base` (регистр `IOADDR`, смещение 0) и в `io_base + 4` (`IODATA`); без I/O BAR `io_base` остаётся 0, и `outl` уходит в порты 0x0000 и 0x0004. В этой машине необъявленный порт останавливает машину (`BusAccessError::UnmappedPort`, [MACHINE_CONTRACT.md](MACHINE_CONTRACT.md), S7-31j), а не возвращает `0xFF`. Вывод: Linux-драйвер, вероятно, остановит машину при первом программном сбросе NIC. **Предусловие S11-33:** I/O BAR (`IOADDR`/`IODATA` — окно порта в BAR2, доступ к тем же регистрам, что в MMIO) либо иное решение, принятое до S11-33 (выбор — Opus high). В S11-32 I/O BAR **не реализован**. Подробности и счёт — раздел 14, п. 2 и ISSUE-674. |
| Почему этот адрес | Лежит в блоке 2 MiB `[0xFC00_0000, 0xFC20_0000)` дисплея и ECAM (число страниц таблиц не меняется), выровнен на 128 KiB, не пересекает окна NVMe (`[0xFC00_4000, 0xFC00_8000)`), xHCI (`[0xFC00_8000, 0xFC00_C000)`), ECAM (`[0xFC10_0000, 0xFC20_0000)`). Решение v1, не требование чипа. |
| Декодирование | Как у xHCI: Command.MSE включает MMIO при BAR0 = запрограммированный адрес; другой адрес в BAR0 выключает декодирование (модель не перемещается). Command.BME разрешает DMA: без него модель не читает и не пишет RAM, записи в регистры запоминаются. Command.IO не реализован (RO 0). Command.INTx Disable (бит 10) снимает линию, Status.Interrupt Status (бит 3) отражает её. |
| Capabilities | Список пуст. MSI/MSI-X, PCI Power Management, PCI-X — нет. |
| Прерывание | INTA, level, active-low, фиксированный маршрут **INTA → GSI 18** (NVMe — 16, xHCI — 17). Маршрут проведён через IOAPIC (`io_apic.rs`, `apic_pair.rs`: `NIC_PIN = 18`) и цепочку `BoardIrqSource` (`nic_e1000/irq_source.rs`) тем же способом, что xHCI. **В ACPI (`_PRT`) маршрут не описан** (как и у xHCI/NVMe в текущей плате): драйверу без `_PRT` линия по таблицам неизвестна — условие S11-33 (раздел 14). |
| Handoff block | Нового кода устройства нет: прошивка находит функцию перечислением PCI. В карте платы и в таблице регионов handoff появляется один регион `MMIO` без владельца; таблица устройств и хеш ACPI-манифеста не меняются (проверено тестом платы). Требуется `pci_ecam = true`; с `linux_profile` не собирается (циклы Linux-профиля устройство не обслуживают, как xHCI). |
| Включение | `FirmwareBoardConfig::nic: Option<NicConfig>`; `NicConfig { mac }`. MAC обязан быть unicast, не нулевым и не равным MAC шлюза `02:4F:44:00:00:02` ([NETWORK.md](NETWORK.md) раздел 3): иначе плата не собирается (`Config`). Backend создаёт и подключает хост: `NicHandle::attach_backend(Box<dyn NetBackend>)`; нового значения опции и строки платы этот документ не вводит: значение `nat` поля `config.plist` по-прежнему отвечает `unsupported` ([VM_BUNDLE.md](VM_BUNDLE.md) 3.5) до решения о подключении VMHost. |
| FLR | Не реализован. |

## 3. Модель обслуживания

Как у xHCI и NVMe: `BusDevice::read/write` не имеют доступа к гостевой RAM, запись в регистр только запоминает состояние и выставляет флаг `wakeup_pending` (он завершает квант гостя). Дескрипторы исполняет `NicHandle::service(&mut MachineBus, committed_write)` **между квантами**: сначала передача, потом приём. Один вызов: не более 256 дескрипторов передачи и не более 64 кадров приёма; остаток — следующий вызов (при исчерпании бюджета передачи флаг остаётся выставленным). DMA — только в RAM; запись сообщает диапазон в `committed_write`. Времени и таймеров в модели нет: `ITR`, `RDTR`, `RADV`, `TIDV`, `TADV` принимаются и читаются обратно, но **не действуют** — прерывание выставляется сразу в `service`. Backend вызывается только из `service` и из путей сброса, не из доступа гостя к регистру; блокировки (`NetBackend::transmit` и `poll_receive` не блокируют) — по [NETWORK.md](NETWORK.md) раздел 4.

## 4. Регистры (BAR0)

Только выровненный 32-битный доступ (иная ширина — `UnsupportedWidth`, невыровненный — `Misaligned`, смещение за 128 KiB — `UnknownOffset`; состояние не меняется). Нереализованные регистры читаются как 0, записи игнорируются, оба случая считаются (`unmodelled_reads/writes`).

### 4.1. Реализованные

| Смещение | Имя | Поведение |
|---|---|---|
| `0x0000` | CTRL | RW. Сброс `0x0000_0201` (FD, SPEED = 1000; решение модели). Бит 26 RST: программный сброс (раздел 12), читается как 0. Бит 31 PHY_RST: сброс регистров PHY, читается как 0. Переход бита 6 SLU 0→1 выставляет ICR.LSC. |
| `0x0008` | STATUS | RO: FD, LU (линк есть), SPEED = 1000, ASDV = 1000. Запись игнорируется. |
| `0x0010` | EECD | Побитовый интерфейс Microwire (раздел 5): SK, CS, DI, FWE записываются; DO, EE_GNT (= EE_REQ), EE_PRES (= 1) только читаются. |
| `0x0014` | EERD | START (бит 0), ADDRESS (15:8), DATA (31:16), DONE (бит 4). Чтение выполняется при записи START; DONE выставлен сразу. Слово вне 64 — данные 0. |
| `0x0018` | CTRL_EXT | Хранится. |
| `0x0020` | MDIC | Доступ к PHY (раздел 6). |
| `0x00C0` | ICR | Причины прерываний. Чтение возвращает значение и **очищает** его; запись единицы очищает бит. |
| `0x00C8` | ICS | Запись единиц выставляет причины (маска `0x0001_E6DF`). |
| `0x00D0` | IMS | Чтение — маска; запись единиц включает причины. |
| `0x00D8` | IMC | Запись единиц выключает причины. |
| `0x0100` | RCTL | EN (1), UPE (3), MPE (4), RDMTS (9:8), MO (13:12), BAM (15), BSIZE (17:16), BSEX (25), SECRC (26). Остальные биты хранятся и не действуют (VFE, LPE, LBM, DPF, PMCF, SBP, CFI). |
| `0x0400` | TCTL | EN (1) разрешает передачу; остальное хранится. |
| `0x2800`/`0x2804` | RDBAL/RDBAH | База кольца приёма (младшие 4 бита нулевые). |
| `0x2808` | RDLEN | Длина в байтах, биты 19:7 (кратно 128); значение 0 — кольцо не задано. |
| `0x2810`/`0x2818` | RDH/RDT | Голова и хвост, 16 бит. |
| `0x3800`/`0x3804` | TDBAL/TDBAH | База кольца передачи. |
| `0x3808` | TDLEN | Как RDLEN. Запись в TDBAL, TDBAH, TDLEN, TDH и снятие TCTL.EN (1→0) сбрасывают недособранную цепочку дескриптора (без EOP) и защёлку ошибки кольца. |
| `0x3810`/`0x3818` | TDH/TDT | Голова и хвост, 16 бит. |
| `0x5200…0x53FC` | MTA | 128 dword хеш-таблицы групповых адресов. |
| `0x5400…0x547C` | RAL/RAH 0–15 | Таблица адресов приёма: пара 0 после сброса — MAC из конфигурации, AV (бит 31 RAH) = 1; остальные пустые. |

### 4.2. Хранятся и не действуют

`FCAL` 0x28, `FCAH` 0x2C, `FCT` 0x30, `VET` 0x38, `ITR` 0xC4, `FCTTV` 0x170, `TXCW` 0x178, `TIPG` 0x410 (сброс `0x0060_200A`), `PBA` 0x1000 (сброс `0x0010_0030`), `LEDCTL` 0xE00, `FCRTL` 0x2160, `FCRTH` 0x2168, `RDTR` 0x2820, `RXDCTL` 0x2828, `RADV` 0x282C, `TIDV` 0x3820, `TXDCTL` 0x3828, `TADV` 0x382C, `RXCSUM` 0x5000. Значения сброса, кроме указанных, — 0 (решение модели).

### 4.3. Не реализованы

Счётчики статистики (`0x4000…`, читаются как 0), `RXCW`, `MANC` и управление manageability, `WUC/WUFC` и пробуждение, VLAN-фильтр (`VFTA`), `TXDMAC`, `TARC`, `FLA`, `PBM` и всё остальное, чего нет в таблицах выше.

## 5. EEPROM

64-словный Microwire, 16 бит. Содержимое строится из MAC конфигурации: слова `0x00…0x02` — адрес (младший байт первым), `0x0B` = `0x001E`, `0x0C` = `0x8086`, `0x0D` = `0x100E`, `0x0E` = `0x8086`, слово `0x3F` подобрано так, что сумма слов `0x00…0x3F` равна `0xBABA`; остальные слова 0. Доступны два пути:

- **EERD** — как в таблице 4.1.
- **EECD (Microwire)**: драйвер запрашивает шину (EE_REQ), ждёт EE_GNT, поднимает CS и по фронтам SK передаёт 9 бит (старт, код чтения `10`, шестибитный адрес; ведущие нули до старт-бита игнорируются), затем читает 16 бит со старшего с DO; перед первым битом данных DO = 0 (пустой бит). Другие команды Microwire (запись, стирание) **не** реализованы: после них модель молчит до сброса CS. Снятие CS возвращает автомат в начало.

Постоянного хранения нет: EEPROM — константа, запись драйвером невозможна.

## 6. PHY

Внутренний PHY на адресе 1 (другой адрес — MDIC.E и READY). Операции: запись (`01`) и чтение (`10`) 16-битных регистров 0…31; другой код операции — E. READY выставляется сразу; бит I (прерывание) выставляет ICR.MDAC. Содержимое: идентификатор Marvell M88E1011 (`0x0141`, `0x0C20`), регистр состояния `0x796D` (линк есть, автосогласование завершено), согласование 1000 Мбит/с полный дуплекс (специфичный регистр 0x11 = `0xAC00`), регистры 4 и 9 записываемы, регистры 1–3, 5, 6, 10, 15, 0x11 — только чтение; запись бита сброса в регистр 0 (решение модели) восстанавливает **только** регистр управления (`0x1140`) и читается как 0, остальные регистры (4, 9, 0x10 и т. д.) сохраняют записанное драйвером; `CTRL.PHY_RST` сбрасывает все регистры PHY. Остальные регистры хранятся. Линк всегда «есть»: отключения кабеля нет ([NETWORK.md](NETWORK.md) раздел 2).

## 7. Передача (кольцо legacy-дескрипторов)

Дескриптор 16 байт: адрес буфера (0..8), длина (8..10), CSO (10), CMD (11), STA (12), CSS (13), special (14..16). Кольцо обрабатывается при TCTL.EN = 1 и Command.BME = 1 от TDH до TDT (не включая); TDLEN кратна 128 байт, то есть минимум 8 дескрипторов.

- **Кадр** — цепочка дескрипторов до CMD.EOP (бит 0); буферы склеиваются в порядке цепочки (дескриптор нулевой длины допустим). Целиком кадр без FCS передаётся в `NetBackend::transmit`. Кадр не длиннее 16 KiB; длиннее — вся цепочка отбрасывается (`tx_discarded`). Кадры больше 1514 доходят до backend, он решает (`Dropped::Oversize`).
- **CMD.RS** (бит 3): после обработки модель пишет STA = DD (`0x01`) в байт 12 дескриптора и выставляет ICR.TXDW. **IFCS, IC, IDE, VLE, RPS, CSO/CSS** игнорируются: FCS не вычисляется и не отрезается (в backend уходит то, что в буферах), контрольные суммы не вставляются, VLAN-тегов не добавляется. Драйвер, рассчитывающий на offload, должен его отключить (раздел 14, ISSUE-674).
- **CMD.DEXT** (бит 5, контекстные и расширенные дескрипторы): не реализован; пакет, к которому дескриптор относится, отбрасывается на его последнем дескрипторе (`tx_discarded`), дескриптор завершается обычным образом.
- Ответ backend `Err(Dropped)` — **успешная передача для гостя** ([NETWORK.md](NETWORK.md) раздел 4): дескриптор завершается, счётчик `tx_backend_dropped`. Без backend кадр теряется так же (`tx_no_backend`).
- После каждого дескриптора TDH = (TDH + 1) mod N. Когда TDH догоняет TDT и обработан хотя бы один дескриптор, выставляется ICR.TXQE.

## 8. Приём

Кольцо читается при RCTL.EN = 1 и BME. Аппаратуре принадлежат дескрипторы от RDH до RDT (не включая). Модель **опрашивает backend только при наличии свободного дескриптора** ([NETWORK.md](NETWORK.md) раздел 4, п. 3), буфер `poll_receive` — 1514 байт.

- **Фильтр.** Кадр проходит, если его адрес назначения совпадает с действительной (AV = 1) парой RAL/RAH; либо это `ff:ff:ff:ff:ff:ff` при RCTL.BAM; либо групповой при RCTL.MPE или при совпадении по MTA: 12 бит адреса (по RCTL.MO: `MO=0` — биты 47:36, `1` — 46:35, `2` — 45:34, `3` — 43:32) выбирают dword (старшие 7 бит) и бит (младшие 5); либо одноадресный при RCTL.UPE. Остальные кадры теряются (`rx_filtered`).
- **Размер.** Кадр короче 60 байт дополняется нулями до 60. Без SECRC добавляется настоящий FCS (CRC-32 IEEE) — длина +4. Буфер дескриптора: BSIZE 2048/1024/512/256, с BSEX — 16384/8192/4096 (BSEX с BSIZE = 00 — 2048, решение модели). Кадр занимает столько дескрипторов, сколько нужно (не более 6 при буферах по 256 байт и кольце ≥ 8).
- **Если свободных дескрипторов меньше нужного**, кадр остаётся в NIC (один кадр) и доставляется, когда драйвер вернёт дескрипторы; потерь в NIC нет — переполнение видно как `drop_rx_queue_full` backend ([NETWORK.md](NETWORK.md) раздел 12). Поэтому ICR.RXO **не выставляется**.
- **Запись.** В каждый дескриптор — данные в буфер, затем длина (8..10), STA = DD | IXSM (бит 2: «контрольная сумма не вычислена»), у последнего ещё EOP (бит 1), поле ошибок 0. Контрольные суммы приёма, VLAN (VP), special не вычисляются.
- После доставки RDH сдвигается, выставляется ICR.RXT0; если свободных дескрипторов осталось не больше N/2, N/4 или N/8 (по RDMTS 0, 1, 2) — ещё ICR.RXDMT0.

## 9. Прерывания

Линия INTA = (ICR & IMS) ≠ 0 и Command.INTx Disable = 0. Причины, которые выставляет модель: TXDW (0), TXQE (1), LSC (2, при SLU 0→1), RXDMT0 (4), RXT0 (7), MDAC (9); ICS может выставить любой бит маски. Остальные причины (RXSEQ, RXO, GPI, TXD_LOW, SRPD) только через ICS. Линия читается цепочкой источников на границах APIC и подаётся в IOAPIC INTIN18 как level/active-low с Remote IRR и повтором по EOI. Задержки прерываний (`ITR` и таймеры) не моделируются (раздел 3).

## 10. Классы ошибок

| Ситуация | Результат |
|---|---|
| Ширина не 32 бита, невыровненный доступ, смещение вне BAR | `DeviceError` до изменения состояния. |
| Нереализованный регистр | чтение 0, запись игнорируется; счётчики `unmodelled_*`. |
| TDH или TDT (RDH или RDT) вне кольца | кольцо не обрабатывается, `ring_errors`; исправляется записью в регистр. |
| Выборка дескриптора вне RAM или переполнение адреса | `dma_errors`, кольцо остановлено (защёлка) до записи в его базу, длину, голову или в TCTL/RCTL. |
| Буфер передачи вне RAM | пакет отбрасывается, `dma_errors`, дескриптор завершается. |
| Буфер приёма вне RAM | кадр отбрасывается, `dma_errors`, дескриптор остаётся аппаратному. |
| Дескриптор DEXT; цепочка > 16 KiB | пакет отбрасывается (`tx_discarded`). |
| Backend вернул длину кадра больше буфера 1514 байт | кадр теряется, `rx_bad_backend_length`; panic нет. |
| `Err(Dropped)` backend, backend не подключён | см. раздел 7. |
| Panic | не используется ни на одном входе гостя. |

## 11. Сброс

- **CTRL.RST:** регистры возвращаются к значениям сброса (кольца, маски, RCTL/TCTL = 0, PHY по умолчанию, пара RAL/RAH 0 — MAC), кадр, ожидающий доставки, теряется, вызывается `NetBackend::reset()` ([NETWORK.md](NETWORK.md) раздел 4: потоки и очереди backend очищаются, счётчики сохраняются). PCI-конфигурация сохраняется; драйвер программирует кольца заново.
- **Сброс платы** (`platform_reset`): то же и PCI-конфигурация в состояние создания (декодирование выключено, BAR0 на месте). Диагностические счётчики модели сохраняются.

## 12. Не входит в v1

MSI/MSI-X; I/O BAR; flash и EEPROM записываемые; расширенные и контекстные дескрипторы TX (checksum offload, TSO, VLAN-вставка); контрольные суммы приёма; VLAN-фильтрация; jumbo-кадры (backend ограничен 1514); несколько очередей, RSS; режимы loopback RCTL.LBM; wake-on-LAN; счётчики статистики; таймеры задержки прерываний; сохранение состояния NIC в снимок (поле `vm_snapshot` не расширено); горячее подключение и отключение кабеля.

## 13. Проверки

- **Модель** (`crates/od-machine/src/nic_e1000/tests.rs`, 58 тестов): идентичность PCI, BAR и Command, ширина и выравнивание доступа, нереализованные регистры, сброс, EEPROM (EERD и Microwire в последовательности драйвера, контрольная сумма), PHY, ICR/IMS/IMC/ICS и линия, передача (одиночный дескриптор, цепочка, нулевая длина, бюджет, кольцо вне RAM, индексы вне кольца, DEXT, 16 KiB, отказ backend, без backend), приём (фильтры, хеш MTA, дополнение, FCS, несколько буферов, ожидание дескрипторов, RXDMT0, кольцо вне RAM).
- **IOAPIC** (`io_apic.rs`): GSI 18 — level, active-low, Remote IRR, повтор по EOI, независимость от GSI 16 и 17.
- **Плата** (`firmware_board/tests/nic_board.rs`): конфигурация и отказы, карта и handoff без изменений, чтение функции через ECAM, регистры, `wakeup_pending`, обмен кадрами между кольцами и backend, цикл запуска прошивки, сброс платы.
- **Подключение к `NatBackend`** (`crates/od-host/src/nat/nic_tests.rs`): ARP-запрос шлюза проходит кольцо передачи → `NatBackend` → кольцо приёма с ожидаемыми байтами; рантовые, слишком длинные и чужие по MAC кадры завершаются для гостя и считаются по причинам; 300 кадров при очереди L2 из 256; CTRL.RST очищает очереди backend; ответ ждёт свободный дескриптор. Эти тесты не открывают сокетов; вызов `process_pending` в них играет роль потока ввода-вывода из S11-31b…e.

## 14. Не проверено и решения модели

1. Редакция и дата Intel SDM (раздел 1); положения битов регистров и значения сброса не сверены построчно.
2. Реальный драйвер (Linux `e1000`, Windows `e1g`/`nete1g3e`) модель не видел. **Главная известная точка отказа — отсутствие I/O BAR: Механизм (upstream-драйвер Linux `e1000`, по памяти, исходник в этой сессии не читался): `e1000_is_need_ioport()` для 82540EM возвращает true, драйвер находит I/O BAR; `e1000_reset_hw()` записывает CTRL.RST не через MMIO, а через `outl` в порт `io_base` (регистр `IOADDR`, смещение 0) и в `io_base + 4` (`IODATA`); без I/O BAR `io_base` остаётся 0, и `outl` уходит в порты 0x0000 и 0x0004. В этой машине необъявленный порт останавливает машину (`BusAccessError::UnmappedPort`, [MACHINE_CONTRACT.md](MACHINE_CONTRACT.md), S7-31j), а не возвращает `0xFF`. Вывод: Linux-драйвер, вероятно, остановит машину при первом программном сбросе NIC. **Предусловие S11-33:** I/O BAR (`IOADDR`/`IODATA` — окно порта в BAR2, доступ к тем же регистрам, что в MMIO) либо иное решение, принятое до S11-33 (выбор — Opus high). В S11-32 I/O BAR **не реализован**.** Другие ожидаемые точки отказа: отсутствие `_PRT` для GSI 18, значения регистров PHY и EEPROM (слова `0x0A`, `0x0F` и ID-слова выбраны моделью), поведение при чтении неизвестных регистров статистики (0).
3. **Linux по умолчанию включает аппаратную контрольную сумму TX и TSO для этого чипа**; модель их не умеет (раздел 7). До ISSUE-674 гость должен отключить offload (`ethtool -K <if> tx off tso off`) либо поддержка контекстных дескрипторов добавляется до S11-33.
4. IFCS = 0 (драйвер сам кладёт FCS) модель не обрабатывает; Linux и Windows всегда ставят IFCS.
5. CTRL по умолчанию, значения сброса латчируемых регистров, DO «пустой бит» Microwire, ICR write-1-to-clear — решения модели по памяти.
6. Работа с прерываниями проверена до IOAPIC; доставка в гостя в рамках Linux не проверялась.
7. Производительность не измерялась; лимиты 256 дескрипторов и 64 кадра за `service` — гипотезы по правилу [AGENTS.md](../../AGENTS.md) о замерах.
