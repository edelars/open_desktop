# Хранилище переменных UEFI

## Формат store

`ODVARSTR` v1 хранит снимок переменных с атрибутом `NV`. Размер снимка с заголовком не превышает 256 КиБ. S7-09 строит снимок в RAM прошивки из той же таблицы, которая обслуживает volatile-переменные. Обновление переменной с `NV` синхронно обновляет снимок. Удаление учитывает атрибуты сохранённой записи, в том числе при `Attributes = 0`. Сброс и сохранение снимка определяются в S7-10.

Все многобайтовые числа имеют порядок little-endian. `GUID` кодируется как `u32 Data1`, `u16 Data2`, `u16 Data3`, восемь байт `Data4`. Байты за `total_size` лежат за пределами снимка. Между записями нет padding.

| Смещение | Ширина | Заголовок снимка |
|---|---:|---|
| `0x00` | 8 | ASCII `ODVARSTR` |
| `0x08` | 2 | Версия `1` |
| `0x0A` | 2 | Размер заголовка `24` |
| `0x0C` | 4 | `total_size` от начала заголовка до конца последней записи, `24…262144` |
| `0x10` | 4 | IEEE CRC-32 заголовка с нулём в этом поле |
| `0x14` | 4 | Зарезервировано, `0` |

| Смещение | Ширина | Запись переменной |
|---|---:|---|
| `0x00` | 4 | `record_size`, включая заголовок записи, имя и значение |
| `0x04` | 4 | `record_size` с инвертированными битами |
| `0x08` | 1 | Состояние `1` для действующей записи |
| `0x09` | 1 | Зарезервировано, `0` |
| `0x0A` | 2 | Число кодовых единиц имени, `1…127` |
| `0x0C` | 4 | Атрибуты UEFI с `NV` и `BS` |
| `0x10` | 4 | Число байт значения, `1…16384` |
| `0x14` | 16 | GUID поставщика |
| `0x24` | 4 | IEEE CRC-32 всей записи с нулём в этом поле |
| `0x28` | переменная | Имя UCS-2 без NUL и суррогатов, затем байты значения |

Стоимость записи равна `40 + 2 × name_units + value_size`. Таблица разделяет общий предел `262120` байт между всеми переменными. Записи идут в порядке создания ключей `(GUID, имя)`. Замена сохраняет позицию, удаление сразу уплотняет следующие записи, повторное создание добавляет ключ в конец. Снимок сохраняет этот порядок среди записей `NV`. `APPEND_WRITE` задаёт операцию записи и в снимок не попадает.

Декодер отклоняет неверный заголовок. Когда размер записи и его инверсия задают проверенную границу, неверный CRC или содержимое возвращает ошибку с байтовым смещением и декодер продолжает со следующей записи. При усечении или неверной границе он возвращает ошибку хвоста, сохраняя уже прочитанные записи. Ошибки формата обрабатываются как данные. Политика доступности, аутентификации и встроенных переменных описана в [профиле UEFI](UEFI_PROFILE.md#переменные).
