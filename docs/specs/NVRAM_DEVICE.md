# Хранилище переменных UEFI

## Формат store

`ODVARSTR` v1 хранит снимок переменных с атрибутом `NV`. Размер снимка с заголовком не превышает 256 КиБ. S7-09 строит снимок в RAM прошивки из той же таблицы, которая обслуживает volatile-переменные. Обновление переменной с `NV` синхронно обновляет снимок. Удаление учитывает атрибуты сохранённой записи, в том числе при `Attributes = 0`. На плате с [устройством NVRAM](#устройство) S7-10 добавляет восстановление и `FLUSH` при записи.

Все многобайтовые числа имеют порядок little-endian. `GUID` кодируется как `u32 Data1`, `u16 Data2`, `u16 Data3`, восемь байт `Data4`. Байты за `total_size` лежат за пределами снимка. Между записями нет padding.

| Смещение | Ширина | Заголовок снимка |
|---|---:|---|
| `0x00` | 8 | ASCII `ODVARSTR` |
| `0x08` | 2 | Версия `1` |
| `0x0A` | 2 | Размер заголовка `24` |
| `0x0C` | 4 | `total_size` от начала заголовка до конца последней записи, `24…262144` |
| `0x10` | 4 | IEEE CRC-32 заголовка с нулём в этом поле |
| `0x14` | 4 | Зарезервировано, `0` |

| Смещение | Ширина | Запись переменной |
|---|---:|---|
| `0x00` | 4 | `record_size`, включая заголовок записи, имя и значение |
| `0x04` | 4 | `record_size` с инвертированными битами |
| `0x08` | 1 | Состояние `1` для действующей записи |
| `0x09` | 1 | Зарезервировано, `0` |
| `0x0A` | 2 | Число кодовых единиц имени, `1…127` |
| `0x0C` | 4 | Атрибуты UEFI с `NV` и `BS` |
| `0x10` | 4 | Число байт значения, `1…16384` |
| `0x14` | 16 | GUID поставщика |
| `0x24` | 4 | IEEE CRC-32 всей записи с нулём в этом поле |
| `0x28` | переменная | Имя UCS-2 без NUL и суррогатов, затем байты значения |

Стоимость записи равна `40 + 2 × name_units + value_size`. Таблица разделяет общий предел `262120` байт между всеми переменными. Записи идут в порядке создания ключей `(GUID, имя)`. Замена сохраняет позицию, удаление сразу уплотняет следующие записи, повторное создание добавляет ключ в конец. Снимок сохраняет этот порядок среди записей `NV`. `APPEND_WRITE` задаёт операцию записи и в снимок не попадает.

Декодер отклоняет неверный заголовок. Когда размер записи и его инверсия задают проверенную границу, неверный CRC или содержимое возвращает ошибку с байтовым смещением и декодер продолжает со следующей записи. При усечении или неверной границе он возвращает ошибку хвоста, сохраняя уже прочитанные записи. Ошибки формата обрабатываются как данные. Политика доступности, аутентификации и встроенных переменных описана в [профиле UEFI](UEFI_PROFILE.md#переменные).

## Устройство

Плата с NVRAM использует handoff v1.7. Запись устройства 5 и регион типа `NVRAM` описывают один диапазон `[0xFF00_0000, 0xFF04_1000)`. Первые 256 КиБ служат окном данных, последние 4 КиБ содержат регистры. В карте UEFI это `EfiMemoryMappedIO` с `EFI_MEMORY_UC | EFI_MEMORY_RUNTIME`. [Контракт handoff](FIRMWARE_BOOT.md#63-таблица-устройств-запись-48-байт).

Регистры требуют выровненный 32-битный доступ. Смещения в таблице отсчитываются от `0xFF04_0000`. Многобайтовый доступ к данным передаёт 1, 2, 4 или 8 байт в порядке little-endian. Доступ должен целиком помещаться в выбранный диапазон данных или регистр.

| Смещение | Имя | Доступ | Поле |
|---|---|---|---|
| `0x00` | `ADDR` | R/W | Смещение в окне данных для следующей команды |
| `0x04` | `LEN` | R/W | Число байт для следующей команды |
| `0x08` | `CMD` | W | `1` READ, `2` WRITE, `3` FLUSH |
| `0x0C` | `STATUS` | R | Результат последней команды |
| `0x10` | `ACTIVE_LEN` | R | Число байт в последнем принятом снимке |

`READ` запоминает непустой диапазон `[ADDR, ADDR + LEN)` внутри активного банка. Чтение производится через эти же смещения в окне данных. `WRITE` принимает `ADDR = 0` и `1 ≤ LEN ≤ 262144`, инвалидирует неактивный банк и запоминает длину снимка. Записи в окно идут подряд с нулевого смещения. Неверное смещение или ширина доступа сохраняют состояние и позицию передачи. Новая команда завершает предыдущую передачу.

`FLUSH` при полном WRITE вычисляет CRC по записанным байтам и новому поколению, затем делает этот банк активным. При неполной записи, неизвестной команде, недопустимом диапазоне или исчерпании поколений активный банк сохраняется. Гость меняет запись в рабочей таблице переменных только после успешного `FLUSH`.

| `STATUS` | Значение |
|---|---|
| `0` | Устройство только что создано |
| `1` | READ готов |
| `2` | WRITE готов |
| `3` | FLUSH завершён, новый банк активен |
| `0x80000001` | Недопустимый диапазон |
| `0x80000002` | FLUSH без полной записи |
| `0x80000003` | Неизвестная команда |
| `0x80000004` | Исчерпаны поколения |

Ошибки доступа на шине описаны в [контракте машины](MACHINE_CONTRACT.md#устройство-nvram). `STATUS` сообщает результат команды, записанной корректным доступом к `CMD`.

## Host API

`LoadedFirmwareBoard::nvram_snapshot()` возвращает `None` для платы без устройства. При наличии устройства владелец получает байты между квантами. `NvramDevice::with_contents(&bytes)` проверяет снимок и создаёт отдельное устройство. `NvramConfig::Empty` и `NvramConfig::Snapshot` задают начальные данные устройства при создании платы. Runner использует `Snapshot` для повторной загрузки того же ROM в одном процессе. Сохранение в bundle относится к S9-26.

Host-снимок `ODNVBANK` v1 имеет длину `0x80030`. Числа little-endian. Первые 16 байт содержат magic `ODNVBANK`, `u32 version = 1`, `u32 reserved = 0`. Далее по порядку идут два слота по `0x40010` байт.

| Смещение в слоте | Ширина | Поле |
|---|---:|---|
| `0x00` | 8 | Поколение. `0` обозначает недействительный банк |
| `0x08` | 4 | Длина полезных байт `1…262144` |
| `0x0C` | 4 | IEEE CRC-32 над поколением, длиной и полезными байтами |
| `0x10` | `0x40000` | Полезные байты, далее нулевое заполнение до конца слота |

При записи снимка незавершённый банк и хвост за полезными байтами заполняются нулями. При создании устройства из снимка каждый банк проверяется отдельно. Выбирается наибольшее валидное поколение. Отсутствие валидных банков, два одинаковых валидных поколения или неверный заголовок дают ошибку. Регистры и курсор передачи создаются заново.

В новом устройстве банк 0 содержит поколение `1` и пустой `ODVARSTR` v1 из 24 байт. Банк 1 недействителен.

```text
4f 44 56 41 52 53 54 52 01 00 18 00 18 00 00 00 5b ed 3b 0b 00 00 00 00
```
