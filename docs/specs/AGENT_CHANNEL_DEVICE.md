# Устройство канала агента (COM2)

**Задача:** [S11-21](../plans/STAGE_11.md#s11-21-устройство-канала-агента-в-od-machine-и-abi). **Решение о канале:** [ADR-0007](../decisions/ADR-0007-agent-channel-transport.md) (предложен; ждёт подтверждения владельца). **Протокол поверх канала:** [AGENT_PROTOCOL_V1.md](../../protocols/guest/AGENT_PROTOCOL_V1.md). **Host ABI:** [AGENT_HOST_ABI_V1.md](AGENT_HOST_ABI_V1.md). Код: [`agent_channel.rs`](../../crates/od-machine/src/agent_channel.rs), [`uart16550.rs`](../../crates/od-machine/src/uart16550.rs).

Статус: реализовано на уровне регистров и host-очередей (тесты — раздел 8). Не сделано: маршрутизация IRQ3 в IOAPIC, запись COM2 в манифесте платы (handoff, DSDT), опрос канала в циклах платы (раздел 9). Строка платы — предложенная правка [VIRTUAL_BOARD.md](VIRTUAL_BOARD.md) («Канал агента»), ожидает подтверждения владельца.

## 1. Что это

Второй экземпляр модели `Uart16550PollingTx` (файл модели не копируется) на портах `0x2F8–0x2FF` с профилем 16450 без FIFO, плюс ограниченные host-очереди вокруг него. Гость видит обычный последовательный порт COM2; VMHost обменивается с ним байтами через [`AgentChannel`](../../crates/od-machine/src/agent_channel.rs). Устройство не знает формата кадров протокола агента.

## 2. Размещение

| Параметр | COM1 (диагностика) | COM2 (канал агента) |
|---|---|---|
| Порты | `0x3F8–0x3FF` | `0x2F8–0x2FF` |
| Линия ISA | IRQ4 | IRQ3 |
| Профиль | 16450, без FIFO | 16450, без FIFO (явно, ADR-0007 п. 2) |
| Тип в коде | `UartPortSpec::COM1` | `UartPortSpec::COM2` |

Срез S4-24f: модель регистров не зависит от порта (она видит смещения внутри привязки); размещение задаёт `UartPortSpec { base_port, irq_line }`, который хранят устройство и его handle (`port_spec()`). Источник IRQ через 8259 (`UartPicIrqSource`) берёт линию из handle, поэтому COM2 даёт IR3; поведение COM1 не менялось (`UART_IRQ_LINE` = 4, тесты COM1 без правок). Источник через IOAPIC (`UartIoapicIrqSource`) поддерживает только IRQ4: конструктор проверяет линию (раздел 9).

Плата: опция `FirmwareBoardConfig::agent_channel` (по умолчанию `false`). С опцией устройство привязано к `0x2F8–0x2FF` независимо от Linux-профиля, а `AbsentPortRegion::Uart2` на Linux-профиле не привязывается; COM3 (`0x3E8`) и COM4 (`0x2E8`) остаются absent (`0xFF`, запись игнорируется) на Linux-профиле и ловушками без него. Без опции плата ведёт себя как раньше: COM2 — absent-UART Linux-профиля (S7-31j) или ловушка (S7-31k). Handoff-блок и манифест ACPI опция не меняет.

## 3. Регистры

Те же, что у COM1 (правила S4-24e, S4-38L7bq/br/L9y/L9z/L9C, раздел UART в [MACHINE_CONTRACT.md](MACHINE_CONTRACT.md)); все доступы — байтовые PIO.

| Смещение | Чтение | Запись |
|---|---|---|
| 0 | RBR (DLAB = 0): принятый байт; DLL (DLAB = 1) | THR (DLAB = 0): нужны 8N1 и ненулевой делитель, иначе `UnsupportedConfiguration`; занят THR — `Busy`; DLL (DLAB = 1) |
| 1 | IER (биты 3..0) или DLM | IER (биты 7..4 отбрасываются) или DLM |
| 2 | IIR; биты 7..6 всегда 0 (16450) | FCR принимается и хранится; на IIR не влияет |
| 3 | LCR | LCR (все биты, включая DLAB) |
| 4 | MCR | DTR/RTS/OUT1/OUT2; LOOP и биты 7..5 — `UnsupportedConfiguration` |
| 5 | LSR: DR (бит 0), THRE (бит 5), TEMT (бит 6) | `ReadOnly` |
| 6 | MSR = 0 | `ReadOnly` |
| 7 | SCR | SCR |

LSR.OE (overrun) не вводится: приёмный регистр занят — хост-байт ждёт в очереди (раздел 4). Если S4-24 введёт OE или FIFO, профиль COM2 остаётся 16450 параметром экземпляра. Ошибки доступа — как у COM1: не байтовая ширина — `UnsupportedWidth`, не PIO — `UnsupportedSpace`, смещение 8 и выше — `UnknownOffset`. Классы ошибок согласованы с [DISPLAY_DEVICE.md](DISPLAY_DEVICE.md). Часть семантики записана по памяти из даташита 16550 и не сверена с первоисточником (как у COM1).

## 4. Host-очереди

Один байт RX живёт в самом UART (`LSR.DR`); дальнейшие байты ждут в ограниченной очереди и подаются в приёмный регистр через существующий `inject_received_byte`, когда он пуст. TX — THR плюс сдвиговый регистр (как у COM1); завершённые байты уходят в ограниченную TX-очередь.

| Очередь | Направление | Ёмкость | Переполнение |
|---|---|---|---|
| RX | host → гость | 65 536 байт (`AGENT_CHANNEL_RX_QUEUE_BYTES`) | `write_to_guest` принимает то, что влезло, и возвращает число; остаток отвергнут и учтён в `rx_overflow_bytes` |
| TX | гость → host | 65 536 байт (`AGENT_CHANNEL_TX_QUEUE_BYTES`) | завершённый байт при полной очереди отбрасывается и учитывается в `tx_overflow_bytes`; гость не блокируется |

Ёмкость — гипотеза до замера (ADR-0007, порог перехода): один максимальный кадр протокола — 61 464 байта, 64 КиБ его вмещают. Порядок байтов сохраняется. Потеря байта допустима для протокола (он ищет границы кадров и проверяет CRC). `reset` платы очищает очереди (стёртые байты не считаются потерянными) и сбрасывает регистры; суммарные счётчики сохраняются.

Статистика (`AgentChannelStats`): ёмкости, заполнение очередей, `rx_bytes_accepted`, `rx_bytes_delivered`, `rx_overflow_bytes`, `tx_bytes_accepted`, `tx_bytes_read`, `tx_overflow_bytes`.

## 5. Движение байтов: pump

Модель не знает времени передачи. Байты движутся, когда владелец вызывает `AgentChannel::pump`: завершает THR → сдвиговый регистр → TX-очередь и подаёт байт из RX-очереди в пустой приёмный регистр. Вызывают pump: сессия после каждого кванта гостя; `read_from_guest` и `write_to_guest` (в начале и в конце соответственно). Сессия должна завершать квант сразу после записи в THR (`AgentChannel::holding_occupied`), как для COM1. Гость, читающий RBR, видит следующий байт только после следующего pump: скорость канала — скорость pump (замер — S11-23/S11-25).

Циклы платы `firmware_board` этот pump пока не вызывают: сессию «CPU + устройства» (S10-09) строит другой срез, она и владеет вызовом.

## 6. Потоки и блокировки

`AgentChannel` — `Clone`, любые потоки. Порядок блокировок: очередь, затем UART; шина блокирует только UART, поэтому доступ гостя и вызов host не образуют взаимную блокировку. Вызовы host не блокируются.

## 7. Прерывания

Линия UART (`Uart16550Handle::interrupt_line`: OUT2 и включённое условие RDA или THRE) наблюдаема и проверена тестом. Подключение к контроллеру прерываний: 8259 — параметризованный источник готов (тест на IR3), в плате не подключён; IOAPIC — INTIN3 в `apic_pair` не моделируется (раздел 9). Агент-зонд S11-23 работает опросом LSR и IRQ не требует.

## 8. Тесты

- `cargo test -p od-machine --offline --lib agent_channel` — регистры, ограниченные очереди RX и TX, переполнение каждой, ошибки записи в read-only и неподдержанной ширины, профиль 16450, reset, потоки.
- `... --lib uart16550`, `... --lib absent_ports`, `... --lib uart_pic_irq_source` — модель COM1 и источник IRQ без изменений (плюс тест IR3 для COM2).
- `... --lib firmware_board` (фильтры `linux_profile_absent_uarts`, `absent_uarts_are_not_bound`, `linux_profile_with_the_agent_channel`, `the_agent_channel`) — S7-31j/k и их версии с COM2.
- `cargo test -p od-host --offline --lib agent_abi_v1` — ABI и harness шины без CPU.

## 9. Не сделано и открыто

1. **IRQ3 в IOAPIC.** `apic_pair` держит специальную логику уровней для INTIN4, SCI, NVMe и xHCI; пина 3 нет. Это часть S4-24 (ADR-0007 п. 3). До неё IOAPIC-источник отвергает не-IRQ4 UART.
2. **Манифест платы для DSDT.** Генератор DSDT описывает один COM из записи типа 1 (`PNP0501`, `_UID` = param0, `_CRS` с I/O и IRQ). Для COM2 нужна вторая запись; предлагается (не реализовано): новый код устройства, `PRESENT|PIO`, `base = 0x2F8`, `length = 8`, `gsi = 3`, edge/active-high, `param0 = 2` (номер COM); значения берутся из `UartPortSpec::COM2`. Реализация затрагивает handoff (новая минорная версия), `firmware/uefi` (разбор handoff, манифест, блоб ACPI, DSDT) и пересборку образа микропрограммы с её эталонами; поэтому вынесена из S11-21 в отдельный срез и требует подтверждения владельца по ADR-0007.
3. **Циклы платы.** Вызов pump и STOP-предикат `holding_occupied` в `firmware_board` (Linux-цикл, квант vCPU) — работа сессии S10-09.
4. **Ответ владельца** по ADR-0007: допускается ли COM2 как канал агента и изменение строки платы. До ответа опция выключена по умолчанию и строка платы помечена как предложение.
5. **Поведение Linux 8250 и Windows** на COM2 с профилем 16450 (автоопределение, loopback-тест при `MCR = 0x1A`) не проверено в гостях (S11-27/28).
