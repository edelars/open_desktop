# Общие папки: контракт и host-сервис

Статус: **написан в задаче S11-26 [плана этапа 11](../plans/STAGE_11.md#s11-26-общие-папки-контракт-и-host-сервис-с-защитой-корня), ожидает независимого архитектурного ревью, не принят**. Реализован и проверен только host-сервис файловых операций над открытым дескриптором корня ([shared_folders.rs](../../crates/od-host/src/shared_folders.rs), тесты рядом). **Нет:** гостевого драйвера или редиректора (blocked до этапов 5/8, S11-29), кадров и кодека транспорта к гостю, устройства/агента в VMHost (S11-22), C ABI вызова сервиса из VMHost (см. раздел 12), запуска чего-либо в гостевой ОС. Ни одно число и ни одно правило не проверено на госте.

Связанные документы: [CONTROL_PROTOCOL_V2.md §8](../../protocols/control/CONTROL_PROTOCOL_V2.md) (`ATTACH_RESOURCE`) и §6.1 (слоты `shared_folders[]`), [VM_BUNDLE.md §3.3](VM_BUNDLE.md#33-элементы-disks-и-shared_folders), [AGENT_PROTOCOL_V1.md](../../protocols/guest/AGENT_PROTOCOL_V1.md) (диапазон типов `0x0100–0x01FF`), [ADR-0007](../decisions/ADR-0007-agent-channel-transport.md), [ADR-0006](../decisions/ADR-0006-desktop-app-shell.md), [план S11-26](../plans/STAGE_11.md), [roadmap](../ROADMAP.md) (общие папки требуют явной семантики прав, ссылок, регистра имён, блокировок и конкурентного доступа).

**Пометка источника.** «Решение документа» — выбор этого документа, который ревью вправе изменить; числа лимитов — решения, а не замеры (правила [AGENTS.md](../../AGENTS.md): производительность не обещается). Значения флагов, `errno`, смещения `dirent` и номера `_PC_*` сверены C-пробой с SDK macOS 26 на arm64; поведение системных вызовов — по `man 2 open` и `man 2 rename` той же системы (источники в шапке модуля).

## 1. Область

Документ задаёт: как корень общей папки попадает в VMHost (раздел 2), набор файловых операций и их лимиты (3), права (4), правила ссылок (5), регистра имён (6), Unicode (7), блокировок и конкурентного доступа (8), алгоритм защиты корня (9), ошибки (10), выбор транспорта к гостю (11) и что остаётся открытым (12). Он **не** описывает SMB, NFS, 9P и чужие серверы файлов (не используются), производительность, квоты, гостевые драйверы.

Сводка по строкам roadmap: права — раздел 4; ссылки — 5; регистр имён — 6; блокировки — 8.1; конкурентный доступ — 8.2.

## 2. Ресурс: корень как открытый дескриптор

- Корень приходит в VMHost **только** сообщением control v2 `ATTACH_RESOURCE` с ролью `shared_folder_root` (`3`), `index` — слот `shared_folders[]` (0–7) из `CONFIGURE`. Дескриптор каталога передаётся `SCM_RIGHTS`; путь к каталогу через control не ходит (CONTROL_PROTOCOL_V2 §8, ADR-0006 решение (б), подтверждение владельца ожидается). Дескриптор получен приложением через `NSOpenPanel`/bookmark: доступ привязан к процессу приложения, поэтому передаётся открытый дескриптор, а не путь.
- Проверки до использования выполняет слой control (CONTROL_PROTOCOL_V2 §8, «Проверки до использования»): роль и индекс, слот существует и не занят, `fstat` → `S_ISDIR`, режим доступа `F_GETFL` — только чтение. Конструктор сервиса [`SharedFolder::new`](../../crates/od-host/src/shared_folders.rs) повторяет проверку каталога (`NotADirectory` иначе), ставит `FD_CLOEXEC` и опрашивает регистр тома (раздел 6). Сервис **владеет** дескриптором до конца процесса и не хранит и не принимает путь корня.
- Права папки задаёт слот: `read_only` (0/1) из `CONFIGURE` — единственный источник политики записи (раздел 4); `guest_name` (имя, под которым гость видит папку) — на уровне подключения, а не файловых операций.
- Нет дескриптора — нет папки: ни один код сервиса не принимает строку-путь корня, и гость не может её указать.

## 3. Операции и лимиты

Сервис — набор операций над одним корнем. Путь — UTF-8, разделитель `/`, относительно корня; пустая строка — сам корень (допустима только для `stat` и `readdir`). Обратный слэш и `:` в пути отвергаются: драйвер гостя сам переводит разделители и имена своей ОС в этот вид.

| Операция | Аргументы | Результат | Заметки |
|---|---|---|---|
| `stat` | путь | тип (`File`, `Directory`, `Symlink`, `Other`), размер, время изменения (нс от эпохи Unix) | сама запись, ссылка не разрешается |
| `open` | путь, режим `Read` / `Write` / `Truncate` / `CreateNew` | handle | только обычный файл; `CreateNew` не заменяет существующее; режимы записи — только в папке с записью |
| `read` | handle, смещение, длина ≤ 32 768 | данные (меньше длины — только в конце файла) | |
| `write` | handle, смещение, данные ≤ 32 768 | — | handle от `Read` — отказ `ReadOnly`; смещение + длина ≤ `i64::MAX` |
| `close` | handle | — | |
| `readdir` | путь каталога, курсор, размер страницы 1–64 | записи (имя, тип), следующий курсор, число пропущенных имён | имена по возрастанию байт; `.`/`..` не выдаются |
| `rename` | путь от, путь к | — | не заменяет существующее (`renameatx_np` с `RENAME_EXCL`); смена только регистра на регистронезависимом томе разрешена |
| `unlink` | путь | — | файл или сама ссылка; каталог — `IsADirectory` |

Лимиты (решения документа): имя ≤ 255 байт UTF-8 (`NAME_MAX` macOS); путь ≤ 1 024 байта (`PATH_MAX` macOS) и ≤ 32 компонентов; ввод-вывод ≤ 32 768 байт за вызов (меньше payload кадра агента 61 440 байт — AGENT_PROTOCOL_V1 §2 — с запасом на заголовок вызова; при меньшем согласованном `max_payload` гость и host используют меньшее значение); ≤ 64 открытых файлов на сервис; каталог — не более 65 536 записей за листинг (больше — `TooManyEntries`); страница `readdir` — не более 64 записей. В v1 **нет**: `mkdir`, `rmdir`, создания ссылок, `chmod`/атрибутов, `truncate` по handle, блокировок, `fsync`, квот (раздел 12).

Курсор `readdir` — индекс в отсортированном списке: каждая страница заново читает каталог, поэтому при изменении каталога между страницами имя может повториться или быть пропущено (записанное поведение, решение документа). Имена, которые нельзя выдать гостю (не UTF-8, содержат `\`, `:`, управляющие символы), в листинг не попадают и считаются в `skipped`. Записи, тип которых том не сообщил (`DT_UNKNOWN`), выдаются как `Other`; точный тип даёт `stat`. На APFS имена не-UTF-8 невозможны (ядро отвечает `EILSEQ`), `:` допустим.

## 4. Права

- Владелец данных — пользователь host: VMHost работает с его правами и ничего не повышает. Гость не получает прав сверх прав процесса VMHost на дескриптор и вложенные записи.
- **По умолчанию гость получает только чтение.** Запись — флаг `read_only = 0` слота папки в `CONFIGURE`; без него `open` в режимах `Write`/`Truncate`/`CreateNew`, `rename` и `unlink` возвращают `ReadOnly` до любого разрешения пути. Дескриптор корня всегда открыт только на чтение (CONTROL_PROTOCOL_V2 §8): запись в записываемой папке идёт через дескрипторы вложенных файлов, открытые сервисом, а не через дескриптор корня.
- Права файлов macOS (владелец, режимы, ACL) действуют как есть: отказ системы — `PermissionDenied`. Создаваемый файл получает режим `0644` с учётом `umask` процесса (решение документа). Атрибутов Windows (скрытый, системный, только чтение) в v1 нет.
- Права host-тома (том только для чтения) — `ReadOnly`.

## 5. Ссылки

**Политика (решение документа): символическая ссылка не следуется нигде — ни на промежуточном компоненте, ни на последнем, и даже если она указывает внутрь корня.** Это строже требования плана («не разрешаются за пределы корня»): разрешение ссылки внутри корня потребовало бы своего разрешителя и окна гонок, а выигрыш для гостя не подтверждён.

- Ссылка в листинге видна как `Symlink`; `stat` описывает саму ссылку; `unlink` и `rename` действуют на ссылку, а не на цель.
- `open` на ссылке и любой путь **через** ссылку (`link/x`) — `SymlinkRefused`, также для `readdir` и `CreateNew` (висячая ссылка не приводит к созданию цели).
- Создать ссылку гость не может (операции нет). Жёсткие ссылки (созданные пользователем host) — обычные записи; внешний файл, жёстко привязанный внутрь корня, внутри корня достижим — это выбор владельца папки, не выход за корень.
- Точки монтирования внутри корня система проходит как обычные каталоги; сервис их не определяет (раздел 12).

## 6. Регистр имён

- APFS по умолчанию **регистронезависима с сохранением регистра**. Гостю объявляется то, что даёт том: [`SharedFolder::info`](../../crates/od-host/src/shared_folders.rs) возвращает `case_sensitive` и `case_preserving` из `fpathconf(_PC_CASE_SENSITIVE / _PC_CASE_PRESERVING)` (SDK `<unistd.h>`); том, не ответивший, объявляется как регистрозависимый с сохранением (складывание не предполагается). Драйвер гостя MUST следовать этим флагам.
- Регистронезависимый том: `CreateNew` для имени, отличающегося от существующего только регистром, — `AlreadyExists`; `stat`/`open` находят файл при любом написании; листинг и `stat` возвращают регистр, с которым файл создан; смена регистра через `rename` разрешена (один файл, новое написание).
- Регистрозависимый том: `file.txt` и `File.TXT` — два разных файла, гость видит оба. Это не соответствует формулировке плана («гостю объявляется регистронезависимость»): том, который регистр различает, регистронезависимость обеспечить не может без собственного слоя имён. **Открытый вопрос для владельца:** принимать такой том с флагом (так сделано) или отказывать в подключении.
- Имена слотов (`guest_name`) в control v2 уникальны по байтам. Гость сравнивает имена общих папок без учёта регистра, поэтому имена, отличающиеся только регистром или формой нормализации, для гостя неоднозначны. **Открыто:** валидатор конфигурации (S11-02/S11-03) должен отвергать такие пары; в этой задаче control и bundle не менялись (ISSUE-649).

## 7. Нормализация Unicode

- Сервис **сам не нормализует** имена (ни NFC, ни NFD): нужны таблицы Unicode, которых нет в стандартной библиотеке, а добавление crate не обосновано (DEPENDENCIES.md). Байты имени передаются системе как есть.
- APFS нечувствительна к форме нормализации и сохраняет её: файл, созданный как NFC (`é` = U+00E9), находится по NFD (`e` + U+0301) и наоборот; листинг возвращает форму создания. Том без этого свойства различает формы. Сервис не вносит собственного поведения: тест требует совпадения результата с прямым обращением системы к тому же пути.
- Защита корня от нормализации не зависит: проверки `.`, `..`, `/` делаются над исходными байтами до системных вызовов; символы, которые лишь выглядят как `.` или `/` (U+FF0E, U+FF0F, U+2024), — обычные символы имени. Совместимостная нормализация (NFKC), превращающая их в `.`/`/`, APFS не выполняется; если бы том её выполнял, результат всё равно оставался бы одним компонентом ниже родителя (путь разбирается по компонентам, `..` системой не разрешается никогда).
- Драйвер гостя отвечает за представление имён в своей ОС (Windows: UTF-16 ↔ UTF-8; недопустимые для Windows имена, завершающие точки и пробелы). Не-UTF-8 путь сервис отвергает (`InvalidPath`).

## 8. Блокировки и конкурентный доступ

### 8.1. Блокировки

В v1 **нет** byte-range locks, share-режимов Windows (`FILE_SHARE_*`) и `flock`: сервис не берёт никаких блокировок ни на файлы, ни на каталоги, и драйвер гостя не может их запросить. Драйвер гостя, которому ОС требует блокировок, обязан отвечать успехом без эффекта или отказом по своей политике; сервис это не обслуживает. Сервис не взаимодействует с `flock` писателя диска ([STORAGE_FORMAT.md](STORAGE_FORMAT.md)): общие папки и образы дисков не пересекаются.

### 8.2. Конкурентный доступ

**«Последняя запись побеждает», без обнаружения конфликтов.**

- Каждый `open` — отдельный дескриптор; запись — `pwrite` на смещение. Несколько handle одного файла, несколько сервисов и посторонние процессы host пишут независимо. Порядок определяется порядком системных вызовов: байт, записанный позже, остаётся.
- Атомарность перекрывающихся записей сверх одного системного вызова не обещается. Тест требует: параллельные писатели не получают ошибок, размер файла остаётся ожидаемым, каждый байт равен байту одного из писателей.
- Чтение при параллельной записи может вернуть смесь старых и новых байт.
- `CreateNew` атомарен (`O_EXCL`): из нескольких одновременных создателей одного имени успех получает ровно один, остальные — `AlreadyExists` (тест).
- Файл, удалённый или переименованный, пока открыт гостем, остаётся доступным по handle (семантика POSIX, тестом не проверено); `rename` не заменяет существующую запись.
- Изменения, сделанные на host, видны гостю при следующем обращении; уведомлений об изменениях нет.

## 9. Граница корня

Каждая операция:

1. **До системных вызовов** разбирает путь ([`parse_path`](../../crates/od-host/src/shared_folders.rs)): допустимый UTF-8; не длиннее 1 024 байт; не более 32 компонентов; пустой путь — корень; **абсолютный путь** (начинается с `/`), пустой компонент (`a//b`, завершающий `/`), `.`, `..`, компонент с `\`, `:`, NUL или управляющим символом (U+0000–U+001F, U+007F) — `InvalidPath`; компонент длиннее 255 байт — `NameTooLong`.
2. Идёт вниз **по компонентам от дескриптора корня**: `openat(текущий, имя, O_RDONLY | O_DIRECTORY | O_NOFOLLOW | O_NONBLOCK | O_CLOEXEC)`; промежуточные дескрипторы закрываются при переходе вниз. `..` не используется нигде, поэтому цепочка не может подняться выше корня; строка пути хоста не строится и не передаётся ядру.
3. Последний компонент — операция семейства `*at` относительно дескриптора родителя: `openat` с `O_NOFOLLOW` (а для `stat` и проверок — `O_SYMLINK | O_NONBLOCK`, открытие самой ссылки без чтения цели), `unlinkat`, `renameatx_np`/`renameat`.
4. Тип проверяется по открытому дескриптору (`fstat`), а не по имени: не обычный файл — `IsADirectory`/`UnsupportedKind`; усечение (`Truncate`) выполняется только после этой проверки. `O_NONBLOCK` не даёт FIFO в папке блокировать сервис.
5. Ошибки системы переводятся в закрытый список (раздел 10).

Источник выбора флагов: `man 2 open` macOS (`O_NOFOLLOW` — ELOOP на последнем компоненте; `O_SYMLINK` — открытие самой ссылки; `O_NOFOLLOW_ANY` и `O_RESOLVE_BENEATH` существуют в новых выпусках, но не используются: пошаговый разбор от дескриптора от них не зависит, а требование к минимальной версии macOS не вводится).

Что граница **не** обещает: содержимое каталога вне контроля сервиса, если им одновременно владеет другой процесс пользователя host (он и так имеет те же права); точки монтирования и жёсткие ссылки внутри корня (раздел 5); защита от гостя, у которого есть произвольный доступ к памяти host (вне модели).

## 10. Ошибки

Закрытый список `SharedFolderError` (числовые коды wire назначаются вместе с форматом транспорта, раздел 11): `InvalidPath`, `NameTooLong`, `PathTooLong`, `NotFound`, `AlreadyExists`, `NotADirectory`, `IsADirectory`, `SymlinkRefused`, `UnsupportedKind`, `ReadOnly`, `PermissionDenied`, `NoSpace`, `TooLarge`, `BadHandle`, `TooManyOpenFiles`, `TooManyEntries`, `Io(errno)`. Ошибка гостя (неверный путь, handle, лимит) — результат операции, а не panic host; panic через границу не пересекает. Недоверенный ввод — каждое поле проверяется до использования.

## 11. Транспорт к гостю

**Выбор (решение документа, ждёт ревью).** Для малого объёма данных — **расширение протокола агента** [AGENT_PROTOCOL_V1](../../protocols/guest/AGENT_PROTOCOL_V1.md): типы кадров из зарезервированного диапазона `0x0100–0x01FF` (раздел 4 протокола) и новый бит возможностей `SHARED_FOLDERS` (бит 4 в `capability_bits`/`enabled_bits`). По правилу версии протокола (добавление типов и битов без изменения существующих) версия остаётся `1`, формат заголовка не меняется, v1 не правится. Соответствие операций кадрам — запрос и ответ на каждую операцию раздела 3; числа типов и расположение полей payload фиксируются в `protocols/guest/` вместе с первым потребителем (S11-29), до того формат не определён (раздел 12).

Требования к транспорту, из которых следует семантика выше:

- Не более одного незавершённого запроса общей папки (модель повтора AGENT_PROTOCOL_V1 §3: повтор запроса с тем же seq получает тот же ответ без повторения действия; это единственное, что делает безопасными неидемпотентные `write`, `rename`, `unlink`, `CreateNew`).
- Новый `HELLO` агента (перезапуск агента или гостя) — все handle закрываются ([`close_all`](../../crates/od-host/src/shared_folders.rs)).
- Размер данных ограничен согласованным `max_payload` (раздел 3).
- Скорость COM2 с профилем 16450 без FIFO низкая и не измерена; транспорт агента пригоден для проверки семантики и небольших файлов, а не для интенсивной работы. **Быстрый транспорт — после появления PCI-шины и устройства (этап 5/8);** семантика и лимиты этого документа от транспорта не зависят и при его смене не меняются («Готово» задачи).

## 12. Открыто и не сделано

- **Формат кадров** (числа типов, поля payload, коды ошибок wire) — не определён; принадлежит `protocols/guest/` и S11-29. Здесь зафиксированы только операции, лимиты и семантика.
- **C ABI подключения корня и обслуживания запросов из VMHost** (`include/open_desktop/shared_folders_abi_v1.h`, `SHARED_FOLDERS_HOST_ABI_V1.md` из «Где» плана) — **не создан**: в плане задачи нет шага для него, вызывающего кода VMHost (S11-22) и формата кадров ещё нет, а пустой заголовок запрещён [include/AGENTS.md](../../include/AGENTS.md). Нужен до подключения сервиса к VMHost.
- Решение владельца: том с различением регистра (раздел 6).
- Проверка уникальности `guest_name` без учёта регистра и формы нормализации в конфигурации (раздел 6).
- Известные ограничения реализации — [ISSUE-649](../KNOWN_ISSUES.md): нет квот и ограничения роста файла; `stat` файла без права чтения даёт `PermissionDenied`; листинг больших каталогов ограничен и стоит O(n) на страницу; нет `mkdir`/`rmdir`; открытие устройств и сокетов внутри папки не исключено заранее (отвергается по типу после `open`).
- Не проверено: работа на любом гостевом ОС; поведение на сетевых и не-APFS томах (HFS+, exFAT, SMB): тесты шли на APFS; сохранение доступа к дескриптору после окончания security-scoped доступа приложения (ADR-0006: источник не найден, smoke S11-04).

## 13. Проверки

Тесты — `cargo test -p od-host --offline --lib shared_folders` (только macOS; каждый тест строит временное дерево в `std::env::temp_dir`): перебор выхода за корень (`..` и `.` во всех позициях, абсолютные пути, `//`, пути Windows, NUL/управляющие, не-UTF-8; симлинк на `/`; симлинки на внешний файл и каталог, относительная и висячая; симлинк внутрь корня; подмена каталога симлинком; NFC/NFD и символы-двойники `.`/`/`; слишком длинные имя и путь и глубина); read-only отвергает каждую запись; конкурентные записи и конкурентное создание; жизненный цикл файла; лимиты ввода-вывода и числа handle; листинг со страницами и пропуском имён; регистр по свойству тома; FIFO; корень не каталог; `FD_CLOEXEC`. Результаты прогона — в отчёте задачи.
