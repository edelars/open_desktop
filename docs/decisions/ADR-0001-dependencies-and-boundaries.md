# ADR-0001: стек, зависимости и границы реализации

- **Дата:** 22 октября 2026 года.
- **Статус:** принято для начального стека; граница общих библиотек уточнена [ADR-0002](ADR-0002-general-purpose-libraries.md).
- **Связанные документы:** [политика зависимостей](../policies/DEPENDENCIES.md), [архитектура](../ARCHITECTURE.md), [план этапа 0](../plans/STAGE_0.md).

## Вопрос

Какие языки, инструменты и зависимости допустимы для первой реализации Open Desktop, и где проходит граница собственного runtime-кода?

## Альтернативы

1. Собственные CPU/JIT/firmware/TPM/графическая трансляция с использованием системного toolchain и API.
2. Подключение готовых сторонних runtime-движков для ускорения разработки.

## Основания

- Требование проекта — самостоятельная реализация движка и указанных системных компонентов без сторонних runtime-библиотек эмуляции, декодирования, JIT, firmware, TPM и графической трансляции.
- Swift соответствует границе macOS-приложения, Rust — границе host-ядра и CPU/JIT.
- Штатные компиляторы, стандартные библиотеки, SDK и системные API разрешены. LLVM допустим как backend компилятора Rust, но не как библиотека нашего runtime-JIT.
- Исходные Cargo-манифесты шести crate не объявляют внешних зависимостей. Swift Package-манифестов в репозитории нет.
- Решения на горячем пути требуют измерений согласно правилам проекта; этот ADR не утверждает результат о производительности.

## Решение

Принят вариант 1: Swift для macOS-продукта, Rust для host-ядра; системные инструменты и API разрешены; перечисленные runtime-компоненты реализуются самостоятельно. Подробные правила категорий, аудита и происхождения данных заданы в политике зависимостей.

Уточнение по решению пользователя от 22 октября 2026 года: библиотеки общего назначения разрешены, включая runtime. Первоначальная более строгая трактовка запрета не применяется; актуальная граница зафиксирована в ADR-0002 и политике зависимостей. Самостоятельность ключевых компонентов и выбранный стек сохранены.

## Последствия

- Новые зависимости классифицируются и проверяются до добавления; `Cargo.lock` версионируется, а при появлении Swift Package Manager версионируется и его файл разрешения версий.
- В текущем workspace не обнаружены сторонние Rust runtime-пакеты. CPU-прототип ещё не реализован, поэтому его соответствие будет повторно проверено при S0-07/S0-09.
- Прототипы, результаты замеров и решения не могут представляться как доказательство готовности целой подсистемы.

## Условие пересмотра

Пересмотреть решение, если нормативные требования выбранных гостевых систем не укладываются в самостоятельный стек, если системные интерфейсы требуют другого языка или если фактические замеры выявят необходимость изменить границу компонентов. Пересмотр требует описания альтернатив, свидетельств, последствий и обновления политики; запрет не обходится добавлением зависимости без фиксации.
