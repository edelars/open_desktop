## Вопрос

Как исполнять код CPL3, чтобы пользовательский режим Windows (`smss.exe` → `csrss.exe`, `winlogon.exe`, `setup.exe`/`SetupHost`, позже — установка S8-24) шёл с архитектурной семантикой SDM для любой формы, которую исполняет набор CPL0, а не останавливался на первой форме вне списка, и при этом ни одна операция с семантикой CPL0 не исполнилась на CPL3 молча?

## Факты

1. **Белый список.** `run_with_cpl3_profile_set` (EX) допускает состояние Ring3 (`ring3_state_admitted`: CS RPL 3, DPL 3, L = 1; SS RPL 3), декодирует инструкцию и пропускает её в общий шаг набора (`run_cpl0_profile_set_inner` с `PrivilegeLevel::Ring3`) только в двух случаях:
   - её форма есть в `cpl3_allows`: около 1 500 строк, формы `/init` Linux и статической initramfs S6, каждая с ограничениями по префиксам и размерам;
   - её берёт один из параллельных путей: `cpl3_rep_string` (прямые `MOVS`/`STOS`, DF = 0, единица бюджета на итерацию), `cpl3_sse_set_form`/`step_cpl3_xmm`/`step_cpl3_scalar_fp` (SSE на `state.sse`; MMX и x87 на CPL3 отказаны), `cpl3_aligned_atomic_destination` (невыровненный `LOCK` — `Unsupported`).

   Форма вне списка — честная остановка `Unsupported`. Инструкция декодируется дважды.
2. **Правила CPL3 в шаге набора реализованы местами и не проверены систематически.**
   - Центральный `#GP(0)` при CPL > 0 есть только для `MOV CRn`/`MOV DRn`.
   - Свои проверки есть у `HLT`, `CLI` (IOPL), `RDTSC` (CR4.TSD), `RDMSR`/`WRMSR` (член MSR Windows), `SYSRET`, `INT n` (DPL шлюза).
   - `IRETQ` на CPL3 не моделируется: `iretq_cpl0` работает только на CPL0. `POPF` на CPL3 моделирует лишь статусные флаги при IOPL = 0.
   - Набор не проверяет CPUID для реализованных форм: SSE на Linux-профилях без объявленного SSE исполняется — S2-39m, S2-57; так работают и `stage4a-apic`, и статическая нагрузка S6-22.

   Список был единственной гарантией.
3. **Что исполняет пользовательский код Windows.** Статический обзор 8 образов, ≈1,6 млн инструкций; данные в `.text` дают шум, поэтому редкие формы проверены в контексте.
   - Весь целочисленный набор всех размеров и адресаций.
   - SSE/SSE2–SSE4.2: `pcmpistri` и `crc32` в строковых функциях.
   - ≈1 600 `LOCK`-форм, `prefetchw`, `std`/`cld`.
   - Заглушки системных вызовов ntdll выбирают `SYSCALL` или `INT 0x2E` по флагу `KUSER_SHARED_DATA` `0x7ffe0308`.
   - `INT 0x29` (`__fastfail`), `INT 0x2C`, `INT 0x2D`.
   - `RtlCaptureContext` — `PUSHFQ`, `FXSAVE`; восстановление контекста ntdll — `FXRSTOR`/`XRSTOR` и `IRETQ` из CPL3 в CPL3.
   - `RtlGetCurrentProcessorNumber` выбирает по глобальной переменной ntdll один из способов: `RDPID`, `RDTSCP`, `LSL` с селектором `0x53` (дескриптор GDT `0x50`, номер процессора — в пределе: `shr eax, 14`) или системный вызов. Без `RDPID`/`RDTSCP` в профиле ожидается путь `LSL`; какой способ выберет ядро — гипотеза. `LSL` и `LAR` декодер набора не знает (поиск по `long_decode.rs`).
   - `RDPMC` в `RtlReadThreadProfilingData`.
   - `RDTSCP`, `RDPID`, `XGETBV`, `XSAVE*` и VEX (AVX/FMA) — за проверками CPUID.
4. **KVA shadow, по разбору кода, включится.** Решение ядра — `ntoskrnl` `+0xb730d8` (bugcheck `0x5D` с `0x4B56414C`): Intel семейства 6 вне списка старых моделей Atom (`0x1C, 0x26, 0x27, 0x35, 0x36`) считается уязвимым, если `CPUID(7).EDX[29]` и `IA32_ARCH_CAPABILITIES.RDCL_NO` не объявлены. Наш профиль — `GenuineIntel`, модель `0x9C`, максимальный базовый лист 6. Ожидаем две записи CR3 на каждый переход CPL3 ↔ CPL0 (секция KVASCODE: `mov cr3, rsp`, `swapgs`, `lfence`, `verw`, `rdsspq`, `sysretq`, `iretq`). Это **гипотеза** статического разбора, а не наблюдение: подтверждается в срезе C4 счётом записей CR3 на один `SYSCALL`. PCID и INVPCID не объявлены — бит 63 CR3 не используется. SMEP, SMAP, UMIP, PKU, CET не объявлены (лист 7 вне профиля), Windows их не включает.
5. **Windows держит CR0.AM = 1** (CR0 `0x80050033` в прогонах S7-32): `#AC` возможен при RFLAGS.AC = 1 на CPL3.
6. **Прерывания внутри REP.** Набор CPL0 исполняет не больше `REP_ITERATION_WORK_LIMIT` (1 024) итераций за вызов; дальше выход `RepIterationBudgetExhausted` без ретирации. Плата возобновляет строку с флагом `BOUNDARY_SKIP_FIRST` (IS): на первой границе нового вызова ничего не доставляется. Итого прерывания ждут конца всей строки. Виртуальное время платы — ретирации × 1 нс плюс тик на `RDTSC`; частичный REP его не двигает.
7. **Скорость.** Общий шаг — 2,19 млн инстр./с (ADR-0022, `--no-turbo`); turbo на ядре Windows — порядка 6·10⁸ инстр./с (срез Q: 1,67·10¹⁰ за 27 с). Turbo на CPL3 не работает:
   - допуск `!cpl3` (PMA);
   - быстрый обход `fast_translate` — только доступ супервизора;
   - `view_host` — только супервизор;
   - шаблоны `CLI`/`STI`/`INVLPG`/`RDTSC` не учитывают CPL;
   - ключ блока — `(rip, page)`.

   Число пользовательских инструкций до экрана Setup неизвестно (гипотеза 10¹⁰–10¹¹, то есть часы на общем шаге).

## Решение 1. Классификация операций вместо белого списка

На CPL3 исполняется **весь набор CPL0** тем же шагом, с правилами CPL3 по SDM. Белый список (`cpl3_allows`, `cpl3_aligned_atomic_destination`) удаляется, второе декодирование уходит. Параллельные пути **переносятся или переименовываются в общее ядро**, а не удаляются вместе с формами: `step_cpl3_xmm` уже исполняется на любом CPL (вызов из ветки FP-члена набора, `sse_cpl0_cpl3_handler_form`: `MOVD`/`MOVQ` XMM, `PSHUFLW`, `PINSRW m16`, `MOVLPD`/`MOVHPD`/`MOVHPS`, `PCMPEQB m128`, `PMINUB m128` — формы BusyBox/glibc), `step_cpl3_scalar_fp` — только на CPL3, `cpl3_rep_string` — до C2b (решение 3). Корректность держит **исчерпывающая классификация** — функция `od-isa` над `Operation` с `match` без `_`: новая операция не компилируется без класса. Узкие формы привилегированных инструкций (`WriteCr0Rdi`, `ReadCr3Into`, `WriteCr4From`, точные формы `INVLPG` и т. п.) относятся к `Privileged`, как их общие формы.

| Класс | Правило | Состав (по SDM) |
|---|---|---|
| `Neutral` | семантика не зависит от CPL; явные доступы — с привилегией контекста (U/S, R/W по всем уровням пути), неявные доступы к GDT/LDT/IDT/TSS — с правами супервизора (Vol. 3A §5.6.1) | целочисленные, стековые, ближние переходы, строковые, `LOCK`-формы, SSE/x87/MMX, `FXSAVE`/`FXRSTOR`, `CPUID` (CPUID faulting не объявлен), `PAUSE`, барьеры, `PREFETCH*`, `CLFLUSH`, NOP и CET-NOP; `SGDT`/`SIDT`/`SLDT`/`STR`/`SMSW`, пока CR4.UMIP = 0 |
| `Privileged` | CPL > 0 → `#GP(0)`, после всех условий `#UD`/`#NM` и до любого эффекта; один центральный блок (расширение существующего блока для `MOV CRn/DRn`) | Vol. 3A §6.9 и Table 2-3 (§2.8): `LGDT`, `LIDT`, `LLDT`, `LTR`, `LMSW`, `CLTS`, `MOV CRn`, `MOV DRn`, `INVD`, `WBINVD`, `INVLPG`, `HLT`, `RDMSR`, `WRMSR`; Vol. 2B: `SWAPGS`, `SYSRET`, `SYSEXIT` (#GP(0) if CPL ≠ 0), `XSETBV`, `INVPCID`, `WBNOINVD`, `RDMSRLIST`/`WRMSRLIST` (если признак объявлен; иначе решение 5) |
| `Cr4Gated` | разрешение зависит от CR4 (Vol. 2B, страницы инструкций) | `RDTSC`/`RDTSCP` (TSD = 1 → `#GP(0)` при CPL > 0), `RDPMC` (PCE = 0 → `#GP(0)` при CPL > 0), `SGDT`… (UMIP = 1 → `#GP(0)`), `RD/WRFSBASE`… (FSGSBASE = 0 → `#UD`), `XGETBV`/`XSETBV`/`XSAVE*`/`XRSTOR*` и VEX SIMD (OSXSAVE = 0 → `#UD`), `RDPKRU`/`WRPKRU` (PKE = 0 → `#UD`), формы CET (CR4.CET = 0 — CET-NOP или `#UD` по странице) |
| `IoplSensitive` | Vol. 1 §20.5.1–20.5.2, Vol. 2A/2B | `CLI`/`STI` (IOPL < CPL → `#GP(0)`; CR4.PVI политикой не допускается); `IN`/`OUT`/`INS`/`OUTS` (CPL > IOPL → битовая карта ввода-вывода TSS через TR, `IoMapBase` по смещению `0x66`; бит 1 или карта за пределом TSS → `#GP(0)`); `POPF` (IF меняется, только если CPL ≤ IOPL; IOPL — только при CPL0; VIP/VIF/VM не меняются, без `#GP`); `IRETQ` (те же правила для IF и IOPL) |
| `CplSpecific` | свой исполнитель с правилами CPL3 | `INT n`/`INT3` (DPL шлюза — есть); `SYSCALL` (есть; EFER.SCE = 0 → `#UD`); `IRETQ` CPL3 → CPL3 (возврат на тот же уровень по псевдокоду Vol. 2A «IRET»: SS:RSP из кадра, RPL CS = CPL, проверки CS и SS, бит Accessed дескрипторов — неявная запись супервизора); `LSL`/`LAR` (Vol. 2B «LSL», Vol. 2A «LAR»: допустимые типы дескриптора, видимость для неподчинённых — DPL ≥ CPL и DPL ≥ RPL, предел с масштабом по G — `(limit << 12) \| 0xFFF`, ZF = 1 при успехе, при отказе ZF = 0 и приёмник не меняется, чтение дескриптора — неявный доступ супервизора); `VERR`/`VERW` (та же видимость); загрузки сегментных регистров (RPL/DPL против CPL) |
| `NotAtCpl3` | честная остановка `Unsupported` без изменения состояния | операции узких профилей, кроме привилегированных (они — `Privileged`); дальние `CALL`/`JMP`/`RET`, шлюзы вызова и задачи; `INT1` и TF = 1 (модели `#DB` нет, ISSUE-710); ввод-вывод на CPL3, разрешённый битовой картой (вход CPL3 не имеет порта; Windows его не даёт); CS с L = 0 (compatibility mode — S2-24/S8-60) |

Вне классов — то, что решает декодер: `INTO` в 64-битном режиме — `#UD` при декодировании; `RSM` вне SMM — `#UD`. Отдельный вид «CPL > 0 → `#UD`» (а не `#GP`) — `MONITOR`/`MWAIT` (если не разрешены на CPL > 0) и `CLAC`/`STAC`: эти признаки (MONITOR, SMAP) профиль не объявляет, поэтому сейчас ими управляет решение 5; при объявлении они получат свою строку. `LKGS`, `ERETS`, `ERETU` (FRED) не объявлены — решение 5.

Вход CPL3 остаётся отдельным только в допуске состояния Ring3.

### Порядок проверок

- **Между инструкциями** — Vol. 3A §7.9, Table 7-2. Ошибки декодирования следующей инструкции (приоритет 9: `#UD`, `#NM`) возникают раньше исполнения. Поэтому класс `Privileged` (`#GP(0)`) проверяется после всех условий `#UD`/`#NM` — «список декодирования»:
  - `LOCK` у формы, которой он запрещён;
  - CR1, CR5–CR7, CR9–CR15 и REX.R у `MOV DRn`;
  - DR4/DR5 при CR4.DE = 1;
  - `SYSCALL`/`SYSRET` при EFER.SCE = 0;
  - `XGETBV`/`XSETBV`/`XSAVE*`/`XRSTOR*` и VEX SIMD при CR4.OSXSAVE = 0;
  - необъявленный признак CPUID (решение 5; например, `INVPCID` без признака — `#UD`, не `#GP(0)`);
  - `#NM` по CR0.TS/EM для форм FP.
- **Выбор модели внутри списка декодирования** (SDM порядок не задаёт): условия `#UD` проверяются раньше `#NM`. Для `MOV DR4/DR5` `#UD` по CR4.DE идёт раньше `#GP(0)` по CPL — тоже выбор модели (страница `MOV DRn` перечисляет оба условия без порядка).
- **`SYSRET`** — порядок по разделу Operation его страницы (Vol. 2B): EFER.SCE = 0 → `#UD`, затем CPL ≠ 0 → `#GP(0)`, затем неканонический RCX → `#GP(0)`.
- **Внутри исполнения** SDM порядок ошибок не задаёт (Table 7-2, примечание: «does not specify the prioritization of faults that arise during instruction execution … #GP, #PF, #AC»). Выбор модели, который закрепляет модельный тест C1:
  1. Проверки привилегии, IOPL и CR4 (`#GP(0)`) — до любого доступа к памяти: `LGDT m` на CPL3 даёт `#GP(0)`, даже если операнд не отображён. **Исключения, где проверка сама читает память:** `IN`/`OUT`/`INS`/`OUTS` при CPL > IOPL сначала читают битовую карту TSS — её `#PF` раньше `#GP(0)`; у `INT n` DPL шлюза проверяется после чтения шлюза (его `#PF` раньше `#GP`).
  2. Затем доступы к данным в порядке инструкции. Для каждого: каноничность (`#GP(0)`; для адреса с сегментом SS — `#SS(0)`) → выравнивание (`#GP(0)` выровненных 16-байтовых форм, затем `#AC`) → трансляция (`#PF`). Доступ поперёк двух страниц — `#PF` младшей страницы раньше старшей. У инструкций с несколькими записями (кадр `PUSH`/`CALL`, строки, `FXSAVE`, кадр доставки) все проверки записей выполняются до первой фиксации, где это делает существующий исполнитель; где нет — порядок фиксации записывается в контракте формы.
  3. Затем проверки прочитанных значений: зарезервированные биты MXCSR (`LDMXCSR`, `FXRSTOR`), каноничность базы `LGDT`/`LIDT`, селектор `POP SS`/`MOV SS`, кадр `IRETQ`, ожидающие `#XM`/`#MF`.

### Основание: почему необъявленное — не «известный пробел»

Принцип ADR-0013 («Известные пробелы остаются остановками прогона, не тихими результатами») относится к тому, что архитектура определяет для объявленного CPU, а модель исполнить не может. Это объявленная, но не реализованная форма, MSR вне файла, compatibility mode: такое остаётся остановкой, в том числе по решению 5.

`#UD` для признака, который профиль не объявляет, — это и есть архитектурный ответ объявленного CPU (Vol. 2A §2.5: «#UD … If any corresponding CPUID feature flag is ‘0’»), а не пробел модели. Тихим он не становится: каждый случай считается и попадает в отчёт прогона, а режим `stop` возвращает прежнюю остановку (решение 5). Требование ADR-0013, решение 4 — видеть встречу `XSAVE*`/`XGETBV`/VEX с модулем и RVA — выполняется первым случаем в отчёте (с модулем и RVA) и режимом `stop`; ненулевой счётчик в приёмочном рецепте — находка с разбором (решение 5, «Видимость»). Текст решения 4 поправляется ссылкой сюда срезом C2c.

## Решение 2. FP-состояние: одна ячейка FP-члена

x87, MMX и SSE на CPL3 работают на ячейке FP-члена набора (`GuestFpState`), как на CPL0. Ядро сохраняет и восстанавливает её при переключении потоков (`FXSAVE`/`FXRSTOR`), а пользовательский код восстанавливает контекст через `FXRSTOR` — обе стороны должны видеть одно состояние. `FXSAVE`/`FXRSTOR` в 32- и 64-битном формате — `Neutral`; выравнивание — по решению 4, `#NM` при CR0.TS/EM — по их страницам (FXSAVE при CR0.EM = 1 — `#NM`).

**Без FP-члена** x87 и SSE на CPL3 — `Unsupported`, как на CPL0. Сейчас без члена формы `step_cpl3_xmm` на CPL3 исполняются на `state.sse` (ветка CPL3 шага набора перед FP-членом: условие `fp_cpl0.is_none() || sse_cpl0_cpl3_handler_form(…)`); поэтому ожидания `crates/od-isa/tests/s2_39_cpl3_sse.rs` и `crates/od-isa/tests/cpl3_profile_set.rs` для наборов без FP-члена меняются **намеренно**, каждое изменение называется в отчёте среза. Профили Linux с FP-членом этого не замечают.

## Решение 3. Строковые инструкции: правило набора CPL0 для обоих CPL

Строковые формы всех ширин, с DF = 1 и сегментными префиксами, на CPL3 исполняет реализация набора CPL0 с её правилом:
- за одно исполнение — не больше `REP_ITERATION_WORK_LIMIT` (1 024) итераций;
- если предел достигнут, исполнение частичное: RIP остаётся на инструкции, RCX/RSI/RDI продвинуты, инструкция не ретирована;
- завершённая инструкция — одна ретирация.

Списание единицы бюджета на итерацию на CPL3 (S4-39f20, S6-22) убирается.

**Прерывания внутри строки.** Действует правило платы `BOUNDARY_SKIP_FIRST` (факт 6): внутри частичного REP ничего не доставляется, прерывание ждёт завершения строки. Для архитектуры это допустимо: строка завершается, прерывание остаётся ожидающим. Цена — задержка доставки.
- В гостевом времени задержки нет: частичный REP не ретирует и часы не двигает.
- В хостовом времени задержка равна времени всей строки. Длинный пользовательский REP (1 МиБ `REP MOVSB` — ≈10⁶ итераций, ≈1 000 частичных вызовов) задерживает доставку на это время. Цена итерации общего шага не замерена: замер в C2b.

Если доставку внутри REP когда-нибудь включат, кадр должен нести RF = 1 (Vol. 3B §20.3.1.1: «For any interrupt arriving after any iteration of a repeated string instruction but the last iteration, the value pushed for RF is 1»), а сохранённый RIP — указывать на REP.

**Эталоны.** Если из-за этого меняются эталонные записи Linux (рецепт S6-21 `stage4a-apic`: число ретираций, прерываний, COM1), запись перезаписывается с причиной и разницей поле за полем. Правило под старые записи не подгоняется. Это отдельный срез C2b.

## Решение 4. `#AC` и невыровненный `LOCK` моделируются архитектурно

**`#AC`** (Vol. 3A §7.15, «Event 17», Table 7-7) — fault, вектор 17, код ошибки 0 (EXT — по общим правилам доставки).
- **Когда проверяется:** CR0.AM = 1, RFLAGS.AC = 1, CPL = 3; только доступы к данным и стеку. Выборка и неявные доступы супервизора (загрузка дескрипторов) не проверяются.
- **Требование выравнивания передаёт исполнитель** вместе с доступом: размер выравнивания по Table 7-7 или «без проверки». Адаптер выбирать его не может, потому что требование зависит от инструкции, а не от ширины доступа.
- **Выбор модели по классам SDM:**
  - 16-байтовые `MOVUPS`/`MOVDQU`/`MOVUPD`/`LDDQU` — без `#AC`: Vol. 2A §2.5, Type 4 — «For 2, 4, or 8 byte memory access if alignment checking is enabled»;
  - выровненные 16-байтовые формы — `#GP(0)` при невыровненном адресе (Table 7-7: «#GP is generated 128-bit data types that are not aligned on a 16-byte boundary»);
  - `FXSAVE`/`FXRSTOR` с невыровненным операндом — `#GP(0)` (из двух вариантов SDM, «#AC или #GP», модель выбирает `#GP(0)`);
  - `SGDT`/`SIDT` на CPL3 — 4 байта (Table 7-7);
  - остальные — по своим строкам Table 7-7.
- **Сверка выбора** с аппаратным оракулом этапа 2 (стенд KVM на Intel Mini) — если он позволяет CPL3 с AM ∧ AC. Иначе в отчёте среза: «оракул не применялся».

**Невыровненный `LOCK` (split lock)** на CPL3 исполняется атомарно, как на CPL0 (`SplitLockGate`). `#AC` за bus lock не возникает: обнаружение split lock не объявлено. При AM ∧ AC ∧ CPL3 невыровненный `LOCK` даёт `#AC` по правилу выравнивания.

## Решение 5. Необъявленные расширения: монотонное правило `#UD` со счётчиком

**Правило (монотонное).** `#UD` даётся только при выполнении обоих условий:
1. набор **не реализует ни одной формы класса признака**. Условие — не «этот случай дал `Unsupported»`: `Unsupported` бывает и у реализованного класса (отказ по форме адресации, префиксу, FS/GS-операнду, отсутствию члена набора). Иначе новая форма SSE с отказанной формой операнда в Linux-профиле без объявленного SSE стала бы `#UD`, и BusyBox получил бы `SIGILL`;
2. признак **точно не объявлен** CPUID-членом набора или его разрешающий бит CR4/CR0 не допускает форму.

«Объявлено» значит: лист не выше максимального (базового — `CPUID(0).EAX`, расширенного — `CPUID(0x80000000).EAX`) и бит равен 1. Лист выше максимального — признак не объявлен. Строка с несколькими условиями даёт `#UD`, если не выполнено любое из них. Строка с альтернативой объявлена, если объявлен любой из её признаков: `XTEST` — HLE ∨ RTM.

Основание — Vol. 2A §2.5: «#UD … If any corresponding CPUID feature flag is ‘0’», «If CR4.OSXSAVE[bit 18]=0»; для не-VEX форм — списки исключений их страниц.

Действует на любом CPL. Последствия правила:
- Реализованная, но необъявленная форма исполняется, как сейчас: «интерпретатор не проверяет CPUID», S2-39m, S2-57. Профили Linux поэтому не меняются.
- По каждому профилю признаки, у которых набор реализует хотя бы одну форму при бите 0, записываются в CPU_CONTRACT как отступление — перечень «реализовано, но не объявлено». **Для признаков из перечня любая нереализованная форма остаётся `Unsupported`**, а не `#UD`.
- Перечень строит тест из таблицы признаков и множества реализованных форм, а не человек, так что документ не расходится с кодом. Тест также утверждает, что строки таблицы с действием `#UD` с перечнем не пересекаются. Поэтому таблица признаков покрывает и реализованные кодировки, а не только нереализованные.
- Нереализованная, но объявленная форма остаётся `Unsupported`.
- Для набора без CPUID-члена «точно не объявлено» не определено: там остаётся прежнее `Unsupported`, в том числе для условий по CR4.

**Режим.** `--undeclared-isa ud|stop`, по умолчанию `ud`: для необъявленного это архитектурный ответ, а не пробел модели. `stop` даёт прежнюю остановку `Unsupported` для диагностики.

**Откуда множество.** «Не объявлено» вычисляется из CPUID-члена набора (`CpuidProfile::query`) и CR4/CR0, а не задаётся вручную. Вручную задаётся только архитектурная таблица «класс кодировки → признаки CPUID (лист, подлист, регистр, бит), их сочетание (И/ИЛИ) и биты CR4/CR0». Её строки берутся из списков исключений страниц инструкций и таблиц классов исключений Vol. 2A §2.5–§2.6. Биты управляющих регистров — в строках явно:
- `XGETBV`/`XSETBV`/`XSAVE*`/`XRSTOR*` — CR4.OSXSAVE;
- legacy SSE — CR4.OSFXSR и CR0.EM;
- `RD/WRFSBASE`… — CR4.FSGSBASE;
- `RDPKRU`/`WRPKRU` — CR4.PKE;
- формы CET — CR4.CET.

По классам VEX:
- VEX SIMD (Types 1–8, 11, 12) — OSXSAVE/XCR0 и признак CPUID;
- VEX GPR (BMI1/BMI2, Type 13, §2.6.1) — только признак CPUID.

Таблица лежит в `od-isa` рядом с декодером, а её строки ссылаются на страницы SDM.

**Не `#UD`:** кодировки, у которых без признака есть определённая прежняя семантика. Для каждой такой строки таблица говорит, что делать без признака.
- `F3 0F BC`/`F3 0F BD` без BMI1/LZCNT исполняются как `BSF`/`BSR` (страницы `TZCNT`/`LZCNT`).
- `F3 0F 09` без WBNOINVD исполняется как `WBINVD`. Источник — правило префиксов Vol. 2A §2.1.1 для префикса `F3` у инструкции, которая его не определяет, а не страница WBNOINVD.
- Префиксы, которые без признака игнорируются, а инструкция исполняется как базовая: `XACQUIRE`/`XRELEASE` (`F2`/`F3` у `LOCK`-форм и `XCHG`; HLE), `BND` (`F2` у переходов; MPX), `NOTRACK` (`3E` у косвенных переходов; CET-IBT).
- `PREFETCHW`, `CLDEMOTE`, `PAUSE`, остальные подсказки и NOP-пространство исполняются по SDM.

**Видимость.** Каждый такой `#UD` исполнитель помечает: исход «ошибка `#UD`» с маркером «необъявленный признак», гостю не видимым. Плата доставляет его как обычный `#UD` (режим `ud`) или останавливается (режим `stop`) и считает его отдельно. В отчёте прогона (unified-блок JSON `boot-firmware` и отчёт `linux`):
- счётчик `undeclared_isa`;
- первый случай: RIP, модуль и RVA (как снимок S8-10), CPL, байты инструкции, признак;
- ограниченный журнал различных пар (признак, RIP).

Ненулевой счётчик `undeclared_isa` в приёмочном рецепте (S6-21, S6-22, прогоны Windows) считается находкой и разбирается: какой код и почему исполнил необъявленное.

## Решение 6. KVA shadow остаётся включённым

Профиль CPUID для этого не меняется: включённый KVA shadow — корректное поведение Windows на объявленной идентичности, и его пути (две записи CR3 на переход, KVASCODE) модель обязана исполнять. Объявлять ли лист 7 с `ARCH_CAPABILITIES` (EDX[29]) и MSR `0x10A` с `RDCL_NO`, решается по замеру в срезе C6: частота и цена смены CR3 на пути Windows, вытеснение слотов turbo. Изменение — только поправкой ADR-0013 (идентичность CPU).

Довод за C6: у Tremont (Jasper Lake, N5105), по сведениям координатора, `RDCL_NO` объявлен. **Источник не найден** — до любой правки профиля это нужно сверить по документации Intel.

## Решение 7. Turbo на CPL3 — после первого замера

Срез C5 начинается после первого прогона Windows в CPL3 (срез C4), который даёт `cpl3_retired` и время. Если скорости не хватает для итераций C4, C5 идёт параллельно с ними. Ограничения дизайна проверяются дифференциальными тестами turbo против общего шага на CPL3:
- **Ключ слота трансляции включает CPL.** При KVA shadow на процесс приходится три ключа: (CR3 ядра, CPL0), (теневой CR3 пользователя, CPL3) и (теневой CR3 пользователя, CPL0) — код входа и выхода KVASCODE до и после смены CR3. Это нагрузка на 4 слота при нескольких процессах; число слотов — по замеру.
- **Права в быстром обходе:** пользовательский доступ требует U = 1 на всех уровнях; запись — R/W = 1 на всех уровнях независимо от WP.
- `view_host` учитывает CPL.
- **Шаблоны:** блоки различаются по CPL, или план CPL3 не допускает шаблонов с правилами CPL0 (`CLI`/`STI`, `INVLPG`, `RDTSC`, `HLT`). `PUSHF` — с правилами CPL3 (VM и RF в образе сброшены). `POPF` в шаблонах — только с правилами IF/IOPL для CPL3 либо не допускается на CPL3.
- **Выравнивание:** при AM ∧ AC на CPL3 сгенерированный код не допускается — шаблоны не проверяют выравнивание.
- `SYSCALL`, `INT n`, `IRETQ` и исключения выходят в общий шаг.
- **FS/GS-операнды** (доступ к TEB): шаблоны — по профилю медленных выходов (правило замеров `AGENTS.md`).
- Без глобального состояния CPL — готовность к turbo на нескольких vCPU (S6-43b, S8-24).

Запись в ADR-0022 — дополнением при C5.

## Альтернативы

- **Продолжать белый список по формам** — отвергнуто (решение 1): сотни итераций, нет систематической проверки привилегий.
- **Отдельный исполнитель CPL3** — отвергнуто: две семантики одного CPU.
- **`#UD` для любого необъявленного признака, включая реализованные формы** — отвергнуто (ревью, B1). Набор не проверяет CPUID для реализованных форм, а Linux-нагрузки `stage4a-apic` и S6-22 исполняют SSE на CPL3 при профиле без SSE: правило сломало бы эталоны Linux и изменило бы поведение профилей. Монотонное правило (решение 5) меняет только то, что сейчас и так останавливается.
- **`Unsupported` вместо `#UD` для необъявленного и нереализованного** — оставлено только режимом `stop` (решение 5). Процессор без признака отвечает `#UD`, и код под `__try` может на это полагаться.
- **Сохранить списание бюджета по итерации на CPL3** ради прежних эталонов — отвергнуто (решение 3): одно правило для обоих CPL.
- **Сразу отключить KVA shadow профилем** — отложено (решение 6): это меняет идентичность CPU без замера и без источника.

- **CPU_CONTRACT:**
  - раздел S4-39a и подсрезы белого списка становятся историей со ссылкой сюда;
  - новый раздел «Классификация CPL3» — таблица классов по операциям (из функции классификации) и таблица признаков решения 5;
  - по каждому профилю — перечень «реализовано, но не объявлено».
- **Тесты:** ожидания `crates/od-isa/tests/cpl3_profile_set.rs` меняются намеренно — запрещённые формы вместо `Unsupported` дают `#GP(0)`/`#UD` по классу или исполняются; ожидания `crates/od-isa/tests/s2_39_cpl3_sse.rs` и `cpl3_profile_set.rs` для наборов без FP-члена — по решению 2. Каждое изменение называется в отчёте среза.
- **Linux:** путь CPL3 меняется целиком. В C2a эталон S6-21 обязан совпасть поле в поле. В C2b он перезаписывается с разницей (решение 3).
- **MACHINE_CONTRACT и runner:** счётчик и первый случай `#UD` необъявленных признаков в отчёте прогона, режим `--undeclared-isa` (решение 5).

- **KVA shadow** открывает на CPL0 пути KVASCODE, которые до первого CPL3 не исполнялись: возможны новые остановки набора CPL0.

| C2a | Классификация вместо белого списка для класса `Neutral` (решение 1), перенос параллельных путей в общее ядро, одна FP-ячейка (решение 2), split lock (решение 4); учёт REP и политика `#UD` — прежние. Подробности — ниже | C1 |
| C2b | Правило REP набора CPL0 для CPL3 (решение 3): удаляется `cpl3_rep_string`, новый эталон S6-21 с разницей поле за полем, замер цены итерации и задержки прерываний на длинных пользовательских REP | C2a |
| C2c | `#UD` для необъявленного и нереализованного (решение 5): таблица признаков, маркер, режим `--undeclared-isa`, счётчик в отчёте, перечень «реализовано, но не объявлено» по профилям (тест), правка ADR-0013, решение 4 ссылкой | C2a |
| C3 | Сценарии платы байт в байт (подробности — ниже) | C2a; предусловие ниже |
| C4 | прогоны Windows по остановкам; первый прогон — замер CPL3 и счёт записей CR3 на `SYSCALL` (подтверждение факта 4) | C3 |

| C6 | замер KVA shadow и решение по листу 7 (решение 6) | данные C4/C5 |

**C1 — подробности.**
- Функция классификации и слой привилегий CPL3: классы `Privileged`, `Cr4Gated`, `IoplSensitive`, `CplSpecific`, включая `IRETQ` CPL3 → CPL3, `LSL`/`LAR` с декодированием и `VERR`/`VERW`; `#AC` (решение 4); порядок проверок.
- **C1 наблюдаем, а не каркас:** вход CPL3 для классов, отличных от `Neutral`, уже идёт через классификацию (`#GP(0)`/`#UD`/исполнение по правилу вместо `Unsupported` белого списка). Для `Neutral` решает прежний список.
- **Модельный тест** против независимой модели SDM гоняется по байтам кодировок со всеми вариантами REX/ModRM, независимо от `cpl3_class`: ошибка классификации видна как расхождение с моделью. Матрица: CPL {0, 3} × IOPL {0…3} × достижимое политикой CR4.
- CR4.TSD, PCE, UMIP, FSGSBASE, OSXSAVE, PKE политика не допускает (они = 0). Их ветки проверяются статически: `const`-проверки, что политика CR4 их исключает, и тест решающей функции «класс × CR4 × CPL → исход» по всем значениям битов вне набора.
- Тест `IRETQ` CPL3 → CPL3 с установкой бита Accessed дескрипторов CS/SS.

**C2a — подробности.**
- Классификация заменяет белый список для класса `Neutral`, второе декодирование уходит. Параллельные пути переносятся или переименовываются в общее ядро (решение 1).
- **Критерий переноса:** каждая форма, которую принимали `cpl3_allows`, `step_cpl3_xmm` и `cpl3_scalar_fp_form`, исполняется новым путём с тем же результатом. Регрессионный тест генерируется из старых путей **до их удаления**: перечень принятых форм и их результаты на наборе входов фиксируются тестом на старом коде и сверяются на новом.
- Намеренно меняемые ожидания — `s2_39_cpl3_sse.rs` и `cpl3_profile_set.rs` для наборов без FP-члена (решение 2).
- Учёт REP прежний: `cpl3_rep_string` остаётся для своих форм, остальные строки — по правилу набора. Политика `#UD` прежняя.
- **Эталон S6-21 совпадает поле в поле.**
- До кода — статическое покрытие декодера пользовательских образов: `od-runner decode-coverage --cpl 3`.
- Тесты: дифференциальный CPL0 ↔ CPL3 утверждает, что **каждый вариант `Neutral` покрыт** (состояние и память равны на пользовательских страницах); отдельно — U/S- и R/W-отказы.

**C3 — подробности.**
- Сценарии платы байт в байт:
  - заглушка системного вызова ntdll — `SYSCALL` и `INT 0x2E`;
  - вход и выход KVA shadow с двумя CR3;
  - `RtlCaptureContext` и восстановление контекста (`IRETQ` CPL3 → CPL3);
  - `RtlGetCurrentProcessorNumber` через `LSL` с дескриптором GDT `0x50`;
  - пользовательский `#PF` с повтором;
  - `INT 0x29`;
  - `RDPMC` → `#GP(0)`.
- **Предусловие:** сверить поле IST у векторов 3, 0x29, 0x2C, 0x2D в IDT Windows (снимок остановки). `INT3`/`INT n` через IST-шлюз — отказ `UnsupportedIst`, ISSUE-710: при IST ≠ 0 этот пункт ISSUE-710 закрывается до C3.

## Проверки (общие для срезов)

- Функция классификации исчерпывающая (`match` без `_`).

- Для каждого среза — инъекции, которые тесты обязаны поймать.
- Полные наборы `od-isa`, `od-machine`, `od-runner`, а для изменений входа и шага ещё `od-testkit`, `od-host`, `od-jit` — один раз на итоговом коде.
- `firmware_boot_smoke`.
- Рецепт Linux S6-21 (`stage4a-apic`). Поля делятся на **семантические** — `exit_kind`, ретирации, ретирации CPL3, прерывания, исключения по векторам, COM1, `--verify-report`, состояние в записи остановки — и **статистические** — статистика кэша выборки, обходов, turbo, время. Семантические совпадают поле в поле в C1, C2a, C2c и перезаписываются с разницей в C2b; статистические могут меняться, с разбором.

## Открытые вопросы

1. При каких условиях ядро ставит флаг `0x7ffe0308` (`INT 0x2E` вместо `SYSCALL`) — не разобрано; модель обязана поддерживать оба пути (C3).
2. Какой способ номера процессора выберет ядро для `RtlGetCurrentProcessorNumber` при нашем профиле (факт 3) — по C4.
3. Объём класса `NotAtCpl3` после C1: какие из сегментных загрузок и дальних переходов понадобятся Windows x64 без WoW64 — по остановкам C4.
4. Порог «скорости не хватает» для запуска C5 параллельно с C4 — по первому замеру C4 (решение 7).
