# ADR-0002: библиотеки общего назначения разрешены

- **Дата:** 22 октября 2026 года.
- **Статус:** принято пользователем.
- **Связанные документы:** [политика зависимостей](../policies/DEPENDENCIES.md), [ADR-0001](ADR-0001-dependencies-and-boundaries.md), [правила агентов](../../AGENTS.md).

## Основание

Пользователь согласовал использование готовой инфраструктуры при сохранении собственной реализации ключевой технологии. Это уточняет исходный запрет любых сторонних runtime-пакетов. Выбор библиотеки в критичном по производительности участке по-прежнему требует воспроизводимых замеров.

## Решение

Разрешить runtime/dev/build-библиотеки общего назначения: логирование, CLI, конфигурацию, сериализацию, коллекции, очереди, синхронизацию, асинхронную инфраструктуру, системные bindings, криптографические примитивы и инструменты проверки/измерений.

Собственными остаются x86-семантика/decoder/interpreter, IR, ARM64 emitter/JIT, MMU и модель памяти, виртуальное оборудование, firmware, TPM-протокол, собственные драйверы, графическая трансляция и семантика собственных дисковых форматов. Готовые реализации этих компонентов нельзя подключать прямо, транзитивно или переносить исходниками.

Граница проходит по ответственности, а не имени языка/пакета. Например, библиотека сериализации допустима, но наш wire format, его ограничения и поведение проектируем сами. Общие коллекции допустимы внутри JIT, но готовый JIT/compiler backend — нет.

## Последствия и проверка

- Разрешённые пакеты добавляются при реальной необходимости без повторного согласования каждого пакета с пользователем; назначение, версии, features, происхождение и транзитивные зависимости фиксируются по политике.
- Не вводится список автоматически выбранных пакетов и не добавляются зависимости «на будущее».
- Выбор на горячем пути подтверждается замерами; этот ADR не утверждает ускорение и не заменяет benchmark report.
- Синхронизированы корневые/вложенные инструкции, архитектура, roadmap, карта проекта и критерии S0-01.
- Это изменение политики и документации. CPU-прототип и завершение иных задач этапа 0 им не подтверждаются.

## Условие пересмотра

Пересмотреть конкретную зависимость, если она заменяет собственный ключевой компонент, нарушает target/ABI-ограничения либо не соответствует измеренным требованиям. Самостоятельность технологии не отменяется удобством внешнего пакета.
