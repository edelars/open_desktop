# ADR-0012 — Транспорт установочного носителя Windows

**Дата:** 2026-11-20

**Задача:** [S7-35](../plans/STAGE_7.md#s7-35-транспорт-установочного-носителя-windows)

**Статус:** направление одобрено Sol High. Приёмка официального носителя открыта.

Готовим установочный диск на host, с обычным GPT, FAT32 ESP и существующим
NVMe namespace с логическими секторами 512 байт. Разбор источника и запись
формата принадлежат `od-storage`. `od-image-tool` принимает пути, удерживает
lease источника и публикует новый raw-файл без замены существующего. Первый
срез принимает ограниченный ISO-9660 и проверяется собственным EFI-приложением
до его запуска с конвертированного ESP. Для Windows потребуются UDF и
поддержка исходного WIM. [Карта проекта](../PROJECT_LAYOUT.md).

Первый срез принимает первичный том ISO-9660 Level 1 с дескриптором и
структурой файлов версии 1, логическими блоками 2048 байт и одним extent
на файл. Переносятся обычные файлы и каталоги с именами 8.3. Глубина
ограничена восемью уровнями, включая корень, а число записей данными
формата и лимитом импорта 65 536. Дополнительные деревья, Rock Ridge,
Joliet, UDF, interleave и многотомность требуют отдельной поддержки.

Проверенный в S7-30 ISO занимает 9 047 330 816 байт. Его каталог El Torito
задаёт UEFI-запись с platform ID `0xEF`, image RBA 536 и sector count 1.
UEFI 2.11 в этом случае определяет раздел до конца носителя. FAT12-том
в `efisys.bin` занимает 1 474 560 байт и содержит 512-байтные блоки.
Путь CD-ROM в UEFI завершает работу при передаче управления ОС, где PCI
namespace по-прежнему распознаётся как NVMe. Microsoft документирует
поддержку 512- и 4096-байтных секторов для дисковых устройств Windows.
2048-байтный namespace выходит за эту границу. 4Kn с представлением
2048-байтных блоков на уровне firmware потребовал бы отдельной проверки
поиска UDF и источника установки после `ExitBootServices`. [Аудит носителя](../specs/WINDOWS_PLATFORM_REQUIREMENTS.md#1-носитель-и-цепочка-загрузки-наблюдения-в-iso), [UEFI 2.11 §13.3.2.1](https://uefi.org/specs/UEFI/2.11/13_Protocols_Media_Access.html#iso-9660-and-el-torito), [политика секторов Windows](https://learn.microsoft.com/en-us/troubleshoot/windows-server/backup-and-storage/support-policy-4k-sector-hard-drives).

`sources/install.wim` занимает 8 155 984 950 байт. Размер одного файла
в FAT32 ограничен 4 294 967 295 байтами. Конвертер проверяет совместимость
источника до создания выходного файла. Windows Setup принимает набор
`sources/install.swm`, `sources/install2.swm` и следующих частей,
подготовленных штатной командой `DISM /Split-Image` на Windows.
Ручное получение SWM само по себе оставляет исходный критерий S7-35
открытым. Для приёмки нужен проверенный путь подготовки официального
носителя из ISO без ручной подготовки. [Инструкция Microsoft](https://learn.microsoft.com/en-us/windows-hardware/manufacture/desktop/install-windows-from-a-usb-flash-drive#if-your-windows-image-is-larger-than-4gb).

В будущей настройке VM установочный носитель отображается отдельным
диском. Импорт должен явно сообщать о неподдерживаемом источнике до
изменения конфигурации VM. Проверка установки Windows относится к
гостевому сценарию S7-32.

## Описание форматов

- ISO-9660. [ECMA-119, 5-е издание, декабрь 2024](https://ecma-international.org/wp-content/uploads/ECMA-119_5th_edition_december_2024.pdf).
- GPT. [UEFI 2.11, глава 5](https://uefi.org/specs/UEFI/2.11/05_GUID_Partition_Table_Format.html).
- FAT. [UEFI 2.11, §13.3](https://uefi.org/specs/UEFI/2.11/13_Protocols_Media_Access.html#file-system-format).
