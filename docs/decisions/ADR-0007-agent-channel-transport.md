# ADR-0007 — Канал гостевого агента: второй UART как COM2

**Дата:** 2026-11-22
**Задача:** [S11-20](../plans/STAGE_11.md#s11-20-adr-0007-и-протокол-гостевого-агента)
**Статус:** предложен. Выбор канала (COM2, 16450) рекомендован Opus high; ждёт независимого ревью документа и подтверждения владельца (см. «Вопрос владельцу»). Пока ответ не записан, плата v0.1 и [VIRTUAL_BOARD.md](../specs/VIRTUAL_BOARD.md) не меняются; код канала не пишется.

## Вопрос

Каким устройством платы гостевой агент (буфер обмена, время, shutdown, передача файлов) разговаривает с VMHost. Протокол поверх выбранного канала — [AGENT_PROTOCOL_V1.md](../../protocols/guest/AGENT_PROTOCOL_V1.md).

## Контекст

- Плата v0.1 имеет один UART: COM1 (`I/O 0x3F8`, IRQ4), назначение — диагностика ([VIRTUAL_BOARD.md](../specs/VIRTUAL_BOARD.md), строка «Диагностика»). Строка «Не включено» ([VIRTUAL_BOARD.md](../specs/VIRTUAL_BOARD.md), строка 27) говорит: «Остальное добавлять по отдельным требованиям и этапам». Дополнительных USB-функций в v0.1 нет; сеть — только модель 82540EM, которой ещё нет (PCI — S4-30 не выполнена).
- Модель [uart16550.rs](../../crates/od-machine/src/uart16550.rs) (`Uart16550PollingTx`): байтовый PIO, один байт RX (`inject_received_byte`, повторная инъекция при занятом RBR — `Busy`), THR плюс сдвиговый регистр, IER bits 0..3 с источниками RDA и THRE, IIR, MCR OUT2 как затвор линии прерывания, LCR/DLL/DLM (делитель только хранится, времени нет), SCR. FCR принимается, но IIR[7:6] остаётся 0, поэтому драйвер распознаёт 16450 без FIFO (S4-38L9z, тест `kernel_probe_sequence_after_fcr_reads_as_a_16450`). Loopback (MCR bit 4) отказывает, MSR всегда 0. Часть семантики записана «по памяти из даташита» и не сверена с первоисточником ([MACHINE_CONTRACT.md](../specs/MACHINE_CONTRACT.md), раздел UART).
- Путь IRQ уже есть в ограниченном виде: S4-24e (`Stage4UartIrqProbe`, затем `InterruptPump`) маршрутизирует линию COM1 в IOAPIC INTIN4, LAPIC и гостевой обработчик ([MACHINE_CONTRACT.md](../specs/MACHINE_CONTRACT.md), раздел S4-24e). На прочих платах (firmware board, плоские probe) линия не подключена.
- `0x2F8–0x2FF` на Linux-профиле firmware board занят привязкой absent UART (S7-31j, `crates/od-machine/src/absent_ports.rs:39-42`, `:59`; `firmware_board.rs:4648-4653`): отсутствующий UART читается как `0xFF`.
- Родительская задача [S4-24](../plans/STAGE_4.md#s4-24-uart-16550a-сначала-polling-затем-irq) остаётся открытой; регистровую модель UART ведёт этап 4.
- Собственных гостевых драйверов нет (`guest/*/drivers` пусты), PCI на плате нет, Windows и Linux в гостях не приняты как продуктовые. CPU-путь `IN AL,DX`/`OUT DX,AL` сейчас адресует только COM1.
- Правила проекта: чужие эмуляторы устройств и готовые virtio-драйверы не входят в реализацию, публичные спецификации использовать можно, реализацию пишем сами ([ROADMAP.md](../ROADMAP.md)); решения по скорости — по замерам ([AGENTS.md](../../AGENTS.md), «Решения в критичных по производительности участках»).

## Варианты

| Вариант | Гостевая сторона | Что нужно на плате | Оценка |
|---|---|---|---|
| А. Второй 16550-совместимый UART, COM2 (`0x2F8–0x2FF`, IRQ3), профиль 16450 | inbox-драйверы последовательного порта обеих ОС; PCI не нужен | второй экземпляр существующей модели; IRQ3 в IOAPIC (по образцу S4-24e); описание порта в ACPI (нужно Windows; для Linux — по версии ядра) | байтовый поток, низкая пропускная способность, дешёвый старт |
| Б. Собственное PCI-устройство с кольцами | собственные драйверы Windows и Linux | PCI (S4-30), BAR, MSI/INTx, DMA-кольца | быстро; зависит от PCI и от драйверов, которых нет |
| В. USB CDC-ACM | inbox-класс USB обеих ОС (наличие не проверено по первичному источнику) | xHCI с дополнительной функцией и конечными точками bulk | отклонён для v1, см. ниже |
| Г. virtio-console | Linux — inbox; Windows — драйвер вне ОС | PCI, virtio-транспорт | отклонён |
| Д. vsock (virtio-vsock) | то же, что Г | PCI, virtio-транспорт | отклонён |
| Е. TCP через NAT | сетевой стек гостя | NIC 82540EM, NAT backend, TCP/IP на host | отклонён |

## Решение

**Канал агента v1 — второй UART как COM2.**

1. **Устройство.** Порт `0x2F8–0x2FF`, IRQ3, тот же `Uart16550PollingTx`, второй экземпляр с параметрами порта; файл модели не копируется.
2. **Профиль 16450 без FIFO.** `IIR[7:6] = 0` при любой записи FCR, как у COM1. Поэтому шаг 1 задачи S11-21 («FIFO 16 байт с обеих сторон») этим решением заменяется: RX — один байт с `LSR.DR`, дальнейшие байты ждут в ограниченной host-очереди и подаются при `DR = 0`; TX — THR плюс сдвиговый регистр, host-очередь ограничена. Потеря байта (переполнение очереди) учитывается счётчиком; `LSR.OE` — только если регистровая модель этапа 4 его вводит (решает S4-24). Числа очередей — в S11-21.
3. **Путь IRQ.** Линия COM2 идёт в IOAPIC INTIN3 по образцу S4-24e (при тождественном ISA-отображении; не проверено). Общий механизм принадлежит S4-24; S11-21 не реализует IRQ сам. Проверочный probe S11-23 работает опросом LSR и IRQ не требует. Настоящим агентам в ОС IRQ3 нужен: см. «Открытые вопросы».
4. **COM1 не трогается.** Семантика, адреса, IRQ4 и тесты COM1 остаются как есть; тесты COM1 проходят без правки ожиданий.
5. **Протокол не зависит от устройства.** [AGENT_PROTOCOL_V1.md](../../protocols/guest/AGENT_PROTOCOL_V1.md) описывает кадры в упорядоченном байтовом потоке с возможной потерей байтов и не использует скорость, FIFO, IRQ и регистры. Переход на вариант Б меняет гостевой транспорт агента и ABI VMHost, но не формат кадров.
6. **Согласование с S4-24.** Регистровую модель UART, FIFO-семантику (если она появится) и IRQ ведёт S4-24 этапа 4; S11-21 добавляет второй экземпляр, привязку `0x2F8–0x2FF` в `bus.rs` и host-очереди. Любое изменение общей регистровой семантики идёт через ветку S4-24 с регрессией по COM1; если S4-24 когда-либо включит FIFO 16550A, профиль COM2 останется 16450 явным параметром экземпляра (решение: потоковый агент не нуждается в FIFO, а лишняя семантика увеличивает риск).

### Почему не остальные варианты

- **Б (собственное PCI-устройство с кольцами)** отложено, не отклонено: нужны PCI (S4-30), собственные драйверы обеих ОС (на 2026-11-22 их нет; подпись Windows-драйвера — отдельная задача этапа 8, не изучена), то есть гораздо больший объём работ до первого результата. Порог перехода — ниже.
- **В (USB CDC-ACM)** требует xHCI с дополнительной функцией (в v0.1 их нет; xHCI и доставка ввода сами ещё blocked), дескрипторов, конечных точек bulk и колец передач. Это тоже изменение платы, но с большей реализацией, чем у А. Пересматривается вместе с Б по тем же замерам.
- **Г и Д (virtio-console, vsock)** в Windows требуют драйвера вне ОС; готовые virtio-драйверы запрещены [ROADMAP.md](../ROADMAP.md), а собственные драйверы под чужой ABI дают сложность Б без его свободы выбора формата. Нужны PCI и virtio-транспорт, которых нет.
- **Е (TCP через NAT)** требует NIC (S4-30, S11-32), NAT backend и стека TCP/IP на host (ADR-0008 ещё не принят), а NAT запрещает входящие соединения, так что гостю нужен специальный адрес host с listener. Канал не должен зависеть от сети: у машины может быть `network = 0`. Это превращает недоверенный сетевой стек в зависимость управления.

### Порог перехода с А на Б

Решение А — предварительная гипотеза до замера ([AGENTS.md](../../AGENTS.md)): пропускная способность и стоимость не измерены, обещаний нет. Замер выполняется по probe S11-23 и в S11-25 на сценариях «60 000 байт буфера обмена в каждую сторону» и «файл 1 MiB host → гость», в обе стороны по возможности, не менее 5 прогонов, через `nice` с итоговым значением `-5`, с записью конфигурации железа и сборки. Измеряются:

- **T1** — устойчивая пропускная способность по payload (байт/с, медиана и разброс);
- **T2** — CPU host на байт payload (нс/байт процесса VMHost) и доля одного ядра при насыщении;
- **T3** — число исполненных гостевых инструкций (или PIO-обращений) на байт payload.

Начальные пороги (гипотеза, подтверждаются или заменяются первым замером): вариант А недостаточен, если T1 ниже 64 КиБ/с, или T2 при насыщении занимает более 25 % одного ядра host, или принятая задача, использующая этот канал (например, общие папки по решению S11-26), требует устойчивой скорости выше измеренной T1. При срабатывании порога готовится новый ADR о варианте Б (или В) с тем же протоколом кадров.

## Вопрос владельцу

Плата v0.1 имеет один UART; строка «Не включено» [VIRTUAL_BOARD.md](../specs/VIRTUAL_BOARD.md) (строка 27) говорит «добавлять по отдельным требованиям и этапам». Вопрос: допускается ли второй 16550-совместимый UART (COM2, `0x2F8`, IRQ3) как канал агента и изменение строки «Диагностика» (один UART → два)?

**Ответ владельца:** ожидается (вопрос поставлен 2026-11-22). Рекомендация Opus high: допустить. Дата и текст ответа записываются здесь. До ответа не меняются VIRTUAL_BOARD.md и `bus.rs`; это граница между S11-20 и S11-21.

## Последствия

- S11-21 реализует второй экземпляр как профиль 16450 (без FIFO) и host-очереди; её текст в плане (шаг 1, «FIFO 16 байт») нужно исправить в соответствии с пунктом 2 решения; строка «Диагностика» в VIRTUAL_BOARD.md меняется там же и только после ответа владельца.
- S11-21 снимает `AbsentPortRegion::Uart2` с плат с COM2 и обновляет тесты S7-31j/k (`firmware_board.rs:9022-9026`).
- S11-22 (сервис агента), S11-23 (probe) и агенты реализуют [AGENT_PROTOCOL_V1.md](../../protocols/guest/AGENT_PROTOCOL_V1.md) независимо.
- S11-23 blocked, пока CPU PIO-путь не адресует диапазон COM2 (сегодня только COM1) и пока нет сессии S10-09.
- Скорость канала мала и ограничена стоимостью одного PIO-обращения на байт; файлы больших размеров и общие папки этим каналом могут не обслуживаться. Решение — по замеру и порогу выше, не по предположению.

## Открытые вопросы

1. Ответ владельца (см. выше).
2. Перечисление COM2 в гостях: Windows требует описания порта в ACPI: генератор DSDT уже умеет COM на `0x2F8`/IRQ3 (`firmware/uefi/src/acpi/dsdt/tests.rs:191`, `:222`), нужна запись COM2 в манифесте платы; поведение Linux 8250 (автоопределение, тест loopback при `MCR = 0x1A`, номер устройства для `0x2F8`) не проверено по первичному источнику. Модель отказывает loopback (S4-38L7br), как и для COM1. Проверка — S11-21 (уровень регистров) и S11-27/28 (в ОС); при необходимости изменение регистровой модели идёт через S4-24.
3. IRQ3 в IOAPIC на плате с прошивкой и ACPI MADT (override не нужен при тождестве, не проверено): путь есть для COM1 только в профиле S4-24e; для агентов в ОС он обязателен до S11-27/28.
4. Привилегия смены системного времени в госте (Windows и Linux) отличается от привилегии shutdown и не даётся обычному пользователю: схема запуска агента (служба или пользовательская программа) — решение S11-27/28; протокол допускает ответ «нет привилегии».
5. Семантика `SHUTDOWN_DONE` и сброс дисков: см. [AGENT_PROTOCOL_V1.md](../../protocols/guest/AGENT_PROTOCOL_V1.md), раздел 6; решение о том, ждать ли после `DONE` остановки гостя, принадлежит S11-22.

## Условие пересмотра

Срабатывание порога T1/T2 (см. выше), появление PCI и собственных драйверов (S4-30, этапы 5/8), отказ владельца от второго UART (тогда пересматриваются варианты Б и В), либо обнаружение, что inbox-драйвер одной из ОС не работает с профилем 16450 на COM2.
