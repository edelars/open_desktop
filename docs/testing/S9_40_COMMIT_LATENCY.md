# S9-40: стоимость durable commit по числу F_FULLFSYNC-барьеров

Статус: измерение latency на одной машине. Документ не делает выводов о гарантиях долговечности и не выбирает схему; он даёт только цену барьеров в миллисекундах на commit.

## Что сравнивается

Все схемы идут через `od_host::storage_io::HostFileStorage` (эксклюзивный `flock`, `write_at` с проверкой identity, `flush_file_durable` = `fcntl(F_FULLFSYNC)`). Размеры взяты из `crates/od-storage/src/cow_proto.rs`: блок 512 Б, слот корня 512 Б, запись карты 12 Б, заголовок 2 слота (1024 Б).

| Схема | Что делает commit | Барьеров |
|---|---|---|
| A, RAW-подобная | запись 1 блока 512 Б in-place, затем барьер | 1 |
| B, CoW 1 барьер | `set_len`, append 4 блоков (2048 Б) + карта (64 записи, 768 Б) + копия корня (512 Б), барьер, затем запись корня в неактивный слот без барьера | 1 |
| C, CoW 2 барьера | как B до первого барьера; корень в неактивный слот (`gen & 1`), второй барьер | 2 |
| D, CoW 3 барьера | копия корня N+1 (512 Б), барьер; затем 4 блока + карта, барьер; затем корень в слот, барьер | 3 |

Схема B является только моделью стоимости (один барьер, нет упорядочивающего барьера перед корнем). Она не является безопасным протоколом и не предлагается как вариант. Схема D моделирует только число барьеров из варианта решения ISSUE-057; порядок и расположение копии корня в ней упрощены до отдельного append перед данными.

Размер transaction одинаков для B, C, D: 4 блока по 512 Б данных, карта на 64 логических блока (768 Б), корень 512 Б; для A один блок 512 Б.

## Методика

- На схему: 50 прогревочных commit (не учитываются) и 300 измеряемых; 5 прогонов (run1..run5), каждый прогон создаёт свой новый файл через `create_new_exclusive`. Порядок внутри прогона A, B, C, D; файл удаляется сразу после прогона.
- Wall-clock каждого commit через `std::time::Instant` вокруг полного commit (включая `set_len`, записи, барьеры, проверку identity внутри `write_at`). Верификация в замер не входит.
- Корректность: после каждого commit (включая прогрев) файл читается через независимый read-only дескриптор и сверяется. Для A сверяется записанный блок. Для CoW сверяются CRC и generation слота корня, его `end_offset`, совпадение копии корня со слотом, CRC и смещение карты, данные и CRC каждого из 4 блоков, размер файла. Расхождений не было (иначе бенчмарк завершился бы паникой).
- Статистика: p50, p90, p99, mean по всем 1500 измерениям схемы (5 x 300), линейная интерполяция перцентилей; разброс между прогонами = стандартное отклонение (выборочное, n=5) соответствующей метрики, посчитанной по каждому прогону отдельно.
- Cold: run1 (первый прогон процесса, первые созданные файлы); warm: run2..run5. Под cold здесь понимается именно это; кэш накопителя и контроллера не сбрасывался.
- Условия: питание от сети, Mac без другой намеренной нагрузки, но фоновые процессы системы не отключались.
- Сырые данные: `results.csv` (схема, run, commit_index, latency_ms), 6000 строк, хранится вне репозитория в каталоге scratchpad сессии (`s9bench-run1/`). Код бенчмарка — отдельный cargo-проект в scratchpad (`s9bench-src/`, подключает `od-host` и `od-storage` по path); в репозиторий не добавлялся.

## Стоимость барьера

- C минус B (один дополнительный барьер, остальная работа та же): p50 +4.03 мс, mean +4.14 мс.
- D минус C (ещё один дополнительный барьер плюс отдельный append копии корня): p50 +4.07 мс, mean +4.43 мс, p99 +7.78 мс.
- D дороже C в 1.46 раза по p50, в 1.50 раза по mean, в 1.70 раза по p99.
- D дороже A в 3.2 раза по mean (13.35 против 4.21 мс); C дороже A в 2.1 раза.
- B минус A: +0.57 мс по mean: накладные расходы CoW-записей (`set_len`, append нескольких диапазонов, запись слота) без учёта барьеров.

Итого цена одного дополнительного F_FULLFSYNC на этой машине около 4 мс на commit (p50), при этом хвост p99 растёт заметно сильнее медианы (в D до 19 мс).

## Ограничения

- Измерение на уровне процесса и файловой системы; сбой питания не моделировался и не выполнялся. Документ ничего не говорит о том, переживает ли какая-либо схема потерю питания.
- Кэш накопителя и контроллера не контролируется; фактическая работа, выполняемая `F_FULLFSYNC` на встроенном SSD, не наблюдаема. Для внешних накопителей или иных файловых систем цифры могут отличаться кратно.
- Одна машина, одна ОС, один том, одна сессия измерений; независимого повтора в другие дни и при других тепловых режимах нет. Фоновая нагрузка системы не исключалась.
- Файлы лежали в scratchpad на системном томе данных (APFS); нагрузка на том ограничена этими файлами, но том почти заполнен на 89% и разделяется с остальной системой.
- Схема B не является безопасным протоколом; схема D упрощена (см. выше). Результаты не показывают, что протокол C или D корректен.
- 300 commit на прогон ограничивают оценку p99 (около 3 наблюдений выше p99 на прогон); p99 по 1500 точкам устойчивее, но хвост определяется редкими выбросами.
- Малый размер transaction (4 блока); при больших transaction доля передачи данных относительно барьеров растёт, и вывод о цене барьера нужно проверять заново.
