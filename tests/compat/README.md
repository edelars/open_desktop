# Совместимость: сценарии и матрица

Каталог межкомпонентных проверок совместимости гостя с приложениями и сценариями. Нормативная методика — [docs/testing/WINDOWS.md](../../docs/testing/WINDOWS.md), план — [этап 8](../../docs/plans/STAGE_8.md).

Что лежит здесь:

- [WINDOWS_MATRIX.md](WINDOWS_MATRIX.md) — матрица «сценарий × статус» для Windows-гостя (статусы «не запускается» / «запускается с ограничениями» / «проходит приёмку»);
- `payloads/` — собственные манифесты диска полезной нагрузки (какие файлы, их SHA-256, источник; формат — S8-27, `od-image-tool make-data-disk`); сейчас там только тестовый пример `stage0-fixtures.example.json` на собственных fixtures, манифестов дистрибутивов приложений нет;
- [windows_collect_logs.py](windows_collect_logs.py) — сбор журналов Windows с остановленного образа в режиме чтения (S8-12; описание запуска — раздел «Журналы с диска» в [WINDOWS.md](../../docs/testing/WINDOWS.md));
- [test_windows_collect_logs.py](test_windows_collect_logs.py) — тесты сборщика (`python3 -I tests/compat/test_windows_collect_logs.py`);
- `.gitkeep`.

Чего здесь быть не должно:

- дистрибутивов приложений, образов Windows, установочных носителей, виртуальных дисков, пакетов обновлений и аварийных дампов (рабочие файлы — в `work/stage8/<run-id>/`, он игнорируется Git);
- ключей, паролей, ключей продукта, сертификатов подписи;
- результатов, полученных с обходом проверок (`LabConfig`, отключённый Secure Boot, удалённый TPM, `testsigning` и т. п.), под статусом «проходит приёмку»;
- записей о статусе выше «не запускается» без run-id и nonce-маркера текущего прогона;
- описаний будущей функциональности как найденных проблем (для этого есть [KNOWN_ISSUES.md](../../docs/KNOWN_ISSUES.md) только для реально найденных дефектов).
