# Rust workspace

Читать корневой `AGENTS.md`, `docs/PROJECT_LAYOUT.md` и `README.md` конкретного crate.

| Crate | Размещать здесь |
|---|---|
| `od-isa` | x86 CPU state, decoder, эталонный interpreter и архитектурная семантика |
| `od-jit` | Собственный IR, ARM64 lowering/emitter, allocator, dispatcher и кеш кода |
| `od-machine` | Гостевая RAM/MMU/TLB, bus, модели устройств, vCPU scheduling и виртуальное время |
| `od-storage` | RAW/будущий CoW, дисковые метаданные, сериализация состояния и контейнер снимка |
| `od-host` | macOS host-примитивы, JIT memory, OS I/O и входная host-граница C ABI |
| `od-testkit` | Генераторы собственных тестов, сравнение состояния и уменьшение ошибок; только проверки |

Правила:

- Внутри crate код размещать в `src/`, локальные интеграционные тесты — в его `tests/` при необходимости. Межкомпонентные сценарии — в корневом `tests/`.
- `od-isa` не зависит от JIT, machine, storage, host или testkit. Production-код не зависит от testkit; допустимы только обоснованные dev-dependencies без циклов.
- Целевая схема зависимостей указана в карте. Пустые crates ещё не требуют всех будущих зависимостей: добавлять path dependency только вместе с реальным использованием.
- Не связывать `od-jit` с `od-machine` циклом. Узкий runtime-контракт для JIT принадлежит нижнему слою или стороне, которая его вызывает, и реализуется верхним слоем.
- Не создавать `common`, `utils` и универсальные crates для обхода ответственности.
- Не выдавать Rust layout за wire/disk format. Адреса гостя, физические адреса и host pointers различать.
- Изолировать `unsafe`, документировать необходимые инварианты. `UnsafeCell` сам по себе не разрешает data races.
- Ошибка гостя — результат архитектурного исполнения, а не host panic. Rust panic не пересекает FFI.
- Нельзя подключать сторонние decoder, assembler, JIT или runtime-пакеты. Системные ABI — через собственный ограниченный слой.
- Нынешние `lib.rs` — только документация каркаса. Не утверждать наличие реализации по факту их сборки.
